你的语言画像:三个方向

产品的命脉是四通道闭环 + gap-(c) 跨端差异,但它的呈现从来是通用组件堆叠: dashboard 是 Card + Chip,词条快照是四个 Material 图标。下面三个方向给它一个 只属于 listen 的图形语言——同一套语言覆盖 dashboard 聚合、词条详情、列表行内三个尺度, 并让「能认不能产出」一眼可读。呈现≠语义:数据与 evidence 门控零改动。

✓ 一套语言 · 三个尺度✓ gap-(c) 一眼可读 ✓ 三态诚实(不藏 unassessed)✓ 16px 行内立得住 ✗ 无庆祝动效✗ 不改数据语义

共享语义 SHARED SEMANTICS

四通道不是并列的四项,是一张 2×2:声音模态(听↔说)与文字模态(读↔写), 各有接收端与产出端。gap-(c) 就住在每一列里——同模态、跨方向:听得懂却说不出,读得懂却写不出。 三个方向共享这张结构与同一套三态色,选型只在「形」。

四轴放射:垂直轴=声音(听上说下),水平轴=文字(读右写左), 轴长=已证实比例,连成风筝。gap-(c) = 形状的上倾。是三案里实现最快的一个。
诚实的证伪:它也是三案里最通用 BI 仪表的一个—— 雷达图属于任何 dashboard 库。三态被挤压:未评估在图形里没有位置,轴长必须归一化, 词库早期(多数 unassessed)整只风筝塌缩成中心一粒,mock 里说/写轴已经贴底; 16px 行内退化成无法解读的歪多边形(左列可见)。列入以完成探索,不推荐。

拍板记录 DECISION · OWNER · 2026-07-23

方向:B 总览 + A 通道细节,词条尺度统一用 B 的小环。 dashboard 顶部一只语言罗盘做画像(聚合环 + gap-(c) 环心);通道分解走回声条 (镜像条 + 回声虚框);词条详情与列表行内一律用 B 的三态四象限环—— owner 裁决:小环比 A 的四小方块更立得住。
acquired 的光 = 信号青(画像与内容同源;colorScheme.primary 映射, AA 由 listen_theme_test 钉住)。
unassessed = 压暗在场 + 悬停显数;聚合尺度不堆三态数字。 gap 标注只并置既有计数(听得懂 46 · 说得出 12),不做前端减法造新指标。

我的私心排序:B 与 A,C 出局。 B(语言罗盘)最有「画像」气质——一个可指认、可截图、可比较的形,上亮下暗即 gap, 是产品名片;弱点是行内尺度只剩三态、且要防健身环即视感。 A(回声条)概念血缘最正(wordmark 双向波形的直系),gap-(c) 的「回声虚框」是三案里 语义最精确的表达,三尺度退化也最稳;弱点是第一眼冲击力弱。 两者可组合:dashboard 顶部一只罗盘做画像,通道细节与词条尺度走回声条语言—— 代价是两套形要维护一致性。请拍板:

  1. 方向:A 全套 / B 全套 / B 总览 + A 细节 / C(不推荐)?
  2. acquired 的光:信号青(画像与内容同源,「光」语言统一)还是 learningRecognized 绿(与词级高亮的既有「已认得」语义一致)?拍板后由 colorScheme 映射,AA 交给 listen_theme_test 钉住。
  3. unassessed 的深度:细暗段/细暗弧的「在场但压暗」是否足够诚实, 还是聚合尺度必须同时裸露三态数字(现稿 dashboard 只裸露 acquired 数)?
