# 内容层 / 获取层 / 准备层 — 产品功能与用户旅程

> 范围：只覆盖内容层、获取层、准备层。学习层与管理层已有实现，不在本文档内。
> 本文档描述目标形态，不代表已实现。

## 0. 一句话

像每日英语听力那样开箱即学；区别是当你想学的东西不在库里，你可以用自己的机器把它变成可学的材料。

## 1. 中心概念：媒体库文件夹

**媒体库文件夹**是用户指定的一个目录。它同时是：

- 获取层的**唯一终点**——下载落在这里，用户自己的文件也放这里；
- 内容层"我的媒体"的**唯一来源**。

这个合并带来三个结果：

1. 「已下载」不再是需要单独追踪的状态，它退化成「这个文件在库里」；
2. `path.contains('[<外部id>]')` 这类文件名猜测可以删除；
3. "下载来的"和"自己放的"在获取层之后合流，准备层只面对一种输入。

**权威归属：Core 是媒体库的权威，文件系统扫描只是发现机制。**
扫描产出路径 → 注册进 Core → 显示 Core 的库。UI 永远不直接渲染文件系统，
否则会出现两个真相源。

---

## 2. 内容层

三个并列的面。它们回答三个不同的问题。

| 面 | 回答的问题 | 内容归属 | 等待 |
| --- | --- | --- | --- |
| **备好的内容** | 我现在能学什么？ | 我们预生成并托管 | 0 秒 |
| **频道** | 我还能学什么？ | 外部目录，尚未获取 | 需获取 + 准备 |
| **我的媒体** | 我手上有什么？ | 媒体库文件夹 | 视资源状态而定 |

### 2.1 备好的内容 —— 方向已定，本阶段不做

我们自己跑完准备层、连媒体一起托管的资源。点开即播、字幕高亮跟随、翻译就位，
**不需要登录、配置、下载或生成**。媒体取自公有领域或明确开放授权的内容，
因此可以连媒体一起分发。

这将来是新用户的默认落点，但**本阶段不实现**。

由此产生的后果必须被诚实对待：在它到位之前，新用户的第一分钟就是"下载 + 生成"，
产品没有零等待的门面。本阶段不应对外宣称开箱即学。

### 2.2 频道

外部内容目录（当前为 YouTube 频道聚合）。它是**发现**，不是拥有：一个频道条目
是"可以获取的东西"，不是"可以学的东西"。条目经获取层进入媒体库后，才成为
"我的媒体"里的一项。

### 2.3 我的媒体

媒体库文件夹的视图——不是"导入过的文件列表"。用户在 Finder 里放进去的文件，
和从频道下载来的文件，在这里没有区别。

---

## 3. 获取层

**唯一职责：把媒体弄进媒体库文件夹，并让 Core 知道它存在。**

### 3.1 三种进入方式

1. 从频道条目下载；
2. 从 URL 导入下载；
3. 用户自己放进去（拖入窗口 = 复制进媒体库文件夹；或直接在 Finder 里放）。

三种方式的终点相同。下载成功不是终点状态——**文件落进文件夹、被扫描发现并注册，
才是终点**。

### 3.2 扫描与注册流水线

```
扫描媒体库文件夹
  → 按扩展名白名单筛出候选
  → 与已注册记录比对（路径 + 大小 + mtime）
  → 新文件：探测 → 注册进 Core → 出现在「我的媒体」
  → 已消失的文件：标记为不可用，不删除记录
```

**识别分三级，昂贵的操作必须惰性执行：**

| 级别 | 手段 | 用途 | 时机 |
| --- | --- | --- | --- |
| 便宜 | 路径 + 大小 + mtime | 判断是否为没见过的新文件 | 每次扫描 |
| 中等 | ffprobe | 时长、是否有音轨 | 首次发现该文件时 |
| 昂贵 | fingerprint | 媒体身份、资源匹配 | 注册时或真正需要时 |

没有音轨的文件不进入列表。

**扫描触发时机**：首次设置、启动时增量扫描、下载完成后、手动刷新。
不做 FSEvents 实时监听（价值不抵复杂度）。

**扫描不得阻塞启动**，必须增量出结果、可中断；离开该界面即停止。

### 3.3 旁挂字幕配对

扫描时，若 `talk.mp4` 同目录下存在同名的 `talk.srt` / `.vtt` / `.ass`，直接配对。

这类文件**不需要经过准备层**，可以零等待开始学。对一个"生成慢"是核心摩擦的产品，
这是性价比最高的一条路径。

### 3.4 下载的状态机

下载仍需完整状态，因为它是有进度、会失败的长任务；但它**不再负责回答"这条内容
是否已获取"**——那个问题问媒体库。

```
none → downloading → completed
                   → failed（可重试，错误可见）
downloading|failed --cancel/dismiss--> none
```

必须复用仓库中已有的 `DownloadController`（含单调 generation 守卫），
不要维护第二套下载状态。当前 discovery 路径的三个缺陷——失败被静默吞掉、
`handle.completed` 的错误无 handler、无 generation 守卫——由此一并消除。

### 3.5 macOS 具体事项

应用未启用 sandbox（`com.apple.security.app-sandbox: false`），因此不涉及
security-scoped bookmark：目录路径持久化后，重启仍可直接读取。

但 TCC 仍然适用：媒体库文件夹若位于 `~/Documents`、`~/Desktop` 或 `~/Downloads`，
系统会弹一次访问授权。这一点必须在首次设置引导里说明，不能以"扫描不到文件"的
形式暴露。

## 4. 准备层

**输入**：一条已在媒体库中的 media。**输出**：可学习的资源。

### 4.1 资源阶梯与"可以开始学"的门槛

| 级别 | 内容 | 解锁的能力 |
| --- | --- | --- |
| L0 | 无 | 仅能当播放器用 |
| **L1** | 字幕文本 | **可查词、可按句导航——此处即可开始学** |
| L2 | 词级时间轴 | 高亮跟随、精确 AB / 单句循环 |
| L3 | 更深层（音素、chunk 等） | 精读能力 |

**「可以开始学」= L1，「完全就绪」= L2 及以上。** 这两者是 UI 上两个不同的信号。

### 4.2 渐进可用

生成不是一个开关，是一个阶梯。转录一落地就让用户进去学，不必等全部完成——
把一次 8 分钟的等待变成 2 分钟后就能开始。

### 4.3 后台队列

生成是后台任务，不是模态等待。用户点完就该能去做别的：浏览、学别的材料、
再排队几条。需要一个可见的任务列表，能看到排队中、进行中、失败、可重试。

这是"睡前排三条，早上起来都好了"这个真实使用模式的前提。

### 4.4 阶段呈现

沿用 `listen-gen` 的 machine-event 阶段名（`validating`、`probing_media`、
`normalizing_audio`、`transcribing`、`building_package`），**不发明百分比进度**。

### 4.5 机器准备引导

每日英语听力零配置，因为它在云端。本地生成必然有前置：ffmpeg / ffprobe、
模型下载、磁盘空间、耗时。

**必须在用户第一次点"生成"之前一次性讲清楚并引导装好**，而不是让它以一串失败
的形式暴露出来。

## 5. 状态模型

### 5.1 媒体状态（一条内容相对于媒体库）

- `notInLibrary` — 频道条目，尚未获取
- `acquiring` — 获取中，带进度
- `acquireFailed` — 获取失败，可重试，错误可见
- `inLibrary` — 在库中，可播放
- `missing` — 库中有记录，磁盘上文件已不在

学习记录挂在 media id 上，不挂路径；文件消失只标记不可用，不删除记录。

### 5.2 资源状态（一条已在库的 media）

- `none` — 没有
- `preparing` — 准备中，阶段可见
- `partiallyReady` — 已达 L1，可以开始学
- `ready` — 已达 L2 及以上
- `failed` — 准备失败，可重试，原因可见
- `undetermined` — Core 未连接或查询失败，答案缺失（不等于"没有"）

### 5.3 可学性

不是独立事实，是上面两条的函数。UI 不得把它存成第三个状态。

## 6. 用户旅程

### 旅程 1 · 新用户第一次打开（依赖「备好的内容」，本阶段不做）

```
启动 → 落在「备好的内容」→ 点一条 → 立即播放并学
```

全程不需要：登录、选文件夹、配置工具、下载、等待生成。

**本阶段的实际首次体验**是落在「频道」，任何一条都要经历获取 + 准备。
媒体库文件夹的设置推迟到用户第一次获取内容、或第一次进入「我的媒体」时，
不放在首次启动。

### 旅程 2 · 设置媒体库文件夹

```
进入「我的媒体」→ 选择文件夹（说明 TCC 授权）→ 增量扫描，边扫边出
  → 已配对旁挂字幕的条目直接标为可学
  → 其余标为「无资源」
```

### 旅程 3 · 从频道获取一条并学

```
浏览频道 → 点开一条
  → 【不在库中】下载（后台，可离开，失败可重试）
  → 文件落进媒体库 → 扫描发现 → 注册 → 成为「我的媒体」的一项
  → 【无资源】点「生成学习资源」
  → 后台生成，阶段可见；用户可以去学别的
  → 达到 L1 → 可以开始学
  → 达到 L2 → 高亮跟随与精确循环解锁
```

### 旅程 4 · 我自己的文件

```
把文件放进媒体库文件夹（Finder 或拖入窗口）
  → 扫描发现 → 注册
  → 有旁挂字幕：直接可学（零等待）
  → 没有：走准备层
```

## 7. 与当前代码的差距

本阶段的范围是**频道 + 我的媒体**这一条；「备好的内容」不在其中。

| 需要的 | 现状 |
| --- | --- |
| 媒体库文件夹与扫描 | 无。仅有一次性的下载目录选择 |
| 旁挂字幕配对 | 无 |
| 下载失败可见可重试 | 静默吞掉，且有未捕获异步异常 |
| 生成任务队列 | 仅单条，绑在详情面板 |
| 渐进可用（L1 即可学） | 仅 available / notAvailable 二元 |
| 机器准备引导 | 无 |
| 按外部身份查媒体 | 靠文件名子串猜测（见 listen-core #110） |

---

## 8. 后端依赖

本阶段唯一的实质后端依赖是 **listen-core #110**（media origin 身份 +
按 origin 批量查询），已提出并获后端确认。

首次扫描需要逐个注册数百个文件，若实测确认单条注册的往返成本不可接受，
再向 Core 提批量注册请求——**先测量，不预先索取**。

---

## 9. 非目标（本阶段明确不做）

- 「备好的内容」的产出与托管（方向已定，见 2.1）
- 社区、包交换、发布、评分
- 托管生成
- 时间轴重对齐
- 播客及其他非 YouTube 来源（代码须显式拒绝，不得默默按 YouTube 处理）
- 移动端
- 全盘扫描、多媒体库文件夹、FSEvents 实时监听
- 学习层与管理层的任何改动
