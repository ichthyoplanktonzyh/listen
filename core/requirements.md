# 跨平台听力理解播放器 Requirements

## 1. 文档用途

本文档将 `prd.md` 中的产品目标映射为可实施、可测试、可追踪的需求。

每项需求包含：

- 稳定需求编号。
- 优先级。
- 目标交付阶段。
- 需求说明。
- 验收标准。
- 主要依赖。

实施计划、代码提交、测试用例和发布验收应引用需求编号，避免需求、实现与验证脱节。

## 2. 范围与术语

### 2.1 优先级

| 优先级 | 含义 |
|---|---|
| P0 | 当前目标里程碑发布前必须完成 |
| P1 | MVP 后优先增强，或移动端准备必须完成 |
| P2 | 后续研究或扩展 |

### 2.2 目标阶段

| 阶段 | 名称 |
|---|---|
| M0 | 架构基线与播放技术验证 |
| M1 | 共享核心、契约与数据基础 |
| M2 | 字幕基础设施 |
| M3 | 桌面播放基础设施 |
| M4 | 可交互字幕与词汇状态 |
| M5 | 查词、音标与当前句诊断 |
| M6 | 桌面 MVP 集成与质量加固 |
| M1.5 | 词汇学习资产强化 |
| M7 | 移动端技术验证 |
| M8 | LLPlayer 核心体验增强 |
| FUTURE | MVP 后研究与增强 |

M0-M6 与 M8 共同构成已完成的 Milestone 1，M1.5 词汇学习资产强化也已
完成。M7 和 FUTURE 需求进入 Milestone 2 或后续里程碑。

### 2.3 关键术语

| 术语 | 定义 |
|---|---|
| 共享核心 | 与具体 UI 和播放器实现无关的领域模型、业务规则和持久化能力 |
| 客户端 | 桌面或移动端 UI、播放控制和平台能力实现 |
| 播放器适配器 | 将具体平台播放器能力映射为统一播放契约的模块 |
| 字幕句 | 一个带开始时间、结束时间和文本的标准化字幕单元 |
| token | 从字幕文本中拆分出的单词、空白、标点或其他文本片段 |
| 全局词汇状态 | 用户通常是否认识并能听出某个词的长期状态 |
| 上下文观察 | 用户在某个具体字幕句中是否听出某个词的一次记录 |
| 来源快照 | 用户主动记录词汇时保存的原句、媒体标题与时间范围持久化副本 |
| 动态词汇本 | 按当前全局状态查询得到的词汇集合，不复制词汇 Profile |
| 当前句诊断 | 根据当前字幕句中的词汇状态生成的可解释诊断线索 |

## 4. 平台需求

### PLAT-001：Windows 桌面支持

- 优先级：P1
- 阶段：FUTURE
- 需求：macOS MVP 后，应用应能够在受支持的 Windows x64 环境安装、启动并完成核心学习流程。
- 验收标准：
  - 可以打开本地视频、音频、SRT 和 VTT。
  - 可以完成播放、字幕同步、单词标记、查词和诊断流程。
  - 发布包无需开发环境即可运行。
- 依赖：PLAY、SUB、WORD、DICT、DIAG、NFR 相关需求。

### PLAT-002：macOS 桌面支持

- 优先级：P0
- 阶段：M6
- 需求：桌面 MVP 必须在受支持的 macOS Apple Silicon 环境完成核心流程。
- 验收标准：
  - 完整核心流程可在 macOS Apple Silicon 上独立完成。
  - 文件选择、媒体播放和数据库路径符合 macOS 平台约定。
  - 发布包能够独立运行；签名与公证可在个人使用阶段记录为手工步骤。
- 依赖：PLAY、SUB、WORD、DICT、DIAG、NFR 相关需求。

### PLAT-003：Linux 桌面支持

- 优先级：P1
- 阶段：FUTURE
- 需求：macOS MVP 后，应用应在选定的 Linux 基线发行版完成核心流程。
- 验收标准：
  - 明确支持的发行版和所需系统依赖。
  - 核心流程与 Windows、macOS 一致。
  - 不支持的解码器或系统依赖具有明确错误信息。
- 依赖：PLAT-004 与 macOS MVP 已验证能力。

### PLAT-004：平台差异隔离

- 优先级：P0
- 阶段：M1
- 需求：平台文件路径、播放器实现、窗口行为和权限处理必须通过适配层隔离。
- 验收标准：
  - 共享核心不得引用桌面 UI 框架或平台播放器类型。
  - 每个平台差异具有明确接口或适配器。
  - 平台差异不会改变领域 API 语义。
- 依赖：ARCH-001、ARCH-004。

## 5. 架构需求

### ARCH-001：共享领域核心

- 优先级：P0
- 阶段：M1
- 需求：字幕、词汇状态、字典缓存、诊断规则和持久化逻辑必须位于独立共享核心中。
- 验收标准：
  - 共享核心能够在无 UI、无播放器情况下运行自动化测试。
  - 核心模型不依赖 Flutter、React、Tauri、WPF、libmpv、ExoPlayer 或 AVPlayer。
- 依赖：无。

### ARCH-002：Rust 核心基线

- 优先级：P0
- 阶段：M0
- 需求：共享核心采用 Rust 作为首选实现语言，并以 workspace 组织领域、应用服务、持久化和传输层。
- 验收标准：
  - 技术验证确认 Rust 工具链能覆盖目标桌面平台。
  - workspace 边界和 crate 职责形成架构决策记录。
- 依赖：无。

### ARCH-003：传输无关的应用服务

- 优先级：P0
- 阶段：M1
- 需求：领域应用服务不得直接依赖 HTTP；HTTP、WebSocket 和未来 FFI 只负责传输适配。
- 验收标准：
  - 同一个应用服务可以从单元测试直接调用。
  - HTTP handler 中不包含核心业务规则。
  - 移动端可以在不重写业务规则的情况下增加 FFI 适配。
- 依赖：ARCH-001、ARCH-002。

### ARCH-004：统一播放器适配器契约

- 优先级：P0
- 阶段：M0
- 需求：客户端定义统一播放器契约，覆盖打开、播放、暂停、跳转、位置事件、倍速、音量、轨道和区间循环。
- 验收标准：
  - 契约不暴露某个具体播放器库的类型。
  - 桌面播放器实现通过契约测试。
  - 契约设计能够映射到 ExoPlayer 和 AVPlayer 的核心能力。
- 依赖：无。

### ARCH-005：实时播放路径不得依赖 API 往返

- 优先级：P0
- 阶段：M0
- 需求：播放位置监听、当前句切换、区间循环和视频渲染必须在客户端本地完成。
- 验收标准：
  - 客户端不会按播放帧或高频定时调用后端查询当前字幕。
  - 后端服务停止响应时，已加载媒体仍能执行基本播放和字幕同步。
- 依赖：ARCH-004、SUB-006。

### ARCH-006：LLPlayer 仅作为行为参考

- 优先级：P0
- 阶段：M0
- 需求：新项目参考 LLPlayer 的行为、边界案例和测试，不直接依赖 WPF/Flyleaf 实现。
- 验收标准：
  - 形成 LLPlayer 行为参考清单。
  - 每个被参考的关键行为至少具有一个新项目测试或验收场景。
  - 复制源代码时记录许可证影响。
- 依赖：TEST-001。

### ARCH-007：稳定领域标识

- 优先级：P0
- 阶段：M1
- 需求：媒体、字幕轨道、字幕句和词汇必须使用稳定标识，避免重复导入和路径变化造成无控制重复。
- 验收标准：
  - 相同媒体和字幕重复导入不会创建重复学习数据。
  - 文件变化时能够识别为更新或新内容。
  - 标识策略有文档和测试。
- 依赖：DATA-003、DATA-004。

### ARCH-008：版本化契约

- 优先级：P0
- 阶段：M1
- 需求：HTTP API、WebSocket 事件和序列化领域对象必须具有版本策略。
- 验收标准：
  - API 路径或 Schema 包含版本信息。
  - 不兼容变化需要明确迁移或版本提升。
  - 契约变更由自动化测试验证。
- 依赖：API-001、TEST-008。

### ARCH-009：桌面客户端技术验证后定型

- 优先级：P0
- 阶段：M0
- 需求：桌面 UI 和播放器组合必须经过 macOS Apple Silicon 技术验证后才成为 MVP 正式基线。
- 验收标准：
  - 至少比较并记录 Flutter + media_kit 与 React/TS + libmpv/Tauri 的实现风险。
  - 选定方案在 macOS Apple Silicon 通过播放、位置事件、跳转、循环和字幕覆盖验证。
  - 记录未来 Windows 与 Linux 适配风险，但不阻塞 M1-M6。
  - 形成技术决策记录。
- 依赖：PLAY-001 至 PLAY-008。

### ARCH-010：移动端可嵌入能力

- 优先级：P1
- 阶段：M7
- 需求：共享核心必须能够通过 FFI/UniFFI 或等价方式嵌入移动客户端，不能只支持桌面侧车 HTTP 服务。
- 验收标准：
  - Android 或 iOS 原型能够调用至少一个核心应用服务。
  - 移动端无需复制词汇状态和诊断规则。
- 依赖：ARCH-003、MOB-001。

## 6. 媒体与播放需求

### PLAY-001：打开本地视频

- 优先级：P0
- 阶段：M3
- 需求：用户可以通过文件选择器打开本地视频。
- 验收标准：
  - 支持选定测试集中的常见容器和编码格式。
  - 成功后显示时长并可开始播放。
  - 失败时显示可操作的错误信息。
- 依赖：ARCH-004。

### PLAY-002：打开本地音频

- 优先级：P0
- 阶段：M3
- 需求：用户可以打开本地音频，并在无视频画面时使用完整字幕学习功能。
- 验收标准：
  - 音频可以播放、跳转、变速和循环。
  - 字幕文稿与诊断功能不依赖视频画面存在。
- 依赖：ARCH-004。

### PLAY-003：基本播放控制

- 优先级：P0
- 阶段：M3
- 需求：支持播放、暂停、停止和重新播放。
- 验收标准：
  - 状态变化可观察并反映到 UI。
  - 快速连续操作不会导致播放器失效。
- 依赖：PLAY-001 或 PLAY-002。

### PLAY-004：播放位置与时长

- 优先级：P0
- 阶段：M3
- 需求：播放器提供稳定的当前位置、总时长和播放状态事件。
- 验收标准：
  - UI 能持续显示当前位置。
  - 字幕同步使用同一时间基准。
  - 事件频率足以支持字幕同步且不造成明显性能问题。
- 依赖：ARCH-004。

### PLAY-005：跳转

- 优先级：P0
- 阶段：M3
- 需求：用户可以通过进度条或字幕开始时间跳转。
- 验收标准：
  - 点击字幕后跳转到目标句开始附近。
  - 前向和后向跳转均可用。
  - 跳转后当前字幕及时刷新。
- 依赖：PLAY-004、SUB-008。

### PLAY-006：精确字幕跳转

- 优先级：P0
- 阶段：M3
- 需求：播放器适配器提供面向字幕学习的精确跳转能力。
- 验收标准：
  - 在测试媒体集上，目标句开头不会被明显跳过。
  - 平台差异和允许误差有明确记录。
- 依赖：PLAY-005、TEST-004。

### PLAY-007：区间循环

- 优先级：P0
- 阶段：M3
- 需求：用户可以循环播放当前字幕句的开始至结束区间。
- 验收标准：
  - 到达区间结束后自动返回区间开始。
  - 用户可以立即退出循环。
  - 区间变化后使用新范围。
  - 循环不会持续累积明显时间漂移。
- 依赖：PLAY-004、SUB-007。

### PLAY-008：上一句与下一句

- 优先级：P0
- 阶段：M3
- 需求：用户可以切换并播放上一字幕句或下一字幕句。
- 验收标准：
  - 在首句和末句具有明确行为。
  - 切换后当前句、文稿高亮和诊断同步更新。
- 依赖：SUB-009、PLAY-005。

### PLAY-009：播放速度

- 优先级：P0
- 阶段：M3
- 需求：用户可以调整播放速度。
- 验收标准：
  - 至少支持 0.5x、0.75x、1.0x、1.25x、1.5x、2.0x。
  - 变速后字幕继续按媒体时间同步。
- 依赖：ARCH-004。

### PLAY-010：音量与静音

- 优先级：P0
- 阶段：M3
- 需求：用户可以调整音量和静音。
- 验收标准：
  - 控制状态与播放器实际状态一致。
- 依赖：ARCH-004。

### PLAY-011：轨道发现与选择

- 优先级：P0
- 阶段：M3
- 需求：客户端可以发现并选择媒体中的音频轨道和文本字幕轨道。
- 验收标准：
  - 可列出轨道名称和语言信息（可获得时）。
  - 切换轨道后播放继续稳定。
- 依赖：ARCH-004。

### PLAY-012：播放错误处理

- 优先级：P0
- 阶段：M3
- 需求：打开失败、解码失败、文件丢失和不支持格式必须返回明确错误。
- 验收标准：
  - 错误不会导致应用崩溃。
  - 错误包含用户可理解描述和诊断日志标识。
- 依赖：NFR-010。

### PLAY-013：播放进度恢复

- 优先级：P0
- 阶段：M6
- 需求：重新打开已登记媒体时，可以恢复最近播放位置。
- 验收标准：
  - 进度定期或在关闭媒体时保存。
  - 用户可以选择从头开始。
- 依赖：DATA-006、API-004。

### PLAY-014：在线媒体播放

- 优先级：P0
- 阶段：M8
- 需求：可通过直接 URL 或 `yt-dlp` 内容获取适配器打开合法、受支持的在线媒体。
- 验收标准：
  - `yt-dlp` 可用时能够解析并播放支持的 URL。
  - 工具缺失或解析失败时具有明确反馈且不影响本地播放。
  - 不绕过登录、DRM、访问控制或网站政策。
- 依赖：PLAY-001、PLAT-004。

## 7. 字幕需求

### SUB-001：导入 SRT

- 优先级：P0
- 阶段：M2
- 需求：共享核心能够导入和解析 SRT 文本字幕。
- 验收标准：
  - 正确解析顺序、开始时间、结束时间和文本。
  - 支持常见换行和编码情况。
  - 解析错误包含行号或上下文。
- 依赖：ARCH-001。

### SUB-002：导入 WebVTT

- 优先级：P0
- 阶段：M2
- 需求：共享核心能够导入和解析 WebVTT 文本字幕。
- 验收标准：
  - 正确解析 cue 时间和文本。
  - 不支持的高级标记不会导致整个文件失败。
- 依赖：ARCH-001。

### SUB-003：标准化字幕模型

- 优先级：P0
- 阶段：M2
- 需求：不同字幕来源必须转换为统一 `SubtitleTrack` 和 `SubtitleSentence` 模型。
- 验收标准：
  - 模型包含稳定标识、索引、开始时间、结束时间、原始文本和 token。
  - 时间统一使用整数毫秒或更高精度的明确单位。
- 依赖：ARCH-007。

### SUB-004：保留原始文本

- 优先级：P0
- 阶段：M2
- 需求：解析和 token 化不得丢失原始字幕中的可见文本、空格、标点和换行语义。
- 验收标准：
  - token 重组后与规范化显示文本一致。
  - 原始文本可单独读取。
- 依赖：TXT-001。

### SUB-005：字幕轨道身份

- 优先级：P0
- 阶段：M2
- 需求：字幕轨道具有稳定身份和内容指纹。
- 验收标准：
  - 相同文件重复导入不产生重复轨道。
  - 修改后的字幕可识别为新版本或更新。
- 依赖：ARCH-007、DATA-004。

### SUB-006：客户端时间轴

- 优先级：P0
- 阶段：M2
- 需求：客户端可基于完整标准化时间轴在本地计算当前字幕。
- 验收标准：
  - 查询复杂度适用于大字幕文件。
  - 不需要为每次位置变化调用后端。
- 依赖：ARCH-005、SUB-003。

### SUB-007：当前句计算

- 优先级：P0
- 阶段：M2
- 需求：根据播放位置计算当前字幕句，并定义重叠和空隙行为。
- 验收标准：
  - 空隙期间返回无当前句。

- 阶段：M6

- 需求：加载文稿时不得按 token 或字幕句逐个查询词汇状态。

  - 性能测试或请求日志证明使用批量加载。

- 阶段：M6
- 需求：至少 2,000 条字幕句的文稿可流畅滚动和同步。

- 阶段：M4
- 需求：数据库写入不得阻塞播放器位置处理和 UI 主线程。

### NFR-006：启动可靠性

- 阶段：M6
- 需求：本地核心服务启动失败、端口冲突和数据库迁移失败具有恢复路径。

### NFR-007：崩溃后数据完整性

- 阶段：M6
- 需求：异常退出后，已确认写入的数据保持一致。

- 优先级：P0
- 阶段：M6
- 需求：核心领域行为通过平台无关契约约束，并在当前支持的桌面平台保持一致。

- 阶段：M5

## 18.1 Milestone 1 桌面增强需求

### ENH-001：双文本字幕

- 优先级：P0
- 阶段：M8
- 需求：桌面端可同时加载主字幕与副字幕，并使用同一播放位置独立同步。
- 验收标准：
  - 主字幕保持逐词学习交互、跳转、循环和诊断能力。
  - 副字幕可独立显示、隐藏和设置时间偏移。
  - 两条字幕轨道不得互相覆盖持久化身份。

### ENH-002：字幕外观与布局设置

- 优先级：P0
- 阶段：M8
- 需求：用户可以调整字幕字体、字号、颜色、背景透明度、垂直位置和文稿宽度。
- 验收标准：
  - 设置修改后立即预览并持久化。
  - 无效或旧版本设置安全回退。

### ENH-003：桌面拖放导入

- 优先级：P0
- 阶段：M8
- 需求：用户可以拖放媒体、SRT 和 VTT 文件到主窗口。
- 验收标准：
  - 媒体文件打开播放。
  - 第一条字幕作为主字幕，第二条字幕作为副字幕。
  - 不支持文件具有明确反馈。

### ENH-004：内嵌文本字幕学习化

- 优先级：P0
- 阶段：M8
- 需求：将媒体容器中的文本字幕提取为标准字幕轨道并用于学习交互。
- 验收标准：
  - 支持的文本字幕可转换并导入主字幕或副字幕。
  - 位图字幕明确标记为暂不支持学习化。
  - 工具缺失或提取失败不会阻断媒体播放。

### ENH-005：在线视频与 yt-dlp

- 优先级：P0
- 阶段：M8
- 需求：用户可输入受支持的在线视频 URL，通过 yt-dlp 解析后播放。
- 验收标准：
  - 解析过程具有超时、错误反馈和取消后的安全降级。
  - URL 获取能力与播放器、字幕核心保持适配器边界。
  - 不绕过登录、DRM、访问控制或网站政策。

### ENH-006：桌面界面本地化

- 阶段：Milestone 1.6
- 需求：桌面端支持简体中文与英文即时切换，首次启动跟随系统语言。

### ENH-007：外部词汇表初始化

- 阶段：Milestone 1.6
- 需求：支持 TXT 与带 `word`、可选 `status` 列的 CSV 初始化词汇状态，
  默认不得覆盖本机已有非空状态。

### ENH-008：可插拔词典聚合

- 阶段：Milestone 1.6
- 需求：词典查询通过稳定 Provider 注册与聚合边界返回多个来源结果，单个
  Provider 失败不得阻断其他来源。

### ENH-009：统一单词与短语学习资产

- 阶段：Milestone 1.8
- 需求：单词与用户确认的短语共享状态、历史、来源、释义和笔记；短语候选
  不得未经确认自动进入学习资产。

### ENH-010：可修正 Lemma 与离线学习资源

- 阶段：Milestone 1.8
- 需求：Lemma 归一化具备版本和 Provider 标识并允许安全修正；ECDICT 与
  CMUdict 通过显式、checksum 验证的流程安装和删除。

### ENH-011：Provider 中立字幕搜索

- 阶段：Milestone 1.8
- 需求：首个 OpenSubtitles 实现支持标题、文件名和媒体 hash 搜索，失败
  不得阻断播放器。
