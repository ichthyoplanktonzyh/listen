# listen 完整用户学习活动路径

状态：DISCUSS -> 已作为 Phase 3.x 规划输入

日期：2026-07-04

## 文档目的

这份文档把 listen 的全部现有与规划功能串成一条完整的用户学习活动路径，回答：

> 用户的一天 / 一周里，listen 的每个功能在哪一刻、以什么身份服务他？

它是 `.planning/discuss/listen-user-journeys-current-and-planned.zh.md`（按功能组织的
旅程清单）的姊妹篇：那份文档回答"每个功能怎么用"，这份文档回答"功能如何组成学习生活"。

本文来源于 2026-07-03 ~ 07-04 的产品讨论（用户 + GPT 讨论输入 + 批判性评审），
是 Phase 3.1 ~ 3.10 规划的直接上游输入。

## 一级产品原则（本轮讨论确立）

### P1. 精听 / 泛听是一级心智模型

```text
精听：高注意力输入 -> 发现卡点 -> 诊断 -> 主动验证 -> 内化 -> 处理完毕
泛听：低注意力输入 -> 轻量捕获 -> 事后整理 -> 资产沉淀
资产层：词 / phrase / chunk / 句子 / 语流现象 / 卡点 / 语料锚点
```

复习、听力词典、dashboard 不是第三类输入场景，而是两类场景共同沉淀出的
**资产消费层 + 回访动线**。回访动线有显眼入口（到期复习数量等），但它的内容
永远由两个输入场景喂养，自己不发明学习材料。

### P2. 功能按场景分，不按设备分

- 精听、泛听、复习、词典、整理、词汇、诊断在**所有端都是全量功能**。
- 用户在哪个端做什么完全自由；不存在"手机只能泛听"这类限制。
- **唯一的硬件分界：生产端（重模型精炼）只在 PC。** 移动端可用轻量生成
  （基础字幕/词级时间），重精炼（高精度 timeline、音素证据、批量订阅加工）只在 PC；
  移动端产生的临时材料回到 PC 后自动"补课"精炼升级。
- 先在桌面端把所有完整功能做出来，再决定移动端的呈现与适配；设计时不得把
  交互绑定在桌面专有假设上（如"必须有大屏才能整理"）。

### P3. 可组合，不强制流程（本轮最重要的新增原则）

规划中的闭环是**推荐路径，不是强制流程**：

- 每个功能必须有独立入口、独立价值，可以单独使用。
- 用户可以按规划场景走完整闭环，也可以只用其中任何一块：
  只当播放器用、只查词、只做听写、只用词典、只泛听不整理——全部合法。
- 任何功能不得以"先完成上一环"作为使用前置条件；环节之间只做自然引导
  （"要不要把它加入复习？"），不做门槛。
- 不整理 Inbox 不阻塞下次泛听；不复习不阻塞精听；不标状态只降级诊断精度。

### P4. 泛听默认零打扰

泛听的默认态是纯粹连续播放。猎词单、微复习、回听提醒等全部是**显式开启的增强模式**，
并有严格的打扰预算。判断标准：用户纯当播放器用一个月，不应感觉到任何学习功能在骚扰他。

### P5. 不课程化、不游戏化

- 教练只建议，永远不指派；不内置教材、关卡、学习路径。
- 不做连续天数、成就徽章式打卡；dashboard 每个数字都必须回答
  "哪里没听懂、是否变好了、下一步练什么"。

### P6. 硬件北极星："一颗按钮、没有屏幕"

自研泛听硬件是远期方向，近期作为设计约束使用：泛听场景的核心交互必须在
"一颗按钮、没有屏幕"下成立（单键标记、单键作答、语音软打断为备选词汇）。
交互假设先用耳机键位 / 锁屏控件 / 手表验证。`.lltimeline` 预计算设计使硬件形态
天然便宜：哑播放器 + 按钮日志记录器，回家同步事件流。

## 核心概念定义

| 概念 | 定义 |
|---|---|
| 三姿态（精听） | 理解型（听懂了吗？→诊断）、验证型（测一下？→cloze/听写）、内化型（跟一下？→shadowing）。共享同一句子界面，是入口词汇不是三个模式。 |
| 双维难度 | Meaning fit（意思上可理解程度）× Sound fit（声音上可听出程度）。每个分数可解释（点开见依据信号）。 |
| 内容分拣器 | 用双维难度把进入的材料路由到三个队列：泛听队列 / 精听靶单 / 暂缓区。只建议不阻塞。 |
| 精听靶单 | meaning fit 高 + sound fit 低的材料——"看得懂、听不出"，精听收益最大的靶区。 |
| 卡点 | 精听中一处"没听懂"的位置及其生命周期：未听懂 → 已定位原因 → 已通过提示听懂 / 已主动验证通过 / 已加入复习 / 暂时跳过 / 仍未解释。状态优先从事件流派生，不先建状态机实体。 |
| Session summary | 精听会话结束总结：卡住 N 处 / 当场解决 / 加入复习 / 仍未解释 + 主要问题归因。 |
| 悬案区 | "仍未解释"卡点的容器。悬案不进复习（还没有答案可复习），等待新证据（词典新例句、更好的分析）再唤醒。 |
| 软打断 | 泛听中单键标记"刚才一句 / 最近几秒"，播放不停。 |
| 硬打断 | 泛听中明确暂停、展开当前句，瞬时借用精听动作（查词、标状态），然后继续。 |
| Listening Inbox | 泛听标记片段的收件箱。整理流：回听 → 秒建资产 / 建复习 / 升格微精听 / 片段收藏 / 丢弃。未处理项过期自动降级归档，不制造负罪感。整理在任意端可做。 |
| 微精听 | Inbox 中"回听仍定不了性"的片段升格成的一个最小精听任务。 |
| 片段收藏 | 非学习性收藏出口（"这段有意思"），与学习资产分离，避免污染 Inbox。 |
| 熟料回听 | 精听完毕的材料自动进入泛听队列供原速重听（narrow listening）。是"当场解决"的天然检验器。 |
| 猎词单 | 用户带 3-5 个攻克目标进入泛听狩猎模式：目标句前置提示（priming）+ 后置确认（check），单键作答产生真实语境识别证据。显式开启、严格提示预算。 |
| 理解度自报 | 泛听结束单键自报（全懂 / 大意 / 迷糊），回流校准 fit 模型。 |
| 升级建议 | 系统聚合多语境识别证据（练习、复习、猎词、词典标记）后建议 `known_not_recognized -> known_recognized`，用户确认才改。阈值是 heuristic，不硬编码为真理。 |
| Audio-first 复习 | 声音卡优先的复习队列：听音识词、chunk 填空、听句辨 phrase、跨例句认目标。单键作答，适合无屏场景。 |
| 听力词典 | 词/phrase 的真实语料例句集合（本地个人语料优先），逐例可播（词窗口/chunk/整句）、逐例标"听出/没听出"。覆盖不足时 YouGlish 外链兜底。 |
| 材料补课 | 移动端轻量路径产生的材料，回到 PC 后自动重精炼升级能力。 |
| 冷启动校准 | 新用户用自己的材料做两分钟高频词快速标注，建立初始词汇画像供 fit 计算。 |

## 完整学习活动路径

**人物设定**：阿澜，中文母语，应试英语底子好（词汇量 8000+，阅读无碍），真实语速
听不懂。每天通勤约一小时，晚上约一小时自由时间。设备：MacBook（含生产端）+ 手机 +
耳机。所有学习资产跨端同步。以下每一幕标注的地点/设备只是典型情形，**任何一幕都
可以在任何端发生**（生产精炼除外）。

### 第 0 幕 · 冷启动（第一周）

1. 导入几集想啃的 podcast，订阅两个 YouTube 频道。
2. 生产端夜间精炼：高精度 timeline、听感结构、音素证据。
3. 冷启动校准：从已导入材料抽高频词快速标注（两分钟），加上日常点词自然积累。
4. 第一次分拣结果：

```text
访谈：meaning fit 高 / sound fit 低  -> 精听靶单（黄金靶材料）
新闻：双高                          -> 泛听队列
脱口秀：meaning fit 低              -> 暂缓区
```

诚实降级：第一周 fit 是粗估（heuristic_proxy），界面明示"初始估计，会随使用越来越准"。

### 第 1 幕 · 材料供给（持续后台发生）

- 订阅源自动进入 PC 精炼厂 → 双维分拣 → 泛听队列 / 精听靶单 / 暂缓区。
- 手机临时导入的材料走轻量路径（能力降级标注），回 PC 自动补课。
- 熟料回听向泛听队列供货。
- 用户完全可以无视队列，手动打开任何材料——分拣只是建议。

### 第 2 幕 · 泛听（典型：通勤，手机 + 耳机）

1. 打开泛听队列连续播放，默认零打扰。
2. 没抓住一句 → **软打断**：单键标记"刚才那句"，播放不停。今天标 6 处。
3. 实在好奇一处 → **硬打断**：暂停看字幕、点词、标状态，继续播。
4. 结束单键**理解度自报**："大意懂了"，回流校准 fit。
5. 今天显式开了**猎词单模式**：带着 "would have" 和弱读 "for"，全程被提示 3 次
   （不超预算），单键答"听出/没听出"，每次都是真实语境证据。

产出：6 个 Inbox 片段、1 个词汇状态、3 条猎词证据、1 条理解度自报。

### 第 3 幕 · 精听（典型：晚上大屏；午休手机上也补过两句）

1. 从精听靶单选那集"看得懂、听不出"的访谈。
2. 第三句卡住，句循环两遍仍糊，进入三姿态：

```text
听懂了吗？ -> 诊断：known_not_recognized 短语 + 弱读，chunk 边界切错
           -> 复听 chunk、看 A/B/C 听感对比："would have" 压成了 "would've"
测一下？   -> chunk cloze，填对，卡点标记为已主动验证通过
跟一下？   -> shadowing 一遍，录音 A/B 对比
```

3. 每个卡点走状态流转；不想处理的直接跳过，无任何惩罚。
4. 结束 **session summary**：

```text
本段卡住 12 处：当场解决 7（5 处经主动验证）/ 加入复习 4 / 仍未解释 1 -> 悬案区
主要模式：弱读 function words、known_not_recognized 短语
本段精听完毕 -> 已加入熟料回听队列
```

产出：卡点记录、observations、4 个复习项、1 个悬案、熟料标记、练习历史（喂 sound fit）。

### 第 4 幕 · 整理时刻（任意端，约十分钟）

1. Inbox 里 6 个片段逐条回听：
   - 2 条是没听出的已知词 → 秒建资产 + 复习项；
   - 1 条像短语 → 确认 phrase，进猎词单候选；
   - 1 条回听就懂了 → 丢弃；
   - 1 条仍定不了性 → 升格**微精听**任务；
   - 1 条只是内容有趣 → **片段收藏**（非学习资产）。
2. **升级建议**弹出："'would have' 已在 5 个不同语境识别成功，标为 known_recognized？"
   → 用户确认。
3. 未处理项过 N 天自动降级归档；不整理不阻塞任何后续使用。

### 第 5 幕 · 回访（碎片时间，任意端）

- **Audio-first 复习**：等咖啡时耳机过 8 张声音卡，单键作答。反复失败项自动成为
  猎词单候选。
- **听力词典**：又栽在 "gonna"，点进词典——本地语料 11 次真实出现，逐条听、逐条标
  "听出/没听出"；本地不足时 YouGlish 外链兜底。
- **熟料回听**：第二天通勤，泛听队列顶部出现"上周精听过的访谈，原速重听？"
  ——7 个"当场解决"的卡点这次真的自己听出来了；1 个又糊了，软打断标记回流 Inbox。

### 第 6 幕 · 教练时刻（每周看一次 dashboard）

```text
本周：泛听 5.2h / 精听 87 句 / 复习正确率 74%
known_not_recognized -> known_recognized：+9
最顽固：弱读 for/have、t/d deletion（L1 提示：中文听觉习惯对尾辅音不敏感）
建议：
  1. 复习到期 12 项
  2. 弱读 function words 专项（从你的语料聚合了 15 个片段）
  3. 访谈理解度已达标，试试靶单里 sound fit 略高一档的下一集
```

材料毕业、难度爬坡、专项推荐——只建议，不指派。

## 资产流转总表

| 活动 | 产出 | 被谁消费 |
|---|---|---|
| 泛听标记 | Inbox 片段 | 整理时刻 → 资产 / 复习 / 微精听 / 收藏 |
| 理解度自报 | fit 校准信号 | 分拣器 |
| 精听卡点 | observation / 复习项 / 悬案 | 复习、词典、dashboard |
| 精听完毕 | 熟料标记 | 泛听队列（回听） |
| 练习 / 复习作答 | 识别证据 | 升级建议、猎词单、sound fit |
| 猎词作答 | 真实语境证据 | 升级建议 |
| 词典逐例标记 | 泛化证据 | 升级建议、dashboard |
| dashboard 建议 | 下一步行动 | 回到各队列（可无视） |

每类资产都有生产者和消费者，闭环无断头路；同时每个消费者都能在没有上游的情况下
独立工作（P3 可组合原则）。

## 路径暴露的缺口与决议

1. **"精听完毕"由谁判定** → 用户宣告 + app 提示（"还剩 3 个未处理卡点，仍然结束吗？"）。
2. **悬案区是新容器** → "仍未解释"卡点不进复习，等待新证据唤醒。
3. **Inbox → 微精听升格路径必须存在** → 整理时"回听仍定不了性"是必然情形。
4. **片段收藏与学习资产分离** → 否则用户拿学习标记凑合，污染 Inbox。
5. **猎词单来源收口** → 手选 + 复习反复失败 + 整理确认 phrase，上限 3-5 个。
6. **卡点状态先派生后建模** → 大部分状态可从 LearningEvent 流派生，仅"标记 / 跳过"
   需要新手势；派生覆盖不了时再升格显式实体（C-6 允许改形状）。

## 已明确的决策记录

- 双维难度直接实现，不做前置分化实验；但分数必须可解释、按 evidence class 标注。
- 精听 / 泛听 / 复习 / 词典 / 整理功能在所有端全量；生产端（重模型）只在 PC。
- 先在桌面把完整功能做出来，再考虑移动端呈现。
- 闭环是推荐路径不是强制流程（P3），所有 3.x phase 的 exit signal 必须包含
  "该功能可独立使用"的验收。
