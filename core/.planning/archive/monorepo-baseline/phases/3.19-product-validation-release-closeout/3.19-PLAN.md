# Phase 3.19 Plan: Product Validation & Release Closeout

状态：ACTIVE — FEATURE FREEZE / AUTOMATED BASELINE IN PROGRESS

日期：2026-07-19

上游输入：Phase 3.1–3.18 的已交付实现、各阶段 owner manual QA 清单、
`.planning/codebase/TESTING.md`、`docs/release/known-issues.md`。

## Objective

把 Phase 3.x 从“各能力 code complete”收口为一套经过真实端到端使用验证、可明确说明风险边界的
macOS 单用户产品。阶段不新增产品能力；它统一执行自动化、打包 smoke、owner 真机体验与缺陷
清偿，并为下一里程碑提供真实使用证据。

## Product Judgment

- 当前主要风险是跨阶段组合、真实设备/网络/音频焦点、数据 authority 与日用可理解性，不是缺少
  新功能。
- 原 phase QA 继续作为历史验收来源，但执行单位改为用户旅程；一条旅程可以同时覆盖多个清单项。
- 自动化通过不能代替 owner 对麦克风、听感、barge-in、视觉可理解性和学习价值的判断。
- Phase 4 或算法线重启不在本阶段预先承诺；以收口结果和后续真实使用记录决定。

## Scope

### In

1. 建立统一的 `3.19-RELEASE-ACCEPTANCE.md`，映射所有尚未完成的高风险 owner QA。
2. 在 clean `main` 基线上执行 full strict、契约、macOS release build 与独立解压启动 smoke。
3. 使用真实媒体和 owner 数据副本执行五条核心旅程：
   - 内容学习 → 词典/猎词 → Review Queue → 能力建议；
   - Speaking → Personal Expression → Projection Review → Coach；
   - 重启/来源删除/snapshot/override/zero-writer；
   - realtime provider/device；
   - embedding/TTS lifecycle、性能、听感与音频焦点。
4. 只修复验收中发现的 P0/P1，或直接阻塞核心旅程的 P2；每项修复补最小自动化回归。
5. 记录允许保留的已知问题、owner acceptance、release decision 和下一阶段证据。

### Out

- 新产品 surface、新 provider 类别、新学习事实或新 capability writer。
- 为了让清单通过而改变算法阈值、学习语义或扩展现有 phase scope。
- Apple Developer ID、公证、App Sandbox 或商业分发许可整改；它们在本阶段只做 release-risk
  裁决，除非 owner 另行决定进入公开分发准备。
- 把真实听感、麦克风或整体产品体验伪装成自动化通过。

## Feature Freeze And Defect Policy

| 级别 | 本阶段处理规则 |
|---|---|
| P0 | 立即修复并重跑受影响旅程和全量门禁；未清零不得收口。 |
| P1 | 本阶段修复，或由 owner 明确批准书面例外；不得静默延期。 |
| P2 | 仅在阻塞核心旅程、破坏 authority 或造成高频明显摩擦时修复。 |
| P3 / enhancement | 记录到下一里程碑输入，不在本阶段实现。 |

任何修复都不得顺带引入新功能。发现超过当前授权范围的产品方向选择时停止扩展，只记录证据和
可选方案。

## Work Slices

### Slice 0 — Baseline And Safety

- 确认工作树干净，保存测试 commit/build/machine 信息。
- 对 owner 数据先备份或使用副本；不在唯一真实库上做删除/迁移破坏测试。
- 执行 `./scripts/test.sh --full --strict --low-memory`。
- 执行 release build，验证 app bundle 内 sidecar/runtime/notice 与签名结果。
- 从新目录解压，验证首次启动、sidecar ready、打开本地媒体和安全退出。

### Slice 1 — Core Learning Asset Journey

- 真实内容、精听/泛听、词典、Hunting、Review Queue 与能力建议串联。
- 清偿 Phase 3.4 延期的真实媒体 ≥8 卡验收和 Phase 3.5 延期的真实材料分档体验，但不要求
  3.5 结果成为其他旅程的前置。
- 重点检查来源回听、音频焦点、重启持久化、`unassessed` 与 `not_acquired` 分离。

### Slice 2 — Four-channel Journey

- 复用一次真实新闻/对话完成 Speaking、Personal Expression、Projection Review 与 Coach。
- 以一条连续旅程覆盖 3.14、3.16、3.17、3.18 的重复准备和返回路径。
- 核对 attempt/judgment/observation/proposal/confirmed projection/override/history 不被 UI 混写。

### Slice 3 — External Runtime And Device Journey

- 单独执行 3.15.7 真实 socket、麦克风、扬声器、barge-in 与 local Whisper 闭环。
- 单独执行 3.15.8 首装、离线、stale/rebuild、大语料 latency/RSS。
- 单独执行 3.15.9 system voice 听感、cache 与跨播放器音频焦点。
- key 只经 App 写 Keychain，不进入终端、截图、数据库或验收文档。

### Slice 4 — Failure, Recovery And Authority Audit

- 未配置 provider、断网、错误凭据、来源媒体删除、模型损坏、应用重启与中途退出。
- 前后比较 authority 行数；只读浏览、Coach、semantic query、TTS 与失败 realtime 不得制造学习事实。
- 抽取可稳定重现且不依赖主观判断的失败路径，补为 integration/widget/contract regression。

### Slice 5 — Closeout And Next-stage Decision

- P0 清零；P1 清零或存在 owner 批准的书面例外。
- 完成 acceptance record、known issues、release note 与 phase closeout。
- 压缩 `.planning/STATE.md`，更新 codebase 文档至 3.18/3.19 实际边界。
- 用真实使用证据选择下一方向：核心 UX 压缩、2.19–2.21 算法质量、conversation 扩展、公开分发
  hardening，或继续 dogfooding；本阶段不提前选择。

## Exit Signal

- full strict、contracts、release build 和 packaged-app smoke 全绿，或有明确且获批的非 P0 例外。
- 核心两条跨阶段旅程无 P0/P1，数据/声音/返回路径没有已知破坏性行为。
- 3.15.7/3.15.8/3.15.9 的真实 provider/device/runtime 边界得到 owner 记录。
- 所有仍 pending 的原 phase manual QA 均有 PASS、FAIL 或显式 deferred with reason，不再只有分散清单。
- owner 明确给出 `ACCEPT` 或 `DO NOT RELEASE`；实现者不得代签。

## Deliverables

- `3.19-RELEASE-ACCEPTANCE.md`
- 自动化与打包基线记录
- P0/P1 defect log 与回归证据
- `3.19-CLOSEOUT.md`（仅在 exit signal 成立后创建）
- 更新后的 `STATE.md`、`ROADMAP.md`、release known issues/notes
