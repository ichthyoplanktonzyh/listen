# Phase 2.21 Plan: Audible Structure Architecture

状态：ACTIVE

## Objective

Turn the Phase 2.20 rhythm-first direction into a stable audible-structure
architecture:

```text
actual audible structure contract
  -> provenance-bearing RhythmFrame data model
  -> WordTimeline/duration/energy generation path
  -> evaluation/UI updated to distinguish predicted vs measured claims
```

This phase is allowed to break old `RhythmFrame` compatibility if the old shape
blocks the architecture.

## Source Of Truth

- `2.21-AUDIBLE-STRUCTURE-MODEL.md` is the contract.
- Phase 2.20 documents are input history and scaffolding, not the active
  architecture when they disagree with this phase.

## Step 0: Architecture Lock

Deliverable:

- Move the audible-structure model into Phase 2.21.
- Normalize definitions:
  - rhythm group / foot can attach pre-head or trailing weak material;
  - default connected form is ranked/contextual, not a single always-rule;
  - nucleus is phrase-scoped and may abstain when evidence is insufficient;
  - syllable timing is an explicit seam, even if v1 approximates it from
    WordTimeline + dictionary.

Acceptance:

- `2.21-AUDIBLE-STRUCTURE-MODEL.md` is the top-level reference.
- Phase 2.20 handoff/STATE/ROADMAP point future structure work to Phase 2.21.

## Step 1: Contract Rewrite

Goal:

Replace the v0 `RhythmFrame` shape with a model that can honestly represent:

- A/B/C references:
  - citation;
  - default connected variants;
  - actual delivery;
- L1 prominence anchors with `prominence`, `prominence_cues`,
  `evidence_class`, and source provenance;
- L2 phrase-scoped `nuclei`;
- L3 phrase boundaries with timing/energy/pitch cues;
- L4 connected-speech refs rather than duplicate segmental truth;
- quality fields that distinguish `text_prior`, `timing`, `energy`, `pitch`,
  and `phone_segmental`.

Implementation target:

- `crates/domain/src/sound_analysis.rs`
- `contracts/openapi/v1.yaml`
- Flutter typed model in `apps/desktop/lib/models/timeline.dart`
- fixture resources and tests that exercise the new model

Acceptance:

- Contract validation passes.
- Rust and Flutter model tests parse the new shape.
- Old v0-only assumptions such as `quality.timing_source = phone_timeline` are
  removed from active fixtures/tests when they contradict the lock.

Progress:

- Completed on 2026-06-30: Rust domain, OpenAPI, Flutter model, subtitle ribbon,
  diagnosis card, QA scorers, and committed fixtures now use the
  provenance-bearing audible-structure shape.

## Step 2: Generation Boundary

Goal:

Route production generation around the locked dependency direction:

```text
WordTimeline + dictionary/syllable structure + duration/energy/pitch
```

and keep CTC phones as L4 segmental evidence.

Deliverable:

  RhythmFrame L1-L3 without phone evidence.
- A clear seam for syllable timing and Rust pitch/F0.
- CTC connected-speech evidence linked via refs, not used as the rhythm skeleton.

Acceptance:

- A no-phone-evidence fixture can still produce valid anchors, weak groups,
  compression spans, phrase boundaries, and nuclei candidates.
- Phone evidence can enrich L4/hotspots without changing L1-L3 ownership.

Progress:

  substrate; application phonetic-analysis builders pass current-sentence
  `WordTiming` when available.
- Completed energy seam on 2026-06-30: `RhythmWordAcousticCue` can carry
  normalized word-level energy prominence into anchor prominence, nucleus
  selection, `generated_from`, `references.actual`, and quality provenance.
  W4 added the artifact path; the 2026-07-01 consumer correction adds Rust RMS/F0.
  W8 calibrates thresholds and records failure modes.

## Step 4: UI Semantics

Goal:

Keep the rhythm-first surface but make provenance honest.

Deliverable:

- UI distinguishes predicted/text-prior cues from timing/energy-supported
  audible cues.
- The compact subtitle control switches among three Rhythm references: A citation,
  B default connected, and C actual delivery.
- Reference B projects rule surface text, family/hint, canonical/default symbols,
  and display IPA so learners can inspect the teachable A → B change.
- Phrase nucleus is visible or inspectable when available.
- Phone details remain an expandable L4 evidence surface inside C, not a peer mode.

Acceptance:

- Learner-facing copy does not call text-only predictions "actual".
- Missing measured evidence degrades cleanly to predicted/reference mode.
- Existing `rhythm` / `phones` preferences migrate to C (`actual`).

Status: completed 2026-07-01. Rust/OpenAPI/Flutter carry B presentation fields;
the overlay and settings use `citation` / `connected` / `actual`, while Phones is
available on demand from C.

## Step 5: Closeout Criteria

Phase 2.21 can close when:

1. The new audible-structure contract is implemented in Rust/OpenAPI/Flutter.
2. The generation boundary no longer requires CTC phone evidence for L1-L3.
3. The evaluation tools understand provenance and predicted-vs-measured claims.
4. The UI can render the new model without reviving v0 semantics.
5. Handoff clearly states the next implementation phase or closeout path.

## Next Work — 2026-06-30 Review Outcomes

A focused architecture review on 2026-06-30 confirmed the direction and surfaced
concrete remaining work. Steps 0–2 above are largely implemented; this section is
the prioritized backlog to finish Phase 2.21 and make the audible-structure feature
usable on a WordTimeline-only import (e.g. local Whisper, no CTC).

### Confirmed Decisions

- Audible structure = four layers (L1 prominence beats / L2 nucleus / L3 phrasing /
  L4 connected-speech reduction), unified by the foot. Locked in
  `2.21-AUDIBLE-STRUCTURE-MODEL.md`.
- Three references: **A** citation (dictionary), **B** default connected
  (rule-predicted), **C** actual (measured). `B − A = teachable rule`;
  `C − B = clip-specific surprise`. A + B is the text-side "expected structure".
- Substrate: L1–L3 from WordTimeline + dictionary; CTC demoted to L4. The algorithm
  is decoupled from CTC, but the packaging is not yet.
- Acoustic enhancement (energy, F0) is classical DSP in the bundled **Rust local
  service**, not Flutter UI and not a heavy model. The consumer baseline adopts both;
  production sidecars may replace or enrich them with higher-quality evidence.
  Credibility comes from independent cues agreeing, not from signal count.

### Open Issues Found In Review

1. **Honesty leak — `timing_source` ignored.** `rhythm_tokens_from_word_timings`
   sets `from_word_timeline = true` for any `WordTiming` and never inspects
   `TimingSource`. An `Estimated` (character-weight, text-derived) WordTimeline is
   labeled `Timing` / `AudioSupported`, re-introducing the exact "text-predicted
   masquerading as actual" bug this phase exists to remove.
2. **RhythmFrame still trapped in the phone pipeline.** `build_sound_analysis` is
   only reachable through a phonetic-analysis job and is stored on a `PhoneTimeline`.
   A WordTimeline-only import can produce a RhythmFrame only by borrowing the
   synthetic `research-fixture` path. There is no first-class
   `WordTimeline → RhythmFrame` generation/storage path.
3. **Energy seam dangling.** `RhythmWordAcousticCue` is plumbed through, but builders
   pass `word_acoustic_cues: None`. The only live audio cue is duration.
   Resolved for the architecture path by W4 on 2026-06-30; manual calibration
   and promotion evidence remain W8.
4. **Reference B unimplemented.** `connected_speech_rules_seam` is a label only. The
   system detects connected speech from audio (C-side, via CTC) but does not predict
   default connected forms from rules (B-side), so teachable-vs-surprise is a
   CTC-status proxy, not a real A/B/C distinction.
   Resolved by W3 on 2026-06-30 for English text-side default connected forms.
5. **No real product QA yet.** Only fixtures exist; manual listening labels (the
   release-facing gate) have not been collected.

### Prioritized Work Units

Owner key: **[arch]** = architecture/code (this track); **[exp]** = experiment/QA
(owned outside this plan, see `scripts/prepare-rhythm-acoustic-qa.py`).

- **W1 [arch] · P0 · Honesty fix: respect `timing_source`.**
  Treat `Timing` as an audio source only for `ForcedAligned | AsrAligned |
  UserAdjusted`; map `Estimated` to `TextPrior` / `Predicted`. Thread `TimingSource`
  into `RhythmToken` and `claim_status`.
  Files: `crates/speech-analysis/src/sound_analysis.rs`.
  Accept: an estimated-timing fixture yields `Predicted` anchors and no nucleus; an
  aligned-timing fixture yields `AudioSupported`. Unit tests for both.
  Status: completed 2026-06-30. `RhythmToken` now carries
  `timing_audio_supported`; estimated WordTiming produces predicted anchors,
  no nuclei, no `Timing` signal source on L1-L3 claims, and
  `quality.timing_source = word_timeline_estimated`.

- **W2 [arch] · P1 · First-class WordTimeline → RhythmFrame path.**
  Generate RhythmFrame L1–L3 directly from active WordTimeline + dictionary,
  independent of any phonetic-analysis job; do not fabricate synthetic phones.
  Decide storage (dedicated rhythm resource or RhythmFrame attached to the
  WordTimeline/sentence, not only `PhoneTimeline.sound_analysis`). Phone evidence,
  when present, enriches L4 via refs only.
  Accept: importing a Whisper WordTimeline (no CTC, no model) produces a valid
  rhythm frame through a named non-fixture path, and the UI renders it.
  Status: completed 2026-06-30. `LLTimelineDocument.rhythm_frames` is the named
  non-fixture resource path; application export derives it from the active
  WordTimeline and Flutter renders it by sentence before using the PhoneTimeline
  fallback. Imported rhythm frames are validated as LLTimeline resources while
  the active WordTimeline remains the persisted source for regeneration.

- **W3 [arch] · P1 · Reference B: default connected-form rule engine.**
  Deterministic, text + dictionary only, language-profile dispatched. Start with the
  closed weak-forms lexicon (~50 English function words, strong/weak forms), then add
  cross-boundary rules (linking, elision, assimilation, flapping, contraction)
  incrementally. Wire B into `references.default_connected`; reclassify divergences
  as `teachable_rule` (matches B) vs `clip_specific` (beyond B) from real B, not CTC
  status.
  Files: new `connected_speech_rules` module in `crates/speech-analysis`; profile
  dispatch.
  Accept: B is generated for English; weak forms such as "could have" → /kʊdəv/
  appear; teachable-vs-surprise derives from A/B/C with unit tests.
  Status: completed 2026-06-30. `speech-analysis::connected_speech_rules`
  generates English B-side default connected forms from text: a closed weak-form
  lexicon, phrase reductions such as `could have -> K UH D AH V`, linking,
  t/d weakening, assimilation, contraction, and flapping candidates. RhythmFrame
  refs now classify B-matched audio as `teachable_rule` and B-unmatched audio as
  `clip_specific`.

- **W4 [arch+exp] · P2 · Energy cue into the live seam.**
  Rust RMS/loudness extraction produces per-word energy prominence in the consumer
  baseline; production providers can provide a higher-quality compatible artifact.
  Accept: anchors/nuclei backed by duration + energy report both sources; confidence
  reflects agreement; Flutter stays DSP-free and no Python/model runtime is required.
  Status: completed. Production Python and bundled Rust both write compatible
  `rhythm_word_acoustic_cues`; application export consumes them so generated
  RhythmFrames report `energy` provenance. W8 calibrates release thresholds.

- **W5 [arch] · P2 · Reference A hardening: OOV G2P fallback.**
  Add grapheme-to-phoneme fallback (+ stress) for dictionary-missing words so
  citation/syllable structure is not silently degraded.
  Status: completed 2026-06-30. The deterministic fallback is now `fallback-v2`:
  it handles common English digraphs, soft c/g, final silent e, x, and assigns a
  single primary stress to the first fallback vowel with later fallback vowels
  unstressed.

- **W6 [arch] · P3 · Information-structure-aware prominence prior.**
  Improve the text prior beyond "content word + lexical stress": down-weight
  given/repeated information, up-weight focus, to improve anchor and nucleus
  placement before acoustic confirmation.
  Status: completed 2026-06-30. RhythmFrame anchor scoring now applies a
  conservative information-structure prior: repeated content words are slightly
  backgrounded and phrase-final content gets a small focus boost. The cue remains
  `TextPrior`; it does not upgrade claim status without timing/energy/pitch/phone
  evidence.

- **W7 [arch] · F0 / pitch baseline.**
  Status: completed 2026-07-01 by consumer-closure decision. Rust performs a
  lightweight normalized-autocorrelation F0 analysis on bounded word frames, with
  silence/voicing correlation guards and sentence-relative pitch prominence. Pitch
  prominence feeds anchors/nuclei; upward pitch reset can support phrase boundaries.
  No Python/model runtime is required. Manual QA calibrates thresholds and catches
  octave/voicing failures but no longer gates adoption.

- **W8 [exp] · Product QA loop.**
  Collect 5–10 real sentences' manual labels (anchors, nucleus, weak groups,
  reductions). This is calibration/regression and closeout evidence, not an adoption gate.
  Status: QA tooling advanced 2026-07-01; manual evidence still pending. The
  RhythmFrame QA schema/scorer now treats `nuclei` and `connected_speech_refs`
  as first-class manual-label fields, template emission can skip missing-frame
  rows and cap row count, and quality gates can require minimum
  `rhythm_frame_sentence_count`, `word_timeline_rhythm_sentence_count`, and
  `energy_prominence_sentence_count`. Current local Phase 2.17 real-media
  artifacts are not sufficient for W8 closeout: 47 selected sentences contain
  only 1 old v0 phone-timeline RhythmFrame, 0 WordTimeline RhythmFrames, 0 energy
  prominence RhythmFrames, and 0 manual labels. Update 2026-07-01: local Brooklyn
  product-media W8 pack generated under `.tmp/rhythm-frame-qa/w8-product/` with
  114 WordTimeline + energy RhythmFrames and a selected 10-sentence
  `annotations-template.jsonl` plus clips. Manual listening labels are still
  pending, so W8 remains open as calibration/regression evidence. During generation
  W8 exposed and fixed an import remap bug where `rhythm_word_acoustic_cues`
  artifacts kept stale WordTimeline/sentence ids after LLTimeline import.
