# Phase 2.18 Refactor Audit

状态：RESOLVED_BY_PHASE_2_18_IMPLEMENTATION

审阅时间：2026-06-27 CST

## Executive Summary

当前项目不需要换栈，也不需要推倒重写。真正的问题是：核心能力增长很快，但领域模型、仓储边界、API 契约和 Flutter 状态机没有同步收敛。

Phase 2.18 应作为一次受控的代码架构重构窗口：先冻结行为，再收敛权威模型，最后拆边界和状态机。否则后续每个学习能力都会继续叠在“双模型 + 全能仓储 + 动态 JSON + 巨型 orchestrator”之上。

约束更新：不需要历史兼容性。旧数据库、旧 LLTimeline、旧 WordProfile 资源、旧 API/UI 路径都可以抛弃。
因此本审计建议优先删除旧模型和旧路径，而不是为它们设计长期 adapter。

## Implementation Resolution — 2026-06-27

本审计的主要 P0/P1 问题已经进入代码实现：

- Contract drift：OpenAPI / generated client / route parity test / validation script 已同步。
- Learning asset convergence：active path 已收敛为 `LexicalEntry + LexicalUnit`；旧 word-profile
  domain/repository/API/OpenAPI/generated client/script/Flutter fixture 路径已删除。
- Repository boundary：`AppServices` 依赖拆成 subtitle track、pronunciation、timeline resource、
  LLTimeline resource、learning asset 等窄 trait。
- Application DTO：chunk partition/diagnostic/provider DTO 不再以 public type alias 暴露
  `speech_analysis` 类型。
- Timeline envelope：Rust `TimelineMetrics` / `ChunkEvidence` 与 Flutter 同名 envelope 已落地。
- Flutter learning state：`LearningController` 中 lexical entries、phrase candidates、selected details、
  dictionary lookup、word pronunciation、language profile、diagnosis 已 typed；SSE lexical event 已 typed parse。
- Flutter subtitle/diagnosis payload：`SubtitleController` 中 pronunciation provider、sentence pronunciation、
  phonetic analysis 已 typed；`WordLearningPanel` / `DiagnosisCard` 不再接收这些业务 payload 的裸 map。
- Learning workflow：phrase candidate、word entry load/open/update、observation、learning-content save
  已下沉到 `LearningWorkflowController`。
- Speech/timeline workflow：timeline resource refresh、word timing、sentence pronunciation、chunk partition、
  phone/sound-pattern analysis 加载解析已下沉到 `SpeechEnhancementWorkflowController`。

仍保留为后续债务：

- `main.dart` 仍偏大，但核心 learning 与 speech/timeline refresh workflow 已迁出；剩余主要是
  media/session/resource action wiring。
- API route manifest 尚未抽成共享事实源；当前由 OpenAPI parity test 守护。

## P1: Domain Model Convergence

### 1. Learning Asset Has Two Parallel Models

`crates/domain/src/learning.rs` 同时存在：

- legacy word 模型：
  - `WordProfile`
  - `WordOccurrence`
  - `WordStatusHistory`
- newer lexical 模型：
  - `LexicalEntry`
  - `LexicalOccurrence`
  - `LexicalStatusHistory`

`crates/domain/src/lexical_unit.rs` 又定义了更通用的 `LexicalUnit`，包含 language、granularity、normalization、normalized_key，可覆盖 word / char / phrase / morpheme 等身份模型。

问题：

- `LexicalUnit` 是更好的跨语言身份抽象，但当前业务主路径仍主要围绕 `WordProfile` 与 `LexicalEntry` 并行。
- `WordStatus` 名称暗示只属于 word，但实际已经被 `LexicalEntry` 复用。
- `LexicalEntryKind` 只有 `Word` / `Phrase`，与 `LexicalUnit.granularity` 的开放字符串体系重叠。
- 旧 API、旧 UI、新 M18 lexical UI 之间概念分叉，继续保留 adapter 会延长双模型生命周期。

建议：

- 将 `LexicalEntry + LexicalUnit` 定为新学习资产权威模型。
- 删除 `WordProfile` 业务路径；必要时短期保留 endpoint 转换层，但不保留旧资源兼容。
- 将 `WordStatus` 语义重命名或文档化为 learning status，避免未来 phrase/char 被迫使用 word 命名。
- 新增 new-model identity tests，确保 lexical unit identity 稳定且覆盖 word/phrase/char 等粒度。

### 2. Timeline Lifecycle Is Split Across Generic Status And Ad Hoc Stage

`crates/domain/src/lib.rs` 有通用 `TimelineStatus`：

- `Candidate`
- `Active`
- `Archived`

`crates/domain/src/word_timing.rs` 又有 `WordTimelineLifecycleStage`：

- `AlgorithmCandidate`
- `UserAdjusted`
- `Published`

问题：

- `Candidate/Active/Archived` 是 lifecycle。
- `AlgorithmCandidate/UserAdjusted/Published` 更像 provenance 或 revision stage。
- ChunkTimeline / PhoneTimeline 没有同等 lifecycle stage，导致 word timeline 的状态语义更特殊。

建议：

- 抽象通用 `TimelineResourceLifecycle`。
- 把 `created_by`、`published`、`user_adjusted`、`parent_timeline_id` 等归入 provenance/revision metadata。
- 对 WordTimeline / ChunkTimeline / PhoneTimeline 统一 active/candidate/archive transition tests。

### 3. JSON Extension Fields Lack Typed Envelope

当前以下字段承担了很多关键语义：

- `WordTimeline.metrics_json`
- `ChunkTimeline.metrics_json`
- `ChunkTimelineChunk.evidence_json`
- `PhoneTimeline.metrics_json`
- `LLTimelineMetadata.extra`
- `LLTimelineArtifact.payload`

问题：

- 这些字段适合保留扩展性，但关键字段进入了无类型 JSON，Rust/Dart/contract 很难同步验证。
- Flutter 端大量保留为 `Map<String, dynamic>`，状态和 UI 对 payload 结构形成隐式依赖。

建议：

- 为关键 resource metrics/evidence 建 typed envelope。
- envelope 内保留 `extra`。
- Dart model 同步 typed parse。

## P1: Persistence And Repository Boundaries

### 1. `SubtitleRepository` Is A God Interface

`crates/application/src/repositories.rs` 中 `SubtitleRepository` 同时负责：

- subtitle track CRUD/status/language。
- sentence lookup。
- pronunciation cache 和 sentence pronunciation analysis。
- word timings / timeline resource consumption。
- WordTimeline CRUD/lifecycle。
- ChunkTimeline CRUD/lifecycle。
- PhoneTimeline CRUD/lifecycle。
- LLTimeline persisted resource。

问题：

- use case 依赖面过宽，任何 timeline 或 pronunciation 变动都会牵动 subtitle repository。
- persistence-sqlite 的实现文件 `crates/persistence-sqlite/src/subtitles.rs` 被迫变成 1000+ 行。
- 测试 fixture 和 mock 难以只表达一个聚合边界。

建议：

- 拆为 `SubtitleTrackRepository`、`PronunciationRepository`、`TimelineResourceRepository`、
  `LLTimelineResourceRepository`。
- `AppServices` 依赖 use-case 所需的最小 trait。
- 保留 `SqliteRepository` 作为多 trait 实现体，不要求物理上立刻拆成多个数据库对象。

### 2. Timeline Persistence Mixes Query Columns And Full JSON Snapshots

SQLite schema 中：

- `word_timeline_runs`
- `chunk_timeline_runs`
- `phone_timeline_runs`

都保存了 query columns 加 `timeline_json` 完整快照。

问题：

- 这是资源快照模型，合理；但 active uniqueness 主要靠 repository 事务维护。
- `active_*_timeline()` 当前按 `status=active ORDER BY updated_at_ms DESC LIMIT 1` 读取，schema 侧不防止多个 active。
- `activate_*_timeline()` 在不同 resource 上重复实现。

建议：

- 抽出 shared active transition helper。
- 直接在新 schema 中增加 partial unique index 或等价约束，保证每 track/resource kind 只有一个 active。
- 至少以 persistence tests 固化 active uniqueness。

### 3. Single SQLite Mutex Is Acceptable But Should Stay Implementation Detail

`crates/persistence-sqlite/src/connection.rs` 使用 `Mutex<Connection>`。

判断：

- 对本地 sidecar 小规模请求可接受。
- 风险不在 Mutex 本身，而在全能 repository 边界让所有 use case 都争同一个巨接口。

建议：

- Phase 2.18 不必先引入连接池。
- 先拆 trait 边界和事务 helper；SQLite schema 可以破坏性重建。

## P1: Application And API Boundaries

### 1. Application DTO Leaks Algorithm Crate Types

`crates/application/src/dto.rs` 公开：

- `SentenceChunkPartition = speech_analysis::chunk_partition::SentenceChunkPartition`
- `SentenceChunkDiagnostics = speech_analysis::chunk_partition::SentenceChunkDiagnostics`
- `LearnedProsodicProviderInfo = speech_analysis::learned_prosodic_provider::LearnedProsodicProviderInfo`

问题：

- HTTP 层虽然已不直接依赖 `speech-analysis`，但 application public contract 仍被算法 crate 形状约束。
- 未来替换 chunk provider 或重组 speech-analysis 会波及 API DTO。

建议：

- 复制/映射为 application-owned DTO。
- 算法 crate 结果在 use case 内转换为 application DTO。

### 2. API Router Has No Contract Fact Source

`crates/api-http/src/lib.rs` 的 router 链式注册已经很长。

问题：

- route 字符串、OpenAPI、generated client 三者不是同一事实源。
- 新 route 很容易只实现不入契约。

建议：

- 建立 `RouteSpec` manifest 或强 parity test。
- 新 endpoint PR 必须同步 OpenAPI/generated client/parity test。
- `api-http` root 只保留 route group assembly。

## P1: Flutter State Machine And Orchestration

### 1. `main.dart` Is Still The Primary Orchestrator

`apps/desktop/lib/main.dart` 约 3235 行，承担：

- local API lifecycle。
- media open / progress save / progress restore。
- player stream subscriptions。
- subtitle import/resource lifecycle。
- LLTimeline import/export。
- timeline generation/activate/archive/delete。
- diagnosis / phrase candidate / pronunciation refresh。
- SSE event routing。
- settings sync。
- dialogs and UI assembly。

问题：

- 已有 controller，但 workflow 仍在 screen state 中。
- 业务异步流程与 UI lifecycle 混在一起，难以测试 stale result。

建议：

- `main.dart` 收缩为 composition root。
- 抽 `MediaSessionController`、`BackendEventCoordinator`、`TimelineResourceController`、
  `LearningWorkflowController`。

### 2. State Store Exists But State Is Not Fully Modeled

`apps/desktop/lib/state/store.dart` 提供 fine-grained `Store<T>`，这是好的基础。

问题：

- `LearningState` / `SubtitleState` 的核心 learning、pronunciation、phonetic-analysis 字段已 typed。
- state 缺少显式 loading/error/stale/session 字段，UI 只能依赖 status string 或 nullable value。

建议：

- 保留 `Store<T>`，不要盲目换状态管理库。
- 将核心 API response 转为 typed model。
- 对 async workflow 建模为 sealed-like states：
  - idle
  - loading(session)
  - ready(data, session)
  - stale(previous, session)
  - failed(error, session)

### 3. Async Guards Are Local And Incomplete

`_onPosition` 在 cue 变化时触发：

- `_refreshDiagnosis()`
- `_loadPhraseCandidates(primaryCue)`
- `_ensureCurrentPronunciation(primaryCue)`

当前只用 `_lastPrimaryCueId` 去重，部分方法内部再检查 cue/track。

问题：

- 媒体切换、track 切换、language 切换、API reconnect 时没有统一 generation。
- SSE event handler 使用裸 map 判断 media/track，过期事件可能更新新 session 的状态。

建议：

- 引入 `MediaSessionKey(mediaId, trackId, generation)`。
- 每类请求带 `RequestToken(session, cueId, kind, sequence)`。
- response apply 前统一验证 token。
- Flutter tests 覆盖 rapid cue switch / media switch。

## Architecture Decision Needed Before Implementation

Phase 2.18 开工前必须确认：

- 新学习资产权威模型是否为 `LexicalEntry + LexicalUnit`。
- `WordProfile` 是否从业务路径删除，而不是保留 legacy adapter。
- timeline lifecycle 是否统一为 resource lifecycle + provenance metadata。
- Flutter 是否继续沿用现有 `Store<T>`，只补 typed model/coordinator/state union。

默认建议：以上答案均为“是”。
