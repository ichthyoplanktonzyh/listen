# Phase 2.2 Context: App Timeline Resource UI Alignment

更新时间：2026-06-19 15:55:21 CST

## Background

Phase 2.0/2.1 将项目重新定义为两条协同路线：

- 本地重装生产引擎：使用 WhisperX、MFA、MMS_FA 和后续候选 aligner 生成高质量
  `.lltimeline.json` 时间轴资源。
- 轻量消费端 LLPlayerNext：不内置重型 ASR/FA 运行时，读取这些资源驱动词级高亮、
  chunk 播放和学习体验。

当前生产端已具备可运行的核心闭环：

```text
media
  -> prepare-media
  -> WhisperX
  -> LLTimeline JSON
  -> optional post-aligner: MFA / MMS_FA / fallback to WhisperX
  -> production-report.json
```

对齐器评测与替换路线进入长期研究；当前不继续扩大实验。下一阶段要让 app 端能
理解、展示和消费生产端生成的资源。

## Problem

现在 `.lltimeline.json` 已经能承载多个 WordTimeline 候选，但 app 端体验仍以旧的
字幕/ASR 路径为中心。用户无法在 UI 中清楚看到：

- 当前媒体是否已经导入高精度 LLTimeline 资源。
- 资源中有哪些 WordTimeline 候选，分别来自 WhisperX、MFA、MMS_FA 或人工修正。
- 哪条 WordTimeline 是 active，是否经过人工校对。
- 对齐阶段是否发生降级，当前结果是否可进入人工复核。
- 消费端词级高亮和后续 chunk 划分实际使用的是哪条时间轴。

如果不先补齐这些资源可见性和选择能力，后续人工校正 UI、chunk timeline 生成和
发布流程都会缺少稳定入口。

## Scope

Phase 2.2 聚焦 app 端 UI 与资源模型对齐：

1. 导入/关联 `.lltimeline.json` 到当前媒体。
2. 展示资源摘要、generator、active timeline、候选 timelines 和质量状态。
3. 支持选择/激活某条 WordTimeline。
4. 让播放器词级高亮使用 active WordTimeline。
5. 为后续人工校正和 ChunkTimeline 生成预留入口，但不在本阶段实现完整编辑器。

## Non-Goals

- 不在 app bundle 内集成 WhisperX、MFA、MMS_FA、torch 或 Python runtime。
- 不在本阶段实现复杂人工拖拽校正 UI。
- 不继续扩大 TIMIT/Buckeye/CNN10 benchmark。
- 不把 Qwen3-ForcedAligner、BFA 或其他新 aligner 接入主线。

## Success Criteria

- app 能导入生产端生成的 `.lltimeline.json`。
- 用户能看到 WordTimeline 候选列表、active 状态、provider/version、质量摘要和
  降级 artifact。
- 用户能将某条 WordTimeline 激活为当前播放/高亮使用的时间轴。
- 没有 LLTimeline 资源时，现有字幕和估算/旧 word timing 路径继续工作。
- 文档明确下一步进入人工校正与 chunk timeline 生成。
