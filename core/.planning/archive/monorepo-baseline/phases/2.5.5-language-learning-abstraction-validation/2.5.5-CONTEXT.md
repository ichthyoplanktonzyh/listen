# Phase 2.5.5 Context: Language Learning Abstraction Validation

更新时间：2026-06-22 CST

## Background

Phase 2.5 已经把 Sound Pattern / PhoneTimeline 升级为一等资源。Phase 2.6
（Multilingual Learning Foundation）已经完成第一版规划，并在评审中确认了若干关于
多语言学习架构的核心想法：

- **Listening first**：多语言基础以听力能力为核心，文字/词典/语法是解释层，模型应能
  表达 `audio -> listening units -> meaning candidates -> lexical/text explanation`。
- **Token / LexicalUnit / ListeningUnit 三分**：字幕显示单位、词汇学习对象、真实听觉
  单位是三个独立概念，不能合一。
- **Validation beyond English/Chinese**：本阶段只实现 English + Chinese，但架构要能
  容纳主流语言的听力学习模型，不形成英/中双特例。

评审中又新确认了一个此前缺失、且直接命中产品核心（诊断）的二语习得事实：

> **L2 的听力难度是被 L1 过滤的。** 真实"听不懂"是 `(母语 L1, 目标语 L2)` 配对的函数，
> 不是目标语单变量。当前 `LanguageLearningProfile` 只有 L2 维度，没有 L1 的位置。

这件事会改变诊断模型的形状，因此必须在 Phase 2.6 写任何诊断代码之前定下来。

## Problem

Phase 2.6 的影响面很大：tokenizer、lexical unit、dictionary、pronunciation、
diagnosis、UI 都会动。当前的多语言抽象虽然在文档里被陈述为合理，但还没有经过两类
校验：

1. **它是否立得住真实的二语习得（SLA），还是工程美学的自我想象？**
   - 三分单位、听觉单位语言特定性、诊断轴等判断，需要对照真实听力/词汇研究确认，
     而不是凭直觉。
2. **它是否真的能扩展到主流学习语言，而不被迫打特例分支？**
   - 现有 validation set（es/fr/de/ru）其实同属一个类型学簇（欧洲、屈折、空格分词、
     字母文字），zh 覆盖一部分"无空格/声调"，但**真正会暴露英/中偏置的类型学形状没有
     被压到**：mora/pitch（日语）、非线性词根-词型形态（阿拉伯语）、黏着（韩语）。

如果这两类校验留到 Phase 2.6 实现中途才发现问题，代价是一次重构；现在在纸面上发现，
代价只是一页文档。这正是把校验单独前置成一个 phase 的理由。

此外，已经识别出三个会在"类型学上远的语言"处产生迁移摩擦的抽象泄漏点，需要在 2.6
之前以"命名 seam、暂不实现"的方式定型：

- **L1 维度**缺失于诊断模型。
- **`kind` taxonomy 是闭合枚举还是开放可降级**未定（直接决定 open/closed 扩展性）。
- **Token / LexicalUnit / ListeningUnit 之间的 N:M alignment** 没有概念归宿
  （liaison / 变调 / 弱读的痛点全在这一层）。

## Product Relationship

Phase 2.5.5 不是产品功能阶段，也基本不产出生产代码。它服务于后续产品阶段：

```text
Phase 2.5 Sound Pattern / PhoneTimeline
  -> Phase 2.5.5 Language Learning Abstraction Validation   (本阶段)
  -> Phase 2.6 Multilingual Learning Foundation (English + Chinese 实现)
```

定位与 Phase 2.3.5（Rust 模块拆分）相同：一个插入式的前置加固 phase。区别在于
2.3.5 是机械重构、降低实现成本；2.5.5 是设计校验、降低**抽象错误**的成本。它的价值是
让 Phase 2.6 在一个**已被 SLA 验证、已被类型学证伪测试过**的抽象上写代码，而不是在一个
只被陈述为合理的抽象上写代码。

## Scope

本阶段聚焦"校验并最小化抽象"，不扩张抽象：

1. **SLA Foundation Mapping**：把多语言抽象的每个核心元素映射到真实二语习得/心理语言学
   依据；没有依据、纯工程美学的部分要么标注务实理由，要么删去。
2. **Invariant / Variant 边界锁定**：明确唯一的语言不变量是"理解轴"（词义是否已知 ×
   声音是否听出），其余结构全部 variant，走 profile / provider。
3. **L1 -> L2 Diagnosis Seam**：把 L1 作为诊断模型的一等（可空）维度写进设计；只留 seam，
   不实现 L1-aware 规则。
4. **Extensibility Seams 规格化**：为 `kind` 开放 taxonomy 和单位间 N:M alignment 定型
   概念，命名但不实现。
5. **Typological Falsification**：用 Japanese + Arabic（必要时加 Korean）逐字段跑一遍
   capability matrix 和三单位模型，标出哪些干净通过、哪些逼出特例，并修订抽象直到通过。
6. **Language Envelope Scoping**：明确"主流学习语言 top-15"目标集合及其类型学聚类，声明
   小语种为可选、不承诺。

## Non-Goals

- 不写生产代码（Rust / Flutter）；最多在文档中给出类型/结构草图，不进 crate。
- 不实现任何非英语语言能力（tokenizer / dictionary / provider 全部留到 2.6）。
- 不实现 L1-aware 诊断规则，只留 seam。
- 不承诺实现 Japanese / Arabic / Korean；它们只是证伪探针。
- 不扩张抽象、不追求覆盖世界所有语言；本阶段的方向是**收缩 + 校验**，不是 grand design。
- 不改 API contract、SQLite schema 或 LLTimeline JSON schema。

## Success Criteria

- 多语言抽象的每个核心元素，要么有可引用的 SLA 依据，要么被显式标注为务实工程取舍及其
  理由；没有"凭空想象"的悬空概念。
- Invariant / Variant 边界被写死：理解轴的全局词汇状态枚举声明为语言不变量、跨语言复用；
  一切结构性能力声明为 variant。
- 诊断模型设计包含一个可空的 L1 维度，且不要求本阶段做 schema / 实现改动。
- Japanese 和 Arabic 能在纸面上通过 capability matrix + 三单位模型且**零特例分支**；
  若不能，则抽象被修订到能通过，并记录修订点。
- 三个 seam（L1 / 开放 kind taxonomy / 单位间 alignment）被规格化为"形状 + 为什么"，但
  不被实现。
- Phase 2.6 的 CONTEXT / PLAN 被更新为消费"已校验的抽象"，并引用 2.5.5 为前置。
