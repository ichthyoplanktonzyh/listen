# Phase 2.20 Context: Rhythm-First Listening Analysis

状态：ACTIVE

## Why This Phase Exists

Phase 2.14-2.19 建立了 sound-line、stable learning phone、connected-speech markers、
真实媒体 QA pack 和初始 benchmark scorer。这个方向证明了一件事：

> 真实语流分析不能只停留在“这一句话有哪些 phones”。

用户真正想回答的问题是：

```text
为什么这句话我听不懂？
```

这个问题通常有两类原因：

1. **单词问题**：不知道词义、词形、搭配或上下文含义。
2. **声音识别问题**：认识这些词，但在真实音频中没有把它们听出来。

单词问题已经由 `LexicalEntry + LexicalUnit + LearningStatus`、词典查询、词汇状态、
context observation 和 learning loop foundation 承接。Phase 2.20 聚焦第二类问题：

> 认识文字，却没有听出真实声音。

此前我们把主要精力放在 phone-level CTC 与 expected pronunciation 的对比上。这个方向仍然必要，
但它不是第一层用户体验。原因有三点：

- 当前 phone recognizer 的 PER 仍偏高，raw phone identity 不能作为用户默认教学真值。
- 人耳理解英语真实语流时，优先抓的是 prominence、stress、rhythm、pause、弱读音团和语义锚点，
  不是逐个 phone。
- phone-level 错误对“重音节奏框架”的影响通常小于对“音素级解释”的影响。

因此本 phase 将产品中心从：

```text
expected phones vs observed phones
```

调整为：

```text
expected pronunciation
  -> observed stress/rhythm frame
  -> mismatch/explanation hotspots
  -> optional phone evidence
```

## Product Reframe

用户默认需要看到的不是一串 phones，而是这句话实际听起来的结构：

```text
What should I listen for?
Where are the strong beats?
Which parts are compressed or weak?
Why does the written sentence not sound like the dictionary form?
```

Phase 2.20 的核心产品判断：

> 先树立重音节奏框架，再解释轻读音团里的局部 phone 变化。

这不是放弃 phone-level。phone-level 仍然是 evidence layer，用来解释：

- 某个 expected phone 为什么消失。
- 某个功能词为什么变弱。
- 某个跨词边界为什么连在一起。
- 某个用户疑惑点是否有音频证据。

但用户默认看到的第一层应是：

- stress anchors
- rhythm groups
- weak/compressed spans
- pause / phrase boundary
- expected vs observed prominence mismatch
- learner-facing explanation

## Relationship To Earlier Phases

### Phase 2.14

Phase 2.14 已经提出 Prosodic Hierarchy，并实现最小子集：

```text
Phone / ObservedPhone
  -> LearningPhone
  -> Syllable
  -> pause-based ProsodicPhrase
```

Phase 2.20 不是推翻 2.14，而是把其中未完成的 `Foot / stress group / rhythm` 提升为产品主轴。

### Phase 2.15

Phase 2.15 把 sound line 做成 UI 可见能力，但仍接近“phone/syllable ribbon”。
Phase 2.20 要把默认 UI 从 phone ribbon 转成 rhythm frame surface。

### Phase 2.16

Phase 2.16 的 weak form、deletion、assimilation、flapping、contraction 等 markers
继续保留，但它们应挂在 rhythm frame 的 hotspots 上，而不是独立堆在 phone ribbon 上。

### Phase 2.17

Phase 2.17 的 real-media QA pack 继续作为真实媒体回归材料。
它现在要被重新解释为：

- UI 是否能解释真实听感。
- markers 是否帮助用户定位听不懂原因。
- phone evidence 是否被放在正确层级，而不是误导用户。

### Phase 2.19

Phase 2.19 的 TIMIT / Buckeye / TED-LIUM benchmark scoring 继续有效，但角色调整：

- TIMIT / Buckeye phone PER 是底层 phone evidence 的可信度指标。
- TED-LIUM transcript/timing 是长音频 text/timing 资源稳定性指标。
- phone PER 不再是 sound-line 产品体验的唯一中心指标。

Phase 2.20 需要新增 rhythm/stress/product-listening 维度的评测。

## Working Model

Phase 2.20 引入以下逻辑层：

```text
Sentence
  -> Words / tokens
  -> Expected pronunciation
     - lexical stress
     - syllables
     - canonical phones
  -> Observed timing evidence
     - word timings
     - gaps / pauses
     - duration
     - CTC phone timing / confidence where available
     - optional acoustic evidence later: energy, pitch, spectral cues
  -> RhythmFrame
     - stress anchors
     - weak groups
     - compressed spans
     - phrase boundaries
     - expected-vs-observed prominence mismatch
  -> ListeningExplanation
     - learner-facing reason this sentence sounds different
  -> PhoneEvidence
     - detailed expected/observed phone alignment, optional and expandable
```

## Key Terms

### RhythmFrame

Sentence-level sound view that tells the learner how the sentence is organized for listening.
It is not a raw phone timeline. It is a structured listening map derived from expected stress,
timing, pauses, duration, connected-speech evidence and optional phone evidence.

### StressAnchor

A word or syllable that carries high listening value in the sentence. Usually a content word
or a syllable with primary/secondary stress, but final selection must consider observed timing
and phrase context.

### WeakGroup

A span of words/syllables attached to a nearby stress anchor and likely heard as compressed,
reduced, or backgrounded material. Function words, auxiliary verbs, articles, prepositions and
pronouns often live here.

### CompressionSpan

A time span where many expected units occupy a short duration or show weak/reduced evidence.
This is often where the learner says “I know the words, but I cannot hear them.”

### ListeningHotspot

A local mismatch or explanation target inside the rhythm frame. Examples:

- expected strong syllable is not prominent in audio
- function words collapse into a weak group
- phrase boundary differs from punctuation
- CTC/phone evidence suggests deletion or substitution
- word timing shows unusually compressed speech

### PhoneEvidence

Detailed phone-level expected/observed alignment. It supports explanations but is no longer the
default product center.

## Design Principles

1. **Rhythm first, phones second.**
   The first screen should answer what the learner should actually listen for.

2. **Expected pronunciation remains the teaching reference.**
   Dictionary/canonical pronunciation gives stable labels; observed audio evidence explains how
   real speech diverges.

3. **Audio evidence is required for observed rhythm claims.**
   Text alone can predict stress, but “real rhythm” must be justified by timing, gap, duration,
   confidence or later acoustic evidence.

4. **Phone PER does not block rhythm-frame UX.**
   High phone error rate limits detailed phone explanations, but word timing, duration, pause and
   lexical stress are enough to build a useful first rhythm frame.

5. **Explanations must be learner-facing.**
   Internal labels like insertion/deletion/substitution can exist, but default UI should say what
   changed in listening terms.

6. **Evaluation follows product value.**
   Benchmarks should measure whether the system identifies the right stress anchors, weak groups,
   compression spans and explanation hotspots, not only phone edit distance.

## Open Research Questions

- Can lexical stress + word timing + pause/duration provide a strong enough rhythm frame before
  pitch/energy features are added?
- How much phone evidence is needed before a connected-speech marker can be shown with confidence?
- Which benchmark datasets contain usable stress/prominence or word timing references?
- How should TED-LIUM and product media be manually scored for listening explanation quality?
- Should pitch/F0 and energy extraction enter Phase 2.20, or remain a later 2.21+ enhancement?

Initial decision: Phase 2.20 starts without requiring pitch/F0. It should first make rhythm-frame
product semantics, UI and evaluation reproducible using existing word timing, expected stress,
pause/duration and phone evidence.
