# Phase 2.20 Acoustic Feature Path

状态：REVISED BY ROUTE CORRECTION

日期：2026-06-30

## Current Decision

This document is superseded in direction by:

- `.planning/phases/2.20-rhythm-first-listening-analysis/2.20-ROUTE-CORRECTION.md`

The corrected Phase 2.20 route is:

```text
forced-aligned WordTimeline skeleton
  + duration/rate evidence
  + RMS energy/loudness evidence
  + optional F0/pitch evidence after calibration
  + CTC phone evidence as segmental detail only
```

`RhythmFrame` remains the product contract. The generator source must move away
from CTC-derived rhythm timing as the primary skeleton.

## What The Earlier Implementation Means

`crates/speech-analysis/src/sound_analysis.rs` currently can emit:

```text
evidence = "pre_boundary_lengthening"
```

for a phrase boundary when a boundary-final token is locally lengthened without
an obvious pause.

This is still useful, but it is now classified as:

```text
heuristic_proxy / fallback evidence
```

It should not be treated as the final acoustic prosody route because it is still
attached to the current `sound_analysis` timing path, which is too close to the
CTC-derived pipeline.

## Why The Route Changed

The product goal is actual audible structure, not default/citation reading.

Text-only stress prediction can provide a prior, but it cannot prove what this
speaker actually made prominent. Current stress anchors are therefore mostly
`text_predicted`, not observed prominence.

The missing first-class production signals are:

- forced-aligned word timing as the rhythm skeleton;
- local duration/rate normalization;
- RMS energy/loudness for prominence support;
- later F0/pitch reset if needed for boundary/prominence.

The consumer app's lightweight runtime is not a reason to skip these signals.
They belong in the local production pipeline and should be serialized into
`.lltimeline.json`.

## Immediate Feature Path

Next work should focus on a production-side experiment:

1. Use forced-aligned WordTimeline timings where available.
2. Compute per-word duration and local speech-rate features.
3. Compute per-word RMS energy/loudness over aligned audio windows.
4. Compare against current CTC-derived RhythmFrame on 5-10 manually reviewed
   sentences.
5. Promote evidence labels such as:
   `forced_alignment_timing`, `duration_supported`, `rate_supported`,
   `energy_supported`.

F0/pitch is a formal follow-up candidate, not a vague future wish. Add it if
manual QA shows duration+energy cannot explain enough actual prominence or
phrase-boundary behavior.

## Existing Lengthening Heuristic

The existing `pre_boundary_lengthening` rule remains acceptable as a small
research-backed diagnostic:

- adjacent tokens do not already have a pause boundary;
- the left token duration is at least `220ms`;
- the left token's duration per expected unit is at least `1.75x` the local
  median duration per expected unit;
- at least three nearby reference tokens are available.

Do not tune these constants to tiny Helsinki smoke scores. Use them only as a
failure-mode probe until the production-side WordTimeline + RMS energy path is
implemented.
