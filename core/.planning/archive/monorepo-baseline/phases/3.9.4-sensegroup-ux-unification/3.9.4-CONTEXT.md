# Phase 3.9.4 Context: SenseGroup UX Unification

> 创建：2026-07-14
> 上游输入：`design-notes/upstream-sensegroup-chunk-ux-unification.md`（用户桌面方案文档）
> 起点：main `8bbbd3ba`（Phase 2.24 收口后）

## 一、问题（已逐条对照代码核实）

用户打开"语义分组"后前端无任何视觉变化，且无反馈。断链共四层，
比上游文档描述的更彻底：

1. `run_track_syntax_analysis`（`crates/api-http/src/routes/syntax.rs`）计算出
   batch 内每句的 `sense_groups` 后只写 JSON track cache，从不写
   `sense_group_analyses` SQLite 表。
2. application 层的 syntax-aware 生成路径
   `generate_sense_group_analysis_internal(_, _, Option<&SyntacticAnalysis>)`
   （`crates/application/src/sense_groups.rs`）是私有函数，syntax 参数从未被
   传过 `Some`——死参数。上游文档引用的
   `generate_syntax_aware_sense_group_analysis()` 并不存在。
3. Flutter 全代码库没有任何调用 `generateSenseGroupAnalysis` /
   `activateSenseGroupAnalysis` 的地方（HTTP 入口在
   `apps/desktop/lib/services/api/timelines.dart` 早已存在，零调用方）。
   连文本规则回退生成都从未被触发过。
4. `_loadSenseGroups`（`speech_enhancement_workflow_controller.dart`）只认
   `isActive` 的分析，而生成默认落 `Candidate`。修复必须"生成 + 激活"。

次要问题（同样核实属实）：

- `token_line.dart` 中 `senseGroups.isEmpty` 时静默回退逐词渲染，无 UI 反馈。
- SenseGroup 无播放跟随/点击跳转；semantic 纯模式使用虚线"provisional"降级视觉。
- 3.9.3 QA 只覆盖 batch 响应 sense_groups 非空，未覆盖 SQLite 持久化与激活。

## 二、关键决策

### D1 — 时间戳走 ADR 0016 投影方案，不改 domain 模型

上游文档提议给 SenseGroup 加 `start_ms/end_ms`，但 ADR 0016 §2 明确
"SenseGroup does not store time ranges"，播放区间由消费方把 token span 投影到
active WordTimeline 上取 min/max。ADR 理由（避免时间数据重复、word timing
重估后 sense group 仍有效）依然成立。

采纳：Flutter 端投影。`SpeechEnhancementWorkflowController` 同一状态里已有
`wordTimingsBySentence`，`WordTiming` 自带 `tokenIndex`，纯客户端可得每组播放
区间。零后端改动、零 schema 改动。

### D2 — 持久化直接映射 batch 结果，不重算 partition

两个候选：(a) syntax 路由把 per-sentence `SyntacticAnalysis` 合并后调用
`generate_sense_group_analysis_internal`；(b) 直接把 batch 里已算好的
`SyntacticSenseGroupSpan` 映射持久化。

采纳 (b)，理由：

- `consume()`（`crates/application/src/syntactic_consumers.rs`）为每句构造的是
  单句 `SyntacticAnalysis`（`sentences: vec![1]`、单句 source_fingerprint）。
  合并成整轨 analysis 无法通过 `validate_syntactic_analysis` 的整轨
  fingerprint/coverage 校验，除非伪造 provenance——不可接受。
- (a) 会把同一份 sense groups 算两遍，形成双真相源；batch 是用户在 syntax
  视图看到的东西，持久化自 batch 保证两个 surface 一致。
- Partial 轨道天然处理：batch 中成功句带 syntax 归属
  （`syntactic_analysis_id: Some`），fallback 句是文本规则 span，逐句混合，
  无需整轨二选一。

### D3 — 激活策略与幂等

- 持久化后立即激活（`Candidate → Active`，生命周期已有单 active 保证）。
- `SenseGroupAnalysisId` 由内容 fingerprint 派生；写入前先查该 track 的
  active analysis，fingerprint 相同则跳过，避免每次 syntax 分析都写库/激活。
- syntax-aware 结果应接管 active：若现 active 是纯文本回退版本而新结果含
  syntax 归属，直接激活新的。

### D4 — cache-hit 补偿路径

`run_track_syntax_analysis` 命中 track cache 时提前返回。修复前已被缓存的
轨道永远不会走新鲜计算分支，必须在 cache-hit 分支同样执行
"无匹配 active analysis 则从 cached batch 持久化 + 激活"。

### D5 — 回退生成由 Flutter 触发既有入口

语法能力未安装时（syntax 路由早退 Unavailable，无 batch），Flutter 的
speech-enhancement 加载流程在"无 active analysis"时调用既有
POST `/v1/subtitles/{id}/sense-group-analyses`（文本规则路径）并激活。
不做 GET 生成副作用，不在 Unavailable 早退分支塞生成逻辑。

### D6 — 架构边界

api-http 不做跨 crate 编排（AGENT.md 规则）。持久化编排做成
`MediaAnalysisUseCases` 的公开用例，路由只调用一行。

## 三、范围外

- ADR 0016 数据层分离本身不动（Chunk 与 SenseGroup 各自独立）。
- 上游文档 3.2.6 "模式重设计（广义）" 中超出视觉/交互对等的部分
 （grouping mode 语义重构、新配置体系）不在本 phase。
- SenseGroup 精听练习题型（消费入口）不在本 phase。
- chunk 算法本身（声学证据层）不动。

## 四、QA 缺口修复原则

3.9.3 漏掉此 bug 的原因是集成测试只断言 batch 响应非空。本 phase 的测试
必须覆盖完整链路：syntax 分析 → SQLite 持久化 → active → GET 列表可读 →
Flutter 模型解析，以及 batch sense_groups 与持久化 groups 的一致性。
