# 3.5 Slice 8 实施指南:冷启动快速标注流(交接文档)

状态:HANDOFF——本指南自包含,面向未参与 3.5 前几个 slice 的实现者。
难度评估:**不难,工作量中等**(一个只读端点 + 一个 Flutter 弹出流,零新写入面)。

## 1. 目标与验收

新材料的 fit 常因词汇画像覆盖不足进入"诚实降级态"(fit 卡显示保守估计提示,见
`apps/desktop/lib/widgets/panels/content_fit_card.dart`)。本 slice 提供一个
**两分钟级别、可随时退出**的快速标注流:从当前 track 的 transcript 抽样高频未评估词,
用户逐个三选一标注,完成后 fit 自动重算变准。

验收(全部满足才算完成):

- [ ] fit 卡降级提示出现时,提供"快速标注"入口;点开后逐词标注,可跳过单词、可随时结束;
- [ ] 标注写入**现有** lexical entry 路径(不新建任何写入面/表/迁移);
- [ ] 全部结束(或中途退出)后 fit 卡自动刷新;标注过的词使 `assessed_token_ratio` 上升;
- [ ] `cargo test --workspace` 与 `flutter analyze` / `flutter test` 全绿,CHANGELOG 更新;
- [ ] 文案守 guardrail:预期管理不判决,流程可跳过、不强制、不阻塞任何功能。

## 2. 背景阅读(15 分钟)

- `docs/decisions/0018-dual-dimension-content-fit.md`——尤其决策 4(诚实降级)与决策 5;
- `crates/application/src/content_fit.rs`——token 归一化统计的既有实现,抽样端点要与它
  **共享同一归一化路径**(`normalize_lexical_form`),否则标注后覆盖率不动(最大的坑);
- `crates/application/src/lexical.rs` 的 `create_lexical_entry`——标注写入复用它
  (fingerprint id upsert,天然幂等;status 写入自动触发能力兼容同步,受 ADR 0019
  写入者阶梯约束——冷启动词均无任务证据,阶梯不会拦截,无需特判);
- `apps/desktop/lib/widgets/panels/content_fit_card.dart`——入口挂载点。

## 3. 后端:抽样端点

### 3.1 application 层(新文件或并入 content_fit.rs)

```text
pub fn cold_start_word_candidates(
    &self,
    track_id: &SubtitleTrackId,
    limit: u32,             // clamp 到 50,UI 默认请求 20
) -> Result<Vec<ColdStartWordCandidate>, ApplicationError>

pub struct ColdStartWordCandidate {
    pub display_form: String,     // 原文中最常见的表面形(供 UI 大字显示)
    pub normalized_form: String,
    pub occurrence_count: u32,    // 在该 transcript 中的词次
}
```

实现步骤(镜像 `compute_content_fit_for_track` 的前半段):

1. `subtitle_tracks.get_track` → 语言缺失时 `Validation("subtitle track language")`;
2. 遍历 `track.sentences[].tokens`,`kind == Word`,经 `normalize_lexical_form` 归一,
   空归一排除;按 normalized key 统计词次,同时记录每个 key 最常见的原始 text 作
   display_form(小写化去重前的形态即可,不必完美);
3. `lexical_entries_by_keys` 批量查询;**只保留"未评估"词**:无 entry,或 entry.status
   为 None(注意:`Some(UnknownMeaning)` 是已评估,必须排除,不变量 1);
4. 按 occurrence_count 降序、同频按 normalized_form 字典序(确定性),截断 limit。

不要为它建缓存:抽样是一次性交互前的即时查询,transcript 在内存中,词典查询是一次
批量 SQL。

### 3.2 api-http

- 路由:`GET /v1/subtitles/{track_id}/cold-start-words?limit=20`,挂在
  `crates/api-http/src/lib.rs` 的 content-fit 路由旁;handler 放
  `crates/api-http/src/routes/media.rs`,镜像 `track_content_fit` 的写法;
- openapi:`contracts/openapi/v1.yaml` 加 path + `ColdStartWordCandidate` schema
  (三字段均 required);
- 端点测试:`crates/api-http/src/tests/media_subtitles.rs` 有现成的"注册媒体 + 导入
  timeline.srt"模板(`content_fit_endpoint_serves_dual_dimension_profile`);断言:
  未标注时返回非空且按频次降序;对其中一个词 `POST` 现有 lexical entry 创建端点
  (带 status)后再次请求,该词消失。

### 4.2 交互(一个新 widget + fit 卡入口)

- `content_fit_card.dart`:降级提示 `_NoteLine` 区域加一个 `TextButton`("快速标注"/
  "Quick marking"),回调由面板层注入(参考 `ContentFitCard` 现有 props 的传递链:
  `side_panel.dart` / `subtitle_resources_screen.dart` → `SubtitleResourceManagerPanel`);
- 新 widget `apps/desktop/lib/widgets/panels/cold_start_marking_sheet.dart`:
  - 打开时请求候选词(默认 20);空列表显示"没有需要标注的高频词"并可关闭;
  - 一次一词:大字 display_form + 进度 `x / N` + 四个动作:
    **认识也听得出**(KnownRecognized)/ **看得懂听不出**(KnownNotRecognized)/
    **不认识**(UnknownMeaning)/ **跳过**(不写入,直接下一个);

    (`resource_actions_coordinator.dart` 已有此方法;词汇水位变化会使指纹失效、
    自动重算——这是设计好的路径,不要绕过缓存直调 compute);
  - 文案进 `apps/desktop/lib/localization.dart`(en + zh 双份,键名 `coldStart*`)。
- widget 测试:选择某档 → 断言 API 以正确 status 被调用并推进到下一词;跳过不调 API;
  关闭触发刷新回调。模板:`apps/desktop/test/content_fit_card_test.dart`。

## 5. 全局坑位(读三遍)

1. **归一化同路**:候选词统计必须走 `normalize_lexical_form`,与 fit 计算/词条创建
   同一条路;token.normalized 字段是字幕分词器的归一,**不是**词法归一,不要用它做 key。
2. **未评估 ≠ 不认识**(不变量 1):候选过滤只排除"有 status 的词";
   `Some(UnknownMeaning)` 是用户已给出的判断,不得再次弹出。
3. **零新写入面**:标注 = 调现有 entry 创建/更新端点。ADR 0017 的纪律是写入路径收敛;
   兼容同步会自动把 status 投影到能力画像并产生正确的 provenance。
4. **不阻塞、可无视**(P3/P5 红线):入口只在降级态出现;流程可整体跳过;任何异常
   静默收起,不得影响播放/学习功能。
5. 本地跑 `./scripts/validate-contracts.sh` 若见 4 个 CJK tokenize 失败,是本机缺
   `jieba` 的既有环境问题,与你的改动无关(佐证:干净树上同样失败)。
6. 提交纪律:每次 commit 同步更新 `CHANGELOG.md`;commit trailer
   `Co-Authored-By:` 按仓库近期提交格式。

## 6. 明确不做(Non-goals)

- 不做句级抽样、不做"按覆盖率贡献最优化"的花哨排序(频次降序足够 v1);
- 不做标注撤销(词汇本里已有完整编辑能力);
- 不新增 schema/迁移;不改 fit 算法与阈值;
- 不在非降级态主动推销标注流。
