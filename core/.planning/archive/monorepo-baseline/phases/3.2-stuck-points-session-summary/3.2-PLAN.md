# Phase 3.2 Plan: Stuck Points & Session Summary

状态：PLANNED

上游输入：`3.0-PHASE-BREAKDOWN.md`、`.planning/discuss/listen-learning-activity-path.zh.md`

## Objective

给精听会话建立"问题被处理完"的闭环感：卡点标记、解决状态派生、session summary、
悬案区 v0、"精听完毕"宣告与熟料标记。精听从"听完了"变成"把问题处理完了"。

## User Value

> "这四十分钟我卡了 12 处：当场解决 7 处、存了 4 处复习、还有 1 处连诊断都解释
> 不了——它进了悬案区，等以后有新证据再叫我。"

## Scope

### In

- **卡点手势**（仅两个新手势，遵循"安静播放器"原则）：
  - `标记卡点`：把当前句/chunk 显式标为"没听懂"。句循环、开诊断等深动作可作为
    隐式卡点信号（派生，不打扰用户）。
  - `跳过`：显式放弃处理当前卡点。
- **卡点状态派生**（先派生后建模，C-6）：
  - 从 `LearningEvent` / `PracticeAttempt` / `ReviewItem` / 诊断查看事件派生：
    未听懂 -> 已定位原因 -> 已通过提示听懂 / 已主动验证通过 / 已加入复习 /
    暂时跳过 / 仍未解释。
  - 只有派生覆盖不了的状态转换才考虑升格显式 domain 实体（记录决策再动手）。
- **Session summary**：精听会话结束视图——卡住 N 处 / 当场解决（含主动验证数）/
  加入复习 / 仍未解释 + 主要问题归因（弱读 function words、phrase、chunk 边界等，
  归因来自 3.1 的诊断升级）。
- **悬案区 v0**："仍未解释"卡点的容器。悬案不进复习队列；提供列表、回听入口和
  手动关闭；被新证据唤醒（词典例句、更好的分析）留接口不留实现。
- **精听完毕宣告**：用户宣告"这段啃完了"；有未处理卡点时提示确认（"还剩 3 个
  未处理卡点，仍然结束吗？"）。宣告产生**熟料标记**（Phase 3.5 泛听队列消费；
  3.5 未上线时熟料标记仅存储）。

### Out（Non-goals）

- 泛听侧任何功能（3.3）。
- dashboard 长期聚合（3.10）；summary 只做单次会话。
- 卡点状态机 domain 实体（除非派生被证明不足）。
- 强制用户处理每个卡点（P3：跳过永远无惩罚）。

## Dependencies

- 3.1（practice attempt 是"已主动验证通过"的证据来源；无 3.1 时 summary 只能统计
  提示型解决，含金量不足，故排在 3.1 后）。

## Key Work

1. 精听会话边界定义（何时开始/结束一个 session；复用 `PracticeSession` 或按需扩展）。
2. 卡点标记/跳过手势 + 隐式信号采集（事件写入，不新增权威存储）。
3. 状态派生器（纯读侧聚合，输入 LearningEvent 流）与单元测试。
4. Session summary UI + 归因汇总。
5. 悬案区 v0（存储 + 列表 + 回听 + 手动关闭）。
6. 精听完毕宣告 + 熟料标记持久化。

## Exit Signal

- 一次真实媒体精听会话（手工 QA）结束后，summary 数字与实际操作对得上。
- 悬案项可回听、可关闭，不出现在复习队列。
- 宣告完毕后熟料标记落库。
- **独立可用**：不开 summary 也能正常精听；卡点手势缺席时其余功能无变化。

## Guardrails

- 继承全局规则；卡点是辅助记账，不是待办清单——UI 不制造"必须清零"压力。
- 派生逻辑是读侧事实聚合，不反向修改 practice/review/status 权威记录。
