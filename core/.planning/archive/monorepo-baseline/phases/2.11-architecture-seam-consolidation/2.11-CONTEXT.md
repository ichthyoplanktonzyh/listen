# Phase 2.11 Context: Architecture Seam Consolidation

## 问题

Phase 2.6 多语言基础建设中，为了不过度设计，刻意预留了多个 seam（接缝）——设计层
有位置但代码未实现。随着 Phase 2.7–2.9 推进，部分 seam 已有足够上下文可以落地，
另一些需要等 Phase 2.10（英语音频分析）有进展后才有实际效果。

## 各 Seam 现状

### A1: LANG-004 听觉锚定观察

**来源**：Phase 2.5.5 SLA Foundation 的 R1 修订——听力 observation 可锚定
ListeningUnit（不止 LexicalUnit）。

**现状**：`ListeningUnit` 在设计文档中定义为视图概念，但代码中所有 observation（词汇
状态变更、诊断结论）仍锚定到 word/token 级别。

**影响**：用户学习的是"声音模式"而非"单词拼写"，但系统只能按单词记录学习进度。
例如 "want to" 的弱读形式 /wɒnə/ 是一个听觉单位，但系统分别记录 "want" 和 "to"。

**依赖**：Phase 2.10 的 phone-level 检测为 ListeningUnit 提供声学锚定依据。

### A2: LANG-009 L1 诊断 seam

**来源**：Phase 2.5.5 确认"L2 听力难度被 L1 过滤"（Best PAM / Flege SLM）。

**现状**：诊断签名 `(L1, L2_unit, status, context)` 在 ADR/设计层预留，但 `diagnose`
函数不接收 L1 参数。Phase 2.6 的 `diagnosis_hint.reasons` 按语言输出可能因素
（zh: 声调/词边界/同音；en: 弱读/连读），但这些是 L2 维度，不是 L1×L2 对比。

**影响**：无法告诉用户"你作为中文母语者，这个弱读对你特别难因为中文没有弱读"。

**依赖**：需要 L1×L2 对比难度表（contrastive analysis），可以从小规模硬编码开始。

### A3: 能力矩阵 API 暴露 client

**来源**：Phase 2.6 的 Open Question。

**现状**：后端有 `LanguageLearningProfile` 能力矩阵（tokenization / dictionary /
pronunciation / word_timeline / chunk_timeline 支持级别），但未通过 API 暴露。
Flutter 端用 `_isHan` 等脚本检测门控功能（逐字拼音、诊断因素）。

**影响**：新增语言时 client 需要手动加 if/else，而不是按能力自动适配。

**依赖**：无，可独立推进。

### A4: 学习语言来源优先级

**来源**：Phase 2.6 收口。

**现状**：`_learningLanguage` 读 active 字幕轨语言，无 active 时 fallback en。
用户无法手动指定学习语言，也不读媒体 metadata 语言。

**影响**：如果用户导入无语言标记的字幕，系统可能判错学习语言。

**依赖**：无，可独立推进。

### A5: identity 边界 profile 化

**来源**：Phase 2.6 第三语言证伪。

**现状**：仓储层约 6 处 `normalize_lemma` 对 en/zh/ja 行为等价（都做小写化）。
中文/日文 surface 归一在 tokenizer 层已 profile 化（Phase 2.6 Fix 4），但存储边界
仍用旧的 `normalize_lemma`。

**影响**：对 en/zh/ja 无行为差异（中日文无大小写），但如果加入土耳其语等
大小写敏感语言会出问题（İ/i 不等于 I/ı）。

**依赖**：无实际影响直到加入相关语言，优先级较低。

### A6: domain `lib.rs` 拆分

**来源**：Phase 2.3.5 收口判定暂不作为前置项。

**现状**：`crates/domain/src/lib.rs` 约 1317 行，是 workspace 中最大的单文件。
Phase 2.3.5 已拆分了 persistence-sqlite / application / api-http，但 domain
因为类型定义之间强耦合未拆。

**影响**：随着 PhoneTimeline / ChunkTimeline / LanguageProfile 等类型持续增长，
可维护性下降。

**依赖**：无，mechanical decomposition，不改行为。
