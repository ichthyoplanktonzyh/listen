## Outcome

Speaking 已成为当前内容的真实通道，并由延迟复述资产复用同一状态机。用户可以回听 10–60 秒
来源、录音、用本地 whisper.cpp 转写、分开保存 raw/corrected transcript、请求后自评、修正
已保存 verdict、立即重说一次并安排延迟复述。Role Reply 具三档 assistance；L1 核对独立作为
listening fact。无 qualified judge 时仍以客观录音事实 + 用户自评完整交付。

## Delivered

- 独立 `RecordingAsset -> RecordingTranscriptionJob` 短录音路径：16k mono PCM16/hash 预检、
  language、cancel、segments、latency 和完整 provider/runtime/model/recording provenance。
- Speaking 专属状态机与整面阶段自适应 UI；录音期无 transcript/反馈，核对后保存 attempt，用户
  请求后才显示自评；权限拒绝先于音频焦点交接。
- L2 Retelling 与 Role Reply（full sentence/keywords/no text）事实、prompt/source snapshot、
  fixed rubric、ASR reliability、append-only attempt/judgment/adjudication。
- 内容入口与延迟 review asset 入口；完成或退出回到正确来源，只恢复主媒体位置、不自动播放。
- 单录音 acoustic facts：时长、≥120ms 停顿与 waveform；它们不构成评分。
- 显式 anchored `SpeakingProduction` observation：仅 qualified constructed attempt + corrected literal
  hit + 用户确认；assistance 可追溯，零 projection。
- L1 fallback 复用 typed listening task；无 LLM/judge 路径为一等公民。

## Key Decisions

1. Speaking 是内容通道，延迟复述从资产层进入；不建独立 Studio 首页。
2. Reading/Speaking lifecycle seam 审计未发现足以抵消抽象成本的同语义重复：Reading 恢复
   typed/rubric 草稿，Speaking 还需 recorder/ASR/RecordingAsset/音频焦点副作用。v1 不抽 generic
   interface，也不建 mega-controller。
3. raw transcript 是 immutable ASR fact；corrected transcript 是用户核对版本；ASR uncertainty
   不是 speaking failure。
4. judge 资格由 3.12.1 决定。当前不接 LLM feedback，不用 heuristic 冒充判断；manual self-
   assessment 可 append-only adjudicate。
5. 目标表达证据要求用户显式确认 corrected literal hit；L1、shadowing、模型改写、unreliable ASR
   和不存在的字面目标均不能写 speaking observation。
