## Objective

建立「个人产出语料库」（personal production corpus）：与媒体 corpus 索引同构的**可重建
投影**，索引对象从媒体换成用户自己的语言产出。每条带 channel 标签（written / spoken）、
来源锚点（rubric/attempt/段落/媒体）、时间戳与 lemma 归一。第一数据源是 3.15 已存在的
immutable writing attempts（零新采集）；口语摄入路径等 3.15.7 realtime 落地后再接。

## User Value

用户第一次能查询「我自己用过哪些词、在哪些任务里、说过还是写过」。这是 3.15.6 gap 复盘
和 3.16 个人表达资产的共同数据地基；写作数据先入库，让后续 realtime 一上线产出就有归宿。

## Scope

### In

- **可重建投影（核心红线）**：产出语料库是从 immutable attempts 派生的投影，零新权威
  存储；重建幂等（对照 3.6 corpus reindex 模式），删除重建不丢任何事实。
- 写作产出摄入：3.15 各 kind 的 typed attempts（含 revision 链的最终 learner 文本）→
  分词 + lemma 归一（复用既有 lexical normalization provider）→ 语料行。
- 投影 shape：回答 document 只存一份完整文本；lemma-keyed token occurrence 只存 surface、
  Unicode-scalar span 与 document 引用，避免每词复制全文。document 带 channel（`written`，
  spoken 仅枚举预留）、来源锚点、时间戳与 factual assistance provenance。
- assistance 不写死为 `scaffolding: bool`：记录 `content_anchored`、`source_reconstruction`、
  `learner_revision` 等可观察来源，不在事实层宣判某次产出是否“自主”；未来口语 consumer
  可追加明确目标、模型建议、直接模仿等来源，排除/权重归复盘 policy。
- 读端「我的产出」查询：按 lemma 查产出出现（词典详情可挂"你写过 N 次"入口级视图）；
  FTS/lemma 查询与媒体 corpus 同构。
- 边界裁决（开工时定）：与 3.16「收藏句→个人模板」的资产关系——个人模板应消费本语料库
  还是独立资产，一次裁清，避免两套「用户自己的语言」。

### Out

- 任何 observation/projection 写入（产出语料是事实层；确认门归 3.17，复盘归 3.15.6）。
- 口语摄入、辅助来源的排除/权重逻辑（3.15.7 / 3.15.6）。
- 分布画像 / gap 计算 / 参照系排序（3.15.6，本 phase 只出可查询语料）。
- 语义嵌入、近义检索（3.15.8）。
- 新 UI 面板体系：读端只做最小查询入口，不建"产出中心"页。

## Slices

- **Slice 1 — 投影与重建**：语料 schema（可重建表）+ 写作 attempts 全量重建 + 增量摄入
  （attempt 落库时）；重建幂等测试。
- **Slice 2 — 查询读端**：lemma/FTS 查询 API + 词典详情「我的产出」最小入口；零结果
  诚实空态。
- **Slice 3 — 边界裁决落档**：3.16 关系裁决写入本 phase CONTEXT；语料是可删投影，
  模板是用户显式保存且有独立身份的资产，模板可引用语料来源但不由语料行充当身份。

## Exit Signals

- 代表性真实 shape 的 Writing typed attempts 可全量重建入库；重复重建结果一致（幂等），
  失败重建以事务回滚保留旧投影。
- 词典/查询端可按 lemma 看到自己的写作产出及来源锚点，可跳回原 attempt。
- 零 observation/projection writer（负向测试钉住）；语料表可整体删除而不丢任何权威事实。
- channel/assistance 字段就位但无 spoken 写入者、无排除/权重逻辑（钉住只读事实）。

## Guardrails

- 投影永不成为身份权威：语料行不铸新学习资产身份，只引用既有 attempt/lemma 身份。
- lemma 归一走既有 provider，不在语料层私造归一规则。
- 不为想象中的口语数据形态预设 schema 泛化（守共享上下文 §3.6：additive 字段可预留，
  身份泛化必须等真实 consumer）。
