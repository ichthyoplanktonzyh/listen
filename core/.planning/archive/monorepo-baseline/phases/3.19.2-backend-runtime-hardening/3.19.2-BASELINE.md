## Runtime Risks To Characterize

1. Normal async handlers synchronously enter application and SQLite.
2. One `Mutex<Connection>` serializes reads and writes.
3. Mutex poison is converted to `expect`, widening one panic into later request panics.
4. SSE `while let Ok(...)` disconnects a receiver on broadcast lag.
5. Raw repository error strings are returned in authenticated HTTP 500 bodies.
6. Request duration, slow persistence calls and job phase duration are not uniformly observable.

## Measurement Contract

Before changing SQLite execution:

- add a deterministic concurrency characterization test;
- record interactive read latency while one synthetic slow persistence operation occupies the adapter;
- verify ordinary repository interface tests still run outside a Tokio runtime;
- verify shutdown and SSE remain responsive under database pressure.

Closeout reports baseline/final measurements and any deferred scaling threshold.
