# Phase 3.19.2 Closeout

Status: COMPLETE

Date: 2026-07-26

Scope: backend only; `apps/desktop/**` was not edited.

## Outcome

The backend now has one explicit HTTP-to-synchronous-application execution seam,
recoverable SSE lag semantics, lifecycle-grouped runtime state, coherent route
groups, redacted public errors with correlated diagnostics, non-poisoning SQLite
serialization, and CI supply-chain enforcement. Product semantics, learning
authority and HTTP/OpenAPI wire paths are unchanged.

## Before / After

| Area | Before | After |
|---|---|---|
| Async persistence | Direct synchronous `AppServices` calls in handlers plus ad hoc dispatch | Zero direct route access; all repository-bearing calls use `ApplicationExecutor` |
| Runtime responsiveness | Slow sync call could occupy a Tokio worker | Deterministic single-worker heartbeat stays responsive for sync and mixed async work |
| SSE | lag and channel close collapsed into loop termination | explicit lag diagnostic, retained-event continuation, explicit close |
| SQLite lock failure | 333 poison `expect` paths | non-poisoning mutex; zero poison panic sites |
| Composition | 1216-line root with 600+ line protected chain and flat state | ~469-line root; four coherent protected route groups and four lifecycle contexts |
| Errors | internal repository/process/secret details could become public | generic public body; internal structured diagnostic joined by correlation ID |
| Request diagnostics | no uniform completion record | method/route/status/duration/correlation ID and response header, without body/token |
| Supply chain | no automated Rust advisory/license/source gate | `cargo-deny 0.19.7 --locked` CI gate and explicit narrow exceptions |

The pre-change direct-call architecture could serialize an unrelated heartbeat for
the full duration of a slow repository call. The post-change characterization uses
a deliberately blocked operation on a current-thread runtime: a 10 ms heartbeat
completes inside a 100 ms bound while the repository operation remains blocked.
This is a deterministic responsiveness bound rather than machine-dependent
throughput marketing.

## Durability And Deferrals

SQLite keeps one connection, a five-second busy timeout, pre-migration backup and
default journal/synchronous modes. WAL/pooling is deferred because a single local
writer gains no demonstrated benefit and changing it would alter durability and
transaction behavior. A dedicated bounded blocking executor is likewise deferred
until saturation measurements justify it; the stable `ApplicationExecutor`
interface allows that internal change later.

A future diagnostic export can filter the existing structured events by
correlation ID and time window. It must continue excluding bearer tokens,
credentials, request bodies, learner text, subtitle content and raw filesystem
paths by default.
