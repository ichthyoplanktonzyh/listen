## Objective

在不改产品语义、学习权威、Flutter UI 和既有 HTTP wire contract 的前提下，把已经正确的
本地后端架构补齐为 release-grade runtime：同步 SQLite 不阻塞 async transport，事件 lag
可恢复，composition interface 按领域保持 locality，内部错误不泄漏，关键请求/任务可诊断，
依赖供应链有自动门。

目标形态：

```text
Axum root router
  -> domain route modules
  -> request execution / tracing module
  -> application deep use-case modules
  -> persistence execution seam
       -> SQLite adapter + explicit blocking strategy
  -> runtime contexts
       -> transcription / analysis / syntax / TTS / embedding

SSE notification --lag--> explicit resync signal/behavior --> authoritative GET state
```

## Slice 1 — Recoverable Event Delivery

- replace `while let Ok(receiver.recv())` with explicit `Ok` / `Lagged` / `Closed` handling;
- define notification loss behavior without pretending SSE is a durable log;
- ensure reconnect/resync uses existing authoritative job/read endpoints;
- add deterministic tests for normal delivery, lag, close and post-lag continuation;
- preserve existing event envelope versions unless a typed resync event is proven necessary.

Acceptance:

- a slow receiver no longer silently conflates lag with server shutdown;
- lag behavior is observable and test-covered;
- no event payload or Flutter change is required for the preferred implementation.

## Slice 2 — Persistence Execution Module

### 2.1 Characterization

- build a controlled slow-operation adapter/test;
- measure concurrent request responsiveness and persistence serialization;
- inventory transaction-heavy operations and current explicit `spawn_blocking` exceptions.

### 2.2 Design checkpoint

Compare:

1. dedicated blocking executor around synchronous application calls;
2. SQLite actor/command queue;
3. connection pool with per-call blocking dispatch;
4. repository-internal `block_in_place`.

Judge by interface depth, compatibility with sync tests, transaction locality, cancellation semantics,
tail latency and migration cost. Do not select an option merely because it minimizes diff size.

### 2.3 Implementation

- establish one execution module used by all blocking transport work;
- prevent ordinary SQLite work from occupying Tokio async workers;
- preserve synchronous domain/application tests and transaction invariants;
- remove ad hoc duplicate dispatch after replacement;
- replace mutex-poison panics with typed repository failure where practical;
- document connection/journal/busy-timeout durability choices.

Acceptance:

- deterministic test proves health/SSE or another non-DB task remains responsive during slow DB work;
- no long-lived per-handler `spawn_blocking` boilerplate;
- repository and migration tests retain behavior;
- concurrent workload has recorded before/after latency;
- no database or schema replacement.

## Slice 3 — Composition Locality

### 3.1 Route modules

- each resource-domain route module exposes its own `Router<ApiState>` or coherent route-group function;
- root `router()` owns only merge, auth, health and state;
- OpenAPI parity remains bidirectional;
- route movement must be mechanical before any behavior cleanup.

### 3.2 Runtime contexts

- group `ApiState` fields by shared lifecycle/change reason, such as analysis jobs, language resources,
  generative providers and event/security infrastructure;
- keep use-case modules in `AppServices`; do not introduce a second fat repository interface;
- constructor accepts coherent contexts or a production composition input instead of a growing flat list;
- tests may install deterministic context adapters without constructing unrelated runtimes.

### 3.3 Application composition

- inventory `AppServices` fields against its public module accessors;
- move dependencies owned by one use-case module into that module when doing so improves locality;
- delete superseded pass-through state immediately;
- retain shared repositories where cross-module transaction authority genuinely requires them.

Acceptance:

- root router is a small composition module;
- adding a route to one domain does not edit a 600+ line route chain;
- focused route tests construct only coherent context inputs;
- no new one-adapter hypothetical seam;
- architecture guard prevents regression.

## Slice 4 — Error Safety And Observability

- split public error message from internal diagnostic source;
- repository/secret/process internal details never enter generic HTTP 500 bodies;
- correlation ID joins response and structured diagnostic;
- add request method/route/status/duration tracing with token/header/body exclusion;
- add slow persistence operation and long job phase diagnostics;
- keep learner text, subtitle content, filesystem paths and provider credentials out of default logs;
- document a future user-exportable diagnostic bundle, implementing only the backend primitives needed now.

Acceptance:

- tests prove internal SQLite/path text is absent from HTTP response but present in captured diagnostic metadata;
- every request has one completion record with duration and correlation context;
- auth token and request body never appear;
- logging failure cannot fail a user request.

## Slice 5 — Supply Chain And Guards

## Exit Signals

- a slow SQLite operation cannot stall unrelated async lifecycle work;
- a lagged SSE receiver has explicit, tested recovery semantics;
- changing one route domain stays local to its route module;
- internal failures are diagnosable by correlation ID without leaking implementation details to UI;
- adding a runtime capability does not expand one flat `ApiState` constructor indefinitely;
- vulnerable or disallowed Rust dependencies fail an automated gate;
- Flutter/frontend work can merge without semantic or wire-contract reconciliation.
