# Phase 2.9 Context: Production Engine Multilingual Decoupling

状态：PLANNED

## 来源

Phase 2.6-2.8 完成后，app 消费侧已实现语言无关：分词、发音、诊断、时间对齐、
韵律估算全部由 profile + provider 驱动，加语言 = 加 profile + provider + 注册点。

但**生产侧**（从音频生成精确时间轴的管线）仍对英语强绑定：

1. **发音分析**：`speech_analysis::analyze_sentence` / `analyze_rules` 内硬编码
   CMUDict + 英语语流规则（weak form、linking、flapping 等），对非英语句子产出空
   或无意义结果。
2. **强制对齐**：MFA / MMS_FA sidecar 只支持英语声学模型。
3. **文本 chunk 检测**：`detect_text_chunks`（COCA/PHRASE 词表）有英语门控。
4. **转写管线**：whisper.cpp 本身支持多语言，但后处理（DTW 提取 → 强制对齐 →
   pause refinement → word timeline 快照）中的强制对齐步骤依赖英语模型。
5. **PhoneTimeline**：无任何语言有 release provider（英语 approximate，中文/日语
   unsupported）。

## 用户判断

> 轻装消费端已经基本结束了，现在主要的问题在于重装生产端之前对英语的强绑定。

## 产品目标

让非英语语言（首先是中文）也能走通"音频 → 精确时间轴 → app 消费"的完整链路，
而不只是消费估算时间轴。

## 约束

- whisper.cpp 已支持多语言转写，这是可以直接利用的基础。
- 强制对齐（MFA/MMS_FA）的多语言支持是独立的声学模型问题，本阶段只需确保管线
  能选择语言对应的模型，或在不可用时干净降级。
- 不新增重型 runtime 依赖到 app 端（消费端原则不变）。
- `speech_analysis` crate 的英语特定逻辑（CMUDict、规则分析）应被包装为英语
  provider，而非删除。

## 生产管线当前架构

```
音频 → whisper.cpp 转写 (多语言 ✅)
     → DTW word-level timestamps 提取 (语言无关 ✅)
     → token timing alignment (Phase 2.8, 语言无关 ✅)
     → 强制对齐 MFA/MMS_FA (英语 only ❌)
     → pause refinement (算法语言无关 ✅, 但只在有 forced-align 后运行)
     → word timeline 快照 (语言无关 ✅)
     → chunk 生成 (acoustic: 语言无关 ✅, text: 英语 only ❌)
     → pronunciation 分析 (英语 CMUDict ❌, 中文 CC-CEDICT pinyin ✅)
```
