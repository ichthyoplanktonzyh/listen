# Phase 3.5.7 Closeout: Slice Playback Window

> 收口于 2026-07-10 15:46 CST  
> 状态：COMPLETED（owner 确认收口）

## Summary

本阶段以独立的切片回听浮窗取代了词汇来源语境原有的主播放器劫持路径。用户点击任一 A 组
来源句时，主播放器仅暂停、媒体和位置保持不变；新的第二 fvp/video_player 实例在浮窗中按
来源快照的时间范围循环播放。浮窗默认音频优先，可按需展开视频，关闭即释放第二解码实例，
不会自动恢复主播放器。

实现没有修改 Rust、SQLite、OpenAPI 或 LLTimeline / lexical 后端契约。B 组的当前媒体内
`loopRange`（复习、精听、音素/节奏证据）保持原样，未做无收益迁移。

## Delivered

| 项 | 结果 |
|---|---|
| 双实例关口 | 在真实 macOS debug build 中验证两个 fvp-backed `VideoPlayerController` 共存：主实例持续渲染，第二实例不渲染视频并稳定循环 3 秒切片。无初始化、纹理或音频设备错误。 |
| 媒体解析 | 新增 `OccurrenceMediaResolver`，唯一处理关联媒体、文件存在性、用户定位、指纹验证和 `registerMedia`；linked 命中、指纹不符、源文件丢失恢复均有测试。 |
| 独立播放端 | 新增 `SlicePlayerController` 和可拖动 `SlicePlaybackWindow`，支持播放/暂停、重播、循环开关、音频优先与视频展开；关闭时 dispose。 |
| 焦点策略 | 打开切片后暂停主播放器但不改其媒体、位置或 loop 状态；精听浮窗重新播放时会暂停切片，避免双声源。 |
| 入口迁移 | 侧面板、词汇本、词汇详情与学习资产的来源句入口统一打开切片窗；`playOccurrence` 及 `loopOccurrence` 死路径删除。 |
| 失败可见性 | 文件定位取消、指纹不匹配或注册失败在切片窗显示明确文案，不静默失败。 |

## Key Decisions

- 第二解码实例已由 Slice 0 证实可行，未触发“快照/恢复主播放器”的降级方案。
- 位置轮询使用 `VideoPlayerController.position`，保证默认不渲染视频时仍能驱动精确的切片边界控制。
- 新播放器只消费 durable `LexicalOccurrence` 快照；不会扩展领域模型，也不走 HTTP 高频播放控制。
- 多切片横向卡片轨道属于未来 3.6 词典详情页的宿主 UI；3.5.7 提供其复用的单切片播放端，不提前建设词典容器。
