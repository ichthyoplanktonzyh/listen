## v3 开工审计裁决（2026-07-18）

- Phase 3.17 已 code complete，但 owner manual QA 仍 pending；3.18 继承其 schema v44、
  proposal-only 自动 writer、confirmation gate、override 优先和 cross-modal review read model，
  不执行或冒充 `3.17-MANUAL-QA.md`。
- Coach 的产品边界是**聚合、解释、编排既有事实/资产**。它不生成 observation、proposal、
  projection、override、judgment 或综合等级，也不从一个通道推断另一个通道 acquired。
- 旧稿中的 `read yes/listen no` 等速记全部收紧为每通道独立的
  `acquired / not_acquired / unassessed` 有效 assessment；只有显式 `not_acquired` 才能形成
  failure gap，`unassessed` 只能形成“尚未主动验证”的邀请。
- v1 不新增 Coach 持久表或第二套缓存 authority。聚合从带索引的 durable source facts 做
  bounded live query，响应携带 `generated_at_ms`；用户返回 Coach 时显式刷新。未来若真实性能
  数据要求缓存，该缓存必须是可丢弃、可重建且不参与任何 writer 决策的 read projection。
- 证据 drill-down 返回 typed source link，并携带不可变 snapshot。来源仍存在时可导航；媒体、
  rubric 或 attempt 丢失时显示 snapshot + `source_unavailable`，不隐藏事实、不伪造失败。
- 建议使用 typed destination，不复制任务住户状态；Flutter 只保存 Coach 自己的时间窗、筛选、
  滚动位置和 suggestion id 作为 return context。任务完成/中退后返回并刷新，不自动恢复播放。
- LLM/provider 只报告“未配置/已配置/当前核心 Coach 不依赖”这类可用性事实；不探测后臆测
  在线健康，不聚合模型分数。LLM judgment 仍是 provenance 完整、可纠正的 supporting
  evidence，永不单独产生 acquired。
- `UserSentencePattern` 只作为用户显式 durable asset 与可选 destination；writing/speaking
  personal-expression attempts 分通道计数，彼此不互推 capability。Hunting List 不迁移，
  embedding/corpus 只读发现边界不变，FocusTarget 未满足三 consumer razor 因而不重开。

## Phase 3.13.5 基线

- Coach 保持资产层入口和独立 dashboard，不进入内容工作台、不成为第五通道，也不使用任务
  容器承载统计页面。这是 3.18 的当前 surface 裁决，不冻结未来更好的产品形态。
- 建议动作只生成 typed destination：内容型建议打开对应内容通道/任务住户，资产型建议打开
  Review/Personal Expression；完成或中退返回 Coach 的来源建议与滚动位置。
- 打开建议可暂停但不得销毁当前内容会话；全局迷你播放条表示可恢复，返回 Coach 不自动播放。
- Coach aggregation 是只读深模块：interface 只接受时间窗/筛选并返回 channel blocks、gaps、
  evidence links 与 suggestions；查询、分页、缺席降级和性能策略留在 implementation。

## Objective

把 3.10 listening-era Coach 扩展为真正的四通道诊断工作台：从 durable facts 分别回答各
通道已有何种描述性事实、哪些 effective assessment 形成已评估 gap、哪些仍 unassessed、
哪些变化有证据以及下一步可选什么；完成四通道产品方向收口。

## User Value

> “我本周不是简单学了 20 个词：有 6 个从读懂变成听出，3 个已经能在复述里主动说出；
> 两个表达写作仍需提示。每条建议都能点回原片、原稿或录音，我可以选择做或不做。”

## Scope

### In

- 扩展 3.10 channel-ready aggregation：reading/listening/speaking/writing 分区与 cross-modal
  gap；drill-down typed provenance union 覆盖 attempt/event/rubric/judgment/adjudication/
  observation/proposal/decision/confirmed projection/history/override，并保留 immutable snapshot
  与来源可用性。
- 指标只来自已存在事实：输入/阅读、主动验证、构造性产出、修订、延迟重用、projection
  proposal/confirmation、复习完成；UI 明确区分 raw fact、supporting judgment、proposal、
  confirmed projection、override 与 effective assessment，绝不把它们折叠成同一 truth。
- Cross-modal insight：reading acquired / listening not_acquired、listening acquired / speaking
  not_acquired，以及 recognition assessed / production unassessed 等；unassessed 与
  not_acquired 分离，通道间无隐式蕴含。
- 建议引擎 v2：Reader、retelling/role reply、dictogloss、personal pattern、cross-modal
  review deep links；邀请式、可追溯、可关闭。
- LLM/provider health 只作为功能可用性说明，不把模型分数聚合成学习者分数。
- Starter state 按通道说明“尚未主动验证”，提供可选入口，不制造零值图表。
- 自动化 fixture/contract/widget/integration 覆盖同一内容的四通道独立事实与 Coach 完整追溯；
  真实内容听→读→说→写及体验验收写入 owner manual QA 清单，由 owner 后续执行。
- 建议 deep link 不持有或复制各任务住户状态，只携带目标、来源和返回上下文。

### Out

- CEFR 认证、标准化考试预测、语言总分、排名、streak、徽章。
- Coach 自动分配强制课程或因未完成而惩罚。
- 在聚合层发明新 evidence 或反写 capability。
- 跨设备云同步实现。

## Dependencies

- 3.10 channel-ready envelope 与 listening suggestions。
- 3.13–3.16 Studio facts；3.17 schema v44、qualification、proposal/confirmation、override 优先
  与 cross-modal review 是必读 authority 基线。某通道数据或合格 projection 可缺席并显式
  unassessed，Coach 不建立替代 authority。

## Key Work

1. 聚合 contract v2：channel blocks、cross-modal gaps、evidence links、availability reasons。
2. Dashboard UI：资产层通道诊断、趋势、来源事实 drill-down 与下一步建议；保持内容会话可恢复。
3. 建议规则 v2 与可解释参数；无上游数据/无 provider/无媒体的降级矩阵。
4. 性能：大 attempt/judgment/history 数据量下分页与索引验证；先以 bounded live query
   交付，不在没有真实性能失败前新增 durable cache/rebuild writer。
5. 自动化 closeout 与 owner QA 清单：覆盖 Coach→任务→Coach 返回、provider 未配置/离线、
   媒体删除，以及 Coach 只读反映外部 adjudication、override 与重投影结果；Coach 不触发
   或写入这些 authority 变化。
6. 更新 PROJECT/REQUIREMENTS/ROADMAP/STATE 与 phase closeout，记录仍未成立的能力；推进到
   code complete / owner manual QA boundary，新增 3.18 owner QA 清单但不由实现者执行。

## Exit Signal

- 自动化 fixture 中同一内容的听、读、说、写独立事实可被 Coach 追溯显示而不混写；真实
  内容体验留给 owner manual QA。
- 所有实际出现的下一步建议均直达真实 consumer 且有可解释依据；真实数据允许 0..N 条，
  缺少合格事实时诚实显示 availability，不为满足数量制造建议。
- 缺任何通道或 LLM provider 时其他区块正常工作，未评估不显示为失败。
- 没有综合语言分；Coach endpoint/service/UI 均无 capability mutation。长期 proposal/
  projection writer 与 confirmation gate 继续由 3.17 独占，override 仅走既有显式用户路径。
- 建议跳转与返回不丢 Coach 上下文，也不破坏可恢复的内容会话。

## Guardrails

- Coach 只读事实并建议，不成为新的权威写入者。
- 纯虚荣指标不上线；数字必须回答诊断或下一步行动问题。
- 四通道完整不等于每个格子有值，诚实缺席是完成条件的一部分。
- Dashboard 不接管任务生命周期；只读事实、生成 destination、接收返回刷新。
