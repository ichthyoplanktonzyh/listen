# Phase 3.3 Plan: Extensive Listening & Listening Inbox

状态：IN_PROGRESS

上游输入：`3.0-PHASE-BREAKDOWN.md`、`.planning/discuss/listen-learning-activity-path.zh.md`

## Objective

建立泛听会话与低摩擦捕获闭环：连续播放、软/硬打断、理解度自报、Listening Inbox
与整理流。泛听保持连续输入体验，但"刚才没听懂的东西"不再流失。

## User Value

> "我在干别的事，一句没抓住——按一下，继续听。回头十分钟把今天标的 8 处理完。"

## Scope

### In

- **泛听会话**：显式的泛听模式（进入/退出一键），默认零打扰——无高亮闪烁、无提示、
  无学习 UI 侵入；本质是"安静播放器 + 会话记账"。
- **软打断**：单键标记"刚才一句"（可配置为最近 N 秒窗口），播放不停。
  - 桌面端：全局快捷键 + 应用内按钮（媒体键/耳机键位映射按平台能力尽力支持，
    不作为退出条件）。
  - 标记实现为对字幕句/时间窗的引用（timeline 已带时间戳，回指最近句是查表）。
- **硬打断**：暂停并展开当前句，瞬时借用精听动作（查词、标状态、句循环），继续播放
  后仍处于泛听会话。
- **理解度自报**：会话结束单键自报（全懂 / 大意 / 迷糊），作为 durable 信号存储
  （3.5 上线后回流校准 fit；此前仅记录）。
- **Listening Inbox**：
  - 标记片段持久化（含字幕上下文 snapshot，媒体丢失可降级显示）。
  - 整理流（任意端可做）：逐条回听 -> 秒建词汇资产 / 建 `ReviewItem` / 升格
    **微精听**任务 / **片段收藏**（非学习资产，独立容器）/ 丢弃。
  - 未处理项过期自动降级归档（默认 N 天，可配置）；Inbox 永不阻塞下次泛听。
- **泛听会话记录**：时长、材料、标记数、自报结果写入 `LearningEvent`（供 3.10）。

### Out（Non-goals）

- 猎词单 / 任何泛听增强提示（3.7）。
- fit 计算与队列分拣（3.5）；本 phase 泛听材料由用户自选。
- 语音软打断（备选交互词汇，记录不实现）。
- 移动端实现（交互设计须通过"一颗按钮、没有屏幕"审视，但落地在桌面）。

## Dependencies

- 无硬依赖，可与 3.1/3.2 并行。微精听升格在 3.1 存在时接入三姿态入口，否则先落为
  "打开该句 + 句循环"的最小形态。

## Key Work

1. 泛听会话模型与进入/退出 UI（含会话记账事件）。
2. 软打断捕获：最近句回指、标记持久化、全局快捷键注册。
3. 硬打断流转：暂停展开当前句、动作借用、恢复播放。
4. Inbox 存储 + 整理流 UI（含收藏容器、过期归档任务）。
5. 理解度自报 UI 与持久化。
6. 手工 QA：一次 ≥30 分钟真实媒体泛听（`/Users/shadow/Desktop/视频` 素材），执行
   `3.3-MANUAL-QA.md`。

## Exit Signal

- 30 分钟真实泛听全程只需单键交互；结束后 Inbox 完整呈现标记。
- 整理流可在十分钟内清空当日标记；每条去向（资产/复习/微精听/收藏/丢弃）正确落库。
- 不整理、不自报均不影响任何后续使用。
- **独立可用**：无 3.1/3.2/3.4 时，Inbox 项仍可建词汇资产与回听。

## Guardrails

- P4 零打扰是硬约束：默认泛听路径不得出现任何主动提示。
- Inbox 不做成待办压力源：过期降级、无红点轰炸、无"清零"话术。
- 片段收藏与学习资产严格分离，避免污染。
