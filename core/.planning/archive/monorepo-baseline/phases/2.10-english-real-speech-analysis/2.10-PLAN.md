# Phase 2.10 Plan: English Real Speech Analysis

更新时间：2026-06-24 CST
状态：PLANNED

> 前置：Phase 2.5 建好了 PhoneTimeline 资源契约和质量门禁，但收口时 no release
> provider selected。Phase 2.7 建好了 PronunciationProvider trait 派发。本阶段的
> 目标是选出一个 phone-level provider，让英语语流分析从"文本预测"升级为"音频检测"。

## Objective

1. 从候选中选出一个 phone recognizer / phone aligner，通过质量门禁
2. 将真实音频检测结果桥接到 PhoneTimeline 资源
3. 语流规则（弱读/省音/闪音/连读/同化）获得音频层证据支撑
4. 英语用户体验升级：从"这里可能有弱读"到"说话人实际说了 /ðə/"

## Position In Roadmap

```text
2.5 PhoneTimeline 资源契约 (no release provider)
  -> 2.7 PronunciationProvider trait dispatch
  -> 2.10 English Real Speech Analysis  ← 当前
```

## Steps

### Step 1: Provider Benchmark（研究阶段）

复跑候选 provider，用真实 connected speech 样本评估：

- 准备 development cases：至少 10 条英语自然语流音频（含已知弱读/省音/闪音实例）
- 复跑 MFA phone alignment（已有 sidecar `mfa-align-cli.py`）
- 复跑 ZIPA（已有 `setup-zipa-research.sh`）
- 评估 Wav2IPA / Wav2Vec2Phoneme（如许可证通过）
- 每个候选记录：PER、timeline validity、token association coverage、RTF、peak RSS、
  connected speech 保真度

交付：`2.10-BENCHMARK.md` 记录各候选评估结果和选型决策

### Step 2: 选型决策

根据 benchmark 结果和许可证审查，选定一个 provider 组合：

- **方案 A — canonical alignment + 声学证据**：MFA 提供 phone boundaries，
  叠加声学偏差检测推断真实语流现象。优势：MFA 已验证最优；劣势：需要额外声学分析层
- **方案 B — direct phoneme recognition**：ZIPA/Wav2IPA 直接输出 detected phones。
  优势：端到端；劣势：timestamp 精度和模型许可证风险
- **方案 C — 双层组合**：MFA alignment 提供边界 + recognizer 提供内容。
  优势：各取所长；劣势：复杂度高

交付：选型决策记入 `2.10-BENCHMARK.md`，必要时新建 ADR

### Step 3: Provider 集成

将选定 provider 集成到生产管线：

- 实现新的 `PhoneAlignmentProvider`（或扩展现有 MFA sidecar）
- 输出 PhoneTimeline candidate（符合 Phase 2.5 契约）
- `detected_in_audio` vs `canonical_alignment` 精度标记
- 非英语语言干净降级（不 panic）

### Step 4: 语流 Finding 升级

将 `analyze_rules()` 的文本预测与音频检测结果融合：

- 有音频证据时：升级为 `DetectedInAudio` + 实际 phone 序列
- 无音频证据时：保留原有 `LikelyByContext` / `PossibleByRule`
- 新增 finding 字段：`detected_phones`、`canonical_phones`、`acoustic_confidence`
- `SpeechRuleFinding` 扩展但向后兼容

### Step 5: App 消费验证

- PhoneTimeline active 后，Sound Pattern View 显示 detected vs canonical 对比
- 诊断卡显示音频证据级别（detected / predicted / possible）
- 用真实英语视频端到端验证

### Step 6: 测试与回归

- `cargo test --workspace` 全通过
- 英语行为升级但不破坏已有功能
- 无音频分析时保留原有文本规则 fallback
- 中文/日语行为不受影响

## Verification Criteria

1. 至少一个 phone provider 通过 Phase 2.5 质量门禁
2. 英语 PhoneTimeline 包含 `detected_in_audio` 精度的 phone entries
3. 至少弱读/闪音两类 finding 有音频层证据
4. 无 phone provider 时优雅降级到文本规则（不 panic）
5. `cargo test --workspace` 全通过

## Out of Scope

- 非英语 phone recognition（中文声调检测、日语 mora 分析）
- 完整的 waveform-level Sound Pattern Editor UI
- 多口音支持（v1 仅 en-US）
- 自建模型训练
