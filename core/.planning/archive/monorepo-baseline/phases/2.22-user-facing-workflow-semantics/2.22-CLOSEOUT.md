# Phase 2.22 Closeout: User-Facing Workflow Semantics

状态：COMPLETED
完成时间：2026-07-02 CST

## Summary

Phase 2.22 的目标是重构前端用户侧语义：确认所有功能的工作流/路径、建立一套**用户可见状态机**、并据此找出并修复当前状态机的问题。

初始由 GPT 完成的一版产出了部分代码，但**没有建成真正的状态机**，功能清单只有模板未填，能力模型内部 L 层号自相矛盾，且把部分工作高估为“前端 closeout 已完成”。本阶段的实质是：把权威模型重建到当前 `main`、纠正记账、并跑通“建状态机 → 找问题 → 修问题”的闭环。

阶段目标已按 journey/状态机层面**判定达成**（用户确认）。逐功能模板化（约 40 个功能）在 journey 层已覆盖，价值低，刻意不做。

## Completed Scope

### 1. 权威模型重建（阶段核心交付）

- 新增 `2.22-USER-VISIBLE-STATE-MACHINE.md`：真正的用户可见状态机——R0-R8 七个 surface 正交区域（backend shell / AppBar / player surface / subtitle overlay / side panel / download bar / bottom controls / status text / full-screen overlays），每区含 states、entry、`on EVENT(guard)`、转移；外加 Section C 五条能力就绪 lane（Word Sync / Chunk Replay / Listening Structure / Phone Evidence + 共享 shape），把静态 readiness 枚举补成动态状态机。
- 修正 `2.22-FEATURE-SEMANTICS-MODEL.md`：统一 Capability Stack 与 Readiness Examples 的 L 层号，新增 Model↔Code 对账表（明确 5/11 层已建 readiness lane、其余为概念层）。
- 重构 `2.22-CURRENT-FEATURE-INVENTORY.md`：从裸清单改为“覆盖清单 + 已验证 P0 模板 F1-F8”。
- Step 0 audit（`2.22-STEP0-UI-AUDIT.md`）在 journey/区域层面确认了 18 条端到端路径与全部 surface 区域，均对当前 `main` 校验。

### 2. 基于状态机的问题识别（Defect Register）

状态机的产出是 Defect Register（`SM-01..SM-08` 新发现 + `SM-F1..SM-F8` 记录既有已修项），即“当前状态机有什么问题”的答案。

### 3. 问题修复（闭环）

- **SM-02**：删除死且分叉的 `widgets/layout/side_panel.dart`（其 Resources tab 用旧 `TimelineResourceSummaryPanel`，接线会退化 → 删而非接）。
- **SM-03**：下载状态从散落 5 处（`activeDownload`/`downloadError`/`downloadGeneration` + `PlayerState.downloadProgress`/`downloadedMediaPath`）收敛为单一 `DownloadController`（generation + disposed 守卫、仅依赖 Stream/Future 原语、可单测）。`main.dart` −84 行。
- **SM-07b**：overlay listening 层对 predicted-only（无 timing/energy/pitch/phone 音频信号源）的当前句显示 `predicted` 徽标 + “基于文本预测、非实测音频” tooltip，共享公开判据 `rhythmFrameHasAudioSupport`；不再让预测读起来像实测。
- **SM-01（缩范围，收口标准 #5）**：全量审计确认自由字符串 `status` 只有一处被读值驱动行为（manual-review 关闭守卫的魔法字符串），改为 typed `_manualReviewStatusPristine` 标志；~99 处显示型写入的全量枚举化判定为镀金，未做。

### 4. 记账纠正

- `STATE.md`、`2.22-PLAN.md` 去除“closeout 已完成/已落地”高估，列清 OPEN 项与真实覆盖度（readiness 仅覆盖 5/11 层且早期只接一个 surface 等）。

## Deferred Items（满足标准 #6 的明确取舍）

- **SM-05**（无副字幕时副字幕行空显示、缺提示）：defer，便宜的 polish，不阻塞。

- **SM-08**（Phone Evidence 的 `generating` 态未接音频分析 job）：defer，**候选下一后端/声音线阶段**——本分支已新增 sound-line/ASR job 基建，届时接入更干净。
