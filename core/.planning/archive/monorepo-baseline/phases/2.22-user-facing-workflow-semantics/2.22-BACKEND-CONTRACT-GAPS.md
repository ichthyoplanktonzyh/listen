# Phase 2.22 Backend Contract Gaps

状态：OPEN GAP LOG

日期：2026-07-01

## Purpose

Phase 2.22 的前端语义重构同时承担一个反向校验职责：

```text
用户能否从前端完成闭环
  -> 前端能否表达入口、状态、降级和下一步
  -> 后端是否真的提供了这些能力事实
```

本文件只记录前端审计暴露出的后端契约缺口。本 phase 暂不修后端。

## Current Findings

| ID | User workflow | Frontend can say today | Backend/API gap to resolve later |
|---|---|---|---|
| BCG-001 | Subtitle resource -> Listening structure readiness | Active subtitle can be inspected through the loaded/exported `LLTimelineDocument`; inactive subtitle resources can only say "activate to inspect". | No direct per-subtitle-resource Listening structure readiness query. The API exposes sentence/word/chunk/phone counts per subtitle resource, but document-level `rhythm_frames` readiness is only known after activation/export. |
| BCG-002 | Local Whisper generation -> generated learning capabilities | The frontend can start a typed subtitle-generation task, load the generated track, then derive Word sync / Chunk replay / Listening structure / Phone evidence readiness after resources refresh. | Transcription job events do not return a user-facing capability result summary, such as generated track id plus which learning capabilities were produced or degraded. |
| BCG-003 | Audio analysis -> Phone evidence task feedback | The frontend can show typed working/success/warning/error task state from raw job status and refresh speech enhancements on completion. | Phonetic/audio-analysis job events do not expose provider/model, missing-model reason, failure category, or recommended next action, so failed states remain generic. |
| BCG-004 | Task center and global feedback | The frontend maps known backend status strings into `working/success/warning/error/cancelled/unknown`. Unknown strings degrade to `unknown`. | Job lifecycle statuses are not yet a stable shared enum contract. Backend and frontend still communicate lifecycle through raw strings. |
| BCG-005 | Resource capability panels at scale | The frontend now makes capability state understandable, but must derive it by combining active timeline summary, subtitle resource summaries, and per-track resource probes. | No batch "subtitle resource capability summary" endpoint that includes Subtitles, Word sync, Chunk replay, Listening structure and Phone evidence in one product-level response. |
| BCG-006 | Practice/Review readiness | Phase 2.22 keeps Practice/Review as a named user capability but does not surface a confident workflow entry yet. | Backend foundations exist, but frontend lacks a product-level readiness contract saying which media/subtitle/word states can enter practice or review. |
| BCG-007 | Degraded evidence explanations | The frontend can distinguish unavailable/degraded/predicted states when data is present in timeline or sound-analysis models. | Backend task/resource results do not consistently include user-actionable degradation reasons, for example "word timings missing", "rhythm frames absent", "phone evidence absent", or "energy artifact missing". |

## Deferred Backend Shape

Future backend work should prefer product-level contracts over UI-specific strings:

```text
SubtitleResourceCapabilitySummary
  subtitle_text
  word_sync
  chunk_replay
  listening_structure
  phone_evidence
  degradation_reasons[]
  recommended_actions[]

TaskLifecycle
  kind
  state enum
  progress
  target resource/media/subtitle ids
  result capability summary
  failure/degradation reason
```

The exact schema should be decided in a backend phase. The frontend closeout only records that these facts are required for a complete user workflow.
