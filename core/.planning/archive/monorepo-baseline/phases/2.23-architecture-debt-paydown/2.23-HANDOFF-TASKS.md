## 公共规则（每个任务都适用）

1. 开工前基于最新 `main`；一个任务一个独立提交序列。
2. 每次 commit 同步追加根目录 `CHANGELOG.md`（分钟级时间戳，规则见
   `.planning/MAINTENANCE.md`）。
3. 完成后在 `2.23-REVIEW-FINDINGS-REGISTER.md` 把对应项改为 ✅ 并写一行结果。
4. 工具路径解析（cargo/flutter 不在 PATH 时）见根目录 `AGENT.md`
   “Toolchain Environment”。
5. 公共验证命令（按任务涉及面选择）：

```sh
cargo test --workspace --quiet
./scripts/validate-contracts.sh
cd apps/desktop && flutter analyze && flutter test
```

6. **通用禁止**：不顺手重构、不改与任务无关的行为、不改已冻结的 phase 文档、
   不改 `docs/decisions/` 既有 ADR。

## T1（B-1）删除 `learning_resources` 僵尸表 ｜难度：低

**事实**：SQLite 表 `learning_resources` 在迁移 0007 创建、0016 destructive
reset 原样重建，但 `crates/persistence-sqlite/src/` 无任何读写。同名概念
`/v1/learning-resources` 路由由 `crates/api-http/src/m18.rs` 的内存+文件系统
资源管理器服务（下载词典等资源），与该表无关。

**步骤**：
1. 新增迁移 `crates/persistence-sqlite/migrations/0017_drop_learning_resources.sql`：
   `DROP TABLE IF EXISTS learning_resources;`
2. `crates/persistence-sqlite/src/migrations.rs` 按现有模式注册 v17
   （事务内执行 + `user_version` 升到 17）。
3. 删除 `crates/persistence-sqlite/src/tests.rs` 中镜像的
   `CREATE TABLE learning_resources`（约第 76 行起）及其相关断言；如有
   `MIGRATION_VERSION` 常量断言，同步升级。
4. **不改** 0007/0016 迁移文件（历史迁移不可变）。

**验收**：`cargo test -p persistence-sqlite --quiet` 通过；
`grep -rn learning_resources crates/persistence-sqlite/src` 仅剩迁移注册；
本地真实库升级后 `PRAGMA user_version` = 17 且表不存在。

## T4（PLAN Step 2）`sound_analysis.rs` 机械拆分 ｜难度：中 ｜纪律要求最高

**目标**：把 `crates/speech-analysis/src/sound_analysis.rs`（约 3383 行）拆为
`sound_analysis/` 模块目录。完整方案与建议切法（tokens / anchors / nuclei /
grouping / boundaries / references / hotspots / quality）见 `2.23-PLAN.md`

- **纯机械移动**：不改任何算法逻辑、不改函数签名、不“顺手优化”。

  字符串值变化。
- 每拆一个子域跑一次 `cargo test -p speech-analysis --quiet`，测试数
  不得低于基线（152）。
- 实际切法与 PLAN 建议不一致时，回填 `2.23-PLAN.md` 说明差异，不静默偏离。

## T6（C-7 余项）零散 SSE 事件 payload typed 化 ｜难度：低-中 ｜照既有模式抄

**模式已建立**，照 `crates/api-http/src/event_payloads.rs` 现有 6 个 struct
的写法执行即可（struct + `envelope()`，可选字段
`#[serde(skip_serializing_if = "Option::is_none")]`）。

**待迁移的发射点**（grep `serde_json::json!` 配合 `EventEnvelope::v1` 定位）：
- `crates/api-http/src/m18.rs`：`lexical-observation-cleared`
  （`{lexical_entry_id, sentence_id}`）等仍为 `json!` 的站点。
- `crates/api-http/src/routes/pronunciation.rs`：
  `pronunciation-provider-unavailable` / `-degraded`
  （`{provider_id, provider_version, diagnostic}`）、route 侧
  `pronunciation-analysis-progress`（`{track_id, processed, total}`，注意与
  speech_jobs 的 batch progress 形状对齐——可直接复用
  `SpeechBatchProgressPayload`，job_id 需要改为可选或新建 struct，
  **以对齐后的单一形状为准**）、`pronunciation-analysis-completed`
  （`{sentence_id}`）。
- 其余文件里残存的 `json!` payload 一并清零：完成判据是
  `grep -rn 'json!' crates/api-http/src --include='*.rs'` 中不再有作为
  event payload 的用法（非事件用途的 `json!` 不在范围内）。

**注意**：这些事件 Flutter 未做 typed 解析，wire 形状允许微调（如 null→缺省），
但**事件名和现有消费字段不得删改**。若统一某事件的多处形状，需检查
`apps/desktop/lib` 有无对该事件 payload 的裸 map 读取（grep 事件名）。

**验收**：`cargo test -p api-http` 通过（含
`event_contract_examples_match_producers`）；如新增 struct 覆盖了 Flutter
typed 消费的事件（当前没有），须同步扩展
`contracts/events/examples.json` 双端测试。
