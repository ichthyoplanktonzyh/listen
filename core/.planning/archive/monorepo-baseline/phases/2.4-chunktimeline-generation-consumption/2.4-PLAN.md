# Phase 2.4 Plan: ChunkTimeline Generation And Consumption

更新时间：2026-06-20 22:45 CST

## Objective

把 chunk 从临时算法结果升级为一等资源：可生成、可持久化、可选择、可激活、可导出，
并能在播放器中驱动 chunk 高亮、跳转、循环和渐进听力训练。

## First Thing To Do

Phase 2.4 第一件事不是继续调 chunk 算法，而是 **定义并打通 ChunkTimeline 资源契约**。

原因：

- 只要资源契约稳定，gap-based、语义规则、learned provider、人工修正都可以输出同一种
  ChunkTimeline。
- UI 消费端只依赖 active ChunkTimeline，不需要知道背后是哪种算法。
- 用户验收的是“能不能用 chunk 播放和学习”，不是内部算法名字。
- 后续质量提升可以不断替换 provider，而不会反复推翻数据库和 UI。

## Design Principle

```text
active WordTimeline is the timing source
  -> Chunk providers produce candidates
  -> User activates one ChunkTimeline
  -> Player consumes active ChunkTimeline
  -> Manual correction creates a new candidate
```

关键原则：

- **资源优先**：ChunkTimeline 和 WordTimeline 一样，需要 candidate / active / archived
  生命周期。
- **消费优先**：第一版必须能播放、跳转、循环，而不是只输出诊断 JSON。
- **语义和声学并重**：停顿不是 chunk 的全部；语义边界和学习可用性同样重要。
- **降级诚实**：estimated timing 可以生成粗略 chunk，但不能标成 precise acoustic
  chunk。
- **可替换 provider**：chunk 生成策略必须以 provider / evidence 形式表达，避免写死在
  Flutter UI。

## Work Breakdown

### Step 1: ChunkTimeline Resource Contract

定义领域模型、LLTimeline JSON 映射和 SQLite 持久化约定。

建议核心字段：

- `chunk_timeline_id`
- `track_id`
- `parent_word_timeline_id`
- `status`: `candidate | active | archived`
- `created_by`: `system | user`
- `provider_id` / `provider_version`
- `algorithm`: `gap_based | acoustic_semantic_v1 | text_only | user_adjusted`
- `precision`: `precise | approximate | text_only`
- `chunks_json`
- `metrics_json`
- `created_at_ms`

每个 chunk 至少包含：

- `chunk_id`
- `sentence_id`
- `chunk_index`
- `start_word_index` / `end_word_index`
- `start_ms` / `end_ms`
- `text`
- `boundary_sources`: `pause | punctuation | semantic | lengthening | learned | user`
- `confidence`
- `warnings`

Exit criteria:

- 文档和代码中明确 ChunkTimeline 如何引用 WordTimeline。
- LLTimeline export/import 可以保留 ChunkTimeline candidates。
- 数据库迁移草案明确。

### Step 2: API And Application Service

新增或整理 ChunkTimeline 应用服务：

- list chunk timelines for track
- generate chunk timeline from active WordTimeline
- activate chunk timeline
- archive / restore / delete
- export with LLTimeline

Exit criteria:

- API 层不包含 chunk 核心算法。
- application service 可以在无 UI 测试中创建、激活和查询 ChunkTimeline。
- 激活 ChunkTimeline 不破坏 active WordTimeline。

### Step 3: Baseline Provider

实现第一版 `acoustic_semantic_v1` provider。

输入：

- active WordTimeline。
- SubtitleSentence tokens / punctuation。
- 可选 LLTimeline chunks。

策略：

- 优先使用非 estimated 的 word timing gap。
- 加入标点和句法/短语启发式作为语义边界提示。
- 加入 chunk 长度约束，避免 1 词碎片和超长 chunk。
- 对 estimated timing 降级为 `text_only` 或 `approximate`。
- 输出 boundary evidence，最后由 partitioner 统一生成 chunks。

Exit criteria:

- 同一输入可稳定生成同一 ChunkTimeline。
- estimated timing 不会生成虚假的 precise acoustic chunk。
- provider 输出带 evidence / warnings，方便后续调参。

### Step 4: Resource Management UI

在字幕资源管理体系中增加 ChunkTimeline 管理能力。

UI 目标：

- 当前字幕资源下显示 WordTimeline 与 ChunkTimeline 的关系。
- 展示 ChunkTimeline candidate 列表。
- 展示 provider、precision、chunk count、parent WordTimeline、active 状态。
- 支持生成、刷新、激活、归档、删除、导出。

Exit criteria:

- 用户能看见 chunk 资源，而不是只能在播放时“猜测系统用了什么”。
- 激活不同 ChunkTimeline 后，播放器消费结果可刷新。

### Step 5: Player Consumption

让播放器真正使用 active ChunkTimeline。

交互：

- 当前 chunk 高亮。
- 点击 chunk 跳转到 chunk start。
- 循环当前 chunk。
- Prev / Next chunk。
- 逐步展开模式：
  - 先播放单个 chunk。
  - 再播放当前 chunk 到下一个 chunk。
  - 最后播放整句。

Exit criteria:

- app 播放时能稳定计算 current chunk。
- chunk 操作不依赖后端高频轮询。
- 无 ChunkTimeline 时回退到句子级播放，不影响现有字幕体验。

### Step 6: Export, Regression, Closeout

- LLTimeline export 包含 active/candidate ChunkTimeline。
- 导入含 chunks 的 LLTimeline 后能恢复资源列表和 active 状态。
- 更新文档、STATE 和 changelog。
- 明确 Phase 2.5 或后续阶段是否进入人工 ChunkTimeline 编辑。

Exit criteria:

- Phase 2.4 可被实际验收：导入媒体和字幕资源后，用户能生成、激活并使用 chunk。
- chunk 质量问题能通过候选切换和后续人工修正继续迭代，而不阻塞消费闭环。

## Testing

- Rust/domain:
  - ChunkTimeline model serialization。
  - chunk boundary monotonicity。
  - parent WordTimeline reference validation。
- Persistence:
  - migration creates chunk timeline tables。
  - list / activate / archive / delete。
  - active uniqueness per track。
- API:
  - generate from active WordTimeline。
  - activate candidate。
  - import/export round-trip keeps chunks。
- Flutter:
  - resource page shows ChunkTimeline candidates。
  - generate / activate / archive controls work。
  - player current chunk highlight refreshes after activation。
  - chunk loop / prev / next work without backend polling。
- Regression:
  - no ChunkTimeline -> sentence fallback。
  - estimated timing -> approximate/text-only behavior。
  - active WordTimeline switching invalidates or warns stale ChunkTimeline。

## Open Questions

- Phase 2.4 是否同时实现人工 chunk 微调，还是先只做 candidate 选择和播放消费？
- ChunkTimeline active 状态是每个字幕轨一条，还是每个 WordTimeline parent 一条？
- 当 active WordTimeline 改变时，旧 ChunkTimeline 是自动 archive，还是保留但标记
  `stale_parent`？
- semantic provider 第一版使用规则/标点/短语词典，还是接入 feature worktree 中已有的
  learned provider 结果？
- UI 上 chunk 管理应放在字幕资源详情页，还是播放器工具栏旁增加专门的 Chunk 面板？
