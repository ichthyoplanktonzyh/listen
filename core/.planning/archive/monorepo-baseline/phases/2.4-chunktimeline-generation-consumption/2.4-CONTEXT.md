# Phase 2.4 Context: ChunkTimeline Generation And Consumption

更新时间：2026-06-20 22:45 CST

## Background

Phase 2.2 已经把 SRT / WebVTT / ASR 字幕 / LLTimeline JSON 统一为“字幕资源”，并让
app 可以导入、管理、激活和消费 active WordTimeline。Phase 2.3 规划为人工校对 UI，
用于把 production WordTimeline 微调为 `user_adjusted` 版本。

Phase 2.4 接在这两步之后：字幕资源提供文本，WordTimeline 提供词级时间锚点，
ChunkTimeline 应成为下一种可管理、可选择、可消费的学习资源。

```text
Subtitle Resource
  -> active WordTimeline
  -> ChunkTimeline candidates
  -> active ChunkTimeline
  -> chunk highlight / chunk loop / progressive listening
```

已有 chunk 研究和实验表明：只用停顿间隙可以形成最小可用的声学 chunk，但不能满足
最终学习体验。chunk 边界需要同时考虑：

- 说话人的真实韵律边界：停顿、语速变化、pre-boundary lengthening 等。
- 文本语义边界：从句、短语、标点、固定搭配、信息结构。
- 学习可用性：chunk 不能过碎、过长，必须适合循环播放和渐进听力训练。

因此 Phase 2.4 不能只做一个“算法函数”。它首先要完成 ChunkTimeline 资源闭环，然后再
把声学和语义策略放入可替换、可评估、可人工修正的 provider 体系。

## Problem

当前 chunk 能力存在三个断点：

1. **不可资源化**：chunk 结果不是像 WordTimeline 一样的可持久化候选资源，用户无法
   选择、激活、导出或回滚。
2. **不可消费**：播放器仍主要按句子和单词工作，缺少 active ChunkTimeline 驱动的
   当前 chunk、高亮、跳转和循环。
3. **质量不可迭代**：gap-based、语义规则、学习模型和人工修正缺少统一输出契约。
   如果直接把某个算法写进 UI，后续替换会破坏消费端。

## Product Position

Phase 2.4 的产品目标不是“自动得到完美 chunk”，而是让用户能够真正用 chunk 学习：

- 看见当前句被切成哪些 chunk。
- 播放时知道当前正在播放哪个 chunk。
- 点击 chunk 跳转。
- 循环当前 chunk。
- 逐步展开：chunk 1 -> chunk 1+2 -> whole sentence。
- 在 chunk 不理想时，可以选择不同候选或进入后续人工修正。

对于没有精确 WordTimeline 的字幕，系统仍可降级生成 text-only / estimated chunks，
但 UI 必须诚实表达其能力边界：它们可用于阅读和粗略循环，不应声称精确声学边界。

## Scope

Phase 2.4 聚焦以下内容：

1. 定义 ChunkTimeline 资源语义、数据结构和状态机。
2. 从 active WordTimeline 生成 ChunkTimeline candidate。
3. 支持 acoustic-first、semantic-assisted 的第一版 chunk provider。
4. 将 ChunkTimeline 持久化到 SQLite，并支持 list / activate / archive / export。
5. 在播放器 UI 中消费 active ChunkTimeline：
   - 当前 chunk 计算。
   - chunk 高亮。
   - 点击 chunk 跳转。
   - 当前 chunk 循环。
   - 逐步展开训练入口。
6. 保持无 chunk / 无 word timing / estimated timing 的降级路径。

## Non-Goals

- 不在本阶段追求最终最优的语义理解模型。
- 不把大型 LLM、WhisperX、MFA、PSST 或 Python runtime 放入轻量消费端。
- 不在第一步做完整 ChunkTimeline 拖拽编辑器；人工 chunk 编辑可以作为 Phase 2.5
  或 Phase 2.4 后半段的扩展。
- 不阻塞 Phase 2.3 的 Word Timing Inspector。
- 不把 chunk 结果直接覆盖 WordTimeline；ChunkTimeline 必须引用其 parent
  WordTimeline。

## Success Criteria

- app 能基于当前 active WordTimeline 生成至少一个 ChunkTimeline candidate。
- 用户能在 UI 中看到 ChunkTimeline candidates，并激活其中一个。
- active ChunkTimeline 能驱动播放时的当前 chunk、高亮、跳转和循环。
- ChunkTimeline 能进入数据库并随 LLTimeline export 导出。
- 无精确词级时间轴时，系统能降级到句子级或 text-only chunk，不破坏字幕播放。
- 文档明确 chunk 质量迭代路线：gap-only -> acoustic evidence -> semantic evidence ->
  user-adjusted / learned provider。
