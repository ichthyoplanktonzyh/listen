# Phase 3.4.4 Plan: Learning Evidence Channelization

状态：COMPLETED（2026-07-07）

启动时间：2026-07-07 CST

定位：3.5（Meaning/Sound fit 难度分诊）的前置证据层。来源于精化评审
（`.planning/discuss/learning-domain-model-v2-refinement-review.zh.md`）§4.2/§4.3 的
高优先裁决与共享上下文 §14。

架构决策：`docs/decisions/0017-channelized-learning-observations.md`

## Objective

建立通道化、追加式的 `LearningObservation` 证据存储:记录 capability、task_type、
assistance、surface_form 与上下文,接线全部四条现有写入路径(上下文标记、练习提交、
复习提交、升级确认),练习成功从此也产生证据。不改任何决策逻辑、不加 API、不动 UI。

## User Value

> "系统开始完整记住我每一次听、读、练的真实表现——在哪个词形、什么辅助条件下成功或
> 失败——将来难度分诊和能力推断有据可依,而我现在的使用体验没有任何变化。"

## Non-Goals（本阶段明确不做）

- 不实现证据投影算法(需研究依据 + 3.5 的 fit 定义)。
- 不迁移 diagnosis 到新证据存储(继续读 LexicalObservation)。
- 不加 HTTP 端点、不动 Flutter。
- 不做证据清理/窗口策略(3.5 定义窗口时再议)。
- 不做 construction/sense 目标泛化(无写入方)。

## Exit Signals

1. 四条写入路径在正常使用中自动产生通道化 observation,用户体验零变化。
2. 练习成功产生 success observation(修复失败偏置)。
3. 同一 (entry, sentence) 的多次表现全部留存(追加式验证)。
4. backfill 的行带 legacy_backfill 来源,不冒充精确用户标记。
5. 资产包导出→导入 round-trip 保留 observation,按 id 幂等。
6. `cargo test --workspace` 全绿;diagnosis/建议/UI 行为无任何变化。
