# 播放界面回退首页 — UX 问题与方案

> 记录于 2026-07-09，Phase 3.5.5 UX 讨论

## 现状

### 当前导航结构

`PlayerScreen`（`main.dart`）是一个单页结构，通过 `playerController.mediaPath` 是否为 `null` 切换两个互斥视图：

| 条件 | 展示内容 |
|------|---------|
| `mediaPath == null` | `ListeningHome` — 首页（媒体库、继续学习、学习工具入口） |
| `mediaPath != null` | `MediaWorkbench` — 播放工作台（媒体区 + 侧面板） |

切换逻辑见 [`main.dart#L1880`](file:///Users/shadow/LLPlayerNext/apps/desktop/lib/main.dart#L1880-L1946)。

### 问题

一旦用户点击媒体进入播放界面（`MediaWorkbench`），没有任何 UI 元素可以回到首页：

- **`PlayerAppBar`**（顶栏）有内容操作、字幕操作、学习操作等菜单，但没有"回到首页"的入口
- **`MediaWorkbench._MediaPane`**（播放区标题栏）只有媒体标题、压缩窗格、重置布局按钮，没有返回功能
- **`ListeningHome` 侧边栏中的"Home"入口**只在首页可见，进入播放后不可达

用户被"困"在播放界面：只能通过打开新媒体切换媒体，或 `Navigator.push` 去词汇/复习等独立页面，但无法回到首页。

### 相关文件

| 文件 | 作用 |
|------|------|
| `apps/desktop/lib/main.dart` | 主页 `PlayerScreen`，控制首页/播放工作台切换 |
| `apps/desktop/lib/widgets/app_bar/player_app_bar.dart` | 顶栏，无首页入口 |
| `apps/desktop/lib/widgets/home/listening_home.dart` | 首页组件 |
| `apps/desktop/lib/widgets/layout/media_workbench.dart` | 播放工作台组件 |

## 讨论方案：类音乐播放器 Mini Player 模式

### 核心思路

参考桌面端音乐播放器的交互模式，将首页和播放界面从**互斥**改为**共存**：

```
┌────────────────────────────────────┐
│          ListeningHome              │  ← 始终渲染的首页底层
│   (媒体库 / 继续学习 / 学习工具)      │
│                                    │
├────────────────────────────────────┤
│  ┌────────── 上浮/下滑 ──────────┐  │
│  │   播放详情页（全屏展开）       │  │  ← 可上浮/下滑的覆盖层
│  │   媒体区 + 侧面板            │  │
│  │   ┌─────────────────────┐   │  │
│  │   │      ↓ 向下箭头      │   │  │  ← 点击下滑回到首页
│  │   └─────────────────────┘   │  │
│  └─────────────────────────────┘  │
├────────────────────────────────────┤
│  [封面] 媒体标题  ████████░░ ▣▢ ▶  │  ← 紧凑播放控制条（始终可见）
└────────────────────────────────────┘
```

### 状态流转

| 用户操作 | 首页可见性 | 播放控制条 | 播放详情页 |
|---------|-----------|-----------|-----------|
| 未播放媒体 | ✅ 可见 | ❌ 隐藏或禁用 | ❌ |
| 点击媒体 → 播放 | ✅ 首页仍在底层 | ✅ 紧凑条出现 | ❌ 未展开 |
| 点击紧凑条/封面 | ⏳ 被覆盖 | ✅ 保持可见 | ✅ 全屏上浮，顶部有向下箭头 |
| 点击向下箭头 | ✅ 恢复显示 | ✅ 保持可见 | ❌ 下滑收起 |

### 优势

1. **首页状态保持** — 首页的 `mediaLibrary`、词汇量、continue card、滚动位置等不需要重建
2. **播放不中断** — 下滑收起详情页时，播放继续，紧凑条保持控制
3. **符合用户预期** — 类似 Spotify、Apple Music 等桌面音乐播放器的交互，学习成本低
4. **空间效率高** — 紧凑态下仅占底部一条高度，不干扰首页内容浏览

### 需要进一步讨论的问题

1. **紧凑播放条的包含信息** — 封面缩略图、媒体标题、进度条、播放/暂停、上/下一首、当前字幕轨道信息？和现有 `PlaybackBar`（cue 导航、倍速、音轨、泛听入口等）的取舍关系需要定义。
2. **上浮全屏后详情页的内容** — 是否完整复用当前 `MediaWorkbench` 的内容（媒体区+字幕覆盖+侧面板）？
3. **下滑是"收起"还是"关闭"** — 按常理应是"收起"，播放状态（位置、字幕、诊断结果）保持，再次上浮时恢复现场。
4. **向下箭头的触发区域** — 全屏详情页顶部固定条，还是跟随内容滚动的悬浮按钮？
5. **首次打开媒体时的默认态** — 是直接上浮全屏详情页，还是仅出现紧凑条让用户主动上浮？

### 与现有架构的关系

当前 `main.dart` 中首页/播放是简单的 `if/else` 互斥：

```dart
child: playerController.mediaPath == null
    ? ListeningHome(...)
    : MediaWorkbench(...),
```

改为共存模式后需要调整为此结构：

```dart
child: Stack(
  children: [
    // 底层：始终渲染的首页
    ListeningHome(...),
    // 上层：可上浮/下滑的播放详情页
    if (mediaPath != null)
      _PlaybackDetailSheet(
        onDismiss: _dismissDetail,
        child: MediaWorkbench(...),
      ),
    // 底部：紧凑播放控制条（始终可见）
    if (mediaPath != null)
      _CompactPlaybackBar(...),
  ],
)
```
