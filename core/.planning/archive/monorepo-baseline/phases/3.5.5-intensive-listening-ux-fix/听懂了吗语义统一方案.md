# "听懂了吗" 语义统一方案

> Phase 3.5.5 子项，来源于精听模块 UX 讨论
> 日期：2026-07-09

---

## 问题：三个入口，语义割裂

当前有三个独立入口/概念，用户感知上是三件不同的事，但核心语义都指向同一个问题：

| 入口 | 位置 | 用户理解 | 实际行为 |
|------|------|---------|---------|
| **听懂了吗？** | 姿态栏按钮 | 一个功能 | 打开侧栏 tab 3 |
| **句子诊断** | 侧栏导航 tab 3 | 另一个功能 | 显示 DiagnosisCard |
| **显示听感层** | 设置开关 → A/B/C | 又一个功能 | 播放器区域三层视觉参考 |

此外，DiagnosisCard 中的两个按钮也存在语义问题：

| 按钮 | 问题 |
|------|------|
| **分析真实发音** | "真实"暗含 A/B 不真实；"发音"太技术化；用户不关心技术动作 |
| **分析整条字幕** | "分析字幕"听起来像文本分析，但实际做的是整轨音频强制对齐 |

两个按钮的本质都是调用 Python sidecar 做 forced alignment，区别仅在于作用范围（当前句 vs 全轨），但用户被迫理解一个纯技术决策。

---

## 核心原则

系统不做诊断。

系统无法判断用户"听懂没听懂"，只做两件事：

1. **展示参考** — A 词典怎么读 / B 语流怎么变 / C 音频实际怎么读
2. **展示已知词汇** — 用户已掌握的词汇在当前句的渲染状态

"听懂了吗"是用户的**自问**，系统只提供辅助回答的工具。

---

## 方案：统一语义树

### 语义模型

```
听懂了吗？ ← 用户的自问，不是系统的答案
  │
  ├─ 已知词汇标注 ← 系统能做的：标记你认识的词，剩下的你自己判断
  │
  └─ 听感参照（A/B/C）← 系统能做的：三种参考帮你定位"没听出来"的原因
      ├─ A · 词典发音 —— 标准发音长这样
      ├─ B · 常见语流 —— 连读弱读怎么变的
      └─ C · 本次音频 —— 实际怎么读的（需加载）
```

### 改动清单

| # | 改动 | 当前 | 改为 | 涉及文件 |
|---|------|------|------|---------|
| 1 | 侧栏 tab 3 标签 | `l.text('diagnosis')` → "句子诊断" | `l.text('understandPosture')` → **"听懂了吗"** | `side_panel.dart` 第 279 行；`localization.dart` 中 `diagnosis` key |
| 2 | 设置开关标签 | `'soundPatternDisplayMode'` → "听感层" / "Listening layer" | **"听感参照"** / **"Sound reference"** | `localization.dart` 第 445、1029 行 |
| 3 | 侧栏 tab 3 空态提示 | `'diagnosisUnavailable'` / `'openSentenceDiagnosisHint'` | 改为与"听懂了吗"一致的文案 | `side_panel.dart` 第 249-256 行；`localization.dart` |
| 4 | DiagnosisCard 中两个分析按钮 | "分析真实发音" / "分析整条字幕" | **移出 DiagnosisCard**，改由 C 视图按需提示加载 | `diagnosis_card.dart` 第 89-109 行 |

### 移除的概念

| 旧概念 | 移除原因 |
|--------|---------|
| 句子诊断（`diagnosis`） | 语义与"听懂了吗"重复，且"诊断"暗示系统能判断用户懂没懂 |
| 分析真实发音（`analyzeRealPronunciation`） | "真实"有误导，"发音"不精确 |
| 分析整条字幕（`analyzeSubtitleTrack`） | "分析字幕"像文本分析，实际做的是音频强制对齐 |

## C 视图按需加载机制

### 交互流程

两个分析按钮从 DiagnosisCard 移除后，入口改为 **C 视图原位提示**：

```
用户切换到 C·本次音频 视图
        │
        ├── 已有音素分析数据 → 直接渲染 RhythmFrameRibbon
        │
        └── 无数据 → 在 C 视图位置显示加载提示：
            ┌──────────────────────────────────┐
            │  [图标] 暂无本次音频的听感数据     │
            │  加载后可查看实际发音的结构分析     │
            │                                   │
            │  ┌──────────┐  ┌──────────────┐  │
            │  │ 加载当前句  │  │ 加载全部字幕  │  │
            │  └──────────┘  └──────────────┘  │
            │  加载当前句较快，加载全部字幕可一次性  │
            │  完成整轨分析，后续切换句子无需等待。  │
            └──────────────────────────────────┘
```

### 两个选项的语义重定义

| 选项 | 旧名（已废弃） | 新语义 |
|------|--------------|--------|
| 加载当前句 | 分析真实发音 | 只看这一句的实际音频结构，快速出结果 |
| 加载全部字幕 | 分析整条字幕 | 一次性分析整轨，后续所有句子切换无需再等待 |

两者的技术行为不变（都是调 Python sidecar 做 forced alignment），但用户看到的不是技术动作，而是**力度选择**。

### 配套行为

- 加载完成后自动切换到 C 视图并渲染
- 加载中有进度指示（复用现有的 phonetic analysis job progress）
- 全部字幕加载完成后，后续切换句子时 C 视图即时显示，无需二次加载
