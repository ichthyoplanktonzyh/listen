## Interpretation

The current pipeline is not yet “good” in a benchmark sense.

What is good:

- The Phase 2.17 QA pipeline is runnable and scoreable.
- TED-LIUM transcript/timing import matches `.stm` reference exactly.
- Some Buckeye windows score around 30-35% PER, which is consistent with the historical fb-espeak range.
- The old false `linking` explosion is gone.

What is not good yet:

- TIMIT Phase 2.17 artifact scores `0.874286` PER on 7/8 generated sentences, far worse than the historical fb-espeak TIMIT dev baseline.
- Buckeye `s0101a` first window scores above 100% PER and includes unknown output symbols (`a`, `aː`, `ɪɹ`), pointing to symbol mapping and/or noisy segment-window problems.
- Current phone scorer uses sequence PER only; boundary error metrics and connected-speech precision/recall are not yet implemented.
- Product-media cases still need manual listening precision because no gold phone reference exists.

## Immediate Next Steps

1. Rebuild `p217-timit-001` with all 8 sentences and verify each job uses the correct sentence audio window.
2. Add phone symbol normalization/mapping audit for sidecar outputs such as `a`, `aː`, `ɪɹ`, `x`, `ei5`, and `s.`.
3. Add boundary metrics after sequence PER is trustworthy:
   - matched-phone start/end MAE
   - median / p95 boundary offset
   - coverage inside segment windows
4. Improve Buckeye scoring:
   - skip pre-speech `{B_TRANS}` / long intro windows or score from first lexical word onward.
   - compare against Buckeye actual pronunciation and canonical pronunciation separately.
5. Add a manual-listening precision sheet for Brooklyn / Venezuela:
   - marker family
   - timestamp
   - audible? yes/no/unclear
   - learner-facing decision
6. Decide a release gate:
   - no marker family domination
   - phone timeline validity = 1.0
   - TIMIT/Buckeye PER trend tracked, not necessarily passing initially
