# Phase 3.9.1 Plan: Shared Syntactic Analysis Provider

状态：COMPLETED — NEGATIVE PROVIDER QUALIFICATION（v1，2026-07-13）

上游输入：Phase 3.9 Reference B、Phase 3.4.2 SenseGroup、Phase 3.4.3 Construction Spike、
ADR 0010、ADR 0011、ADR 0016、ADR 0020、`3.9.1-CONTEXT.md`。

## Objective

建立共享、Provider-neutral、可重建的句法分析基础层，通过现有 Python sidecar 模式验证
至少一个 UD parser，将字幕映射为稳定的 lemma / POS / morphology / dependency artifact；
随后让 Reference B 与 SenseGroup 各完成一条真实消费竖切片，并为 Construction 保留同一
依存图匹配接口。

## User Value

- B 不再把 `going to London` 错误显示为 `gonna London`，但能识别 `going to leave`。
- SenseGroup 不再主要按每 5–8 个词机械截断，而能保持有意义的短语和从句。
- 同一句字幕只分析一次，B、SenseGroup、Construction 对语法角色的理解保持一致。
- 模型未安装、运行失败或低置信时，现有字幕、A/B 和规则 SenseGroup 仍可使用。

## Scope

### In

- Provider-neutral `SyntacticAnalysisProvider` 与版本化输出契约。
- 句子、parser token、SubtitleToken、char span 的显式多对多映射。
- UD-compatible 字段：surface、lemma、UPOS、XPOS、FEATS、HEAD、DEPREL；基础树结构校验。
- Python sidecar research adapter；首轮以 Stanza 为质量基准，并以 spaCy 做英语对照。
- 模型/运行时 capability probe、provider/model provenance、失败 taxonomy 和规则降级。
- 模型许可证、treebank/model card、下载来源、校验和、体积、内存、冷/热启动耗时审计。
- 真实英文字幕 fixture 与歧义集；开发集和验证集分离。
- Reference B 竖切片：至少覆盖 `going to + VERB` vs motion `to + NP`、habitual `used to`
  vs `be used to`，并保留当前保守规则降级。
- SenseGroup 竖切片：句法子树候选 + 粒度规则；与 `punctuation_length_rule_v1` 并存为新
  provider，不原地改变旧分析。
- Construction 只建立 query/matcher seam 和 fixture，不在本阶段建立生产 canonical identity。

### Out

- 把 Python/PyTorch 或大型模型无条件打进消费者安装包。
- 一次支持全部 UD 语言；首个产品验证以英语为准，契约保持多语言。
- 用 parser 结果生成 C、PhoneTimeline 或声学/韵律边界。
- 用句法树替代 ChunkTimeline，或合并 SenseGroup/ChunkTimeline 数据层。
- LLM 句法解析兜底；它可以是未来 Provider，但不是本阶段最低可用路径。
- 在没有模型许可审计和真实字幕评估前锁定 UDPipe、Stanza 或 spaCy 为永久生产实现。

## Target Architecture

```text
SubtitleSentence + SubtitleToken
              ↓
SyntacticAnalysisProvider
              ↓
SyntacticAnalysis (rebuildable, versioned, token-aligned)
       ├── ConnectedSpeechContext → Reference B
       ├── SyntaxAwareSenseGroupProvider → SenseGroupAnalysis
       └── DependencyPatternMatcher → ConstructionOccurrence candidates

provider unavailable / invalid / low coverage
       ├── current conservative B context rules
       └── punctuation_length_rule_v1 SenseGroup
```

建议契约（字段名在 Slice 1 ADR 后锁定）：

```text
SyntacticAnalysis
  provider_id / provider_version
  model_id / model_version
  language
  source_fingerprint
  sentences[]

SyntacticToken
  parser_token_index
  surface / lemma / upos / xpos / features
  head_parser_token_index / dependency_relation
  start_char / end_char
  subtitle_token_indices[]
  alignment_status / confidence?
```

## Work Plan

### Slice 0 — ADR、评估预登记与 fixture

- 新增 ADR：句法 artifact 身份、Provider boundary、降级、模型生命周期、持久化/缓存策略。
- 建立歧义 fixture，至少覆盖：future/motion `going to`、`want to` 疑问抽取、habitual/state
  `used to`、`have to`、功能词、多词专名、contraction、ASR 缺标点、残句和 false start。
- 预登记：token alignment coverage、关键歧义准确率、崩溃/超时率、冷/热延迟、峰值内存、
  模型与 runtime 体积；在验证集运行前锁定通过条件。

### Slice 1 — Provider-neutral contract

- 领域/应用边界建立句法分析 DTO、provider descriptor、closed error taxonomy。
- 明确 token 对齐：按 char span 映射，支持 1:N/N:1；不得只靠数组位置或规范化字符串。
- validator：span 有界、token coverage、HEAD 有效、单 root/树约束、sentence ownership。
- fingerprint 与 provider/model/version 隔离，确保模型升级后可安全重算。

### Slice 2 — Python research providers

- 建立 JSONL sidecar 协议与契约测试；stderr 诊断、stdout 只传协议。
- Stanza adapter：允许输入预分句文本并输出 UD 字段和 offset。
- spaCy 对照 adapter：输出同一项目契约，不把 spaCy 私有 label 泄漏到消费者。
- capability probe：未安装 runtime/model、模型损坏、语言不支持、超时均诚实降级。
- 模型按需下载和 provenance 清单；研究阶段不默认捆绑。

### Slice 3 — Evaluation and provider qualification

- 对开发集调 token mapping/adapter，不以验证集调参。
- 对验证集生成对照报告：关键构式、长字幕、口语残句、专名、数字、缩约。
- 人工复核 parser 错误如何传播到 B/SenseGroup；宁可 abstain，不允许高风险规则静默触发。
- 形成首个 qualified provider 决策；若全部失败，以研究结论收口，不伪造产品能力。

### Slice 4 — Reference B consumer

- `ConnectedSpeechContext` 改为优先消费句法 artifact，当前词表启发式保留为降级。
- 首批仅启用验证过的 syntax-gated 规则；每条包含 parser 正例、语义反例、无模型降级测试。
- B provenance 区分 `syntax_model` 与 `text_heuristic`；二者仍都属于预测，不能进入 C。

### Slice 5 — SenseGroup consumer

- 新增 syntax-aware provider/version，不覆盖规则 Provider 的历史分析。
- dependency subtree 只提供边界候选；最终仍由教学粒度规则控制 3–5 组/典型句。
- 强标点、短语完整性、从句/并列/PP 边界、min/max words 的冲突策略必须 fixture 化。
- 无 parser 时继续使用当前规则 Provider；ChunkTimeline 完全不受影响。

### Slice 6 — Construction seam and product QA

- 实现最小 dependency pattern matcher seam，验证同一 artifact 可支持构式 occurrence 候选。
- 不写 canonical Construction identity，不写 capability projection。
- 使用 owner 真实媒体完成 B 与 SenseGroup 手工 QA；记录模型安装、刷新、降级用户路径。

## Exit Signal

- 同一句字幕只产生一份带完整 provenance 的句法 artifact，可被 B 和 SenseGroup 同时消费。
- parser token 与 SubtitleToken 映射无静默错位；未映射项显式标记，低 coverage 分析不激活。
- 预登记验证集证明 `going to + VERB` / motion `to + NP`、habitual/state `used to` 的 B 行为
  优于当前启发式，且无模型时行为不回归。
- syntax-aware SenseGroup 在人工 fixture 上保持核心 NP/VP/PP/从句结构，并遵守教学粒度；
  规则 fallback 与 ChunkTimeline 均保持可用。
- 模型/runtime/模型数据许可证、下载来源、版本、checksum 和资源成本有可审计记录。
- Python sidecar 异常不会阻断字幕导入、播放、A/B fallback 或规则 SenseGroup。
- Construction matcher 证明能够复用同一依存图，但没有越权建立领域身份。

## Guardrails

- Provider 输出是可重建分析，不是用户资产，也不是学习能力事实。
- parser confidence 缺失时不得伪造概率；使用 coverage/validation status 表达可用性。
- 代码许可证不等于模型许可证；模型、treebank、runtime 分别审计，非商业模型不得进入可
  分发产品路径。
- 字幕/ASR 文本常含残句、缺标点、重复和修复；失败/abstain 是一等结果。
- 不在消费者代码里判断 `provider_id == stanza`；所有消费者只依赖中立契约。
- 不因句法模型加入而删除当前 B/SenseGroup fallback。
- 不用句法边界冒充声音边界，不用文本/句法结果填充 C。
- 不以小型 smoke fixture 宣称整体语言质量；真实媒体 QA 是 phase exit 的必要条件。

- 固定 fixture 的跨 provider golden comparison。
- B 正例、语义反例、无模型降级和 provenance 测试。
- SenseGroup 双 provider lifecycle、边界不变量与 fallback 测试。
- `cargo test --workspace`、Python tests、Flutter contract tests（若增加用户可见模型状态）。
