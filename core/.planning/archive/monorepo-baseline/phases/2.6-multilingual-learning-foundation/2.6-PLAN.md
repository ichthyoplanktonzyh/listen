# Phase 2.6 Plan: Multilingual Learning Foundation

更新时间：2026-06-20 23:40 CST

> 前置：Phase 2.5.5（语言学习抽象校验）须先收口。2.5.5 会校验本计划依赖的抽象、锁定
> invariant/variant 边界与 L1 seam，并把开放 taxonomy / 单位 alignment 作为本阶段实现约束
> 回灌。见 `../2.5.5-language-learning-abstraction-validation/`。

## Objective

将 LLPlayerNext 从“英语优先学习播放器”扩展为“语言能力可插拔的学习播放器底座”，
并以英语 + 汉语作为第一组真实验收语言。

## Position In Milestone 2

Phase 2.6 是延后阶段，不插队当前资源主线：

```text
2.3 Manual WordTimeline Review
  -> 2.3.5 Rust Module Decomposition
  -> 2.4 ChunkTimeline
  -> 2.5 Sound Pattern / PhoneTimeline
  -> 2.6 Multilingual Learning Foundation
```

原因：

- 2.3/2.4/2.5 先把资源生命周期和播放消费模型稳定下来。
- 多语言会触碰 tokenizer、词汇单位、字典、诊断、发音和 UI 状态，影响面大。
- 在资源主线稳定后再扩语言，风险更可控。

## Design Principle

```text
learning language != UI language

language profile
  -> listening model
  -> tokenizer
  -> lexical unit normalizer
  -> dictionary provider
  -> pronunciation provider
  -> diagnosis rules
  -> timeline/resource capabilities
```

核心原则：

- **Capability matrix first**：每种语言声明支持哪些能力，缺失能力干净降级。
- **Listening first**：语言能力来自对真实声音流的理解，文字、词典和语法是解释层。
- **English remains stable**：英语现有行为必须作为回归基线。
- **Chinese as forcing function**：汉语用于暴露空格分词、lemma、拼音/声调等架构假设。
- **Validation beyond English/Chinese**：Phase 2.6 只实现 English + Chinese，但架构必须能
  容纳 Spanish / French / German / Russian 等主流语言的听力学习模型。
- **ListeningUnit != LexicalUnit != Token**：字幕显示单位、词汇学习对象和真实听觉单位
  不能混为一个概念。
- **LexicalUnit over lemma**：学习单位不再默认等于英语 lemma。
- **Provider-based language support**：分词、词典、发音、诊断都通过 provider / profile
  进入系统。

语言听力模型的设计说明见 `2.6-LANGUAGE-LISTENING-MODEL.md`。

## Validated Foundation (Phase 2.5.5)

以下决策已由 Phase 2.5.5 用真实 SLA 校验、并经 Japanese / Arabic 类型学证伪锁定，作为本阶段
实现约束。依据见 `../2.5.5-language-learning-abstraction-validation/`。

1. **唯一不变量 = 理解轴**：全局词汇状态枚举（`Unclassified / UnknownMeaning /
   KnownNotRecognized / KnownRecognized`）语言无关、跨语言复用、作为稳定资产；一切结构走
   profile / provider。
2. **状态 ≠ 诊断理由**：状态 invariant、持久；诊断 reason taxonomy per-profile、可扩展、非
   持久（en: `weak_form`/`liaison`；zh: `tone_confusion`/`word_boundary`/`homophone`；
   ja: `pitch_accent`）。→ 中文诊断**不需要独立状态枚举**。
3. **ListeningUnit = 概念 + 诊断词汇表 + 现有 timeline 资源的视图**，**本阶段不新建持久表**。
   声音侧真相源仍是 Word / Chunk / Phone timeline。
4. **听力 observation 可锚定 ListeningUnit（不止 LexicalUnit）**（修订 R1）：声调 / 音高最小
   对立的"听不出"挂 ListeningUnit + contrast 观察。
5. **开放 `kind` taxonomy 是硬约束**（修订 R0）：tokenization / lexical_units /
   listening_units / rhythm_prosody / morphology 用 namespaced string（`core.*` + `<lang>.*`）
   + 未知即干净降级，**禁止穷举 enum + 穷举 match**。
6. **LexicalUnit 拆粒度 × 归一两轴**（修订 R2）：granularity(`char/word/phrase/morpheme`) ×
   normalization(`surface/lemma/citation/root`)；`normalized_key` 为 normalizer 不透明输出，
   **禁止 substring / 去缀假设**（阿拉伯语非线性词根）。
7. **L1 seam**：诊断签名预留 `(L1, L2_unit, status)`，v1 的 L1 可空、规则不读、不落 schema。

## Work Breakdown

### Step 1: Language Capability Matrix

定义语言能力矩阵。

建议字段：

- `language`
- `display_name`
- `script`
- `tokenization`: `whitespace | cjk_word_segmentation | char | mixed`
- `lexical_units`: `word | lemma | char | phrase`
- `dictionary`: provider IDs
- `pronunciation`: `ipa | pinyin | kana | none`
- `sound_features`: `stress | tone | pitch_accent | vowel_length | none`
- `word_timeline`: supported / approximate / unsupported
- `chunk_timeline`: supported / approximate / unsupported
- `phone_timeline`: supported / research / unsupported
- `diagnosis_rules`: rule set IDs
- `listening_units`: `sound_pattern | chunk | syllable | tone | stress_group | liaison_group | morpheme | compound | phrase`
- `rhythm_prosody`: `stress_timed | syllable_timed | tone | pitch_accent | mixed | unknown`
- `morphology`: `analytic | fusional | agglutinative | compound_heavy | mixed`

首批 profile：

- `en`: English profile，保持现有英语行为。
- `zh`: Chinese profile，支持中文分词、字级 fallback、拼音、声调和基础诊断。

架构校验 profile：

- `es`: Spanish validation profile，验证 syllable flow、stress、linking / elision。
- `fr`: French validation profile，验证 liaison、enchainement、schwa 和书写/发音错位。
- `de`: German validation profile，验证 compound、morphology 和长词边界。
- `ru`: Russian validation profile，验证 mobile stress、vowel reduction 和屈折形态。

Exit criteria:

- UI 和 API 能查询当前学习语言支持哪些功能。
- 不支持的能力显示为 unavailable / degraded，而不是失败。
- capability matrix 可以表达上述 validation profiles，而不要求本阶段实现完整功能。

### Step 1.5: Listening Model And Diagnosis Axis

在 tokenizer 和 lexical unit 之前，先定义语言相关的听力学习模型。

最小概念：

```text
ListeningUnit
- language
- kind: sound_pattern | chunk | syllable | tone | stress_group | liaison_group | morpheme | compound | phrase
- canonical_form
- observed_form
- time_range
- confidence
- explanation_links
```

英语：

- 核心听觉单位偏向 sound pattern、chunk、stress group 和 reduced spoken form。
- 诊断重点是弱读、连读、省音、边界模糊和 known-but-not-recognized。

汉语：

- 核心听觉单位偏向 syllable、tone-bearing syllable、word 和 phrase。
- 诊断重点是声母/韵母、声调、轻声、变调、词边界和同音上下文消歧。

Exit criteria:

- 文档和模型命名明确区分 `Token`、`LexicalUnit`、`ListeningUnit`。
- 中文路径不是英语 pronunciation model 的简单翻译。
- 后续法语 liaison、西语 syllable flow、德语 compound、俄语 stress/reduction 可以进入
  同一 profile/capability 体系。
- （2.5.5 锁定）ListeningUnit 为视图非持久表；listening observation 可锚定 ListeningUnit；
  kind 用开放 taxonomy。见 Validated Foundation。

### Step 2: Language-Aware Tokenization

替换单一 `tokenize_english()` 调用路径。

建议接口：

```text
tokenize(language, display_text) -> Vec<SubtitleToken>
```

英语：

- 保留当前行为和测试。
- 常见缩写、撇号、连字符不回归。

汉语：

- 初版可以采用：
  - 简单词典分词 provider，或
  - 外部资源可用时用分词词典，缺失时 char fallback。
- 保留原始字符范围。
- 支持 mixed token：中文、英文、数字、标点混排。

Exit criteria:

- `我想喝咖啡` 不再被整句作为一个 word token。
- `我想喝 coffee` 能稳定拆成中文单位 + 英文 word。
- token 重组后保留原始显示文本。

### Step 3: LexicalUnit Model

把学习单位从英语 lemma 扩展为语言相关 lexical unit。

建议概念：

```text
LexicalUnit
- language
- kind: word | lemma | char | phrase
- canonical_form
- display_form
- normalized_key
- segmentation_version
```

英语：

- `kind=lemma`，继续使用现有 normalized lemma。

汉语：

- `kind=word` 用于词汇状态。
- `kind=char` 可作为 fallback 或用户切换粒度。
- `kind=phrase` 为后续 chunk / fixed expression 做准备。

Exit criteria:

- 词汇状态不再假设所有语言都有 lemma。
- 旧英语 WordProfile 可继续读取。
- 汉语词和汉字不会污染英语词汇状态。
- LexicalUnit 只负责词汇学习对象，不承担真实声音流分块职责；声音侧由 ListeningUnit
  或 timeline resource 表达。
- （2.5.5 锁定）kind 拆为 granularity × normalization 两轴；`normalized_key` 为 normalizer
  不透明输出，禁止 substring / 去缀假设。见 Validated Foundation。

### Step 4: Remove `language=en` Hardcoding

清理 Flutter client 和 app service 中的学习语言硬编码。

重点路径：

- subtitle import language。
- vocabulary list language。
- dictionary lookup language。
- word profile update language。
- source snapshot language。
- external vocabulary import default language。

语言来源优先级：

1. 当前 active subtitle track language。
2. 用户手动选择的学习语言。
3. 媒体或资源 metadata。
4. 安全 fallback：`en`，但 UI 明确可修改。

Exit criteria:

- 同一个 UI 可以打开英语和汉语字幕，并按不同语言查询词汇状态。
- `_sourceFor` 不再固定写入 `language: en`。

### Step 5: Chinese Dictionary And Pronunciation Provider

接入最小汉语 provider。

第一版能力：

- 中文词 / 字查询。
- 拼音。
- 声调数字或声调符号。
- 英文或中文基础释义。
- 可选 HSK / 频率 / 词性。

数据来源可以先用本地小型 fixture，正式资源后续再确定许可证。

Exit criteria:

- 点击中文 token 能显示拼音和释义。
- provider 缺失时不会影响字幕播放和词汇状态。

### Step 6: Chinese Learning Panel And Diagnosis

为汉语定义最小学习体验。

面板显示：

- 字 / 词。
- 拼音。
- 声调。
- 释义。
- 来源原句。
- 状态切换。

诊断初版：

- 不认识词 / 字。
- 认识但没听出。
- 可能存在词边界切分困难。
- 声调或轻声可能造成识别困难。
- 同音词或上下文消歧可能造成理解困难。

Exit criteria:

- 外国人学汉语的基础使用路径成立：
  `打开中文媒体 -> 导入中文字幕 -> 点击词 -> 看拼音/释义 -> 标记状态 -> 来源复听`。
- 面板解释的是音节/声调到词义的映射，不把中文学习简化为英文式 lemma 查询。

### Step 7: Tests And Closeout

新增双语言 fixtures：

- English existing fixtures。
- Chinese simple subtitle fixtures。
- Mixed Chinese/English subtitle fixtures。

测试：

- tokenizer contract tests。
- vocabulary language isolation。
- dictionary provider language routing。
- source snapshot language correctness。
- UI smoke for Chinese token click。

Exit criteria:

- 英语全部回归通过。
- 汉语最小学习闭环通过。
- 文档更新 ROADMAP / REQUIREMENTS / STATE。
