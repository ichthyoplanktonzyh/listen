# Phase 2.6 Design Note: Language Listening Model

更新时间：2026-06-22 CST

## Core Thesis

LLPlayerNext 的多语言架构应以听力能力为核心。

真正可交流的语言能力来自学习者对真实声音流的稳定理解，而不是先掌握文字符号体系。
文字、词典、语法、翻译和字幕都很重要，但它们是解释层、校准层和复盘层；它们服务于
`audio -> meaning` 的建立，而不是把声音当成文字的附属说明。

因此 Phase 2.6 的多语言基础不应只抽象为：

```text
text -> token -> dictionary -> meaning
```

更准确的产品模型是：

```text
audio -> listening units -> meaning candidates -> lexical/text explanation
```

## Why This Matters

不同语言的听力突破点并不相同。如果架构只围绕 tokenizer、lemma 和 dictionary 建模，
就会把英语经验硬套到其他语言，或者把中文经验做成另一条特例分支。

Phase 2.6 需要建立的是语言相关的听力学习模型：

```text
LanguageLearningProfile
  -> ListeningModel
  -> WritingSystemModel
  -> LexicalUnitModel
  -> PronunciationModel
  -> RhythmProsodyModel
  -> MorphologyModel
  -> DiagnosisModel
  -> ExplanationModel
  -> CapabilityMatrix
```

其中 `ListeningModel` 是核心。它回答：

- 这个语言里，学习者实际需要听出来的单位是什么？
- 真实声音流如何自然分块？
- 哪些听觉线索最决定理解？
- 哪些变化会让文字和真实声音不一致？
- 学习者常见的“听不懂”发生在哪一层？

## Token, LexicalUnit, ListeningUnit

Phase 2.6 需要避免把三个概念混成一个：

- `Token`：字幕显示和点击交互单位，必须保留原始文本范围。
- `LexicalUnit`：词汇状态、词典、复习和来源快照的学习对象。
- `ListeningUnit`：学习者在真实声音流中需要辨认的听觉单位。

英语里 `Token`、`LexicalUnit` 和 `ListeningUnit` 经常不一致：

- written token 可能是 `going`，lexical unit 是 `go`，真实听觉形态可能接近 reduced
  form。
- 多个 written words 可能在听觉上组成一个 chunk 或 stress group。
- function words 在真实语流中可能弱化到无法按书面词边界听出。

汉语里三者也不能简单等同：

- token 可能来自中文分词。
- lexical unit 可以是字、词或短语。
- listening unit 更接近音节、带声调音节、词组或语义短语。

## Architecture Validation Languages

Phase 2.6 的实现验收语言仍然是 English + Chinese，但架构需要用若干主流语言做压力
测试，避免形成英语/中文双特例。

这些语言先作为 design validation set，不代表本阶段都要实现：

| Language | Listening pressure | Architecture concern |
|---|---|---|
| English | stress rhythm, reduction, connected speech, fuzzy word boundaries | sound pattern, chunk, reduced spoken form |
| Chinese | syllables, tones, word boundaries, homophone disambiguation | syllable/tone model, char/word/phrase units |
| Spanish | fast syllable stream, stress, linking/elision | syllable flow, stress, stable orthography mapping |
| French | liaison, enchainement, schwa, silent spelling mismatch | liaison groups, phrase-level pronunciation |
| German | compounds, inflection, stress, long lexical units | morphology, compound segmentation |
| Russian | mobile stress, vowel reduction, inflected forms | stress model, reduction, morphology |

Japanese and Korean can be later pressure tests because they add mora/pitch-accent, script mixing,
spacing, morphology and honorific/register concerns, but they are not required for Phase 2.6.

## Language-Specific Listening Models

### English

English listening difficulty is often driven by the non-linear relationship between written words and
surface audio:

- weak forms
- linking and connected speech
- elision and assimilation
- stress-timed rhythm
- fuzzy word boundaries
- known words appearing in unfamiliar spoken forms

Learning path:

```text
audio stream -> sound patterns / chunks -> reduced spoken forms -> words -> meaning
```

PhoneTimeline and ChunkTimeline are especially important for English because they expose what the
learner actually hears before the written form explains it.

### Chinese

Mandarin listening difficulty is different. It is closer to stable syllable recognition and mapping
from syllable flow to lexical and phrase meaning:

- syllable initials/finals
- tones
- neutral tone
- tone sandhi
- er-hua where relevant
- word boundary discovery
- homophone and context disambiguation

Learning path:

```text
audio stream -> syllables / tones -> words / phrases -> meaning
```

Chinese support is therefore not just "segmentation + pinyin dictionary". The listening model must
represent syllable and tone as first-class explanatory evidence for lexical and phrase understanding.

### Spanish

Spanish has comparatively stable spelling-to-sound mapping, but listening difficulty can come from
fast syllable flow, stress, regional pronunciation, linking and elision.

Learning path:

```text
audio stream -> syllable flow -> stress groups -> words / phrases -> meaning
```

### French

French listening requires modeling phrase-level sound behavior, not just word-level pronunciation:

- liaison
- enchainement
- schwa deletion
- silent final letters
- syllable-timed prosody

Learning path:

```text
audio stream -> syllable / liaison groups -> phrase sound pattern -> written words -> meaning
```

### German

German stresses morphology and longer lexical units:

- compounds
- separable prefixes
- case/gender inflection
- stress in long words
- phrase parsing under long syntactic distance

Learning path:

```text
audio stream -> stressed lexical/morphological units -> compound / phrase parse -> meaning
```

### Russian

Russian listening requires stress and reduction awareness:

- mobile stress
- vowel reduction
- consonant palatalization
- rich inflection
- free word order interacting with morphology

Learning path:

```text
audio stream -> stress / reduction pattern -> inflected forms -> lemma / meaning
```

## Phase 2.6 Implications

Phase 2.6 should still implement narrowly:

- English remains the regression baseline.
- Chinese becomes the first non-English implementation target.
- Other languages are used to validate abstractions, not to expand implementation scope.

The implementation should therefore avoid language-specific branching like:

```text
if English -> lemma
if Chinese -> char / word
```

Instead, language behavior should come from profiles and capabilities:

```text
LanguageLearningProfile
  declares supported tokenization, lexical units, listening units,
  pronunciation model, rhythm/prosody model, morphology model,
  diagnosis rules, and degradation behavior.
```

## Product Principle

LLPlayerNext should treat listening as the primary route to language ability:

> Different languages expose different listening units and sound-to-meaning paths. The system must
> model those paths directly, then use text, dictionary, pronunciation and grammar as explanation
> layers.

This principle should guide Phase 2.6 decisions about tokenization, lexical units, dictionary data,
pronunciation, diagnosis and UI fallback.
