# Phase 2.13 Closeout: Text-Centered Phoneme Ribbon

收口时间：2026-06-26 CST
状态：✅ COMPLETED

## 目标回顾

Phase 2.13 的目标是完成“文字线”的音素学习体验：用户完成 Whisper 转录后，不需要
下载 CTC 模型，也能基于词典发音和词级时间戳看到音素随播放位置跳动；如果后续存在
真实 CTC 音素数据，则自动升级为真实数据驱动。

Phase 2.13 不承担“声音线”的音节化、韵律短语和真实语流结构教学，这部分已拆到
Phase 2.14。

## 完成内容

### 词典音素合成接入

- `main.dart` 的音素渲染分支改为统一消费 `List<DetectedPhone>`。
- 优先使用 `phoneticAnalysisBySentence` 中的 CTC `detected_phones`。
- CTC 数据为空时，使用 `pronunciationBySentence + timingsBySentence` 调用
  `synthesizePhonesFromDictionary()` 合成音素时间轴。
- 两者都不可用时隐藏音素层，不再回退到单行 IPA 文字。

### PhonemeRibbon 长短句自适应

- 短句：完整显示整句音素带，保持全局上下文。
- 长句：自动切换为分页窗口，只展示当前音素附近的一页。
- 分页窗口采用稳定 page，而不是每个音素重新居中滑动：当前音素在页内移动，只有
  播放推进到下一页时才整体换页。

### 低疲劳视觉策略

用户实测后确认：长句中“窗口内容快速变化 + 当前音素高亮变化”叠加会造成明显视觉疲劳。
最终策略：

- 长句模式不使用波浪放大。
- 长句模式不使用脉冲动画。
- 长句模式不使用连续滑动窗口。
- 长句模式不显示底部进度条。
- 当前音素只通过轻量高度、边框和颜色强化。

短句可继续使用轻量 wave，因为完整句子能一次显示，运动源少且上下文稳定。

### 设置链路闭合

- `AppSettings` 新增 `phonemeRibbonStyle`，默认 `window`，保留 JSON 向后兼容。
- `SettingsController` 暴露 `phonemeRibbonStyle`。
- 设置对话框新增“音素带显示方式”：`window` / `wave`。
- `main.dart` 将设置传入 `PhonemeRibbon(style: ...)`。

## 关键设计决策

1. **长句不追求全量展示**

   音素过多时，完整显示会被压缩成不可读噪音；学习价值低于视觉成本。长句只展示
   当前页，把认知焦点收束到当前播放位置。

2. **长句窗口必须稳定**

   连续居中滑动会让整个窗口随每个音素变化，和当前高亮叠加后形成两个高频运动源。
   分页窗口把运动源降到一个：当前音素高亮。

3. **短句和长句不是同一种控件状态**

   短句可以作为“全景时间带”；长句应该是“当前音素阅读器”。同一个组件根据可读宽度
   自动切换，而不是要求用户手动选择。

4. **文字线音素以可用性优先**

   词典音素 + 词级时间戳的合成结果足以支撑“转录后立即可用”的学习体验。真实 CTC
   音素作为增强数据源自动接管，不改变 UI 消费路径。
