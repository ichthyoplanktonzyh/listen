# Phase 3.4.3 Failure Modes: Construction Modeling Spike

状态：COMPLETED — 2026-07-10 CST

本文件记录 gold/manual fixture 暴露的模型边界，不把小样本当作自动分析质量证明。

## Confirmed failures prevented by the validator

| 失败模式 | fixture / validator 处理 | 产品结论 |
|---|---|---|
| 将相同文字的不同来源合并成一个收藏句 | exemplar identity 同时包含 language、source snapshot 和 text | 素材来源、回听和用户笔记不能被 canonical construction 吞并。 |
| 从表面文本自动生成全局构式 ID | construction 只接受人工 key + language + schema version；测试验证同 key/version 稳定、version 改变即不同 | parser / LLM 只能产出候选 occurrence，不能生成 canonical truth。 |
| 把时态、语态、否定、疑问写成全局归并规则 | 每个 construction 明示四维 variant policy；测试把 voice policy 改为 `separate` 后 fixture 失败 | 变体归并由 construction 自己定义，不能做跨语言全局 enum 开关。 |
| 因同句命中多个构式而选择唯一“主构式” | 英语 comparative-correlative 句同时有外层构式和两个嵌套 transitive occurrences，验证器通过 | occurrence 是多值 annotation；重叠/嵌套是正常事实。 |
| 让用户模板依赖系统分析或被其覆盖 | 日语 arbitrary exemplar 没有任何 occurrence，仍可生成无 system link 的 UserSentencePattern 并验证来源快照 | 个人模板是独立 durable asset；系统链接是建议，不是创建前置。 |
| 将“认识 / 会用”错误地压成无来源状态 | profile 保持 recognition / production 两维；evidence 强制 axis 对应 recognition→reading/listening、production→speaking/writing | 简化 read model 可以保留，但 evidence 必须带 modality。 |

## Remaining unknowns (not solved by this spike)

1. 人工 canonical library 的治理：key 命名、编辑审核、schema version 升级、弃用和本地导入。
2. 多语言 tokenization 与 slot 约束的真实 provider contract；当前 token span 仅验证边界，
   `constraint` 是 provider-neutral label，不是 POS/UD schema。
3. 自动 parser / LLM 候选的 precision、置信度、人工修正 overlay 与可重建 lifecycle。
4. `SentenceExemplar` 对媒体、字幕替换、收藏笔记、练习历史的生产级 deletion/import semantics。
5. construction evidence 如何投影出 capability，以及何时允许 user override；本轮只验证
   profile/evidence 的信息不丢失。

## Decision

这些未知项中任何一项都足以改变 schema 和 API 形状。因此 spike 以**不建立生产 schema**收口。
下一步先验证用户价值，不以 parser coverage 或 fixture 数量替代产品证据。
