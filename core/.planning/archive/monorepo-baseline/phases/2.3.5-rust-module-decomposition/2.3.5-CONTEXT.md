# Phase 2.3.5 Context: Rust Module Decomposition

更新时间：2026-06-20 23:25 CST

## Background

Phase 2.1 已经完成生产资源链路的关键正确性加固，并明确将
`application` / `persistence-sqlite` 巨型文件拆分从 2.1 scope 中切出，作为独立
架构债处理。Phase 2.2 已经完成字幕资源生命周期和 LLTimeline 消费闭环。Phase 2.3
将完成 user-adjusted WordTimeline 的人工校正闭环。

在进入 Phase 2.4 ChunkTimeline 和 Phase 2.5 PhoneTimeline 之前，核心 Rust crate
已经出现明显维护压力：

```text
crates/persistence-sqlite/src/lib.rs  ~4164 lines
crates/application/src/lib.rs         ~3375 lines
crates/api-http/src/lib.rs            ~3182 lines
crates/domain/src/lib.rs              ~1317 lines
```

继续在这些文件中加入 ChunkTimeline、PhoneTimeline、Sound Pattern 和多语言能力，
会显著增加合并冲突、导航成本和回归风险。

## Problem

当前巨型单文件带来的直接问题：

- 单个 `lib.rs` 同时包含 trait、DTO、use case、repository impl、helper 和测试。
- 改一个小用例时需要在数千行文件中定位上下文。
- 新增资源生命周期时容易复制旧模式，但很难复用清晰模块边界。
- `persistence-sqlite`、`application`、`api-http` 的领域边界在文件层面不可见。
- 2.4/2.5 会继续新增 ChunkTimeline / PhoneTimeline 资源，如果不先拆分，债务会滚大。

## Product Relationship

Phase 2.3.5 不是产品功能阶段。它服务于后续产品阶段：

```text
Phase 2.3 Manual WordTimeline Review
  -> Phase 2.3.5 Rust module decomposition
  -> Phase 2.4 ChunkTimeline resource lifecycle
  -> Phase 2.5 PhoneTimeline / Sound Pattern resource lifecycle
```

它的价值是降低后续资源化能力的实现成本，而不是改变用户可见行为。

## Scope

本阶段聚焦机械拆分：

1. `persistence-sqlite` 按 repository / 表域拆分。
2. `application` 先拆公共 trait / DTO / error / util，再按 use case 域拆分。
3. `api-http` 继续按 route group 拆分已有巨型 `lib.rs`。
4. 保持对外 `pub use` 兼容，尽量不改变外部 crate import 路径。
5. 将内嵌测试随对应模块移动。

## Non-Goals

- 不新增产品功能。
- 不修改 API contract。
- 不修改数据库 schema。
- 不修改 LLTimeline JSON schema。
- 不重构业务逻辑。
- 不拆 `speech-analysis` crate。
- 不优先拆 `domain/src/lib.rs`，除非某个子模块必须依赖小范围类型移动。
- 不处理 forced-align monotonicity 消融；该项继续作为独立算法评估债务。

## Success Criteria

- `persistence-sqlite/src/lib.rs` 不再承载所有 repository impl。
- `application/src/lib.rs` 不再承载所有 trait、DTO、helper 和 use case impl。
- `api-http/src/lib.rs` 保留 router assembly、state 和少量 glue code，主要 handler
  进入 route group 模块。
- 外部 crate 的主要 import 路径保持兼容。
- 每完成一个拆分批次，相关 Rust 测试通过。
- 用户可见行为、API 响应和数据库内容不变。
