## 1. 矩阵总表

列定义：

- **channel 归属**：该任务的 attempt 事实归入哪个（些）capability 通道的解释域。
- **target kind**：clip（片段/句子级）或 target（词条/pattern 级锚定）。
- **assistance**：被评通道的输入之外，学习者还能接触什么（各任务合法值见 §2）。
- **outcome 语义**：结果在哪一层表达。所有语义任务的 attempt 本身只有
  `completed | abandoned`；per-point 结果只存在于 `SemanticJudgment`。
- **evidence class**：判断来源的可靠性口径（AGENT.md）。3.12.1 资格通过前，
  LLM judgment 不进任何学习 surface；fixture/manual 判定仅用于契约测试。
- **projection candidate**：该证据未来是否允许进入 3.17 的 projection 候选池
  （3.11–3.16 内一律不写 projection）。

|---|---|---|---|---|---|---|---|---|

## 2. 逐任务真实示例

### 2.1 L1 复述（完整逐点判定示例，好/差对照同一 rubric）

任务设置：播放例段（无字幕），要求用中文说出"这段讲了什么"。回答经 ASR 或直接键入。

**回答 A（好）**：「菲律宾南部发生了 7.8 级大地震，至少 19 人死亡、200 多人受伤，
路都裂了，有些房子也塌了。」

| point | 判定 | supporting span（回答 A 内字符区间） |
|---|---|---|
| P1 | covered | 「菲律宾南部」 |
| P2 | covered | 「7.8 级大地震」 |
| P3 | covered | 「至少 19 人死亡、200 多人受伤」 |
| P4 | missing | — |
| P5 | partial | 「路都裂了，有些房子也塌了」（缺"恐慌"） |

**回答 B（差）**：「好像是哪里地震了，死了一些人。」

| point | 判定 | supporting span |
|---|---|---|
| P1 | missing | —（"哪里"不构成地点覆盖） |
| P2 | partial | 「地震了」（无强度/严重性） |
| P3 | partial | 「死了一些人」（无量级） |
| P4 | missing | — |
| P5 | missing | — |

**回答 C（abstain 示例）**：录音空白/ASR 置信度过低 → judgment 级 abstain +
原因 `unreliable_transcript`，逐点不产生任何结论（负向行 #11）。

写入结果：三次回答 = 三条 semantic attempt + 三条 judgment；`learning_observations`
零新增；"earthquake / aftermath / crumble" 等词条画像不变。

Adjudication 示例：用户认为回答 B 的 P3 其实达到了 partial 以上（"我说了死了人"）→
追加一条 `JudgmentAdjudication(judgment=B, point=P3, user_verdict=partial→covered 的
纠正声明)`；原 judgment 行逐字节不变；不触碰任何 capability override。

### 2.2 L2 复述（双通道，判定引用 §3 表）

任务设置：同段音频，隐藏原文，用英语复述。

回答示例：*"There was a strong earthquake in the south of the Philippines. At least
19 people died and more than 200 were injured."* → P1/P2(partial，无震级)/P3 covered；
若此前或随后其 L1 复述充分而 L2 覆盖不足 → 记录为 receptive–productive gap 信号
（§3 第 2 行），不改判 listening 结论。

### 2.3 Reading comprehension

任务设置：只给例段 transcript 文本（不播音频），问"人们为什么恐慌？"（P5 推断）与
主旨题（P1+P2）。与"只听"版本的同 rubric 对照是 3.13 读听差异诊断的基础——两次
attempt 各自记录 assistance 条件，判定共享同一 rubric version 才可比较。

### 2.4 Role reply

任务设置：情境提示「朋友没看新闻，问你 What happened in the Philippines?」，口头回答。
判定维度 = rubric 信息点覆盖 + 应答合意性；不评发音总分（3.14 边界）。

### 2.5 Dictogloss

任务设置：听例段 2 遍，只许记关键词（如 Philippines / 7.8 / Monday / 19 killed），停止
音频后重构一段英文，对照 rubric 修改出第二稿。第一稿与第二稿是**同一 attempt 的两个
版本化回答快照**，各自有 judgment，引用同一 rubric version（可比较性的直接用例）。
关键词笔记存为 attempt 过程材料，不是 writing evidence。

### 2.6 Summary

任务设置：原文可见，用 1–2 句英文概括。rubric 的 required 集合退化为主旨点
（P1+P2+P3 合并语义），optional 为细节点——同一片段可有多个 rubric（复述用/摘要用），
rubric 身份 = (segment, task 用途, version)，不同用途的 rubric 之间不可比较。

### 2.7 Sentence-pattern production

任务设置：从例段提炼模板 “be dealing with the aftermath of …”（用户已存为
pattern，快照锚定），要求在新情境（如洪水）造句。判定 = pattern 使用正确 + 新语境
合意。attempt 记录 pattern 锚点（opaque snapshot），但**不写** construction
observation（推迟 3.16，届时按 ADR 0020 第 5 条 recognition/production 证据模型接入）。

## 3. L2 复述双通道解释表（对齐 final §3.1，逐格照抄，不自创解释）

| 观察 | 允许的解释 |
|---|---|
| L1 覆盖充分、L2 覆盖充分 | 当前片段理解与 L2 表达均有正向证据 |
| L1 覆盖充分、L2 覆盖不足 | 较强 receptive–productive gap 信号 |
| L1 覆盖不足 | 可能是理解、回忆、投入或 ASR 问题；建议回听确认 |
| L1 覆盖不足、L2 覆盖充分 | 合法情况，不应强行改判 |
| 任一转写不可靠 | abstain，不产生自动结论 |

补充裁决：L1 复述**不是**固定前置步骤——默认直接 L2，仅在 L2 失败、用户不确定或
主动请求诊断时提供 L1（final §3.1）。因此 attempt 记录"进入 L1 的触发原因"
（user_requested | l2_failed | diagnosis），供 3.14 交互设计与后续解释使用。

## 4. Typed contract spike 裁决

### 4.1 已核实事实

1. `PracticeKind` 封闭枚举 4 值；Rust 消费点实际极少：
   `application/listening.rs:122`（只构造 `Dictation`）、`application/recording.rs:88`
   （只守卫 `Shadowing`）、**唯一 exhaustive match 压力点是
   `domain/learning_observation.rs` 的 `observation_spec_for_practice`**（ADR 0017
   任务→通道映射，每个新 variant 都强制回答"写什么 lexical observation"）。
2. Dart 侧 `practice.dart` 的 `kind` 是开放 string，无 wire 阻力。
3. `PracticeAttempt` 的 `result: Correct/Partial/Incorrect/Completed/Skipped`、
   `expected_answer`、`evaluation.token_results` 全部假设**确定性单答案**；语义任务
   没有单答案，结果在 judgment 逐点层。
4. `PracticeItem/Target/Anchor` 的定位与快照骨架（Sentence/Segment/Chunk、
   prompt_snapshot、token/时间锚）可直接复用。
5. 3.5.6 练习浮窗、review 队列消费 `practice_*` 表；语义任务 attempt 不应出现在
   这些队列里。

### 4.2 裁决：方案 C（混合），不扩 `PracticeKind`，不改开放 string

- 新建封闭枚举 `SemanticTaskKind = { reading_comprehension, l1_retelling,
  l2_retelling, role_reply, dictogloss, summary, pattern_production }` 与新表族
  `semantic_task_attempts`（Slice 2 命名可微调）。
- 复用 domain 既有 `PracticeTarget` / `PracticeAnchor` 类型做定位与快照；可选引用
  `PracticeSessionId` 暂不加（studio session 概念等 3.13 真实需要时 additive 补）。
- `PracticeKind` / `PracticeAttempt` / ADR 0017 映射完全不动。

理由：

1. **结构性防污染**：语义任务必须"结构性不能"批量写 lexical observation。放进
   `PracticeKind` 意味着 `observation_spec_for_practice` 对它们返回 `None`，把
   "本任务与 lexical evidence 无关"和"跳过/未评估"压进同一条路径——恰好违背本
   phase 的目的（四层事实分离）。独立任务族让"不写 observation"成为类型层事实。
2. **结果模型不同构**：`PracticeResult` 无法承载逐点判定；语义 attempt 只有
   completed/abandoned，评价活在 `SemanticJudgment`。硬塞会让 3.5.6 浮窗/review
   队列面对无法评分的 attempt。
3. **队列隔离免费获得**：新表族天然不进练习/复习队列，无需在既有查询里加排除谓词。

被拒选项：

- **A. 扩 `PracticeKind`**：见理由 1/2；且 `expected_answer`/`evaluation` 字段对语义
  任务全部无意义，会产生大量 null 语义。
- **B. 完全独立、不复用 target/anchor**：重复造定位/快照结构；且 3.5.7 切片回听、
  corpus 定位等生态都讲 `PracticeTarget` 语言，独立结构会立刻需要转换层。
- **D. `kind` 用开放 string**（v1 遗留问题的正式回答：**否**）：每类任务必须先过
  evidence matrix 裁决（channel 归属、写入边界）才允许存在；开放 string 会让新任务
  绕过裁决直接入库。扩展路径 = 改枚举 + 补矩阵行 + 升 ADR 版本，与 ADR 0017 模式一致。

### 4.3 对 Slice 1 契约的直接输入

- `SemanticTaskAttempt` 最小字段集：id、kind、target（PracticeTarget）、anchors、
  rubric_id + rubric_version（任务由 rubric 驱动，attempt 时即绑定）、任务条件
  （assistance/呈现条件，per-kind 合法值见 §1/§2）、回答快照（文本 + 来源
  typed|asr + 可选 recording_asset_id + ASR 质量标记 + 回答语言）、L1 触发原因
  （仅 retelling 族）、版本化回答序列（dictogloss 两稿）、completed|abandoned、
  时间戳。
- rubric 身份 = (source segment 快照, 任务用途, version)；同段不同用途不可比较（§2.6）。
- judgment 引用 attempt + rubric(id,version,source snapshot hash)，校验三方一致。
