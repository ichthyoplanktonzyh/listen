## Objective

在接任何外部 LLM 或 Studio UI 前，固定四通道主动任务的事实层：片段级 attempt、版本化
`SemanticRubric`、逐点 `SemanticJudgment`、用户 adjudication，以及它们与 lexical /
construction observation、projection、override 的边界。

## User Value

本 phase 不以独立 UI 为价值；它保证后续用户看到的“覆盖了哪些信息”“为什么被判为遗漏”
与能力变化可追溯、可纠正，不因换模型或换 provider 改写历史。

## Scope

### In

- 定稿四通道 evidence matrix：task、channel、target kind、assistance、outcome、强度
  （evidence class）与是否允许进入 projection candidate；每类任务明确写入裁决
  （clip fact / target observation / neither）。
- typed contract spike：裁决扩展 `PracticeKind` vs 新建 semantic task 族（v1 遗留的
  开放问题，本 phase 内关闭）。
- 新增 clip/sentence/construction 级 attempt seam，避免非 lexical 事实强塞
  `LearningObservation`。
- `SemanticRubric`：来源快照、required/optional information points、language pair、
  version、generator provenance、人工修订历史。
- `SemanticJudgment`：逐点结果、精确 transcript span、uncertain/abstain 一等、
  ASR 质量、prompt/model/schema provenance。
- `JudgmentAdjudication`：用户对一次自动断言的确认/纠正；不复用 capability override。
- append-only persistence（v35+）、repository/use case、最小 HTTP API + OpenAPI、
  portable/export 边界裁决。
- ADR 0021：semantic attempt / judgment / observation / capability separation。

### Out

- 真实 LLM 网络调用、API key 设置、厂商 adapter（3.12）。
- judge 资格评估与任何 feedback 显示资格（3.12.1）。
- Reading/Speaking/Writing UI（3.13–3.15）。
- reading/speaking/writing 自动 capability projection（3.17）。
- recording→ASR use case（Speaking Studio 前置，3.14 或其前置 slice）。
- construction 生产 persistence（ADR 0020 第 7 条维持；sentence-pattern production
  在 matrix 中只裁决证据归属，不建表）。
- Flutter Dart DTO 与任何 UI 接线（v2 裁决：按 seam 标准 §3.6，OpenAPI/响应形状是
  additive 预留，但无 consumer 的 Dart DTO 是死代码；ADR 0014 手写 DTO + fixture

### Slice 0 — Evidence matrix + typed contract spike（纸面先行，owner 门）

产出 `3.11-EVIDENCE-MATRIX.md`（本 phase 目录）：

1. 至少覆盖六类任务，每类给出**真实媒体句段上的具体例子**（可用
   `/Users/shadow/Desktop/视频` 素材或 testdata 真实转写，L1=中文视角）：
   reading comprehension、L1 复述、L2 复述、role reply、dictogloss、summary、
   sentence-pattern production。
2. 矩阵列：task / channel 归属 / target kind / assistance / outcome 语义 /
   evidence class（`heuristic_proxy` 等，按 AGENT.md 口径）/ 是否 projection
   candidate / 写入裁决（clip fact | target observation | neither）。
3. L2 复述的双通道归属（listening 理解 × speaking 产出）逐格对齐 final 稿 §3.1
   五行表，不得自创解释。
4. 负向裁决显式成行：L1 复述不批量写 lexical evidence；shadowing completion 不是
   constructed speaking success；模型改写文本不是 writing evidence；“未评估”与
   “失败”分离。
5. typed contract spike 结论段：基于 §上游现状核对 2/3 的事实，裁决
   **扩展 `PracticeKind` 枚举 vs 新建 semantic task 族**。裁决标准写明：
   - 既有 4 个消费点是否被迫感知新任务（`observation_spec_for_practice` 等
     exhaustive match 的影响面）；
   - 语义任务的 attempt 是否需要 `PracticeAttempt` 之外的字段
     （rubric 引用、回答转写快照、L1/L2 语言标记）；
   - 3.5.6 练习浮窗与 review 队列是否必须对新任务不可见。
   结论允许是混合形态（如：复用 `PracticeSession/Attempt` 骨架 + 新
   `SemanticTaskKind` 平行枚举），但必须唯一、写明理由与被拒选项。
6. 研究依据：dictogloss、free recall（L1/L2 复述）、summary 任务的证据解释各附
   至少一条已发表文献或公开教学法依据（final 稿 §12 已有 L2 free recall 与 CEFR
   条目，可引用但须核实适用性）。

**门：owner 复核矩阵与 spike 结论后，才进入 Slice 1。**

### Slice 1 — Domain contract + validator（纯 domain，无持久化）

- 新模块 `crates/domain/src/semantic_task.rs`（命名可按 spike 结论调整）：
  - `SemanticRubric`：source segment 身份 + transcript 快照 + 时间范围 + media/track
    引用（可空引用，快照自足）、language pair、`Vec<RubricPoint>`（`point_id` 在
    version 内稳定唯一、required/optional、statement、accepted paraphrase notes）、
    `version`、generator provenance（`fixture | manual | llm` + 细节）、人工修订
    历史（append，不改历史 version）。
  - `SemanticJudgment`：attempt 引用、rubric id + version + source snapshot hash、
    回答 transcript 快照 + 来源（typed / asr）+ ASR 质量标记、逐点
    `covered | partial | missing | uncertain`、每点 supporting span（必须落在回答
    transcript 内）、judgment 级 `abstain` + 原因、prompt/model/schema provenance
    （fixture/manual 时如实记录 generator kind）、raw structured output。
  - `JudgmentAdjudication`：judgment 引用 + point_id + 用户裁定 + 备注 +
    occurred_at_ms；append-only，不含任何回写 judgment 的方法。
- 身份函数沿用项目 fingerprint 惯例（参照 `learning_observation_id`）。
- validator + 负向测试（`domain` 单元测试）：
  - span 越界 / point_id 重复 / judgment 引用错 version 或错 snapshot hash → 拒绝；
  - 同一 rubric version 上两个 judgment 可比较、不同 version 不可直接比较的谓词；
  - adjudication 引用不存在的 point → 拒绝；
  - abstain judgment 不产生任何逐点 covered 结论。
- gold fixture：`testdata/semantic-task/gold-fixture-v1.json` —— 同一 rubric 两个
  真实回答（一好一差）+ 一个 abstain + 一次 adjudication，作为后续所有层的契约输入。

### Slice 2 — SQLite v35 + repository + use case

- migration v35（additive）：`semantic_rubrics`、`semantic_judgments`、
  `judgment_adjudications`，以及 spike 裁决的 attempt 落点（新表或复用
  `practice_*`）。全部 append-only：实现层不提供 UPDATE/DELETE；媒体外键不

- repository trait 加入 `crates/application/src/repositories.rs`，实现放
  `crates/persistence-sqlite/src/`（新文件 `semantic_task.rs`）。
- use case（`crates/application/src/semantic_task.rs`）：保存 attempt / rubric /
  judgment / adjudication，读链路（按 segment 取 rubric、按 attempt 取 judgment
  与 adjudication 全史）。
- 负向测试（application/persistence 层）：
  - L1 复述 attempt 全流程走完，`learning_observations` 零新增；

## Exit Signal

- 同一 rubric 上两个回答可以被保存、比较、人工纠正且全链路可追溯。
- 删除原媒体后，rubric/attempt/judgment 快照仍可解释历史。
- 没有任何网络或模型时 contract 测试完整成立。
- 对每类任务明确“写 clip fact / target observation / neither”，无默认批量升级。

## Guardrails

- 新抽象必须由 3.13–3.15 的具体任务消费；不建通用 LMS 或通用 AI conversation schema。
- 原始自动判断永不被 adjudication 覆盖删除。
- 未评估与失败分离；uncertain/abstain 是一等结果。
- Slice 0 门前不得落任何 schema/API 形状；矩阵与 spike 结论是持久化的输入而非事后
  补写的文档。
- 本 phase 纯 additive：不改既有 practice/observation 表与 wire format；若 spike
  裁决扩 `PracticeKind`，旧值序列化形式不变。
