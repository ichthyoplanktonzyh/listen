状态：CODE COMPLETE — 全部后端可证 exit signal 已自动化核验通过；owner 真实 provider
端到端产品 QA 为剩余人工门（见 §QA 归属）。

上游：`3.12-PLAN.md`（v3）、`3.11-3.18-FOUR-CHANNEL-SHARED-CONTEXT.md` §3.3/§3.4/§3.5/§3.6、
final 讨论稿 §7/§8/§9、ADR 0021。产出决策：ADR 0022。

## Outcome

在不绑定任何厂商、SDK、模型名或单一 wire format 的前提下，建立了可选的语义能力 provider
系统：领域层定义中立任务契约，两个**结构异构**的协议 adapter（OpenAI Chat Completions-
compatible + Anthropic Messages）通过**同一** fake-server 契约套件，证明领域层未被任一 wire
format 绑架。密钥只进 OS keychain，profile 只持不透明 `auth_ref`，全链路（SQLite/日志/
bundle/API 响应）不落密钥。任一 provider 失败（离线/认证/拒绝/截断/schema 无效）一律不写
judgment，核心学习路径不依赖 provider。**本 phase 不新增任何 observation/projection writer，
不点亮任何学习 surface**；provider 判定一律停留在未获显示资格状态（资格评估属 3.12.1）。

## Delivered（按切片）

### Slice 0 — 中立契约层（domain + application）

- `crates/domain/src/llm_provider.rs`：`LlmAdapterKind`、`LlmProviderProfile`、opaque
  `LlmAuthRef`、`ProviderCapability`/`CapabilityClaim`（Declared/Probed/Unknown）、`LlmUse`、
  `DataRetentionPreference`、`CostBudget`、标准化 secret-free `LlmProviderError` 分类学。
- `crates/application/src/providers.rs`：两层 seam——`LlmChatAdapter`（wire）+
  `SemanticRubricProvider`/`SemanticJudgeProvider`（application）+ `RubricDraft`/`JudgmentDraft`
  仅内容草稿（不含身份）。

### Slice 1 — 两异构 adapter + 同一契约套件（中立性证明，必做）

- `crates/llm-provider/`：`OpenAiChatAdapter` + `AnthropicMessagesAdapter` 实现
  `LlmChatAdapter`；泛型 `LlmSemanticProvider<A>` 组合 prompt/schema/parse 一次写成。
- `tests/contract.rs`：两 adapter 过同一场景（成功/拒绝/schema-invalid/截断/限流/超时/
  probe），核心断言 `drafts[0] == drafts[1]`（异构 wire → 相同领域输出）。

### Slice 2 — 用例 + 安全存储 + 诚实降级

- `record_llm_judgment` / `judge_semantic_attempt`：身份 fingerprint/版本/快照 hash/3.11
  validator 全部服务端持有；错误一律不写 judgment。
- `SecretStore` trait + `InMemorySecretStore`；schema v36 `llm_provider_profiles`（只存
  auth_ref）+ `LlmProviderProfileRepository` + register/delete-with-secret use case。

### Slice 2b — provider 工厂 + 真实 keychain + HTTP 路由

- `BuiltSemanticProvider`（profile.adapter_kind → 具体 adapter，暴露 as_judge/as_rubric/probe）。
- `KeychainSecretStore`（api-http，security-framework generic password，cfg-gated macOS +
  非 macOS 显式 unsupported）。
- 四路由：`GET/POST /v1/llm/providers`、`GET/DELETE /v1/llm/providers/{id}`、
  `POST .../{id}/probe`、`POST .../{id}/judge`；响应用 secret-free `ProviderProfileView`；
  OpenAPI v1.yaml 补齐路径与 schema。

### Slice 3 — Flutter 最小设置 UI（AI providers）

- 手写 DTO + fixture 契约测试（ADR 0014）；`LocalApi` 四方法；自包含 `LlmProviderSettings`

## Key Decisions（详见 ADR 0022）

1. **两层 seam**：wire（`LlmChatAdapter`）与 application（Semantic*Provider）分离，
   `LlmSemanticProvider<A>` 一次写成语义逻辑——换 adapter 语义不变即中立性证明。
2. **draft-not-domain-type**：provider 只返内容草稿，身份/版本/hash/validator 服务端持有，
   vendor 层永不成为第二身份写者（守 ADR 0021 四层分离）。
3. **架构照 rust-genai 中立-类型派，拒绝 LiteLLM 归一 OpenAI wire**（踩 final §7.1 红线）。
4. **能力 = 带 provenance 的 claim；本地 endpoint 必须 probe**（Ollama 陷阱）——严于所有远端参考。
5. **密钥 = OS keychain + opaque auth_ref**——严于 genai(env)/aichat(明文)。
6. **WritingFeedbackProvider 降范围**：dictogloss/summary 经 SemanticJudgeProvider 判，
   等 3.15 揭示真实形状（§3.6 seam 纪律）。
7. **无显示资格**：LLM 判定存为 heuristic_proxy，不写 observation/projection，不进 surface。
