## Main 底盘审计与 authority 裁决

- 当前 schema 为 v43。`lexical_capability_states` 已分 projection/override，history 记录层可复用；
  但 listening observation 仍会同步直写 `listening-projection-v1`，非 listening 的旧 upgrade
  confirmation 仍有 transitional direct writer。3.17 必须一次性收口为 proposal → confirmation →
  projection 的唯一长期 writer，不再允许 observation append 或旧 suggestion 直接改 projection。
- 现有合格 target-level evidence 只有：reading 的用户显式逐词 marking、listening 的既有
  channelized evidence、speaking 的 qualified constructed attempt + corrected literal hit + 用户确认。
  Writing Studio 和 3.16 只有 immutable learner attempt/self-assessment；它们没有 lexical target
  confirmation，不能为排期制造 writing lexical observation/projection。Writing 本阶段必须产出独立
  `insufficient_evidence` 资格裁决并保持 unassessed。
- 3.12.1 已取消；3.12.2 的 LLM judgment 获得的是可显示、可纠正 `heuristic_proxy` 资格，不是
  独立 projection 资格。它最多作为 provenance 完整且未被 adjudication 判无效的 supporting
  evidence，且不能单独产生 acquired。
- 3.16 `UserSentencePattern` 与 speaking/writing attempts 保持独立 durable asset/facts。本阶段只读
  handoff 用于来源解释，不把 pattern 变成 lexical target，不泛化 `FocusTarget`，不迁移 Hunting List。
- Cross-modal review 先做 lexical capability gap 的读侧候选与 typed launch contract；Review 编排
  不写 attempt/judgment/observation。来源必须回到 observation/source attempt 或 immutable snapshot。
- 历史重投影新增显式 rebuild；算法升级只新增/替代 proposal，不重写 observation、rubric、judgment、
  personal-expression attempt、override 或 capability history。既有 projection 保留，直到用户确认新 proposal。

## Phase 3.13.5 基线

- Cross-modal Review 是**资产驱动旅程**，由首页到期资产/复习入口进入，不是内容通道，
  也不占用内容工作台常驻面板。
- ReviewCard 只负责呈现可追溯目标与选择合适练习；本阶段 v1 以 typed review kind、target、
  source snapshot、词条详情跳转与返回队列收口编排契约，不复制既有 Studio 生命周期；各 Studio
  的完整任务 deep link 只有在对应住户具备稳定入口后才能接入。
- 完成/中退回到资产队列并保留任务阶段；若原媒体存在可恢复内容现场，若媒体缺失则使用
  snapshot 降级，不把来源缺失误判为学习失败。
- projection 是独立深模块：interface 输入版本化 evidence window，返回可解释 proposal；
  writer、阈值、replay 和 override 保护藏在 implementation，不把算法细节泄漏给 UI/Coach。

## Objective

在 reading/speaking/writing 已积累真实 attempt 和 observation 后，分别建立可解释、版本化、
确认门禁的 projection/suggestion，并让复习能针对“能认不能产出”等跨通道 gap 选择任务。

## User Value

> “这个表达我读听都认识，但两次复述都没说出来。系统没有静默判我‘不会’，而是建议
> 做一次情境接话；我确认后，它进入合适的复习卡，而不是继续给我听音识词。”

## Scope

### In

- Reading / Speaking / Writing 各自独立 evidence audit：任务强度、assistance、不同语境、
  延迟保持、用户 adjudication、LLM validation class。
- 每通道独立 projection proposal：版本化纯函数、writer exclusivity、窗口/阈值依据、
  confirmation gate；证据不足允许长期保持 unassessed。
- LLM judgment 只有在 3.12.1 获得相应用途资格且未被用户纠正为无效时才作为 supporting
  evidence；不单独产生 acquired。
- Cross-modal gap read model：read/listen/speak/write 的已评估组合，不把 unassessed 当失败。
- ReviewCard 扩展：reading comprehension、constructed speaking、writing reconstruction、
  personal pattern reuse；卡型仍尽量读侧派生。
- 目标建议与用户确认：升级、降级、加入专项复习均不静默覆盖 override。
- Review queue 与内容工作台通过 typed launch/return context 连接，不直接操作各 Studio 内部状态。
- 历史重投影和 algorithm version 迁移策略；旧 evidence 不重写。

### Out

- 一个跨四通道的综合等级或 CEFR 分数。
- 用 speaking/writing 成功隐式推出其他通道 acquired。
- 未经研究/QA 的统一阈值。
- Dashboard 大改（3.18）。

## Exit Signal

- Reading、speaking、writing 每个通道都有独立资格报告：证据充分者建立经人工 QA 的
  proposal → user confirmation → projection 路径；证据不足者记录不建算法的结论并保持
  unassessed。完成不要求三个通道都被强行投影，但要求三个通道都被诚实裁决。
- 用户能从一个 cross-modal gap 看到正确 review kind，进入可追溯词条目标并回到原队列；完整
  Studio deep link 不作为缺少稳定住户入口时的虚假 exit 条件。
- 所有结论可展开看到 attempt/observation/rubric/judgment/adjudication。
- 换 projection version 不改写历史 evidence 或 user override。
- 从资产队列进入目标详情并返回原卡，且不复制任务生命周期实现；未来 Studio deep link 必须
  复用相同 typed launch/return context。

## Guardrails

- Phase 不是“把四个状态填满”；诚实 unassessed 优于虚假完整。
- LLM source 与 validation class 正交，provider 品牌不进入投影规则。
- 不建立综合分；通道之间无强制蕴含。
- Review 负责编排，不成为新的 attempt/judgment/observation writer。
