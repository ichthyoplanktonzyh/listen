# Phase 3.6.1 — Sense Folders

**Status:** COMPLETE  
**Created:** 2026-07-10  
**Prerequisite:** Phase 3.6 Listening Dictionary MVP (complete)

## Goal

Add a minimal, durable sense layer to the listening dictionary so a learner can
create a local sense folder under a lexical entry and group selected personal
media occurrences beneath it. The feature validates the sense boundary needed
to consume future SceneLex content without making SceneLex or automatic word
sense disambiguation a runtime dependency.

## Product decision

The local **sense folder** is the identity authority. An external source (for
example, a future `scenelex:reluctant-01`) may be stored as an optional
alignment reference and display annotation, but may never replace or silently
merge a user's local folder identity.

The existing word/phrase-level `LexicalEntry` remains the authority for high
frequency surfaces: subtitle highlighting, vocabulary filtering, corpus search,
and the compact four-channel capability summary. Sense folders are a dictionary
detail-only organization layer in this phase.

## In scope

1. Durable `LexicalSenseFolder` domain object with a user-owned ID, lexical
   entry parent, editable label/definition/gloss, optional external source
   reference, and timestamps.
2. SQLite schema v30 storage and application repository/use cases for create,
   list, update, delete, and occurrence assignment/unassignment.
3. Additive HTTP/OpenAPI/Dart contracts for the above operations.
4. Dictionary-detail UI to create/edit/delete a folder and assign/unassign an
   occurrence; folders show their assigned listening slices while unassigned
   slices remain complete and first-class.
5. Focused migration, persistence, application/API, contract, and Flutter
   tests.

## Explicit non-goals

- No SceneLex API, resource package, media rendering, download, or playback
  integration. Only an opaque optional external reference seam is added.
- No automatic sense disambiguation or mandatory classification. New and
  existing occurrences stay unassigned unless the learner acts.
- No sense-level capability profile, evidence projection, review scheduling,
  subtitle highlighting, vocabulary filters, graph view, or global search.
- No mutation or historical re-attribution of `LearningObservation`; assigning
  an occurrence only creates/removes the folder-to-occurrence organization edge.
- No change to `LexicalEntry` naming or to Construction identity (ADR 0020).

## Data model

```text
LexicalEntry (existing, word/phrase-level authority)
  ├── LexicalOccurrence (existing, may remain unassigned)
  └── LexicalSenseFolder (new, user-owned optional organizer)
        └── lexical_sense_folder_occurrences (new many-to-many edge)
```

An occurrence may be assigned to at most one folder of its parent entry in this
phase. This keeps grouping legible and avoids representing automatic WSD as if
it were confirmed user knowledge. The database enforces parent-entry agreement.

## Implementation slices

### Slice 0 — contracts and migration

- Add domain types and validation.
- Add schema v30 tables/indexes plus migration and migration coverage.
- Extend the `LearningAssetRepository` boundary without changing existing read
  models or hot-path capability APIs.

### Slice 1 — service and HTTP

- Implement application use cases and error behavior.
- Add REST routes and OpenAPI/Dart DTO contracts.
- Verify an occurrence cannot be assigned across lexical entries and cannot
  appear in two folders of the same entry.

### Slice 2 — dictionary-detail workflow

- Show optional folders above/beside the ordinary occurrence list.
- Support learner-created labels and manual assignment from an occurrence.
- Keep unassigned occurrences visible with no “incomplete” treatment.

### Slice 3 — verification and closeout

- Run focused Rust, contract, and Flutter checks; execute the smallest relevant

- Update project active memory and write a closeout only after all scope is
  complete; this phase document then freezes.

## Acceptance criteria

- A learner can create, rename and delete a local sense folder for a word or
  phrase without affecting the lexical entry or its existing learning history.
- A learner can manually move an occurrence into or out of one folder; other
  occurrences retain their current behavior.
- Entry-level capability summaries and existing practice/review evidence are
  unchanged by folder operations.
- A future external content identity can be attached as metadata but no external
  system has write authority over the folder.
- Existing database upgrade succeeds from v29 and all folder data survives
  reopen/round-trip.
