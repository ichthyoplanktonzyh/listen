# Phase 4.0 Plan: yt-dlp Download Manager

状态：PLANNED

上游输入：GitHub 开源 yt-dlp GUI 项目调研、UX 讨论记录

## Objective

将 yt-dlp 下载从主页面零散状态条升级为完整的独立下载管理功能。下载管理作为首页左侧
侧边栏"我的学习"区的一个独立页面（类似词汇本/复习），提供从 URL 输入、格式选择、
队列管理、下载执行到历史记录的完整生命周期管理。

## User Value

> "粘贴一个 YouTube 播放链接，选好清晰度和格式，放在后台下载。下载完成后看到缩略图，
> 点一下就能打开播放。所有下载历史都在，可以随时找到之前下载的内容。"

用户不再被主页面的下载进度条干扰，获得专门的下载管理空间，完整掌控下载任务。

## Scope

### In

- **侧边栏入口**：在首页左侧 `_HomeSidebar` 的"我的学习"区新增"下载管理"条目，
  点击 `Navigator.push` 打开 `DownloadManagerScreen`。
- **URL 输入与格式选择**：
  - 粘贴 URL → yt-dlp `--dump-json` 解析元数据 → 展示标题/时长/缩略图预览。
  - 格式选择：展示可选分辨率+编码+文件大小，支持视频/音频模式切换。
  - 播放列表：识别列表链接，解析后逐项展示，可全选/单选下载。
- **字幕下载**：下载选项内嵌字幕选择（语言/格式），优先选文本字幕（SRT/VTT）。
- **下载队列管理**：
  - 多任务排队下载，支持可配置并发数（默认 1，上限 3）。
  - 每项显示实时进度（百分比/speed/ETA/文件大小）。
  - 支持取消单任务、全部暂停/恢复、失败自动/手动重试。
  - 队列持久化：应用重启后未完成的任务可恢复（yt-dlp `--continue` 天然支持断点续传）。
- **下载历史**：
  - 已完成任务持久化记录（本地 JSON/轻量存储，不走 SQLite 以免污染学习数据 schema）。
  - 每条记录：标题、URL、格式、文件大小、完成时间、保存路径。
  - 操作：打开播放、在 Finder 中显示、删除记录（可选择同时删除文件）、重新下载。
- **缩略图展示**：下载列表中每项显示视频缩略图（从 yt-dlp 元数据获取 URL 后本地缓存）。
- **Cookie 管理**：支持导入 cookies.txt 文件，用于访问受限内容。设置页中配置路径。
- **从首页"Open URL"选择 Download 的整合**：当前 `OnlineSourceDialog` 中若选
  "Download Local"，改为跳转到下载管理页面并自动填入 URL，不再在主页面显示进度条。
- **移除主页面 DownloadStatusBar**：`main.dart` 中的 `_downloadStatusBar` 及其相关
  代码全部移除，下载状态只在下载管理页面展示。

### Out（Non-goals）

- 定时下载（与学习应用定位不符，无常驻后台）。
- 系统托盘/后台通知（按 UX 讨论共识不需要）。
- 应用内代理配置（继承系统代理即可，边缘需求）。
- 视频元数据嵌入（title/description/chapter 等嵌入文件，对学习管线无价值）。
- 硬件加速压缩（Phase 2 候选，首发不包含）。
- Cookie 浏览器自动导入（首发仅支持 cookies.txt 文件导入，浏览器导入后续迭代）。

## Dependencies

- 无 Rust 后端依赖，纯 Flutter 侧功能。
- 复用现有的 `ExternalTools`、`OnlineMediaDownload`、`DownloadController` 基础结构。
- yt-dlp / ffmpeg 路径已通过 `SettingsController` 配置，无需新增。

## Exit Signal

- 从首页侧边栏"下载管理"点击进入管理页面。
- 粘贴 YouTube URL → 解析元数据 → 选择格式 → 加入队列 → 实时进度 → 完成。
- 播放列表 URL 解析为多个视频，可逐项选择下载。
- 下载完成后在列表中看到缩略图，点击"打开"播放视频。
- 所有已完成任务在重启应用后仍然可见。
- 超过并发数的任务自动排队，前一任务完成后自动开始下一任务。
- Cookie 文件配置后能成功下载受限内容。
- 主页面不再显示任何下载状态条。
- **独立可用**：下载管理器作为纯工具页，与 3.x 学习管线无耦合。

## Guardrails

- 下载管理是独立工具页，不依赖 3.x 学习管线的任何组件。
- 不修改 Rust 后端代码。
- 不引入新的外部依赖包（纯 Flutter 标准库 + 现有项目依赖）。
- 队列持久化使用本地 JSON 文件，不污染学习数据的 SQLite schema。
- 缩略图缓存按 LRU 清理，避免无限占用磁盘空间。
- 并发数硬上限为 3，防止过多 yt-dlp 进程耗尽系统资源。
- 已有 `OnlineMediaDownload` 的进程管理逻辑不重构，只扩展。
- 入口整合修改 `openOnlineMediaFlow()` 时不影响"Play Online"路径。
