## Slice 0 技术裁决

- `harper-core` 当前公开 end-to-end API由 `PlainEnglish -> Document::new_curated ->
  FstDictionary::curated -> LintGroup::new_curated -> Linter::lint` 组成。
- `Lint` 的 span 是字符（Unicode scalar）范围，和 3.11 `ResponseSpan` 口径一致，但必须由 adapter
  复制到项目类型；`LintKind`、suggestion 枚举与 priority 不成为持久 schema 的直接类型。
- Harper 只产生语言表面 finding。内容完成与信息遗漏继续来自固定 `SemanticRubric` + 用户自评；
  3.12.1 未资格时不显示 LLM judgment。
- Durable finding identity 必须绑定 attempt/revision、文本 hash、项目 category/span/message 与
  provider/version；不能使用 Harper 明示跨版本不稳定的 `spanless_hash`。
- 实装固定 `harper-core = 0.40.0`。最新 `2.5.0` 在仓库当前 Rust 工具链的上游
  `then_kind_any` 函数项数组处无法编译，`0.65.0` 又引入 Brill/Burn 大型依赖树；`0.40.0`
  保留本阶段所需 curated Document/LintGroup、span/kind/suggestion/message/priority API，focused
  adapter test 通过且不把 Harper 类型泄漏进领域层。
