# Phase 3.15 Manual QA: Writing Studio v1

状态：OWNER QA PENDING（代码与自动化已完成；不在本任务操控 owner GUI）
日期：2026-07-16

本清单只覆盖自动化无法证明的真实内容、窄窗口可用性、进程重启恢复和音频焦点。任意一段带
英文字幕的本地新闻与一段短对话即可；不需要配置 LLM provider。

## 最小准备

1. 打开含英文字幕的真实媒体，停在一个约 30–90 秒、信息完整的段落；记住主播放器位置。
2. 保持主播放器播放一次后切入 Writing，验证进入任务会暂停且不改变当前位置。
3. 准备一句有明显冠词、拼写或标点问题的英文，用于请求本地 Harper feedback。

## A. 摘要与观点回应

1. 从当前内容切到 Writing。确认没有独立 Studio 首页；默认来源是当前播放位置所在段落。
2. 依次选择“一句话摘要”“50–100 词摘要”“观点回应”。确认 prompt 与任务切换，草稿互不覆盖。
3. 输入初稿。确认编辑器是视觉主体（宽屏约 ≥60%），来源可折叠，未提交/未请求时没有反馈栏。
4. 保存初稿后先选择“不看反馈，自己修订”，完成一版；确认原文、修订稿和差异均可见。
5. 重新进入同一任务，确认能看到同 rubric 的上次回答作为延迟复写参照，且新提交形成新 attempt。

## B. 按需反馈与用户文本权威

1. 保存一份含明显表面错误的初稿，主动点击“检查语法与拼写”。确认此前不存在反馈占位。
2. 确认右侧先出现固定 rubric 的“意义与任务自检”，其后才是 Harper 语言表面建议；不显示总分、
   写作能力分或内容遗漏的自动判断。
3. 对一条建议选择“采纳思路”，但不要改正文；确认正文不自动变化。随后亲自输入修订并保存。
4. 另一次选择“保留原文”；确认拒绝不会制造失败/负面能力提示。
5. 对 rubric 各点完成 covered/partial/missing 自评并保存；确认结果明确标为用户自评。

## C. Dictogloss 与音频焦点

1. 选择“听后重构”。确认来源原文隐藏；未播放来源前不能提交初稿。
2. 播放来源一次或多次后用自己的措辞重构，保存并修订。确认任务记录实际播放次数，不要求逐字一致。
3. 播放来源期间确认没有第二个声音源；关闭 slice、切到 Reading/Listening/Speaking 或退出 Writing，
   主播放器位置保持不变且绝不自动播放。

## D. 草稿恢复、来源边界与窄窗口

1. 输入未提交草稿，等待至少 1 秒后完全退出并重启应用；返回同一媒体、段落和任务，确认草稿恢复。
2. 提交该草稿后再次重启，确认 scratch 不再恢复为未提交文本；历史 attempt 仍可见。
3. 在无字幕媒体中确认 Writing 不可用且说明需要 transcript；不得进入空白 Studio。
4. 缩窄窗口并覆盖 A/B 流程：header 可换行、来源可折叠、编辑器和反馈区可滚动，无横向/纵向溢出，
   不出现 bottom sheet、固定三栏或多阶段 dialog。

## 通过口径

- A–D 无阻塞缺陷；反馈可以为空，但必须诚实显示“本地规则未发现问题”，主链路仍可自主修订。
- 用户原文永不被 provider 静默改写；接受必须由用户亲自输入并保存新的 immutable attempt。
- 无 LLM/judge 时摘要、观点回应、dictogloss、版本保存、rubric 自评和本地表面反馈均可完成。
- 任何通道切换只恢复位置、不自动播放；Writing v1 不写 capability projection。
