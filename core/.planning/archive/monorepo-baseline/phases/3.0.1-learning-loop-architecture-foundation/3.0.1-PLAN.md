> recording 持久化和 dashboard 聚合属于后续 vertical slice。

## Objective

先把 Phase 3.0 的学习行为架构立起来，让后续 cloze、听写、字幕渐隐、SRS、
YouGlish-like 搜索、L1-aware diagnosis、shadowing 和 dashboard 共享同一套事实模型。

目标不是一次性实现所有功能，而是让第一条真实学习 slice 能端到端写入：

```text
PracticeAttempt
  -> LexicalObservation / ReviewItem / LearningEvent
```

## Proposed Deliverables

### 1. Domain Model Foundation

新增或规划以下 domain model：

- `PracticeSession`
- `PracticeItem`
- `PracticeAttempt`
- `PracticeKind`
- `PracticeTarget`
- `PracticeEvaluation`
- `ReviewItem`
- `ReviewSchedule`
- `ReviewAttempt`
- `LearningEvent`
- `CorpusOccurrence`
- `PlayableSegment`
- `ContentDifficultyProfile`
- `LearnerProfile`
- `L1L2DifficultyProfile`
- `RecordingAsset` / `ShadowingComparison`（可只留设计，不一定第一批实现）

Acceptance:

- 模型能表达 cloze 和 chunk dictation。
- 模型能锚定 `LexicalEntry`、`SubtitleSentence`、WordTimeline / ChunkTimeline 引用。
- 模型不会把 practice / review 状态塞进 `LexicalEntry`。

### 2. Repository And Persistence Boundaries

新增或规划 application repository traits：

- `PracticeRepository`
- `ReviewRepository`
- `LearningEventRepository`
- `CorpusIndexRepository`
- `DifficultyRepository`
- `LearnerProfileRepository`
- `RecordingRepository`

Acceptance:

- `AppServices` 通过窄 trait 编排，不新增 god repository。
- SQLite schema 能持久化第一条 slice 的 practice attempts、review items 和 learning events。
- 派生数据与权威数据边界清楚。

### 3. Application Services

新增或规划 application modules：

- `practice`
- `review`
- `learning_events`
- `corpus_search`
- `difficulty`
- `learner_profile`
- `shadowing`

第一批真正实现时优先落地：

- build cloze practice item;
- build chunk dictation practice item;
- evaluate submitted text;
- generate lexical observations from failed anchors;
- create optional review item;
- append learning event.

Acceptance:

- 练习失败只生成 observation / review evidence，不静默修改全局 `LearningStatus`。
- evaluation 输出可解释 token diff。
- application DTO 不泄漏 UI-specific state。

### 4. API Boundary

为第一条 slice 设计并实现最小 API：

```text
POST /v1/practice/items
POST /v1/practice/attempts
GET  /v1/practice/attempts/{id}
POST /v1/review/items
GET  /v1/stats/learning/summary   # 可后置，只需确认边界
```

后续再扩展：

```text
/v1/corpus/search
/v1/difficulty/*
/v1/learner-profile
/v1/recordings
```

Acceptance:

- OpenAPI 与 route parity 同步。
- generated client 更新。
- Contract validation 覆盖新 routes。

### 5. Flutter Controller Boundary

新增或规划：

- `StudyModeController`
- `PracticeController`
- `ReviewController`
- `CorpusSearchController`
- `LearningStatsController`
- `ShadowingController`
- `LearnerProfileController`

第一批真正实现时优先：

- `PracticeController` 管理当前 cloze / dictation item、用户输入、提交状态和 evaluation。
- `StudyModeController` 管理精听/泛听和字幕渐隐模式的 typed state。

Acceptance:

- 不把练习状态塞回 `main.dart`。
- controller 使用 typed DTO 和 generation guard。
- UI 能显示一次 practice attempt 的结果。

### 6. First Vertical Slice

第一条 slice：

```text
current chunk
  -> create cloze or dictation item
  -> submit answer
  -> evaluate
  -> persist attempt
  -> write observations
  -> optionally create review item
  -> append learning event
```

建议优先顺序：

1. Chunk dictation，因为它验证 chunk target、text evaluation 和 attempt persistence。
2. Cloze，因为它验证 lexical anchors、`known_recognized` blanking 和 observation generation。

Acceptance:

- 用户可以对当前 chunk 完成一次 dictation 或 cloze。
- 结果持久化，重启后可读取。
- 失败词不会自动改全局状态。
- 可从 result 看到哪些 token 错误、漏掉或正确。

## Non-Goals

- 不实现完整 SRS 算法。
- 不实现 Anki export。
- 不实现 dashboard UI。
- 不实现录音和 shadowing。
- 不实现 corpus search 索引。
- 不实现 L1-aware profile 具体规则。
- 不依赖 connected-speech marker 作为第一条 slice 的前置条件。
