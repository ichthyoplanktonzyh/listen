# Phase 3.0.1 Context: Learning Loop Architecture Foundation

状态：BACKEND FOUNDATION COMPLETED

> 2026-06-28 更新：后端 learning-loop foundation 已落地，见 `3.0.1-CLOSEOUT.md`。

## Why This Phase Exists

Phase 3.0 已确立英语听力学习闭环方向：

```text
真实输入
  -> 可理解度判断
  -> 诊断
  -> 主动练习
  -> 复习巩固
  -> 进度反馈
  -> 回到真实输入
```

这个闭环会引入一批与 Phase 2 不同性质的对象。Phase 2 的核心资产是媒体、字幕、词汇、
WordTimeline、ChunkTimeline、PhoneTimeline、sound analysis 和 diagnosis。Phase 3.0 的核心新增资产是：

> 用户做了一次什么学习行为，结果如何，这个结果如何影响 observation、review、difficulty、
> corpus search、L1-aware diagnosis 和 dashboard。

如果不先把学习行为建模为一等对象，后续 cloze、听写、字幕渐隐、SRS、YouGlish-like 搜索、
shadowing 和统计很容易各自长出一套局部数据模型，最终导致：

- dashboard 从 UI 状态和历史表里临时拼统计；
- SRS 与词汇资产耦合过紧；
- cloze / dictation / shadowing 的结果无法统一复用；
- 个人语料搜索无法召回“用户失败过的真实片段”；
- L1-aware 专项练习缺少稳定证据来源；
- Anki 互操作反过来污染 LLPlayerNext 自己的权威学习资产模型。

Phase 3.0.1 因此先建立学习行为架构地基，再进入具体学习功能实现。

## Current Architecture Inputs

Phase 2.18 后，当前 codebase 已经具备一批适合承接 Phase 3.0 的支点：

| Existing asset | Why it matters |
|---|---|
| `LexicalEntry + LexicalUnit + LearningStatus` | 语言无关词汇学习资产和听力状态 |
| `LexicalObservation` | 语境内识别成功/失败可以不静默覆盖全局状态 |
| WordTimeline | 词级播放窗口、cloze token anchor、dictation diff |
| ChunkTimeline | chunk replay、chunk dictation、chunk shadowing 的默认学习单位 |
| PhoneTimeline / `sound_analysis` | connected-speech marker、声音线 evidence、后续发音对比 |
| Language profile | L2 能力矩阵和降级边界 |
| LANG-009 seam | L1-aware diagnosis 的入口 |
| Typed Flutter controllers | 练习/复习/统计 controller 可以按既有模式接入 |

但当前还缺少一组新的一等边界：

- Practice：用户做了一次 cloze / dictation / shadowing / subtitle fade。
- Review：一个词、chunk、真实例句或失败片段进入复习调度。
- Learning event / activity ledger：统计和 dashboard 的事实来源。
- Corpus search：个人真实语料索引和可播放片段召回。
- Difficulty：可理解输入和 i+1 推荐信号。
- Learner profile / L1-L2 profile：母语背景与目标语言差异。
- Recording：shadowing 录音文件、对齐和对比结果。

## Product Rule

Phase 3.0.1 的产品规则：

> 先让一次真实练习成为可保存、可解释、可复习、可统计的事实。

第一条 vertical slice 建议使用：

```text
当前 chunk
  -> cloze / chunk dictation
  -> PracticeAttempt
  -> LexicalObservation / ReviewItem / LearningEvent
  -> 后续 stats / corpus recall / L1-aware specialty
```

这个 slice 能验证大多数 Phase 3.0 架构假设，但不依赖复杂发音评分，也不依赖在线内容聚合。

## Scope

### In Scope

- 定义 Practice / Review / LearningEvent / Corpus / Difficulty / LearnerProfile 的边界。
- 定义这些对象与 `LexicalEntry`、`LexicalObservation`、WordTimeline、ChunkTimeline、PhoneTimeline 的关系。
- 定义 repository、API route、Flutter controller 的放置原则。
- 定义 cloze + chunk dictation 作为第一条 implementation slice。
- 定义哪些数据是权威事实，哪些是派生缓存。
- 定义 SRS 与 Anki 互操作的边界。
- 定义 L1-aware diagnosis 不写死 UI 文案的架构原则。

### Non-Goals

- 不实现完整 Phase 3.0 功能集。
- 不设计复杂发音评分模型。
- 不设计大而全推荐系统。
- 不把 Anki 数据模型作为内部权威模型。
- 不把 dashboard 先做成 UI 页面。
- 不把 L1-aware explanation 写成固定中文文案。
- 不改变 Phase 2.17 真实声音线 QA 的前置地位。

## Relationship To Phase 2.17

Phase 3.0.1 可以与 Phase 2.17 并行推进，因为它主要建立学习行为和数据边界。

但依赖 sound-line marker 的高风险学习功能仍应等待 Phase 2.17 的真实媒体 QA 决策：

- connected-speech 专项练习；
- sound marker 驱动的复习项；
- phonetic evidence 驱动的 shadowing 反馈；
- raw CTC mismatch 相关高级诊断。

第一条 cloze + chunk dictation slice 可以优先依赖 WordTimeline / ChunkTimeline / LexicalEntry，
避免被真实声音线 QA 阻塞。
