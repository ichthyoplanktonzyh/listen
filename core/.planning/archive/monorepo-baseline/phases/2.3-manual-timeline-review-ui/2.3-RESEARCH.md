# Phase 2.3 Research: 人工校对 UI 相关开源项目与研究调研

更新时间：2026-06-20

## 调研范围

针对 Phase 2.3「句子级 Word Timing Inspector」的需求，调研以下方向：

1. 语音标注与强制对齐审查工具（Praat, ELAN, MFA, Gentle, WebMAUS）
2. 字幕编辑工具的波形/时序调整功能（Aegisub, Subtitle Edit 等）
3. 语音转录审查 UI（WhisperX 生态、BBC react-transcript-editor 等）
4. Flutter/Dart 音频波形可视化方案
5. 人工校正强制对齐的学术研究
6. 与本项目的适配性分析

## 一、现有工具 UI 模式总结

### 1.1 主流语音标注工具的 UI 范式

几乎所有专业语音标注工具（Praat, ELAN, EMU-webApp, Audacity）都采用同一范式：

```
┌──────────────────────────────────────────┐
│  波形图 (Waveform) — 振幅随时间变化        │
├──────────────────────────────────────────┤
│  语谱图 (Spectrogram) — 频率内容          │  ← Phase 2.3 可省略
├──────────────────────────────────────────┤
│  标注层 (Annotation Tiers) — 带标签的区间  │
└──────────────────────────────────────────┘
```

**核心交互模式：**
- **拖拽边界线** 是调整时间边界的主要手势
- **选中区间变色** 提供即时视觉反馈（Praat: 黄色, ELAN: 蓝色框）
- **Tab 键播放选中区间** 用于听觉校验
- **吸附到过零点 (zero crossing)** 提供精确边界放置
- **Shift+拖拽** 同时移动所有层的边界

### 1.2 关键工具的详细分析

| 工具 | 词级支持 | 波形图 | 拖拽调整 | 非破坏性编辑 | 适用性 |
|------|---------|--------|---------|-------------|--------|
| **Praat** | ✅ 音素/词级 | ✅ 波形+语谱图 | ✅ 拖拽边界 | ❌ 直接覆盖 | 行业标准，但需导出 TextGrid |
| **ELAN** | ✅ 多层标注 | ✅ | ✅ ALT+拖拽 | ❌ | 父子层传播机制值得参考 |
| **EMU-webApp** | ✅ | ✅ 波形+语谱图 | ✅ Shift+拖拽 | ✅ 版本保存 | **最接近需求的 Web 工具** |
| **MFA** | ✅ 词/音素 | ❌ 无内置 UI | ❌ | ❌ | 仅 CLI，需配合 Praat |
| **Gentle** | ✅ 词级 | ✅ Web 波形 | ❌ 仅供查看 | ❌ | 查看用，不支持编辑 |
| **Aegisub (卡拉OK)** | ✅ 词/音节 | ✅ 波形 | ✅ 拖拽句柄 | ❌ 仅 undo/redo | **最接近需求的桌面工具** |
| **wavesurfer.js** | 通过 Regions | ✅ Canvas 波形 | ✅ 拖拽区域 | ❌ | Web 端最佳波形+标注参考 |
| **Peaks.js (BBC)** | 通过 Segments | ✅ 双视图 | ✅ | ❌ | 专业 DAW 级波形组件 |

### 1.3 最佳参考工具

**Aegisub 卡拉OK模式** — 与本需求最接近的桌面参考：

- 逐词甚至逐音节的时序调整，每个单词有独立波形操作句柄
- 快捷键: `s` 播放, `d` 播放最后 500ms, `q` 播放开始前 500ms, `g` 提交并跳转
- Lua 脚本 (Automation 4 Lua) 可自定义效果
- **局限性**: 无版本化修订历史，仅 undo/redo；非移动/Flutter 框架

**EMU-webApp** — 最接近需求的 Web 工具：

- 浏览器内完整标注编辑，支持波形图+语谱图+标注层
- 自动预选最近边界 (蓝色高亮)
- `Shift+拖拽` 调整边界，`+`/`-` 微调
- `c` 键播放选中片段
- **局限性**: 面向语言学研究，非字幕编辑场景；需要 R 工具链

**wavesurfer.js Regions 插件** — Web 端波形+标注最佳参考：

- `region.play()` / `region.playLoop()` 播放选中区域
- `region-update-end` 事件 → 拖拽结束后可保存
- 可配合 CSS 自定义手柄样式
- **局限性**: 连续词标注时需手动同步相邻区域边界

## 三、Flutter/Dart 音频波形可视化方案

### 3.1 可用包对比

| 包名 | 波形渲染 | 播放控制 | 交互式 | 维护状态 | 适用性 |
|------|---------|---------|--------|---------|--------|
| **sonix** | ✅ 柱状/波形 | ✅ seek | ✅ onSeek 回调 | 活跃 | **推荐用于波形数据生成** |
| **audio_waveforms** (Simform) | ✅ | ✅ 内置播放 | ✅ 手势拖动 | 活跃 | 功能最全但集成困难 |
| **flutter_audio_waveforms** | ✅ 4种样式 | ❌ | ❌ | 停更 (2023) | 仅 UI 渲染参考 |
| **waveform_visualizer** | ✅ 多样式 | ❌ | 部分 | 活跃 (2025) | 轻量级渲染方案 |
| **just_waveform** | ✅ (数据提取) | ❌ | ❌ | 活跃 | 仅波形数据提取 |

### 3.2 关键发现

**没有任何现有 Flutter 包原生支持词级分段叠加 (word boundary overlay)。**

所有现有包的共同局限：
- 仅渲染波形，不提供区域/分段标注功能
- 没有词边界映射或拖拽调整边界的 API
- 播放同步需自行实现

### 3.4 Rust 端波形数据生成

项目已有的基础设施：
- `hound = "3.5"` 已在 workspace Cargo.toml 中
- `speech-analysis` crate 已使用 `hound` 读取 PCM16 WAV 进行 pause refinement
- application 层已处理 `audio_wav_path`

**推荐方案**: 在现有 `speech-analysis` crate 中添加 ~50 行函数，利用已有 `hound` 依赖生成波形峰值数据，通过 HTTP API 传给 Flutter。

```rust
// 伪代码示意 — 与 pause_refinement.rs 中的模式一致
pub fn compute_waveform_peaks(
    wav_bytes: &[u8],
    target_peaks: usize
) -> Result<Vec<(f32, f32)>> {
    let mut reader = hound::WavReader::new(Cursor::new(wav_bytes))?;
    let samples: Vec<f32> = reader.samples::<i16>()
        .filter_map(Result::ok)
        .map(|s| s as f32 / i16::MAX as f32)
        .collect();
    let window = (samples.len() / target_peaks).max(1);
    Ok(samples.chunks(window).map(|chunk| {
        let min = chunk.iter().cloned().fold(f32::INFINITY, f32::min);
        let max = chunk.iter().cloned().fold(f32::NEG_INFINITY, f32::max);
        (min, max)
    }).collect())
}
```

## 四、人工校正强制对齐的学术研究

### 4.1 量化数据

| 指标 | 数值 | 来源 |
|------|------|------|
| 约束对齐后需校正的词占比 | ~31% | Seifart et al., 2013 (WebMAUS 跨语言评估) |
| 需校正范围 | 14%-69% | 取决于语言和录音质量 |
| 人工标注者间中位差异 | 0-66 ms | 多项研究汇总 |
| 自动标注 vs 人工标注差异 | 30-160 ms | 多项研究汇总 |
| 人机在"坏对齐"上的一致率 | 97.95% (Kappa=0.912) | LREC 2024 |
| MFA vs 人工标注差异 | <25 ms | Nature HSSCOM 2023 (普通话韵律) |
| 自动标注比人工快 | ~20 倍 | Nature HSSCOM 2023 |

### 4.2 常见需校正的情况

1. **无声段** (静音、背景音、填充词) — 边界模糊
2. **多人同时说话** — 对齐器难以区分
3. **文本与音频不匹配** — 录入词与实际说的词不一致
4. **极快语速/极短词** — 功能词、轻读词
5. **非标准发音** — 弱读音节、连音形式

### 4.3 关于修订历史

**重要发现**: 在已发表的所有研究中，**没有任何工具实现继承式/版本化非破坏性修订历史**。现有工具要么直接覆盖原始边界（Praat, ELAN），要么通过文件名约定管理版本（`corpus_v2.TextGrid`）。

**本项目的 `parent_timeline_id` 非破坏性修订模型是设计创新**，在有声学/语音学界尚无先例。

### 5.4 推荐的实现优先级

**高优先级 (Phase 2.3 必须):**
1. 句子级词时序列表 UI（无波形图的纯数据视图）
2. start/end 数字输入 + ±10ms/±50ms 步进按钮
3. 播放当前句/当前词片段校验
4. 保存为 user-adjusted WordTimeline（复用现有 API）

**中优先级 (如时间允许):**
5. 简单波形图叠加（无拖拽，仅可视化）
6. Prev/Next 句子导航
7. 边界校验: start < end, 无倒序, gap/overlap 检测

**低优先级 (推迟到 Phase 2.4 或后续):**
8. 波形图上拖拽调整边界
9. 音素级子视图
10. 语谱图显示

## 七、结论

1. **Phase 2.3 的「句子级 Word Timing Inspector」定位准确** — 先在无波形图的情况下完成数据检查+微调+保存闭环，波形图拖拽可推迟到后续阶段。这与现有工具的演进路径一致（先有 Praat 的数据表格编辑，再有波形拖拽）。

2. **项目的 `parent_timeline_id` 非破坏性修订模型是创新点** — 在所有调研的工具和研究中，没有任何现有方案实现类似的继承式修订链。这是本项目相比学术界和工业界工具的差异化优势。

3. **Flutter 生态缺少词级时序编辑组件** — 需要自行组合 `CustomPainter` 波形渲染 + `WordTiming` 数据映射，但项目已有全部底层数据（WordTiming 模型、Rust 音频处理、播放器集成），不需要引入重型外部依赖。

4. **关键 UI/UX 模式可以直接借鉴** — Praat 的区间选中变色 + Tab 播放、Aegisub 的逐词操作句柄、EMU-webApp 的键盘微调、BBC react-transcript-editor 的数据流设计，都是经过验证的模式。
