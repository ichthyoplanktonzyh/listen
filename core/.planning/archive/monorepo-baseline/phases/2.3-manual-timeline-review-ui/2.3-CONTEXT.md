# Phase 2.3 Context: Manual Timeline Review UI

更新时间：2026-06-20 23:14:44 CST

## Background

Phase 2.2 已经把 LLPlayerNext app 变成 `.lltimeline.json` 资源消费端：

- app 可导入并挂载 LLTimeline JSON v1。
- 字幕资源已经统一为顶层资源概念，覆盖 SRT / WebVTT / ASR 字幕 /
  `.lltimeline.json`。
- 用户可查看当前字幕资源、active WordTimeline、candidate WordTimeline、生产 artifacts
  和 readiness。
- 用户可激活 candidate WordTimeline。
- 播放器词级高亮通过 `trackWordTimings()` 消费 active WordTimeline；没有资源时回落
  legacy word timings。
- 人工复核入口占位已就绪。

Phase 2.3 的任务不是继续扩大生产端 aligner 调研，也不是一次性做出完整音频编辑器。
本阶段要完成消费端最关键的人工校正闭环：

```text
production WordTimeline
  -> user reviews current sentence
  -> user adjusts selected word boundaries
  -> app saves full user_adjusted WordTimeline revision
  -> user revision becomes active
  -> playback highlight and export consume the user revision
```

## Problem

生产端输出的 WhisperX / MFA / MMS_FA timeline 即使整体质量好，仍会有局部词边界需要
人工修正：

- 某个词 start/end 偏早或偏晚。
- 某句局部对齐失败，但整条 timeline 仍可用。
- fallback / estimated timing 需要人工确认。
- 发布学习资源前，需要把最终 WordTimeline 标记为人工复核版本。

如果没有人工校正闭环，Phase 2.4 的 ChunkTimeline 生成会缺少可信的 active
WordTimeline。后续 chunk、phone、sound pattern 等资源也无法明确追溯到“用户确认过的
词级时间轴”。

## Product Decision

Phase 2.3 采用 **句子级 Word Timing Inspector**，暂不实现完整 waveform editor。

波形和拖拽是微调边界的便利手段，不是本阶段的核心产品闭环。它们可以在后续阶段作为
同一 draft model 的增强能力加入，但不应阻塞 `user_adjusted` revision 的保存、激活和
导出。

本阶段推荐工作流：

```text
用户打开字幕资源页
  -> 选择当前 active 字幕资源 / WordTimeline
  -> 点击 Manual Review
  -> 进入当前播放句的 Word Timing Inspector
  -> 微调当前句某些词的 start/end
  -> 试听当前词或当前句
  -> 保存
  -> 创建 user_adjusted WordTimeline
  -> 自动激活
  -> 播放器高亮立即刷新
  -> export 同时保留 production candidate 和 user_adjusted revision
```

## Data Flow

### Read Path

Inspector 需要读取完整 active WordTimeline，而不只是当前句 words：

```text
Timeline Resource Summary active_word_timeline_id
  -> GET /v1/word-timelines/{timeline_id}
  -> source WordTimeline
  -> clone source.words into draftWords
  -> filter draftWords by current sentence_id for the inspector view
```

仍保留现有播放高亮读取路径：

```text
播放器当前词高亮
  -> GET /v1/subtitles/{track_id}/word-timings
  -> AppServices::word_timings_for_track(track_id)
  -> active WordTimeline words if present
  -> legacy sentence word_timings otherwise
```

### Edit Path

用户只编辑当前句，但 draft 必须持有整条 timeline：

```text
source WordTimeline.words
  -> draftWords
  -> current sentence draft rows
  -> user adjusts start/end
  -> local validation
  -> dirty word tracking
```

本地校验至少覆盖：

- `start_ms < end_ms`
- start/end 不越过所属句子的 start/end
- 同一句内相邻 words 不 overlap
- token 顺序不倒序
- duration 不为 0

### Timestamp Precision

WordTimeline 边界时间戳统一使用媒体时间轴上的 **绝对毫秒值**：

- 保存字段固定为 `start_ms` / `end_ms`。
- 单位固定为 millisecond，不使用秒、小数秒、frame index 或相对 offset。
- UI 可以显示为 `mm:ss.SSS`，但编辑和保存必须转换回整数毫秒。
- 人工校对保存的是校正后的绝对边界，不保存“相对父 timeline 的偏移量”作为权威值。
- 若未来加入波形/拖拽，拖拽结果也必须落到同一套 `start_ms` / `end_ms` 毫秒契约。

### Save Path

保存时提交整条 WordTimeline revision，而不是只提交当前句 patch：

```text
POST /v1/subtitles/{track_id}/word-timelines
  parent_timeline_id = sourceTimeline.id
  created_by = "user"
  status = "active"
  algorithm_id = "manual-review"
  algorithm_version = "llplayernext-phase-2.3"
  words = draftWords
```

后端已有 `CreateWordTimeline`、`parent_timeline_id`、`created_by`、
`TimingSource::UserAdjusted`、create/activate/export 路由。本阶段优先复用现有契约，
只补齐 Flutter client、state 和 UI。

## Revision Semantics

Production candidate 必须保持不可变。用户保存时创建新的 revision：

```text
production WordTimeline
  id = timeline-mfa
  created_by = algorithm
  status = candidate / active / archived

user adjusted WordTimeline
  id = timeline-user-xxx
  parent_timeline_id = timeline-mfa
  created_by = user
  status = active
  words = full cloned words + local edits
```

推荐词级标记策略：

- 改动过的 word：`timing_source = user_adjusted`，`provider_id = user`，
  `provider_version = llplayernext-manual-review-v1`。
- 未改动的 word：保留父 timeline 的原始 provider/source/confidence。
- timeline 级别通过 `created_by=user` 和 `metrics_json.review` 表示人工版本。

这样既能证明 active timeline 已经是人工 revision，也能保留每个词的真实来源。

## Scope

1. 从 Timeline Resource Summary / 字幕资源页的 Manual Review 入口进入。
2. 读取 active WordTimeline 完整 words，建立 review draft。
3. 展示当前句 tokens 和 word timing rows。
4. 支持 start/end 数字输入和 `±10ms` / `±50ms` 微调。
5. 支持播放当前句、当前词，试听使用 draft 边界。
6. 支持 Prev/Next sentence 连续校对。
7. 保存为新的 `created_by=user` / `user_adjusted` WordTimeline revision。
8. 保存后自动激活 user revision，并刷新 Timeline Resource Summary 和播放器高亮。
9. 导出 `.lltimeline.json` 时包含 production candidates 和 user revision。

## Non-Goals

- 不在本阶段做完整 waveform editor。
- 不做波形拖拽边界、吸附到过零点、缩放时间轴或语谱图。
- 不做跨句批量拖拽、多轨编辑或音素级编辑。
- 不做自动再对齐 workflow；文本编辑后再对齐可留到后续阶段。
- 不把 WhisperX / MFA / MMS_FA runtime 集成进播放器 app。
- 不覆盖 production candidate timeline。
- 不在本阶段实现 ChunkTimeline 编辑器；那是 Phase 2.4。

## Success Criteria

- 用户能从 active WordTimeline 打开当前句 Word Timing Inspector。
- 用户能查看当前句每个词的 text、start/end、duration、source/provider 和 confidence。
- 用户能微调当前句词边界，并用当前句/当前词试听验证。
- 非法边界会被本地阻止，后端校验失败也有明确错误。
- 保存会创建新的 user-adjusted WordTimeline，不破坏父 production candidate。
- 保存后的 user-adjusted timeline 自动 active，播放器词级高亮立即刷新。
- 用户仍可切回 WhisperX / MFA / MMS_FA 等 production candidate。
- `.lltimeline.json` export 包含原 production candidates 和新 user revision。
