# Phase 2.3 Acceptance And Closeout Standard

更新时间：2026-06-20 23:14:44 CST

## Purpose

本文件定义 Phase 2.3 的验收、回归和收口标准。实现过程中可以把它当成 checklist；
Phase 2.3 完成时，应基于本文件写 `2.3-CLOSEOUT.md`，记录实际 shipped 内容、验证结果和
延期项。

## Required User Journey

Phase 2.3 只有在以下用户旅程完整跑通后才算完成：

```text
Import / activate LLTimeline subtitle resource
  -> open Manual Review
  -> inspect current sentence word timings
  -> adjust one or more word boundaries
  -> hear current word / sentence using draft boundaries
  -> save as user_adjusted WordTimeline
  -> saved revision becomes active
  -> playback highlight reflects the adjusted boundary
  -> export LLTimeline keeps production and user timelines
```

## Functional Acceptance

### Resource Entry

- Manual Review 入口在有 active WordTimeline 时可用。
- 无 active WordTimeline 时入口有明确 disabled / fallback 状态。
- 入口优先打开当前播放句；没有当前句时打开第一句有 word timings 的句子。

### Inspector

- Inspector 显示当前句文本。
- Inspector 显示每个 word 的 text、start、end、duration、source/provider、
  confidence。
- Inspector 支持 Prev/Next sentence。
- Inspector 支持 `±10ms` 和 `±50ms` 微调 start/end。
- Inspector 支持数字输入 start/end。
- Inspector 显示 dirty word 状态。
- Reset sentence 可恢复当前句为 source timeline 边界。
- Cancel 不保存任何修改。

### Validation

- `start_ms >= end_ms` 被阻止。
- word 边界越过句子 start/end 被阻止。
- 同一句 words overlap 被阻止。
- token 顺序倒序被阻止。
- WordTimeline 边界必须保存为整数毫秒 `start_ms` / `end_ms`。
- 保存 payload 必须使用媒体时间轴上的绝对毫秒值，不使用相对 offset。
- UI 显示可格式化为 `mm:ss.SSS`，但不得把毫秒值四舍五入到秒级。
- 后端 validation 失败时 draft 不丢失。
- suspicious gap / very short duration 可以先作为 warning，不阻塞保存。

### Playback Review

- Play current sentence 使用 draft sentence boundary。
- Play current word 使用 draft word boundary。
- 修改 draft 后再次试听能听到新边界。
- 主播放器高亮在保存前不切换到 draft。
- 保存激活后主播放器高亮使用新 active timeline。

### Save And Activation

- Save 创建新的 WordTimeline，而不是覆盖 parent。
- 新 WordTimeline `parent_timeline_id` 指向保存时的 source timeline。
- 新 WordTimeline `created_by = user`。
- 新 WordTimeline `status = active` 或创建后被自动激活。
- 被编辑的 words 使用 `timing_source = user_adjusted`。
- 未编辑的 words 保留父 timeline 的 provider/source 信息。
- Timeline summary 将新 revision 识别为 human reviewed / user adjusted。
- 保存成功后刷新 summaries 和 `trackWordTimings()`。

### Export

- LLTimeline export 包含父 production timeline。
- LLTimeline export 包含 user-adjusted timeline。
- Export 后 active WordTimeline id 指向当前 active revision。
- Import/export round trip 不丢失 parent chain、created_by、status、metrics_json。

## Data Contract Acceptance

Create payload 应符合以下语义：

```json
{
  "parent_timeline_id": "source-timeline-id",
  "created_by": "user",
  "status": "active",
  "algorithm_id": "manual-review",
  "algorithm_version": "llplayernext-phase-2.3",
  "metrics_json": {
    "lifecycle": {
      "human_reviewed": true
    },
    "review": {
      "parent_timeline_id": "source-timeline-id",
      "edited_word_count": 1,
      "reviewed_sentence_ids": ["sentence-id"]
    }
  },
  "words": []
}
```

Word-level semantics:

- Edited word:
  - `timing_source = user_adjusted`
  - `provider_id = user`
  - `provider_version = llplayernext-manual-review-v1`
  - `start_ms` / `end_ms` are absolute integer millisecond boundaries.
- Inherited word:
  - keep parent `timing_source`
  - keep parent `provider_id`
  - keep parent `provider_version`
  - keep parent `confidence`
  - keep parent `start_ms` / `end_ms` exactly unless edited.

## Regression Acceptance

- Candidate WordTimeline activation still works after a user revision exists.
- Archive/delete/export subtitle resource flows from Phase 2.2 still work.
- `trackWordTimings()` still returns active WordTimeline first.
- No-resource fallback still returns legacy timings.
- Existing SRT/WebVTT subtitle resources still work.
- LLTimeline metadata/artifacts persistence from Phase 2.2 still exports.
- App does not require bundled WhisperX/MFA/MMS_FA runtime.


If test names change during implementation, `2.3-CLOSEOUT.md` should record the exact commands that
were run.

## Manual QA Checklist

- Start app with a current debug sidecar, not stale release sidecar.
- Confirm SQLite `user_version` includes Phase 2.2 migrations.
- Open a media item with an imported LLTimeline resource.
- Activate a production WordTimeline candidate.
- Open Manual Review from the resource UI.
- Edit a word boundary in the current sentence.
- Confirm invalid overlap is blocked.
- Play current word.
- Play current sentence.
- Save.
- Confirm a new user-adjusted timeline appears and is active.
- Resume playback and confirm highlight boundary changed.
- Activate original production candidate and confirm highlight switches back.
- Re-activate user revision.
- Export LLTimeline and inspect that both timelines exist.

## Closeout Requirements

Phase 2.3 closeout must include:

- Shipped behavior summary.
- Files/modules changed, grouped by Rust API, Flutter client/state, Flutter UI, tests, docs.
- Exact verification commands and results.
- Manual QA notes.
- Known limitations.
- Deferred waveform/drag work.
- Phase 2.4 handoff notes.

Required `2.3-CLOSEOUT.md` sections:

```text
# Phase 2.3 Closeout: Manual Timeline Review UI

## Status
## Shipped
## Data Contract
## Verification
## Manual QA
## Known Limitations
## Deferred
## Handoff To Phase 2.4
```

## Phase 2.4 Handoff Standard

Phase 2.4 may start when:

- There is a reliable active WordTimeline source after manual review.
- Chunk generation can choose active user-adjusted timeline over production candidate.
- Export can preserve the reviewed WordTimeline.
- The app can still fall back to production/legacy timings when no reviewed timeline exists.
