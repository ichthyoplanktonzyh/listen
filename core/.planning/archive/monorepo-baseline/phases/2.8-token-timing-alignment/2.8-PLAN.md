## Problem Statement

### Whisper BPE ≠ App Tokenizer

Whisper.cpp 使用多语言 BPE 分词器，其 "word" 边界由统计训练决定：
- 英语：BPE ≈ 空格分词 → 与 app 一致（碰巧对齐）
- 中文：BPE 合并高频字序列（"因为我" 可能是一个 token）≠ jieba 分词（"因为"+"我"）
- 日语：BPE 边界 ≠ lindera 形态分析边界

当前 `estimate_word_timings` 完全忽略 whisper 已有的精确时间数据，按字符权重重新分配。

### 韵律不匹配

当前估算统一用字符数加权（长 token → 更长时间），这对 stress-timed 英语合理，
但对 syllable-timed 中文不准（每字 ≈ 一个音节 ≈ 近似等时长）。

## Steps

### Step 1: Token Timing Alignment Utility

在 `speech_analysis` 或 `subtitle_core` 中实现通用对齐函数：

```
fn align_timings(
    source_segments: &[(String, u64, u64)],  // whisper BPE: (text, start_ms, end_ms)
    target_tokens: &[SubtitleToken],          // app tokenizer output
) -> Vec<TokenTiming>
```

算法：按字符重叠比例将 source 时间区间拆分到 target token 上。
语言无关——纯字符级时间插值。

### Step 2: Transcription 导入时执行对齐

在 whisper 转写完成后、存储 word timings 之前，调用对齐函数：
- 读取 whisper JSON output 中的 word-level timestamps
- 读取 subtitle track 的 token 列表
- 对齐后存储为正确 token_index 的 `WordTiming`

### Step 3: 韵律感知估算 Fallback

在 `LanguageLearningProfile` 中增加 `rhythm` 字段：
- `stress_timed`：字符权重（当前行为，适用英语/德语）
- `syllable_timed`：等权分配（适用中文/法语/西班牙语）
- `mora_timed`：mora 计数权重（适用日语）

`estimate_word_timings` 读取 profile 的 rhythm 选择策略。

### Step 4: lltimeline.json 导入对齐

当用户导入 lltimeline.json 时，如果其中的 word 边界与当前 track token 不匹配，
自动执行 Step 1 的对齐。

### Step 5: 验证

- 中文视频用 whisper 转写 → 词级跳动精确对齐到 jieba 分词
- 英文视频回归正常
- 无 whisper 数据时估算 fallback 对中文更均匀
