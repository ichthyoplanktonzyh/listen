# Phase 2.8 Context: Token Timing Alignment

状态：PLANNED

## 来源

Phase 2.7 用户验证时发现：中文词级跳动能工作但不精确。排查确认原因是 whisper BPE
分词边界与 app jieba 分词边界不对齐。进而讨论了"token"才是语言无关的正确抽象——
不同语言对"最小有意义单元"的编码方式不同（英语 word ≈ 意义单元，中文 word = 多字
组合，日语含形态变化），tokenizer 的职责就是把文本切成该语言的最小有意义单位。

## 用户关键表述

> whisper.cpp 已经可生成词级时间戳了

> 英语因为这个特性可以做到词级高亮，但是中文其实应该不叫词级高亮...应该叫 token
> 高亮更加合理。对于其他语言应该也是适用的。

> 对于词级跳动的降级模式，如果有精确时间轴那么就消费精确时间轴，没有的话就降级估算。

## 核心技术问题

### BPE vs 语言学分词

| 系统 | 分词方式 | 中文示例 |
|------|---------|---------|
| Whisper BPE | 统计频率合并 | "因为我" → 1 token |
| Jieba | 语言学词典分词 | "因为" + "我" → 2 tokens |
| 字符级 | 每字一个 | "因" + "为" + "我" → 3 tokens |

Word timings 按 token_index 索引，如果 index 不对齐，高亮就会错位。

### 韵律体系差异

| 类型 | 语言 | 特征 | 对估算的影响 |
|------|------|------|------------|
| stress-timed | 英语、德语、俄语 | 重音间隔等时 | 长词 → 更长时间（字符权重合理） |
| syllable-timed | 中文、法语、西班牙语 | 音节等时 | 每 token ≈ 音节数 × 等时（近似等权） |
| mora-timed | 日语 | mora 等时 | 需按 mora 计数分配 |

## 设计约束

- 对齐算法必须是语言无关的（纯字符级时间插值）
- 不改变现有 `WordTiming` 存储结构（只是产出正确的 token_index 和时间区间）
- 英语不受影响（BPE ≈ 空格分词，对齐是 identity 映射）
- 估算 fallback 在无 whisper 数据时仍可用
