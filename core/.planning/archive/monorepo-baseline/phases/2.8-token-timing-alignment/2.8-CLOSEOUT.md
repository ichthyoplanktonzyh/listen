# Phase 2.8 Closeout: Token Timing Alignment

状态：COMPLETED
完成时间：2026-06-24 CST

## 目标回顾

让词级跳动体验在所有语言上达到最大可能的精度：
1. 有 whisper 精确时间戳时，正确对齐到 app token 边界
2. 无精确时间戳时，按语言韵律特征选择最佳估算策略

## 完成内容

### Step 1 + 2: Token Timing Alignment（字符级时间对齐）

- `asr_timing.rs` 核心重构：当 whisper BPE 合并词数与 app tokenizer 词数不匹配时，
  自动执行字符级时间插值对齐（`align_words_to_tokens`），而非直接丢弃回退估算。
- 算法：将每个 BPE 合并词的时间跨度按字符数等分，然后按 app token 的字符范围收集
  对应的时间片段。对齐前做大小写不敏感的文本匹配验证。
- 新增 `TimingSource::AsrAligned` 变体，表示"来自 ASR 数据但经字符级插值"。
- 公开 `align_timings_to_tokens` 函数供 lltimeline 导入和外部调用。
- `MergedWord` 新增 `text` 字段以支持对齐计算。
- 英语 1:1 路径（`extract_direct`）行为不变，`AsrReported` + `dtw-v2`。

### Step 3: 韵律感知估算 Fallback

- 新增 `estimate_word_timings_with_rhythm(sentence, rhythm_prosody)` 函数。
- 三种估算策略通过 `EstimationStrategy` 枚举：
  - `CharWeight`：字符数加权（stress-timed 英语，原有行为，`v1`）
  - `SyllableEqual`：CJK 字符等权（syllable-timed 中文，`v2-syllable`）
  - `MoraCount`：mora 计数权重（mora-timed 日语，`v2-mora`）
- 策略从 `LanguageLearningProfile.rhythm_prosody` 自动选择。
- `pronunciation.rs` 的 `word_timings_or_estimate` 已接入 profile rhythm。

### Step 4: lltimeline 导入对齐

- lltimeline.json 标准导入路径中 tokens 和 word timings 来自同一文档，无需自动
  重新对齐。
- `align_timings_to_tokens` 已作为公开 API 暴露，供未来 re-tokenize 场景使用。
- `word_timing_cache_is_usable` 已更新以接受新的 `v2-*` provider version。

## 设计决策

1. **AsrAligned 精度定位**：与 AsrReported 同优先级（priority=2），因为时间数据
   仍来自 ASR DTW，只是经过字符级重新分配。
2. **文本匹配验证**：对齐前做 case-insensitive 全文比较，不做模糊匹配——宁可
   回退估算，不做错误对齐。
3. **韵律策略选择**：通过 `rhythm_prosody` 字符串的子串匹配（`syllable` / `mora`），
   而非穷举枚举，保持开放性。
4. **lltimeline 导入不自动重对齐**：标准导入路径的 tokens 和 word timings 来自
   同一文档，保持一致性。对齐 API 供未来 re-tokenize 场景使用。
