## Preconditions

- 从本 phase branch 构建/启动最新 macOS Debug app。
- 准备至少一个已建立 media corpus 的英文字幕 track，以及一份 written production corpus；若要看
  spoken source，可使用**已有** 3.15.7 finalized local-authoritative turn，不在本清单执行真实
  realtime provider/device QA。
- 记录测试机可用磁盘和 Activity Monitor 的内存；首次安装预计约 97 MB 模型 cache，spike 热
  max RSS 约 203 MB。

## QA-1 Explicit Install / Offline Lifecycle

1. 在词汇册点击“按意思搜索”。确认未安装时只显示 opt-in 安装，不自动联网，词汇 exact search
   与 production gap v1 仍可用。
2. 点击安装，确认 indeterminate busy、窗口仍有响应；完成后显示 model、384d、fingerprint 前缀。
3. 退出 app、断网、重启；确认 capability 可从已安装 cache 进入 ready，不发生下载。
4. 依次停用/启用；停用时 semantic query 不可用，exact search 不受影响。
5. 最后阶段可测试“删除模型与索引”：确认回到 not_installed；media/production corpus、attempt、gap
   v1、TTS cache 与学习数据仍在。需要继续其他 QA 时重新安装。

## QA-2 Rebuild / Semantic Search

1. 点击“构建语义索引”，确认结束后 indexed source count > 0。
2. 用不包含原词的意思查询，例如已有 “An enormous hall” 时查 “a very large room”。确认 top-K
   返回相近文本、similarity、source kind/channel；媒体与 written/spoken production filter 均不串源。
3. 查询无关意思，确认分数明显较低；不要把分数文案解释成“同义词”或“掌握/不会”。
4. 修改/重建任一 source corpus 后重新打开 capability：应为 stale 且不返回旧 semantic hit；重建后
   恢复 ready。模型 fingerprint 变化同理，绝不混用空间。
5. 在离线、低磁盘/低内存或人为损坏模型文件条件下抽查一次失败：错误可见，旧权威 source 与
   exact search 仍可用；修复路径是 reinstall/rebuild。

## QA-3 Gap Additive Explanation / Zero Writer

1. 准备既有 3.15.6 target（例如 receptive `big`）和实际产出 lexeme（例如 `enormous`），打开
   “把这些词带进产出”。
2. 确认原 v1 top-K 顺序、frequency/evidence/recency explanation 不变；其下只追加“与你用过的词
   语义相近”及 score，并明确是模型线索、不是同义词结论。
3. 对 threshold 下的无关词不显示 clue；uninstalled/disabled/stale 时 gap v1 仍完整显示。
4. 查询前后抽查 attempt、learning_observation、recognition_evidence、capability state/proposal、
   review item 与 production corpus row count 不变。3.17 confirmation gate 仍在。
