## Outcome

Phase 3.7 将“看得懂但在真实语流中听不出”的少量目标做成了克制的泛听增强：用户明确维护
3–5 个猎词目标，显式开启会话级狩猎模式后，播放器只在预算内进行句前 priming 与句后
三态确认。默认泛听保持零打扰，关闭或切换媒体后不残留状态。

猎词单同时是独立可查看的学习资产，不要求用户必须开启狩猎模式。实现保持 listening-only，
没有为了未来四通道提前引入通用 `FocusTarget`。

## Delivered

### 猎词资产与管理

- schema v32 `hunting_targets`，与系统产生的 `hunting_candidates` 明确分离。
- manual、review candidate、Listening Inbox 三类经用户确认的来源；最多 5 个 active 目标。
- 词典页入口、active 数量徽标、手动加入、候选确认、目标查看与归档，中英文文案完整。

### 当前媒体目标定位

- 当前 media/track occurrence API：word 复用 lemma-normalized corpus key，phrase 复用 FTS
  句子匹配。
- 只有稳定 sentence 关联的 occurrence 可以触发提示；无索引以 `indexed=false` 明确表达，
  UI 提供既有 corpus reindex 入口。

### 会话级狩猎交互

- 狩猎模式默认关闭，仅能显式开启；必要时自动建立 extensive-listening session。
- 本地播放器 position stream 驱动目标句前约 1.5 秒的低调视觉 priming 与句后 check。
- 总提示硬上限 5，同一目标每会话最多 2；不自动暂停、不自动重播，未作答提示自动消失。
- 媒体切换、模式关闭及 successful completion 都会彻底清零瞬态状态。

### 三态证据与 completion 小结

- “是”写 listening RecognizedInContext observation；“否”写 NotRecognizedInContext；两者均走
  ADR 0017 单写入口与 ADR 0019 listening 重投影/recognition evidence 聚合。
- “没注意”是合法答案，只写 `hunting_check_answered` LearningEvent，不创建 observation，
  不计作失败。
- extensive completion 理解度对话显示“命中 N 次 / 听出 M 次”；可选 typed
  `hunting_summary` 将 prompted/recognized/not-recognized/not-noticed 四类计数写入
  `listening_completed` payload。application 校验提示预算与回答数关系。
- 狩猎作答和小结不进入 content-fit 校准，不静默修改 capability override 或 legacy status。

## Key Decisions

1. **用户确认是资产边界**：系统候选不会自动进入 active 猎词单，避免泛听被推荐系统接管。
2. **默认路径零打扰**：模式默认关、会话级、不粘滞；预算和每目标上限是硬约束。
3. **“没注意”不是失败**：它记录交互事实但不制造学习证据。
4. **不提前泛化**：Hunting List 保持听力语境；跨 reading/speaking/writing 的目标抽象留给
   Phase 3.16 以真实需求验证。
5. **小结附着 extensive completion**：不恢复已撤除的通用 session summary 机制。
