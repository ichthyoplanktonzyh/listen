# Phase 2.15 Plan: Sound Line Learning UX

状态：COMPLETED

## Objective

把 Phase 2.14 的声音线从“数据结构和渲染能力”推进为“用户可感知的学习闭环”。

## Steps

### Step 1: Real Media QA

- 选择 2-3 段真实英语视频/音频样本。
- 跑完整 speech enhancement / phonetic analysis / sound_analysis。
- 检查：
  - 文字线是否显示稳定 expected phone。
  - 声音线是否只在 `sound_analysis` 存在时显示。
  - CTC mismatch 是否不会污染教学标签。
  - 长句、短句、无 CTC、无 pronunciation 的降级路径。

### Step 2: UI Semantics

- 让声音线有独立视觉身份，而不是“第二条相同的 phoneme ribbon”。
- 保留紧凑形态，但区分：
  - text phoneme ribbon
  - sound pattern ribbon
- 评估是否需要 label、tooltip、色彩、marker legend 或当前 syllable / phrase focus。

### Step 3: Empty / Loading / Unavailable State

- 当用户开启 sound pattern ribbon 但当前句子没有 `sound_analysis`：
  - 不显示伪 fallback。
  - 给出轻量、非打扰的状态或入口提示。
- 避免让用户误以为功能坏了。

### Step 4: Learning-Friendly Evidence Text

- 将内部 finding family 映射到学习者可理解文案。
- 第一版只做高频、低风险表达：
  - supported by audio
  - possible linking
  - possible reduction
  - possible deletion
- 保留高级诊断信息，但不默认压到用户脸上。

### Step 5: Documentation And Closeout

- 更新 `STATE.md`。
- 更新 changelog。
- 写 `2.15-CLOSEOUT.md`。
- 记录 Phase 2.16 输入：哪些真实语流现象需要进入模型化。

## Non-Goals

- 不扩展真实语流规则引擎。
- 不新增 pitch / F0 pipeline。
- 不做完整 Prosodic Hierarchy。
- 不解决多语言声音组织。

## Verification

- `flutter analyze`
- relevant Flutter widget/model tests
- manual QA notes for selected media samples
