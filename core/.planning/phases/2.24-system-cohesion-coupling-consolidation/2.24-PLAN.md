# Phase 2.24 Plan: System Cohesion & Coupling Consolidation

状态：IN PROGRESS（Step 0–2、5 完成；Step 3–4 深化中；Step 6 守卫已落地）

日期：2026-07-14

上游输入：`2.24-CONTEXT.md`、`2.24-BASELINE.md`、ARCH-003、ARCH-011、
Phase 2.23 closeout、ADR 0014。

## Objective

在不改变产品行为与跨进程 contract 的前提下，把当前“依赖方向正确但 interface 过宽”的
系统重构为一组高内聚、低耦合的深 modules：运行时编排不再寄居 HTTP adapter，算法实现
类型不再穿透 application interface，use case 依赖按变化原因聚合，Flutter controller 不再
理解 JSON wire shape。

目标形态：

```text
Flutter controller/Store
  -> typed resource clients
  -> LocalApi transport seam
  -> api-http transport adapter
  -> application use-case modules
       -> repository/provider interfaces at real seams
       -> speech-analysis curated capability interface
  -> local-runtime implementation
       -> process/filesystem/network adapters
```

## 执行顺序

| Step | 内容 | 优先级 | 风险 |
|---|---|---|---|
| 0 | 基线、公开 interface inventory 与安全网 | P0 | 低 |
| 1 | 收窄 `speech-analysis` facade，清除 application 类型泄漏 | P0 | 中 |
| 2 | 从 `api-http` 抽出 runtime job/resource 深 modules | P0 | 高 |
| 3 | 拆分宽 repository interface 与 `AppServices` 用例聚合 | P1 | 高 |
| 4 | Flutter resource client typed 化 | P1 | 中 |
| 5 | Rust/Python 内部 locality 清理 | P2 | 中 |
| 6 | 架构守卫、文档同步与 closeout | 必须 | 低 |

执行顺序：**0 → 1 → 2 → 3 → 4 → 5 → 6**。Step 4 可在 Step 2/3 interface 稳定后
并行准备，但跨端 contract 不得在本 phase 改形状。

## Step 1：算法 interface 收口（P0）

### 1.1 Application 公共 interface

- 删除 workspace 无调用者的 legacy public chunk detection 方法，或降为 crate-private。
- 所有仍需跨 crate 使用的结果映射到 `application::dto` / domain contract；application
  public signature 中不得出现 `speech_analysis::*`。
- `EnglishPronunciationProvider` 等真实 adapter 可继续封装 speech implementation，但
  caller 只看到 application/provider interface。
- 迁移调用者后立即删除旧 pass-through wrapper；禁止双 interface 长期共存。

### 1.2 Speech facade

- 将 17 个实现模块从“全部 `pub mod`”改为精选 capability interface。
- public capability 按 caller 需要组织，例如 pronunciation、timing、chunking、phonetics、
  audible structure；具体命名由 inventory 决定，不按文件一比一导出。
- 没有外部 caller 的 `rich_acoustic_evidence` 等 module 保持 private。
- 不为纯函数增加 provider trait；替换算法仍通过 module 内部实现演进。

Acceptance gate：

- application public signature 中 `speech_analysis::` 为 0。
- 每个 speech public item 均有已记录 caller；实现 module 不再整体公开。
- `api-http` 对 `speech_analysis::` 直接引用继续为 0。
- application/speech/workspace tests 与 contracts 全绿。

## Step 2：Runtime 编排离开 HTTP adapter（P0）

### 2.1 Design checkpoint

在 `design-notes/runtime-module-interface.md` 先固定 module interface，再搬代码。至少比较：

1. 新 workspace crate `local-runtime`；
2. application 内部 runtime module + 独立 adapters；
3. 保留在 `api-http` 但仅机械拆分（预期否决，因为无法消除 transport coupling）。

按 Depth、Locality、依赖方向、测试 surface、移动端未来 FFI 复用性裁决。默认目标是独立
`local-runtime` crate；若否决，必须记录等价的 semantic extraction 方案。

### 2.2 深 modules

从 `api-http` 迁出：

- transcription model/job lifecycle；
- phonetic model/job lifecycle；
- sound-line/speech batch workflow；
- downloadable learning resource lifecycle；
- tool discovery、process execution、temporary workspace、checksum/download primitives。

HTTP crate 保留：route registration、auth、request/response mapping、SSE adapter、composition。

### 2.3 真实 seams

- `ProcessRunner`：production Tokio process adapter + deterministic fake adapter。
- `ArtifactDownloader`：production HTTP/file adapter + in-memory/fake adapter。
- 文件系统优先使用 temporary directory/local stand-in；若抽象能隐藏更多复杂度且测试确需替换，
  再建立窄 filesystem seam。
- job event interface 使用 transport-neutral event/facts；SSE payload 只在 `api-http` 映射。

禁止让 runtime module 依赖 Axum、`ApiState`、HTTP status 或 HTTP request DTO。

Acceptance gate：

- `api-http` route/handler 代码不再拥有下载、子进程、队列状态机和模型安装实现。
- `sound_line` 不再从 `transcription` module 私借工具函数。
- runtime module 通过 fake adapters 覆盖 install/cancel/retry/failure/cleanup/progress。
- HTTP/OpenAPI/SSE contract 零变化；全栈 integration tests 全绿。

## Step 3：Use-case modules 与 repository interface（P1）

### 3.1 Repository interface 按变化原因拆分

至少处理三个已确认的宽 interface：

- `TimelineResourceRepository` → word/chunk/sense-group/phone stores；
- `LearningAssetRepository` → lexical entry/capability+evidence/sense+import-export stores；
- `ReviewRepository` → review queue/hunting/recognition-upgrade stores。

实际切法以 caller cluster 为准。若两个方法总是由同一用例、同一事务、不变量共同变化，保留
在同一 interface；不得只为压低方法数机械拆 trait。

`SqliteRepository` 继续直接实现这些 interfaces，不新增 fat 聚合 trait或 blanket bridge。

### 3.2 `AppServices` 深化

- 将散布的 `impl AppServices` 按用例族迁为少量深 modules，例如 timeline、lexical learning、
  practice/review、analysis、semantic/corpus。
- 每个 module 只持有所需 repository/provider interfaces，并在内部维护事务、不变量、缓存和
  error mapping。
- 顶层 composition object 只负责装配和暴露 modules，不继续承载跨域的数百个方法。
- 所有 api-http caller 迁移到新 interface 后删除旧 wrapper，执行 replace-don't-layer。

Acceptance gate：

- 三个宽 repository trait 不再存在；新 interface 的聚合理由写入 module doc。
- 不存在重新引入的 fat trait/blanket bridge。
- 顶层 composition object 不直接暴露跨域 use-case 方法集合。
- 测试通过 module interface 验证行为，避免越过 interface 检查内部状态。

## Step 4：Flutter typed resource clients（P1）

- 保留现有 `ApiTransport` seam 和 `LocalApi.withTransport` 测试方式。
- `services/api/*` 负责 request 构造、JSON 解码、typed model 构造和 HTTP error 分类。
- controller/Store/widget 只消费 typed result，不调用 `.fromJson(await api...)`，不 cast
  HTTP response map。
- 对 LLTimeline extension payload、OpenAPI extension objects 等确需开放 JSON 的端点建立
  明确 allowlist，并在 model/interface doc 解释为何不能 typed。
- part 文件可继续存在；如果 resource client interface 仍过宽，按真实 caller cluster 形成
  typed resource clients，但不为每个 controller 制造一套同构 fake interface。
- 每迁移一个资源域，同 commit 增加 transport/contract/controller test 并删除旧 raw path。

Acceptance gate：

- controllers/widgets 中对 HTTP result 的 `Map<String, dynamic>` cast 与 JSON model 构造为 0。
- LocalApi public raw return 仅剩审定 allowlist，且每项有 contract test。
- 现有约 97 个 raw-return 方法显著收敛；最终数字记录在 closeout，不以临时 wrapper 计为完成。
- `flutter analyze`、全部 Flutter tests 和 Rust/Flutter contract tests 全绿。

## Step 5：内部 Locality 清理（P2）

### Rust

- `persistence-sqlite/src/subtitles.rs` 按现有四个 repository interface 拆为内聚 modules；
  SQL、事务和序列化行为逐字保持。
- 生产代码逐步消除 `use domain::*` / `use crate::*`；改为显式 import，测试可按需要保留
  局部 `super::*`。
- `domain` root 改为精选 re-export 或鼓励显式 module path；不在本 phase 拆 domain crate。

### Python production pipeline

- `production_pipeline.py` 留作薄 CLI/composition entry；提取 timeline I/O、acoustic cues、
  quality report、audio preparation、post-alignment orchestration modules。
- 复用现有 aligner plugin interface，不另建第二套 adapter 层。
- 先为纯转换和 orchestrator failure/fallback 写 interface-level tests，再删除旧函数位置测试。

Acceptance gate：

- `persistence-sqlite` 文件按资源职责定位，无四个 repository implementation 混在同一文件。
- production Rust wildcard import 清零或只剩经审定、记录原因的 allowlist。
- `production_pipeline.py` 只负责 parser/dispatch/composition；核心测试不需 import 整个 CLI。
- Python committed tests、Rust workspace tests 全绿。

## Step 6：守卫与 Closeout（必须）

新增/更新守卫：

- architecture dependency test：Cargo 依赖方向继续单向，`api-http` 不依赖算法 crate。
- public interface guard：application public signature 不出现 engine implementation path。
- HTTP runtime ownership guard：Axum route modules不含 process/download/job-state implementation。
- Flutter raw JSON allowlist guard。
- 文档更新：`ARCHITECTURE.md`、`TESTING.md`、必要时 `STACK.md`；新增 crate/interface/事件
  所有权决策若影响长期结构，追加 ADR。

Closeout 必须报告：public surface 前后对比、raw JSON 前后对比、repository interface 变化、

## Exit Signal

- 修改 HTTP transport 不需要理解或编辑任务状态机、下载器和子进程实现。
- 修改 speech algorithm 不会改变 application public result shape。
- 新增一个 timeline/learning/review 用例只触及对应 module/interface，不要求修改无关仓库。
- Flutter controller 测试只面对 typed state/result，不理解后端 JSON。
- Python 生产管线的纯转换和编排可通过各自 interface 独立测试。
- 没有为了“低耦合”新增只有单一真实使用者、没有测试替代价值的浅 trait。
