# Phase 3.19 Owner Journeys v2 — 可执行体验验收

状态：TARGET EXPERIENCE CONTRACT — CORRECTION 完成后执行

日期：2026-07-20

## 1. 这份文档解决什么问题

Run 1 的 J0–J5 能追踪功能，却没有把入口、页面、即时反馈、持久结果和验证位置写清楚，导致
测试者必须猜测产品。本文件取代 Run 1 脚本作为后续 owner QA 的执行说明；Run 1 结果仍保留在
`3.19-RELEASE-ACCEPTANCE.md`，不覆盖历史。

本文件同时是一份目标体验契约：如果实现后的主入口、按钮名称或结果位置与本文不同，先更新产品
设计和本文，再让 owner 测试；不得要求 owner 自己寻找替代入口。

## 2. 统一记录格式

每个步骤记录：

- `PASS`：主入口、操作、即时结果、持久结果和验证位置全部成立；
- `FAIL`：能操作但任何一层结果不成立；
- `BLOCKED`：在指定入口或前置条件处无法继续；
- `N/A`：功能已经在减法审计中正式删除，或自然数据确实不存在，并注明决策/数据原因。

每个失败至少记录：编号、时间、所在页面、点击动作、预期、实际、是否仍在播放/录音、截图或日志。
不提交私人字幕、录音、API key 或 owner 数据库。

### 2.1 禁止“帮产品找入口”

- 只使用每条旅程写明的**主入口**。主入口缺失就是 FAIL。
- 顶部“学习”菜单可作为高级快捷入口，但不能挽救首页缺少的核心资产入口。
- 不使用数据库、HTTP 调用、开发者工具或记忆中的旧页面完成用户动作。
- 文案让 owner 无法判断下一步时直接 FAIL，不猜内部术语。

### 2.2 每一步要观察五层结果

1. **入口结果**：是否进入正确页面，标题和当前对象是否正确；
2. **即时结果**：点击后声音、画面、表单、提示怎样变化；
3. **任务边界**：本次操作针对全文、句子还是短段，边界是否可见；
4. **持久结果**：是否写入 attempt、history、schedule 或用户资产；只读动作不得写；
5. **回访位置**：用户之后从哪里看见这次操作及其影响。

只验证按钮“能点”不算 PASS。

## 3. 目标信息架构与固定入口

以下是 Phase 3.19 必须实现并保持稳定的主入口：

| 用户目标 | 主入口 | 进入后必须看见 |
|---|---|---|
| 打开/继续内容 | 首页 →「继续学习」或「媒体库」媒体行 | 媒体标题、播放位置、听/读/说/写通道 |
| 泛听 | 首页 → 媒体库 → 媒体行「泛听」 | 全文范围、开始/结束状态、可选狩猎 |
| 精听 | 首页 → 媒体库 → 媒体行「精听」 | 明确句子/短段选区与精听活动选择，不自动变成泛听 |
| 复习 | 首页左栏「我的学习」→「复习」；首页资产区也有同名卡片 | 到期数、当前卡、来源、页内播放/练习 |
| 词汇与证据 | 首页左栏「我的学习」→「词汇」→ 词条 | 词条事实、四通道状态、证据与建议入口 |
| 我的表达 | 首页左栏「我的学习」→「我的表达」；首页资产区也有同名卡片 | 搜索、新建、已有表达列表 |
| Coach | 首页左栏「我的学习」→「Coach」 | 四通道事实、数据时间窗、可解释建议；无无意义配置催促 |
| 内容内阅读/口语/写作 | 打开媒体 → 工作台顶部通道「读 / 说 / 写」 | 当前明确选区、任务类型、返回来源 |
| Realtime conversation | 打开媒体 →「说」→ 明确选区 →「实时对话」 | 发送范围、provider、麦克风授权与开始确认 |
| 语义搜索（若保留） | 首页 →「词汇」→「按意思搜索」 | 安装/状态/搜索入口；未安装时精确搜索仍可用 |

窄窗口可以把左栏收起为等价导航，但名称和层级不得改变。若一个功能只存在于顶栏更多菜单，主入口
验收失败。

## 4. 数据与设备准备

- 两份有英文字幕的本地真实媒体：一份 2–5 分钟，一份至少 10 分钟；
- 至少一个出现在多个句子的真实词或短语；
- 至少三张有本地音频来源的到期 Review 卡；不足时只测已有合法卡，不伪造 evidence；
- 一个从 Reading 保存的个人表达，以及一个可删除的手工个人表达；
- macOS 麦克风可在系统设置中撤销/重新授权；
- bundled Whisper `base.en`；
- Realtime 只在有真实 provider 时执行；key 只通过 App 写入 Keychain；
- 开始前复制 owner 数据库。删除来源、损坏模型只在副本环境测试。

## 5. Q1 — 首页与入口可发现性

目的：用户不需要知道项目 phase、内部模型或顶部隐藏菜单，就能找到核心旅程。

起点：完整退出后重新启动 App，停在首页，不打开任何媒体。

| Step | 具体操作 | 当场必须发生 | 之后从哪里验证 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q1.1 | 查看首页左侧「我的学习」。 | 同时看见「词汇」「复习」「我的表达」「Coach」；名称不使用 asset、projection 等内部词。 | 无需跳转。 | 任一核心入口缺失或只能从顶栏菜单进入。 | |
| Q1.2 | 点击「我的表达」，不创建内容，立即返回。 | 进入标题为「我的表达」的完整页面；有搜索、新建和列表；返回后仍是首页。 | 再次点击，页面状态稳定。 | 先进入“学习资产”才能找到；返回到播放器或错误页面。 | |
| Q1.3 | 点击「复习」，再返回。 | 进入「声音复习」；空队列显示为何为空，有卡时显示卡数和来源。 | 首页入口仍可再次打开。 | 空白页、无限 loading、必须先开媒体。 | |
| Q1.4 | 点击「词汇」，打开任一词条，再返回首页。 | 词条详情能找到「证据与历史」和「能力建议」；返回层级正确。 | 用同一入口重新打开该词条。 | evidence 无入口或返回破坏首页。 | |
| Q1.5 | 点击「Coach」。 | 四通道区域可见；冷启动显示“尚无记录/未评估”，不要求先配置 LLM。 | 返回首页。 | 用配置错误阻断只读事实；制造总分。 | |

通过口径：Q1.1–Q1.5 全部 PASS。高级菜单存在与否不影响本旅程。

## 6. Q2 — 媒体库：泛听与精听必须是两种任务

目的：验证两个入口不会只换按钮名字，且任务范围清楚。

起点：首页已加载媒体库，选择同一份有字幕媒体。记录当前媒体标题和最近播放位置。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q2.1 | 在媒体行点击正文区域，不点「泛听/精听」。 | 普通打开媒体工作台；不自动创建任何 listening session，不自动播放。 | 返回首页后最近媒体更新；无 completion。 | 普通打开被强制归为精听或泛听。 | |
| Q2.2 | 返回首页，在同一媒体行点「泛听」。 | 进入媒体工作台；顶部/播放栏明确显示「泛听进行中」；任务范围显示“全文”；不会弹选句器。 | 结束前只存在 active session；首页/Coach 不显示已完成。 | 进入精听活动、范围不明或自动算完成。 | |
| Q2.3 | 播放 20 秒，暂停，再继续。 | 主播放器正常连续播放；暂停后静音；任务仍是全文泛听。 | 当前 session 时长只累计真实播放。 | 暂停后仍有声音；任务范围跟随当前句偷偷改变。 | |
| Q2.4 | 选择「结束泛听」，填写理解度并确认。 | 先显示本次时长、理解度和狩猎摘要（若开启），确认后退出 active 状态。 | 本次 completion 在 Coach/媒体历史的明确入口可见；fit 说明显示“作为校准信号”，不声称立即改级。 | 确认前写 completion；结束后找不到结果；理解度被称为客观真值。 | |
| Q2.5 | 返回首页，在同一媒体行点「精听」。 | 打开该媒体但**不启动泛听**；先显示当前句/短段选区，边界含文本和起止位置，并提供精听活动选择。 | 尚未开始活动时不写 attempt。 | 直接出现「泛听进行中」；只打开泛听侧栏；不知道针对哪一段。 | |
| Q2.6 | 选择一条句子，播放来源一次。 | 只播放该选区，到 end 自动停止；按钮变回可播放；可主动暂停。 | 纯播放不写 learning attempt/evidence。 | 继续播放下一句；移动主播放器后任务边界随之改变。 | |
| Q2.7 | 启动一个精听活动，完成并返回。 | 活动页持续显示选区；完成后回到同一媒体、同一选区，不自动转泛听。 | 活动历史显示 task kind、选区快照和结果。 | 返回首页/泛听；选区丢失；把完成直接写为 acquired。 | |

通过口径：Q2.1–Q2.7 全部 PASS；“精听”和“泛听”任何语义折叠均为 P1。

## 7. Q3 — 泛听中的狩猎及其影响必须可见

目的：用户知道自己在听什么、一次回答记录了什么、以后去哪里看。

起点：词汇页「狩猎清单」至少有一个在测试媒体中出现的 active target；从首页对该媒体开始泛听。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q3.1 | 在播放栏打开「泛听」菜单，点击「开始狩猎模式」。 | 显示本次目标数、总提示预算和当前目标；泛听继续，未到命中点不打扰。 | 狩猎清单仍显示 active target。 | 没说明目标；自动添加未知目标；阻断播放。 | |
| Q3.2 | 到提示点后选「听出来了」。 | 卡片立即消失/进入下一状态，并显示“已记录听出；计入本次命中和 recognition evidence”的短反馈。 | 词汇 → 目标词 →「证据与历史」出现本次 recognized 事件；不直接改 capability。 | 只显示“已保存”；找不到记录；直接变 acquired。 | |
| Q3.3 | 下一次提示选「没听出来」。 | 显示“已记录未听出；可进入候选/复习，但不会自动改变能力”。 | 证据历史出现 not_recognized；若满足候选规则，狩猎/Review 候选入口可见。 | 自动加入 Review 或自动判不会且无说明。 | |
| Q3.4 | 下一次提示选「没注意」。 | 显示“只记录本次未作判断，不形成成功/失败 evidence”。 | 证据历史可以有事件事实，但 proposal/effective state 不变化。 | 被计为听辨失败或负面 observation。 | |
| Q3.5 | 结束泛听并提交理解度。 | 完成页显示三态计数、理解度、分别影响什么；提供「查看本次记录」。 | 点击查看进入本次 completion；再从媒体历史/Coach 可回访。 | 统计只在 toast 出现；关闭后无处查看。 | |

通过口径：每次动作都能回答“记录在哪里、影响什么、不影响什么”。

## 8. Q4 — Review 必须是一个完整的页内体验

目的：在 Review 内完成回听、作答、跟读/复述、评分和下一卡，不把用户抛回首页。

起点：首页 →「复习」。选一张来源为本地媒体、带 start/end 的到期卡。记录队列位置（例如 2/5）。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q4.1 | 查看卡片顶部。 | 看见卡型、目标/提示、来源媒体标题、选区文本或隐藏规则、队列位置；未揭示答案。 | 无写入。 | 不知道在复习什么或来源是什么。 | |
| Q4.2 | 点击「播放声音片段」。 | 按钮变「暂停」；只播放 start–end，终点自动停止并恢复按钮。 | 纯播放不写 attempt。 | 继续播放后文；使用主播放器当前媒体代替来源；无法暂停。 | |
| Q4.3 | 播放中点击「暂停」。 | 立即静音，仍停留当前卡；再次播放从片段起点或明确当前位置开始。 | 无写入。 | 页面跳转、音频继续或出现第二声源。 | |
| Q4.4 | 点击「跟一下这个片段」。 | 当前 Review 页面内展开跟读区；来源、录音、停止、回放均在卡片内；队列位置不变。 | 录音完成前不写 completed attempt。 | 返回首页；打开独立悬浮 panel；看不到当前卡。 | |
| Q4.5 | 录一段并完成跟读，然后关闭跟读区。 | 麦克风释放；回到同一卡；可继续揭示/评分。 | 合法完成才显示一次 attempt/history；取消不写 completed。 | 自动进入下一卡；背景仍录音/播放。 | |
| Q4.6 | 对 delayed retelling 卡执行「复述这段」。 | 原文按规则隐藏；在 Review 页面内完成录音、转写、自评；完成/取消都返回原卡。 | 完成后 attempt 指向本卡和冻结选区。 | 跳到普通 Speaking 首页；选区变成当前播放器句子。 | |
| Q4.7 | 揭示答案，评为 again。 | 写入一次 review attempt，显示“下次复习时间如何变化”的可理解说明，进入下一卡且旧音频停止。 | 队列/历史能看到该次评分；不直接写 capability projection。 | 评分前写成功；切卡后旧声音继续。 | |
| Q4.8 | 对另一张本地来源卡回听。 | 即使主播放器当前打开不同媒体，仍能解析并播放该卡真实来源。 | 无额外学习写入。 | 本地文件存在却显示文字快照。 | |
| Q4.9 | 在数据库副本中让一张来源真正失联。 | 显示“音频来源不可用”、具体原因和「重新关联」；文字快照只用于说明历史，不显示为已经完成回听。 | 卡、schedule、history 保留。 | 用文字快照冒充音频任务；播放了其他媒体。 | |

通过口径：Q4.1–Q4.9 无页面逃逸、错播、双声源或假降级。

## 9. Q5 — 证据、建议和状态影响可追踪

目的：用户做完学习动作后知道结果落在哪里，也能区分 evidence、proposal 与最终状态。

起点：首页 →「词汇」→ 选择本轮 Q3/Q4 使用过的目标词。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q5.1 | 点击「证据与历史」。 | 按通道和时间列出来源、动作与结果；recognized/not_recognized/not_noticed 的语义不同。 | 与 Q3/Q4 实际操作一致。 | 没入口；只展示内部 ID；把没注意当失败。 | |
| Q5.2 | 返回词条，点击「能力建议」。 | 每通道独立；证据不足显示“尚未形成建议”并链接到现有 evidence，而不是空白。 | 纯查看不写 proposal/decision。 | 用户不知道为空的原因；打开页面就生成建议。 | |
| Q5.3 | 若存在 proposal，展开一条。 | 看见建议结论、证据来源数、算法版本/生成时间的用户化说明和“确认/拒绝”。 | 无决策前 effective state 不变。 | 用“系统已判定”误导；看不到来源。 | |
| Q5.4 | 拒绝 proposal。 | 显示拒绝只处理本条建议，不删除 evidence；返回后该建议有 rejected 标记。 | decision/history 可查，effective state 不变。 | evidence 被删或能力状态改变。 | |
| Q5.5 | 确认另一条合法 proposal。 | 确认前再次说明影响哪个通道；确认后该通道状态变化并有 history。 | 重启后 proposal decision、projection/history 仍在。 | 影响其他通道；未确认已变化。 | |

若自然数据没有 proposal：Q5.1–Q5.2 必须执行；Q5.3–Q5.5 标 `N/A — natural evidence insufficient`，
不得制造数据，也不得因此阻塞其他旅程。

## 10. Q6 — 我的表达：稳定资产入口、准确选区、自然返回

目的：个人表达是可独立回访的资产，不依赖记得“从 Reading 保存”这条隐藏路径。

起点：打开一份有字幕媒体 → 工作台「读」。在阅读页选择一句真实句子。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q6.1 | 在选中句工具条点击「保存到我的表达」。 | 表单显示准确句子、媒体标题、start/end；取消后回原阅读句且不创建资产。 | 首页 →「我的表达」列表不新增。 | 带入别的句子；取消后退出内容。 | |
| Q6.2 | 再次进入并填写名称、模板、槽位、说明后保存。 | 保存成功后明确提供「查看我的表达」和「留在阅读」。 | 从首页 →「我的表达」可搜索到；来源快照不随编辑改变。 | 只有 toast；不知道去哪里找；来源被模板覆盖。 | |
| Q6.3 | 从首页主入口打开该表达。 | 看见模板、来源快照、版本、写作/口语动作和历史。 | 页面刷新/重启后仍在。 | 必须重新打开原 Reading 才能访问。 | |
| Q6.4 | 编辑模板并保存新版本。 | 当前版本更新，旧版本仍可查看；已有 attempt 指向旧版本。 | 版本列表显示两版及时间。 | 覆盖历史版本。 | |
| Q6.5 | 点击「写自己的句子」，选择帮助等级，保存一次。 | 输入区明确当前帮助；保存后回表达详情并显示 writing history。 | history 含文本、帮助、自评、版本；不改变 speaking 状态。 | 关闭后历史不见；写作成功让口语 acquired。 | |
| Q6.6 | 点击「脱稿说一遍」。 | 进入口语任务前显示**该表达准确来源选区**；来源播放只到 end；完成/取消后回该表达详情。 | 完成写 speaking history，取消不写 completed；writing history 不变。 | 从主播放器当前句开始；完成后回首页/媒体。 | |

## 11. Q7 — 内容内说/写：任务单位必须明确

目的：验证说和写不会把“当前正在播放”误当成无限任务输入。

起点：打开媒体并暂停，在文稿中选中一句；随后另选连续 2–3 句短段。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q7.1 | 选一句后点击工作台「说」。 | 进入前确认选区；默认可选 Role Reply/句型练习，页面一直显示任务范围。 | 未录音不写 attempt。 | 自动使用整篇；选区不可见。 | |
| Q7.2 | 播放来源并完成一次口语。 | 来源到句末停止；录音、转写、自评完成后回原媒体与原选区，不自动播放。 | speaking attempt 保存准确 selection snapshot。 | 播放继续；完成后丢位置。 | |
| Q7.3 | 选 2–3 句后选择 Retelling。 | 确认短段文本/时长；任务可以隐藏原文，但提供“查看任务范围”。 | attempt 指向短段，不扩大到全文。 | 仍只取当前一句或取剩余全文。 | |
| Q7.4 | 选同一短段后点击「写」。 | 显示写作任务类型、短段范围、是否允许来源回听；不会假定整篇作文。 | 取消不写 completed attempt。 | 输入单位未知；来源播放无边界。 | |
| Q7.5 | 在没有选区时点击「说」或「写」。 | 要求先选择一句/短段，并提供直接选取操作；不猜当前播放位置。 | 无 attempt。 | 静默从当前位置开始或使用全文。 | |

## 12. Q8 — Coach 必须有明确价值，否则做减法

起点：首页 →「Coach」。分别在冷启动数据和已有 Q2–Q7 记录后查看。

| Q8.2 | 点击任一非零指标。 | 进入具体记录列表，能看到来源和时间；返回后保持 Coach 时间窗。 | 纯 drill-down 不写学习事实。 | 数字不可追踪；返回重置上下文。 | |

## 15. Q11 — TTS：证明用户任务，否则删除入口

- 词典没有真人/标准音频时，明确标注的合成发音。

若没有 owner 认可的场景，删除面向用户的 TTS 配置和入口，本旅程标 N/A。

若保留：

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |

## 16. 减法审计表（实现者执行，owner 只裁决灰区）

每个 Phase 3.x 用户可见功能和 fallback 必须填一行；没有住户的代码也要列出。

| 项目 | 核心用户目标 | 稳定主入口 | 真实使用证据 | 不存在时损失 | fallback 是否保持目标 | 决策 |
|---|---|---|---|---|---|---|
| 示例：Review 文字快照代替音频 | 回听真实来源 | Review | Run 1 明确需要音频 | 无法完成回听 | 否，只保留历史说明 | 删除“替代成功”语义 |

决策只允许：

- `KEEP`：目标明确、入口稳定、owner 旅程证明有用；
- `SIMPLIFY`：目标成立但 UI/状态/选项过多，收缩到最短路径；
- `REMOVE`：假需求、无真实住户、与其他功能重复、或只因旧 phase 预设存在；
- `UNAVAILABLE`：真实工程条件阻止原目标，显示原因与恢复，不伪装成 fallback；
- `DEFER RESEARCH`：算法价值可能成立但当前数据不能证明，从发布 UI 移除或标实验性。

不得使用“代码已经完成”“以后可能有用”“离线也许需要”作为 KEEP 理由。

## 17. Phase 3.19 最终出口

只有同时满足以下条件才能 closeout：

1. Q1–Q9 所有保留旅程无 P0/P1；Q10/Q11 已通过真实价值裁决后 PASS 或正式 REMOVE；
2. 所有核心功能有一个稳定主入口，动作后能看见即时结果、持久结果和回访入口；
3. Review、Speaking、Writing、Personal Expression 全部遵守显式 ContentSelection；
4. degradation audit 每一行都有 KEEP/SIMPLIFY/REMOVE/UNAVAILABLE/DEFER RESEARCH 决策与依据；
5. 删除假需求和假 fallback 后，自动化、package smoke 与 owner 回归仍通过；
6. P0 为 0；P1 为 0 或有 owner 针对具体缺陷的书面例外；
7. 在上述条件满足前，ROADMAP 不允许启动任何新功能 phase。
