## 1. 这份文档解决什么问题

Run 1 的 J0–J5 能追踪功能，却没有把入口、页面、即时反馈、持久结果和验证位置写清楚，导致
测试者必须猜测产品。本文件取代 Run 1 脚本作为后续 owner QA 的执行说明；Run 1 结果仍保留在
`3.19-RELEASE-ACCEPTANCE.md`，不覆盖历史。

本文件同时是一份目标体验契约：如果实现后的主入口、按钮名称或结果位置与本文不同，先更新产品
设计和本文，再让 owner 测试；不得要求 owner 自己寻找替代入口。

## 2. 统一记录格式

每个步骤记录：

- `PASS`：主入口、操作、即时结果、持久结果和验证位置全部成立；
- `FAIL`：能操作但任何一层结果不成立；
- `BLOCKED`：在指定入口或前置条件处无法继续；
- `N/A`：功能已经在减法审计中正式删除，或自然数据确实不存在，并注明决策/数据原因。

每个失败至少记录：编号、时间、所在页面、点击动作、预期、实际、是否仍在播放/录音、截图或日志。
不提交私人字幕、录音、API key 或 owner 数据库。

### 2.1 禁止"帮产品找入口"

- 只使用每条旅程写明的**主入口**。主入口缺失就是 FAIL。
- 顶部"学习"菜单可作为高级快捷入口，但不能挽救首页缺少的核心资产入口。
- 不使用数据库、HTTP 调用、开发者工具或记忆中的旧页面完成用户动作。
- 文案让 owner 无法判断下一步时直接 FAIL，不猜内部术语。

### 2.2 每一步要观察五层结果

1. **入口结果**：是否进入正确页面，标题和当前对象是否正确；
2. **即时结果**：点击后声音、画面、表单、提示怎样变化；
3. **任务边界**：本次操作针对全文、句子还是短段，边界是否可见；
4. **持久结果**：是否写入 attempt、history、schedule 或用户资产；只读动作不得写；
5. **回访位置**：用户之后从哪里看见这次操作及其影响。

只验证按钮"能点"不算 PASS。

## 3. 目标信息架构与固定入口

以下是 Phase 3.19 必须实现并保持稳定的主入口：

| 用户目标 | 主入口 | 进入后必须看见 |
|---|---|---|
| 打开/继续内容 | 首页 →「继续学习」或「媒体库」媒体行 | 媒体标题、播放位置、听/读/说/写通道 |
| 泛听 | 首页 → 媒体库 → 媒体行「泛听」 | 全文范围、开始/结束状态、可选狩猎 |

| 复习 | 首页左栏「我的学习」→「复习」；首页资产区也有同名卡片 | 到期数、当前卡、来源、页内播放/练习 |
| 词汇与证据 | 首页左栏「我的学习」→「词汇」→ 词条 | 词条事实、四通道状态、证据与建议入口 |
| 我的表达 | 首页左栏「我的学习」→「我的表达」；首页资产区也有同名卡片 | 搜索、新建、已有表达列表 |

验收失败。

## 4. 数据与设备准备

- 两份有英文字幕的本地真实媒体：一份 2–5 分钟，一份至少 10 分钟；
- 至少一个出现在多个句子的真实词或短语；
- 至少三张有本地音频来源的到期 Review 卡；不足时只测已有合法卡，不伪造 evidence；
- 一个从 Reading 保存的个人表达，以及一个可删除的手工个人表达；
- macOS 麦克风可在系统设置中撤销/重新授权；
- bundled Whisper `base.en`；
- Realtime 只在有真实 provider 时执行；key 只通过 App 写入 Keychain；
- 开始前复制 owner 数据库。删除来源、损坏模型只在副本环境测试。

## 7. Q3 — 低打扰 Hunting 与 Listening Inbox

> 2026-07-20 owner correction：本节初版臆造了目标数/预算常驻 UI、作答后影响说明、证据跳转和
> fit 反馈，并遗漏真实的 Inbox 快捷键。初版 Q3.1–Q3.5 全部作废，不作为产品 FAIL。以下步骤按
> 当前代码的实际入口和 owner 裁决重写：泛听中的作答应安静后台记录，不新增打扰式反馈。

目的：验证 Hunting 只在真实命中点做最小提示，回答后安静退出；同时验证 Listening Inbox 的

快捷键基线：`I` = 当前字幕句加入 Listening Inbox；`Shift+I` = 开始/结束泛听；
`Shift+P` = 暂停、加入 Inbox 并进入快速听感检查。它们不是 Hunting 三态回答快捷键。

## 8. Q4 — Review 必须是一个完整的页内体验

起点：首页 →「复习」。选一张来源为本地媒体、带 start/end 的到期卡。记录队列位置（例如 2/5）。

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |

| Q10.5 | 点击 Disable/Uninstall。 | Disable 后 status 变为 'disabled'，可再 Enable。Uninstall 后 status 变为 'not_installed'，可再 Install。精确搜索和核心学习继续；Search 输入框在 `canSearch == false` 时禁用。 | 重启状态一致。 | 删除源内容或影响核心词汇。 | |

## 15. Q11 — TTS：证明用户任务，否则删除入口

TTS 不是因为 provider 已实现就自动成立。先选择一个保留场景：

- 用户自有写作文本的"听听我写的句子"；或
- 词典没有真人/标准音频时，明确标注的合成发音降级。

若没有 owner 认可的场景，删除面向用户的 TTS 配置和入口，本旅程标 N/A。

TTS 当前在代码中以以下形式存在：
- 词汇详情页：当词典没有真人发音时，`PronunciationButton(synthetic: true)` 作为降级出现，调用 `onSpeakSynthetic(text, 'dictionary_pronunciation_fallback')`
- 写作 Studio：完成草稿后可点击「合成朗读」按钮（`readingAloudSynthetic`），调用 `onSpeakTTS` 回调
- 没有独立的「合成朗读」入口页面或主场景

| Step | 具体操作 | 当场必须发生 | 持久结果与验证位置 | 失败条件 | Result |
|---|---|---|---|---|---|
| Q11.1 | 从词汇详情页（词条无真人发音时）点击合成朗读按钮（标有 synthetic 标志）。 | `AuxiliaryAudioController.speak()` 先 `_acquireAuxiliaryAudioFocus()` 暂停 slicePlayer 和背景播放。文案明确"合成语音"（使用 `PronunciationButton(synthetic: true)`）；只存在一个声源。 | 播放不写 learning evidence/attempt。 | 不知道为何用 TTS；与真人来源竞争；双声源。 | |
| Q11.2 | 播放中离开词汇页面。 | dispose 时调用 `auxiliaryAudio.stop()`。 | 无残留声音。 | 一直播放或返回后继续。 | |
| Q11.3 | 离线重试同一句。 | `SpeechSynthesisAssetView` 有 `cacheHit` 字段，但**前端没有显式的缓存/离线状态 UI**。不可用时显示 "TTS unavailable" snackbar。 | 不把失败算学习失败。 | 文字或其他任务冒充朗读完成。 | |

## 16. 减法审计表（实现者执行，owner 只裁决灰区）

每个 Phase 3.x 用户可见功能和 fallback 必须填一行；没有住户的代码也要列出。

| 项目 | 核心用户目标 | 稳定主入口 | 真实使用证据 | 不存在时损失 | fallback 是否保持目标 | 决策 |
|---|---|---|---|---|---|---|
| 示例：Review 文字快照代替音频 | 回听真实来源 | Review | Run 1 明确需要音频 | 无法完成回听 | 否，只保留历史说明 | 删除"替代成功"语义 |

决策只允许：

- `KEEP`：目标明确、入口稳定、owner 旅程证明有用；
- `SIMPLIFY`：目标成立但 UI/状态/选项过多，收缩到最短路径；
- `REMOVE`：假需求、无真实住户、与其他功能重复、或只因旧 phase 预设存在；
- `UNAVAILABLE`：真实工程条件阻止原目标，显示原因与恢复，不伪装成 fallback；
- `DEFER RESEARCH`：算法价值可能成立但当前数据不能证明，从发布 UI 移除或标实验性。

不得使用"代码已经完成""以后可能有用""离线也许需要"作为 KEEP 理由。

## 17. Phase 3.19 最终出口

只有同时满足以下条件才能 closeout：

1. Q1–Q9 所有保留旅程无 P0/P1；Q10/Q11 已通过真实价值裁决后 PASS 或正式 REMOVE；
2. 所有核心功能有一个稳定主入口，动作后能看见即时结果、持久结果和回访入口；
3. Review、Speaking、Writing、Personal Expression 全部遵守显式 ContentSelection；
4. degradation audit 每一行都有 KEEP/SIMPLIFY/REMOVE/UNAVAILABLE/DEFER RESEARCH 决策与依据；
5. 删除假需求和假 fallback 后，自动化、package smoke 与 owner 回归仍通过；
6. P0 为 0；P1 为 0 或有 owner 针对具体缺陷的书面例外；
7. 在上述条件满足前，ROADMAP 不允许启动任何新功能 phase。
