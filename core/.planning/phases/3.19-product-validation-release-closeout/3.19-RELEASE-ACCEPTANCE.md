## C. Owner Execution Protocol

### C1. 每个步骤如何记录

每个编号步骤只记录以下四种结果之一：

- `PASS`：操作完成，预期结果全部成立；
- `FAIL`：可以完成操作，但存在错误行为；
- `BLOCKED`：无法进入或继续该步骤；
- `N/A`：测试数据确实不具备该条件，并写明原因，不能用 N/A 隐藏失败。

发现问题时记录：journey/step、时间、最短复现、预期、实际、媒体条件、截图或日志位置。不要把
真实字幕、私人录音、API key 或完整数据库提交到仓库。

### C2. 安全规则

1. 先复制 `~/Library/Application Support/listen/listen.sqlite`；来源删除、模型损坏和失败迁移只在
   副本/专用 QA 环境执行。若当前仍使用 legacy 路径，以 sidecar startup log 显示的数据库路径为准。
2. 开始每条旅程前记录当前媒体、播放位置、播放/暂停状态；任何任务返回都应恢复位置但不自动播放。
3. 任一时刻只能有一个声音源。出现双声源、麦克风未释放、旧 response 继续播放或页面关闭后残留
   音频，至少按 P1 记录；涉及隐私录音持续采集时按 P0。
4. UI 卡死、崩溃、数据丢失、secret 泄漏、authority 被静默修改或来源错播时立即停止该旅程并记录
   P0/P1，不继续用后续步骤掩盖问题。
5. 一次只改变一个失败条件。例如测试断网时不要同时删除 model 和 credential。

### C3. 写入边界

- 应当写入：完成 practice/review/Studio/personal-expression attempt，显式 proposal decision，显式
  override，用户主动 CRUD。
- 必须只读：打开 Coach、drill-down、semantic query、TTS 播放、查看 proposal/history、取消或失败的
  realtime session、关闭未保存表单。
- 对只读步骤可使用本文附录 K 的 SQLite count snapshot；不要在运行中的 app 数据库上执行写 SQL。

不要试图一次做完。建议按以下批次执行，每批结束就提交问题和结论，先修阻塞项再进入下一批：

## K. Optional Read-only Authority Audit

以下命令只用于 owner 数据库**副本**的前后计数，不会证明 UI 体验，但能捕获只读 surface 意外写入。
先完全退出 App 或复制数据库；不要对唯一真实库做实验。

```bash
DB="$HOME/Library/Application Support/listen/listen.sqlite"

sqlite3 -readonly "$DB" <<'SQL'
.mode list
SELECT 'learning_observations', COUNT(*) FROM learning_observations;
SELECT 'semantic_judgments', COUNT(*) FROM semantic_judgments;
SELECT 'judgment_adjudications', COUNT(*) FROM judgment_adjudications;
SELECT 'projection_proposals', COUNT(*) FROM projection_proposals;
SELECT 'projection_decisions', COUNT(*) FROM projection_decisions;
SELECT 'lexical_capability_states', COUNT(*) FROM lexical_capability_states;
SELECT 'lexical_capability_history', COUNT(*) FROM lexical_capability_history;
SELECT 'review_items', COUNT(*) FROM review_items;
SELECT 'review_attempts', COUNT(*) FROM review_attempts;
SELECT 'personal_expression_attempts', COUNT(*) FROM personal_expression_attempts;
SELECT 'production_corpus_documents', COUNT(*) FROM production_corpus_documents;
SQL
```

使用方法：

1. 只读子场景开始前保存一次输出；
2. 执行 Coach browse、semantic query 或 TTS playback；
3. 完全结束相关异步请求后再次保存输出；
4. 预期所有表 count 不变；
5. 不要跨越“保存 attempt / proposal decision / explicit override”等合法 writer 再比较，否则差异没有
   诊断意义。

Realtime failure audit 还应额外比较：

```bash
sqlite3 -readonly "$DB" <<'SQL'
SELECT 'realtime_sessions', COUNT(*) FROM realtime_conversation_sessions;
SELECT 'realtime_turns', COUNT(*) FROM realtime_conversation_turns;
SELECT 'production_documents', COUNT(*) FROM production_corpus_documents;
SQL
```

失败/中断可以按设计写 session terminal fact，但不得新增 finalized learner turn 对应的 production
document；判断时同时查看 terminal status，不只看 session count。
