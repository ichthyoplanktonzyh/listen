# Phase 3.19 Product Correction After Owner Run 1

状态：ACTIVE — OWNER QA FINDINGS TRIAGED

日期：2026-07-20

## Outcome

Owner Run 1 proved packaged-app viability and several core Speaking/Personal Expression paths, but it rejected the
assumption that Phase 3.x can close through isolated checklist cleanup. Review, task input scope, action-to-evidence
visibility and several “degradation” paths need one coherent correction before QA resumes.

## Product Decisions

- ADR 0025 makes explicit `ContentSelection` the source of a task. Listening/Reading can be document- or
  selection-scoped; Speaking/Writing must never infer an unbounded document from current playback.
- ADR 0026 keeps only goal-preserving fallbacks. A text snapshot explains history but does not replace requested
  audio; provider configuration is not promoted before its user value is established.
- Cold-start absence is a valid state, not failed learning and not a reason to fabricate proposal/Coach data.

## Correction Slices

### Slice A — Deterministic P1 Hotfixes

Implementation status (2026-07-20): CODE COMPLETE / OWNER PACKAGED RETEST PENDING. Flutter analyze,
456 Flutter tests and macOS Debug build pass.

- Review playback exposes in-page play/pause and clears its loop when paused or leaving the card.
- Realtime audio requests macOS microphone permission before capture and gives a recoverable denial message.
- Regression tests must reproduce the exact owner symptoms before fixes and turn green after fixes.

### Slice B — Content Selection Contract And Entry Routing

- Define a typed, transient `ContentSelection` handoff using existing sentence/range snapshots; do not invent a new
  durable universal target.
- Intensive media CTA opens the document and then an explicit selection/activity chooser; it does not merely select
  a generic side panel or start an extensive session.
- Speaking/Personal Expression seed the exact selected sentence/range and return to the originating asset/content.
- Every task shows selection text and boundaries; source playback is bounded and controllable.

### Slice C — Review As One In-page Experience

- Review owns an inline second-decoder source player, resolving any durable local source by media identity/fingerprint;
  it does not require the source to equal the primary player's current media.
- Play/pause/replay/loop and card transition stay in Review; leaving/rating a card releases audio.
- “跟一下这个片段” and delayed retelling are hosted inside the Review route. They do not pop to home or open a
  separate floating practice panel; completion/cancel returns to the same card/queue position.
- Snapshot-only state appears only after real resolution failure and offers a concrete relink action where possible.

### Slice D — Make Learning Effects Discoverable

- Hunting result immediately states what was recorded: recognized/not recognized/not noticed, and whether it affects
  evidence, candidate pools or neither.
- Extensive completion links to the persisted comprehension report and shows how it contributes to content-fit
  calibration without exposing raw formulas as truth.
- Lexical detail gains a discoverable evidence/history entry even before a proposal exists.
- Replace internal “two channels” and authority jargon in owner-facing copy with speaking/writing history and concrete
  outcomes.

### Slice E — Asset Information Architecture

- Add a stable home/asset-layer “我的表达” entry independent of Reading capture.
- Keep Reading capture as a contextual creation shortcut, not the only navigation route.
- Revisit Coach LLM availability and TTS promotion only after a concrete user action needs them; do not ask owner to
  test configuration for configuration's sake.

### Slice F — Degradation Audit

- Inventory each consumer fallback with trigger, preserved goal, recovery action and regression test.
- Remove or demote paths that substitute text for audio, hide resolver bugs, advertise unused providers or exist only
  because an older phase anticipated them.
- Preserve source snapshots, append-only history and explicit unassessed states; those are data integrity, not optional
  UX degradation.

### Slice G — Resume Owner QA

- Rebuild the packaged app and rerun J1.4, Review E3, J1.7–J1.9, J1.16, J2.6, J2.12, J2.16–J2.17, then J3.2.
- J2.19–J2.29 remain blocked until natural owner data creates qualified facts; do not seed fake learning history.
- J4 resumes only after the exact install error/log is captured. J5 remains deferred until its user-facing role and
  entry points are redesigned.

## Non-goals

- Tuning content-fit thresholds against the current cold-start library.
- Manufacturing proposals or Coach facts for QA.
- Removing data-integrity behavior such as snapshots, append-only evidence or explicit unavailable states.
- Expanding provider categories or adding new learning features during correction.
