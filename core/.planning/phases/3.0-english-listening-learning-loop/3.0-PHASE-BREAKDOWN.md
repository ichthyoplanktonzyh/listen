## 全局设计规则（所有 3.x phase 必须遵守）

1. **可组合，不强制流程（P3）**：每个 phase 交付的功能必须有独立入口、独立价值、
   可单独使用。exit signal 必须包含"该功能在没有其他 3.x 功能的情况下可独立使用"。
   环节之间只做自然引导，不做使用门槛。
2. **场景不绑定设备（P2）**：交互设计不得依赖桌面专有假设；当前实现落在 macOS
   桌面端，但概念与数据模型必须支持未来任何端全量实现。生产端（重模型）是唯一
   PC-only 能力。
3. **泛听默认零打扰（P4）**：任何进入泛听路径的增强（猎词单、提醒等）必须显式
   开启并有打扰预算。
4. **不课程化、不游戏化（P5）**。
5. **capability gating**：所有新入口继承现有能力矩阵降级逻辑（无 Word sync 禁精确
   cloze；无 chunk 回退句级；媒体丢失保留 snapshot）。
6. **继承 3.0 guardrails**：练习/复习失败不静默修改用户能力 override；兼容期 legacy
   `LearningStatus` 也不得被绕过 suggestion 直接升级；raw CTC 不作教学真值；Anki 只是
   adapter；dashboard 从 durable attempt/event 聚合；
   L1-aware 走 profile/provider。
7. **evidence class 纪律**：难度分数、升级阈值、提示预算等启发式参数按
   `heuristic_proxy` 记录，不硬编码为产品真理；UI 呈现保持可解释。
8. **ADR 0014**：3.x 新 Dart DTO 手写 + fixture 契约测试。
9. **先派生后建模（C-6）**：新概念（卡点状态、悬案等）优先从既有事件/资产派生，
   派生不足再升格显式 domain 实体；纸面抽象按切片验证、允许改形状。
10. **目标粒度诚实**：clip/sentence/construction attempt、LLM judgment、lexical observation、
    capability projection/override 分离；一次片段理解不批量升级其中所有词。
11. **LLM 厂商中立且可选**：领域契约不暴露厂商 wire format；无 provider、离线、拒绝或
    schema invalid 时核心任务仍可用，不制造学习失败。
12. **自动判定先校验**：小 smoke 只验证管线；开发集/留出集分离。未经 3.12.1 留出集
    校验的 LLM judge 不进学习 surface；通过后先获"显示可纠正 heuristic feedback"资格，
    不直接影响长期 capability。
13. **Seam 预留裁决**：additive、读端/响应形状、不绑定资产身份的 envelope 可以预留
    （如 3.10 channel-ready envelope）；会固化目标身份或资产 schema 的泛化必须等真实
    consumer（如 FocusTarget 按 3.16 三 consumer razor）。标准详见
    `3.11-3.18-FOUR-CHANNEL-SHARED-CONTEXT.md` §3.6。

## 当前进度审计与后续执行顺序

### Gate Q：3.7 开工前先关闭真实 QA 债务

当前代码已越过 3.6.2，但四个上游 phase 尚未正式收口：

1. 3.3：30 分钟真实媒体泛听 QA + 全局热键/收藏容器裁决；
2. 3.35：按 3.4.1 新 capability UI 重新建立工作台真实 QA 基线；
3. 3.4：迁移后 ≥8 张声音卡真实媒体 QA。
4. 3.5：Slice 9 真实媒体库分档 QA，至少确认一个 meaning 高 / sound 低的精听靶材料。

3.7 同时依赖前三者的泛听交互、工作台入口和 hunting candidate/review 链路；3.5 又是
当前仍为 ACTIVE 的未完成主 phase，因此 Gate Q
必须先完成。Owner 可以逐项明确豁免并把替代验证写入 3.7 QA，但不得默认把“代码完成”
当作“产品已验证”。这不是新 phase，不新增功能，只清偿验收债务。
执行清单：`3.7-GATE-Q-CHECKLIST.md`。

### 执行序列

1. **3.1 先行**：3.0.1 后端 vertical slice 已就绪，直接兑现；验证型精听是
   "已主动验证通过"状态的前提，后续 summary 才有含金量。
2. **3.2 紧随**：把 3.1 的练习变成"处理完了"的闭环感；产出熟料标记供 3.5。
3. **3.3 第三**（可与 3.1/3.2 并行）：泛听闭环独立成立，产出 Inbox 供 3.4。
4. **3.35 UI 重构**：在继续增加复习、难度、词典和 dashboard surface 前，先统一当前
   精听/泛听/Inbox 的信息架构、视觉系统和主工作台；同时为本地与未来在线来源建立
   来源中立的内容入口。
5. **3.4 第五（已实现后暂停 QA）**：精听、泛听两路沉淀进入复习，升级建议引擎形成现有
   listening evidence 基线；其旧状态目标等待 3.4.1 迁移。
6. **3.4.1 ~ 3.4.3 插入式领域重构**：先迁移四通道能力模型，再分离语义/韵律组，最后
   对 Construction 做身份 spike；共享上下文见 `3.4.X-LEARNING-DOMAIN-V2-SHARED-CONTEXT.md`。
7. **3.5 随后恢复**：练习历史与新 reading/listening profile 可分别喂 meaning/sound fit；双维难度直接实现（产品决策，
   不做前置分化实验），但保持可解释 + heuristic_proxy 标注。
8. **3.6**：corpus index 是独立后端工程量；词典证据接入新的 capability projection/suggestion。
9. **Gate Q 后完成 3.7 ~ 3.10**：3.7 保持 listening-only；3.8 只交付 shadowing 模仿层
   并建立 RecordingAsset；3.9 只做 listening L1-aware；3.10 建 listening Coach v1 与
   channel-ready envelope，不提前伪造四通道指标。
10. **3.11 地基先行**：先固定四层事实和证据矩阵，避免 Studio 直接把 LLM 输出写能力状态。
11. **3.12 再接 LLM**：用两个异构协议 adapter 证明厂商中立，完成隐私/密钥/降级；
    其余协议 adapter 为增量 slice。judge 判定在此阶段不进任何学习 surface。
12. **3.12.1 judge 资格评估**：fixture + 人工 gold + 留出集，按预登记门槛授予三级资格
    （不可用 / 仅可显示 / supporting evidence）；可与 3.13 并行，3.13 不硬依赖它。
13. **3.13 → 3.15 一次一个 Studio**：Reading 复用最多、风险最低（无 LLM 资格时以
    手工 rubric + 自评交付），随后 Speaking 消费 3.8 录音和 3.12.1 资格结论，
    最后 Writing 复用 rubric/revision 基础。
14. **3.16 验证个人表达**：兑现 3.4.3 UserSentencePattern；用真实 consumer 决定是否建
    FocusTarget，不为抽象完整提前迁移 Hunting List。
15. **3.17 才做新 projection/review**：先积累真实 evidence；证据不足的通道保持 unassessed。
16. **3.18 最后整合 Coach**：消费所有 durable facts，完成同一真实内容听→读→说→写的
    端到端 closeout。

## 范围外（至 3.18 仍不承诺）

- 移动端正式客户端与跨端同步实现（数据模型保持 sync-ready：durable ID + 事件流）。
- 自研泛听硬件（作为"一颗按钮、没有屏幕"设计约束存在，见 P6）。
- 在线语料聚合 / 系统性下载外部音视频（听力词典只做本地语料 + 外链兜底）。
- speech-analysis 算法质量提升（2.19/2.20/2.21 搁置中）。
- Anki 双向同步（export adapter 是后续增强）。
- 通用 AI 聊天机器人、实时语音 agent、标准化考试/CEFR 预测、综合语言分。
- 云端账号、跨设备同步、LLPlayerNext 托管 LLM 代理与订阅计费。
- 通用 EPUB/PDF 排版生态、长篇作文课程与 canonical Construction 自动库。
