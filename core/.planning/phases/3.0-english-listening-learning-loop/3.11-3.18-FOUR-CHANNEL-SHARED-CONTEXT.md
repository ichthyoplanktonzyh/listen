## 1. 目的

Phase 3.1–3.10 以英语听力闭环完成产品楔子。Phase 3.11–3.18 不推翻这条路线，而是在
真实媒体、个人语料、Practice/Review、四通道 capability profile 和可解释证据之上，
逐个建立 reading、speaking、writing 及跨通道 coach。

执行纪律：一次只推进一个 foundation / Studio phase；每个 Studio 必须独立可用，缺少
LLM 或上游通道时干净降级，不能以“完整四技能”作为单次大爆炸交付。

计划保鲜：3.11–3.18 的 PLAN 写于 3.7–3.10 开工前，是**方向承诺而非执行承诺**
（对照 3.7–3.10 v1 全部需要 v2 重写的教训）。每个 phase 开工前必须按上游落地现状
复核并修订其 PLAN（记修订记录），不得把本批 v1 文本当作可直接执行的规格。

## 2. 当前代码事实

1. `LexicalCapabilityProfile` 已有 reading/listening/speaking/writing 四通道，但它是
   **LexicalEntry 粒度**的长期画像，不是通用语言水平或片段理解分数。
2. `LearningObservation` 当前也是 lexical target，`ObservationTaskType` / `PracticeKind`
   是封闭枚举；新增阅读、复述、写作任务必须显式扩展或建立更合适的 clip/construction
   evidence，而不是把所有结果强塞进 lexical observation。
3. 只有 listening 已有 ADR 0019 evidence projection。reading/speaking/writing 尚无权威
   自动 projection writer，不能因新任务上线就直接写 acquired/not_acquired。
4. Phase 3.8 将兑现 `RecordingRepository` 与麦克风资产，但整媒体 transcription pipeline
   不等于已存在 recording-transcription use case。
5. Phase 3.4.3 只验证了 `UserSentencePattern` 身份，没有生产 persistence/API/UI。
6. Phase 3.10 是 listening-era Coach v1；它提供 channel-ready envelope，四通道完整消费
   在 3.18 完成。

## 3. 不变量

### 3.1 四层事实分离

```text
clip / sentence / construction attempt
    != SemanticJudgment
    != target-level LearningObservation
    != capability projection / override
```

- L1 复述默认是片段级 listening comprehension 事实，不批量升级片段中的词。
- 用户纠正一次 LLM 判断是 adjudication，不是 capability override。
- Shadowing completion 是模仿活动事实，不自动等于 constructed speaking success。
- 模型生成或改写的文本不是用户 writing evidence。

### 3.2 固定评分尺

多个回答只有引用同一个 `SemanticRubric` version 时才可直接比较。判断输出逐信息点包含
covered/partial/missing/uncertain、可定位 transcript span、ASR uncertainty 和完整 provenance。

### 3.3 厂商中立

Application trait 使用项目任务契约，不暴露 OpenAI messages、Anthropic content blocks、
Gemini contents/parts。协议 adapter 初始覆盖：

- OpenAI Responses；
- OpenAI Chat Completions-compatible（含自定义 base URL / 本地服务）；
- Anthropic Messages；
- Gemini native content / interaction API。

Provider capability descriptor 必须诚实表达 structured output、streaming、multilingual、
audio、context、refusal 与版本 provenance；协议兼容不等于能力等价。

### 3.4 安全与降级

- 密钥只进 keychain 或等价安全存储，不进普通 SQLite、日志、LLTimeline、portable bundle。
- 用户明确知道哪些 transcript/字幕/文本离开设备；自定义 endpoint 明示数据去向。
- 无 provider、离线、拒绝、截断、schema invalid 时保留核心学习行为，只退化为客观事实
  与用户自评，不制造失败证据。

### 3.5 Judge 资格

小 smoke 样本只能验证管线。Prompt 开发集与留出评估集分离；跨语言、同义改写、ASR
噪声、好/中/差和 abstain 均需覆盖。资格分三级（对齐 final 稿 §9）：未经独立人工校验
的 judge 输出**不进入学习 surface**；通过 3.12.1 留出集校验后获得"显示可纠正
`heuristic_proxy` feedback"资格；更大规模评估 + 3.17 confirmation gate 之后才可能
作为 supporting evidence，且永不单独产生 acquired。

`source_kind=llm_judgment` 与 `validation_class=heuristic_proxy/manual_product_qa/...`
是正交字段，不二选一。

Judge 资格评估（fixture、人工 gold、留出集、资格裁决）由 **Phase 3.12.1** 独立承担；
3.12 只建 provider 基础设施，其判定默认不获任何显示资格。

### 3.6 Seam 预留裁决标准

为未来预留 seam 时按以下标准裁决（记录 3.7 拒绝 FocusTarget 与 3.10 接受
channel-ready envelope 的一致依据）：

- **可以预留**：additive、读端/响应形状层面、不绑定资产身份或领域语义的 envelope
  （如 3.10 聚合响应的 channel 分区 + 缺席区块契约）。预留成本是一次契约测试，
  错了随时可弃。
- **必须等真实 consumer**：会固化目标身份、资产 schema 或跨通道语义的泛化
  （如通用 `FocusTarget`、Hunting List 的 target modalities）。此类抽象错了要迁移
  数据和语义，必须由 ≥1 个真实用例裁决（FocusTarget 按 3.16 的三 consumer razor）。

### 3.7 过渡期证据权威

3.11 定稿 evidence matrix ADR 之前（即 3.7–3.10 执行期间），证据归属争议以本文件 §3.1
四层分离 + final 讨论稿 §5/§6 为准；实现者不得自行发明证据语义，拿不准就先只记
attempt 事实、不写 observation。

## 5. 共同验证要求

- 所有新 Dart DTO 继续遵循 ADR 0014：手写 + committed fixture contract test。
- Provider adapter 使用同一 contract fixture suite，至少有模拟 server 覆盖成功、拒绝、
  schema invalid、截断、限流与超时。
- 新 evidence writer 必须有“不会污染错误通道/错误 target”的负向测试。
- 自动 projection 需单独研究依据、版本化纯函数、人工 QA 与 writer exclusivity 决策。
- 每个 Studio 至少完成一条真实内容端到端 manual_product_qa。

## 6. 完整退出状态

3.18 收口时，用户能从同一真实内容独立完成听、读、说、写任务；Dashboard 能解释各通道
已有事实和跨通道 gap；无 LLM 时核心任务仍可用；切换 provider 不改变领域语义；任何数字、
判定和 capability 变化均能追溯到 attempt、rubric、judgment、observation 或用户声明。
