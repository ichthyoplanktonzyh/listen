## 1. Why This Series Exists

当前 `LearningStatus`：

```text
null -> unknown_meaning -> known_not_recognized -> known_recognized
```

把至少四种不同事实压进了一条线性状态链：

1. 系统是否评估过该词；
2. 学习者是否知道词义；
3. 学习者是否能在声音中识别它；
4. 学习者在某个具体语境中是否成功。

这条链对早期“文字字幕上的听力词汇状态”足够，但已经无法支撑当前 3.x 学习闭环：

- Phase 3.4 聚合多语境听力证据并建议升级；
- Phase 3.5 需要分别计算 meaning fit 与 sound fit；
- Phase 3.6 需要在词典例句中记录逐例表现；
- Phase 3.8 将产生口语/跟读证据；
- 后续写作或自由产出不能继续塞入听力状态枚举。

同时，当前 `ChunkTimeline` 主要描述音频时间轴和声学/韵律边界；把它直接改名为
SenseGroup 会用语义分析覆盖一个仍然有价值的声音层。句子收藏、句式学习和构式抽象也需要
独立于字幕句及 chunk 的身份。

本系列的目标不是增加几个枚举，而是重新划清四类领域事实：

```text
学习对象        决定“学什么”
能力画像        描述“当前会什么”
观测证据        记录“为什么这样判断”
素材与分析标注  提供“在哪个上下文中学习”
```

## 3. Authoritative Terminology

### 3.1 Learning asset / mastery target

能够形成长期能力画像的对象，例如词汇表达、词义和构式。

### 3.2 Learning material / exemplar

用于接触、收藏、回听和练习的具体内容，例如句子、片段、对话和文章。素材可以长期保存，
但不必拥有 `known / unknown` mastery。

### 3.3 Annotation

附着于素材、可以按 provider/version 重建的结构，例如 token、SenseGroup、韵律组和构式命中。

### 3.4 Observation / evidence

用户在某个任务、通道和上下文中的一次真实表现。Observation 不等于长期能力状态。

### 3.5 Capability assessment

系统或用户对某个长期能力维度的当前结论：

```text
unassessed     尚未评估
not_acquired   已有结论：尚未掌握
acquired       已有结论：已经掌握
```

### 3.6 Override

用户对当前能力结论的显式声明。Override 可以优先于系统投影，但不能删除、改写或伪造历史证据。

## 4. Cross-Phase Invariants

以下规则对 3.4.1、3.4.2、3.4.3 及后续消费者具有约束力：

1. `unassessed` 不等于 `not_acquired`。
2. reading / listening / speaking / writing 默认不存在强制单向蕴含关系。
3. 能力画像不能替代原始证据；算法变化后应能重新投影。
4. 用户 override 不删除历史证据，也不伪装成练习结论。
5. 自动推断不能静默改写用户 override。
6. 所有自动分析和投影必须记录 source、provider/algorithm version、evidence class 或等价 provenance。
7. 第一阶段能力画像仍可锚定现有 `LexicalEntry`，但身份和契约必须预留未来 `sense_id`。
8. SenseGroup 是句子上下文中的 occurrence，默认不是全局词汇资产。
9. 语义组与韵律组是独立分析层，允许一对一、一对多和多对一对齐。
10. Collocation 是 multiword lexical expression 的分类，不是与 word/phrase 并列的粒度。
11. SentenceExemplar、Construction、ConstructionOccurrence 和用户个人句模具有不同身份。
12. 构式最终画像可以保持 recognition / production 两维，但观测必须记录 modality。
13. 自动生成标注可删除重建；收藏、笔记、override 和学习历史属于 durable user asset。
14. 旧模型迁移产生的是带来源的推定，不得伪装成用户明确陈述。
15. schema、API、Flutter 和导入导出采用 additive migration；旧模型只在所有消费者迁移并经过
    稳定期后删除。
16. （2026-07-07 增补）listening 的 `acquired` 结论默认指"无辅助、自然连贯语流"条件；
    更弱条件（孤立慢读、字幕辅助、选项提示）下的成功只是证据，不直接支持 acquired 结论。
17. （2026-07-07 增补）一个 (学习对象, capability) 的 projection 同一时刻只能有一个权威
    算法写入者；algorithm_version 变更即整体重算；手工确认路径要么写入 observation，
    要么显式声明为高优先来源，不得静默共用 projection 槽。
18. （2026-07-07 增补）模型的精细度不得泄漏到用户操作：交互层保持"认识/不认识"一次点击，
    四通道格子是暴露上限；assistance_level 等证据条件由系统从播放状态推断，禁止标注表单。

## 5. Target Learning Model

### 5.1 Lexical expression and future sense seam

长期目标：

```text
LexicalExpression
  └── LexicalSense
        └── LexicalCapabilityProfile
```

Phase 3.4.1 不实现完整词义词典、自动 WSD 或 sense 合并。当前 `LexicalEntry` 暂时承担
LexicalExpression 身份，新的能力记录允许 `sense_id = null`，为以后细化 `bank/银行` 与
`bank/河岸` 留出迁移路径。

### 5.2 Four independent lexical capabilities

```text
reading    从文字形式获得目标意义
listening  从声音形式获得目标意义
speaking   在口语表达中检索并实现该表达
writing    在书面表达中检索并实现该表达
```

每个通道使用 `CapabilityAssessment`，而不是 bool。产品 UI 可保持简单，但系统必须区分尚未评估
和明确尚未掌握。

### 5.3 Evidence shape

目标概念轮廓：

```text
LearningObservation {
  learning_object_id
  capability
  task_type
  result
  assistance_level
  surface_form        // 2026-07-07 增补：listening 证据必须记录词形/语音形式，
                      // lemma 级聚合取保守值（见精化评审 §4.3）
  context_ref
  evidence_class
  occurred_at
}
```

不要求 3.4.1 第一个切片一次性统一所有已有 PracticeAttempt、ReviewAttempt 和
LexicalObservation 表。阶段目标是建立稳定的通道语义和投影 seam，使既有事实能够被适配，
新事实不再只能写入 listening-only 枚举。

### 5.4 Assessment layers

```text
observed evidence
        ↓
system projection + confidence/provenance
        ↓
effective assessment
        ↑
optional user override
```

读模型可以返回 effective assessment，但持久化和导入导出必须能区分 projection 与 override。

## 6. Legacy Migration Contract

旧 `LearningStatus` 迁移不是无损事实转换。默认映射为：

| Legacy value | Reading | Listening | Speaking | Writing |
|---|---|---|---|---|
| `null` | unassessed | unassessed | unassessed | unassessed |
| `unknown_meaning` | not_acquired | unassessed | unassessed | unassessed |
| `known_not_recognized` | acquired | not_acquired | unassessed | unassessed |
| `known_recognized` | acquired | acquired | unassessed | unassessed |

说明：

- `unknown_meaning` 来自文字字幕交互，只能可靠说明阅读入口下未获得意义；不能据此伪造一次
  listening failure。
- `known_not_recognized` 和 `known_recognized` 是旧产品明确的 meaning × sound 组合，可近似
  映射到 reading/listening。
- speaking/writing 没有旧数据，必须保持 unassessed。
- 所有回填记录标记 `legacy_learning_status_migration` 或等价 source。

兼容窗口内：

- API 和导出格式保留 legacy `status` 读取能力。
- 新写路径以 capability profile 为权威；确有旧消费者时，通过明确 compatibility projection
  生成 legacy view，不反向把 legacy view 当成完整事实。
- 无法投影的四通道组合返回保守 legacy view 或 `null`，规则由 ADR 固定并测试。

## 7. Phase Boundaries

### 7.1 Phase 3.4.1 — Learning Capability Model v2

负责：

- Capability / Assessment / source / override 的领域契约；
- 通道化证据 seam 和既有证据适配；
- schema v22 additive persistence 与 v21 迁移；
- legacy status 回填、双读/兼容投影；
- repository / application / API / export-import；
- diagnosis 改用 reading/listening 能力与上下文证据；
- Flutter 词汇详情、词汇本、字幕样式和升级建议迁移；
- Phase 3.4 升级建议从“枚举升级”迁移为 listening capability proposal；
- sense identity seam，但不实现完整 LexicalSense。

不负责：

- SenseGroup 算法；
- UDPipe 或其他解析器集成；
- 完整 SentencePattern / Construction；
- speaking/writing 自动评分；没有证据时保持 unassessed。

### 7.2 Phase 3.4.2 — Semantic / Prosodic Group Separation

负责：

- 新增句子 token-span 型 SenseGroup analysis；
- 明确现有 ChunkTimeline 的 prosodic/audio ownership；
- 双层对齐契约与回放映射；
- provider/version/confidence/lifecycle；
- 固定多语言 fixture 和 parser/provider spike；
- 在证据足够后决定是否把 ChunkTimeline 逐步迁名为 ProsodicGroupTimeline。

不负责：

- 把所有 SenseGroup 变成词汇本资产；
- 用 UD 输出覆盖真实声学边界；
- 在算法未验证前全局重命名数百处 chunk 引用。

### 7.3 Phase 3.4.3 — Construction Modeling Spike

负责：

- SentenceExemplar / Construction / ConstructionOccurrence / UserSentencePattern 的身份；
- slot、变体归并、嵌套命中和用户自定义句模边界；
- recognition / production 画像及 modality-tagged evidence；
- 小型固定语料 spike、去重结果和后续产品切片建议。

不负责：

- 未验证身份前建立大规模生产表；
- 自动生成大量低质量句式；
- 把具体收藏句和抽象构式合成同一实体。

## 9. Persistence and Contract Strategy

### 9.1 SQLite

- 当前基线为 schema v21。
- v22 只能 additive 新增能力/override/必要索引，不删除 `lexical_entries.status`。
- 必须提交 v21 fixture 并覆盖 v21 -> v22 migration、重复打开幂等、失败备份恢复。
- migration 合入 main 后不可原地修改；修正使用下一个 schema version。
- 删除 legacy status 至少推迟到所有 active consumer 迁移后的独立 cleanup phase。

### 9.2 Local API

- `/v1` 内优先使用 additive optional fields，避免 sidecar/Flutter 在过渡提交中同时断裂。
- 新 Dart DTO 继续遵守 ADR 0014：手写解析 + committed fixture contract test。
- legacy status 标记 deprecated，但兼容窗口内仍可读取。

### 9.3 Portable vocabulary assets

- 新 bundle 必须携带 capability assessments、source、override 和必要证据。
- 导入不得用低置信迁移推定覆盖较新的本地用户 override。
- 老 bundle 可导入并走与 SQLite 相同的 legacy mapping。
- 新 bundle 导入旧程序不承诺可用；版本拒绝必须明确，不能静默丢失四通道信息。

### 9.4 LLTimeline

3.4.1 不修改 LLTimeline。3.4.2 如新增 SenseGroup artifact，必须做独立版本决策，且保持旧
ChunkTimeline 可消费。

## 10. Git and Delivery Rules

本系列不使用一个长期巨型重构分支。每个可验证切片使用短分支，从最新 main 创建，rebase 后
以 fast-forward 合入。

3.4.1 推荐切片：

```text
codex/3.4.1-planning-context
codex/3.4.1-domain-contract
codex/3.4.1-persistence-dual-write
codex/3.4.1-diagnosis-api
codex/3.4.1-desktop-migration
codex/3.4.1-legacy-cleanup
```

每个合入 main 的提交必须：

- 可编译并通过对应范围测试；
- 行为与测试同提交；
- 更新 `CHANGELOG.md`；
- 不混入无关格式化、机械重命名或其他 phase 工作；
- 说明处于 additive、dual-read、authority-switch 或 cleanup 哪个迁移阶段。

禁止依赖 `git revert` 作为数据库降级方案。数据库恢复依赖迁移前备份和恢复测试。

## 12. Superseded Decisions

ADR 0012 以下结论仍有效：

- Token / LexicalUnit / ListeningUnit 是不同语言轴；
- normalized key 为 provider-opaque；
- language profile/provider 和 clean degradation；
- diagnosis reason 与能力状态分离；
- L1 -> L2 diagnosis seam。

ADR 0012 中“单一 `LearningStatus` 是跨语言稳定理解轴并作为 durable asset”的决定被本系列新
ADR 部分取代。新的跨语言不变量是：

```text
能力维度语义稳定
+ 每维 assessment 区分 unassessed / not_acquired / acquired
+ 证据和 override 分层
```

旧 ADR 不修改，新的 ADR 记录 supersession，保持历史可追踪。

## 14. 2026-07-07 Refinement Addendum

第二轮模型精化评审（`.planning/discuss/learning-domain-model-v2-refinement-review.zh.md`）
的裁决对本系列生效：

1. **复杂度分层原则**：证据层允许丰富（字段自动采集、不可逆）；决策层保持简单；
   交互层禁止泄漏模型精细度（不变量 18）。字段裁决标准：新增字段必须同时有自动写入方
   和改变具体决策的消费方，否则只预留 nullable seam。
2. **投影 seam 字段**：`CapabilityProjection` 增加 `confidence: Option<f32>` 与
   `evidence_as_of_ms: Option<u64>`，真证据投影算法上线前保持 `None`。
3. **证据层 slice 是 3.5 的前置**：observation 追加式 + 通道化 + surface_form（§5.3），
   连同投影写入者互斥规则（不变量 17）一起落地。
4. **SenseGroup 用户修正 = overlay**：ADR 0016 增补；schema v23 不得把用户修正
   写进 provider analysis 行内数据。3.4.2 无编辑 UI，不建 overlay 机制，只保证不排除。
5. **Sense 身份 spike** 排在 3.4.3 之后、3.6（listening dictionary）之前。
6. **明确砍掉**：混淆词对对象、导入时钟仲裁、override 衰老机制（仅保留 ADR 0015 的
   建议复核语句）、通用 capability registry。单用户假设为显式接受的产品简化。
7. **来源标注修复**：外部词表导入的 capability 同步使用 `Import` 来源；legacy status
   兼容同步使用 `LegacyLearningStatusMigration` 来源 + `legacy-status-compat-v1` 算法版本；
   `EvidenceProjection` 保留给真证据路径。
