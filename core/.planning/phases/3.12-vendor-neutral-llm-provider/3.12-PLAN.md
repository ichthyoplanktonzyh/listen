# Phase 3.12 Plan: Vendor-neutral LLM Provider & Judge Qualification

状态：PLANNED

日期：2026-07-11

上游输入：Phase 3.11、
`.planning/phases/3.0-english-listening-learning-loop/3.11-3.18-FOUR-CHANNEL-SHARED-CONTEXT.md`、
`.planning/discuss/four-channel-product-and-vendor-neutral-llm-final.zh.md`。

## Objective

为 rubric generation、semantic judgment 与 writing feedback 建立厂商中立 provider 系统，
覆盖当前主流原生/兼容 API 格式，并用开发集/留出集验证跨语言 judge 的诚实能力边界。

## User Value

用户可以选择自己的云端或本地模型服务，不被锁定在单一厂商；没有 API、费用预算耗尽或
provider 失败时，阅读、录音、复述和写作仍可继续，只失去自动语义反馈。

## Scope

### In

- Application traits：`SemanticRubricProvider`、`SemanticJudgeProvider`、
  `WritingFeedbackProvider`；输入输出只使用 3.11 contract。
- `LlmProviderProfile`：adapter kind/protocol、base URL、model ID、认证引用、timeout、
  retry、并发/费用预算、retention preference、允许用途。
- Capability descriptor/probe：structured output、streaming、multilingual、audio/context、
  refusal、model-version provenance。
- 初始 adapter：
  - OpenAI Responses；
  - OpenAI Chat Completions-compatible（自定义 base URL，覆盖本地服务）；
  - Anthropic Messages；
  - Gemini native content/interaction API。
- 密钥走 macOS Keychain 或等价 secure store；日志、SQLite、bundle 全链路脱敏。
- 设置 UI：明确选择 provider、用途、数据离开设备范围、连通性/能力测试与费用上限。
- 标准化错误：offline、auth、rate limit、timeout、refusal、truncated、schema invalid、
  unsupported capability。
- LLM-judge eval：开发集和独立留出集；L1/L2、同义改写、ASR 噪声、好/中/差、abstain；
  至少两个协议族/模型族交叉运行。

### Out

- 自动写 reading/speaking/writing capability projection。
- 通用聊天机器人、agent tools、web search、RAG 或平台内置工具使用。
- 托管 LLPlayerNext 代理服务、账号计费与跨设备密钥同步。
- 将 OpenAI-compatible 误认为完整能力兼容；每个能力必须 probe/declare。

## Dependencies

- 3.11 Rubric/Judgment/Adjudication contract 与 persistence。
- 网络 API 是可选能力；本地核心路径不得成为其依赖。

## Key Work

1. 先用两个不同协议 adapter 通过同一 fake-server/contract suite，证明 trait 非单厂商形状；
   再补齐其余初始 adapter。
2. Secure profile storage 与设置/连通测试；自定义 endpoint 显示数据去向警告。
3. 结构化输出 parser/validator、有限重试、费用/usage 记录、取消和超时。
4. Judge fixture 制作与人工 gold：开发/留出隔离，记录 precision/recall、引用真实性、
   abstain、重复稳定性及各 provider 差异；在查看留出结果前预先登记指标、通过门槛和
   “只可展示 / 可作 supporting evidence / 不可用”三级资格语义。
5. 资格裁决：首版默认仅显示可纠正 `heuristic_proxy` feedback；若留出集不足，明确记录
   失败边界，不因接通 API 宣称获得 projection 资格。
6. 新 ADR：provider neutrality、secrets/privacy、provenance、adapter capability semantics。

## Exit Signal

- 至少 OpenAI Responses、Anthropic Messages、Gemini native 和一个 OpenAI-compatible
  endpoint 能通过同一 rubric/judgment contract smoke；协议特有限制有明确 descriptor。
- 切换 provider 后领域 JSON 与 UI 语义不变；历史 judgment 仍指向原 provider/model/prompt。
- 删除/禁用 API key 后核心任务可用，自动反馈诚实降级。
- 留出集报告可复现，且没有用开发集成绩授予产品资格。

## Guardrails

- Flutter 与 HTTP route 不拼 prompt、不持有厂商 SDK 类型。
- 密钥不落普通数据库或日志；错误信息不得回显 credential/header。
- 不保存供应商隐藏 reasoning；只保存产品需要的结构化断言和公开 provenance。
- `source_kind=llm_judgment` 与 validation class 分离。
