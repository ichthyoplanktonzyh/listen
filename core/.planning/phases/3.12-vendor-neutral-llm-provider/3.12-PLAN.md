## Objective

为 rubric generation、semantic judgment 与 writing feedback 建立厂商中立 provider 系统：
application 层任务契约 + 协议 adapter + 安全密钥存储 + 诚实降级。用两个结构不同的协议
adapter 通过同一契约测试，证明领域层未被任何厂商 wire format 绑架。

## User Value

用户可以选择自己的云端或本地模型服务，不被锁定在单一厂商；没有 API、费用预算耗尽或
provider 失败时，阅读、录音、复述和写作仍可继续，只失去自动语义反馈。

## Scope

### In

- Application traits：`SemanticRubricProvider`、`SemanticJudgeProvider`、
  `WritingFeedbackProvider`；输入输出只使用 3.11 contract。
- `LlmProviderProfile`：adapter kind/protocol version、base URL、model ID、认证引用、
  timeout、retry、并发/费用预算、retention preference、允许用途。
- Capability descriptor/probe：structured output、streaming、multilingual、audio/context、
  refusal、model-version provenance。协议兼容不等于能力等价，能力必须声明或探测。
- **Slice 1（中立性证明，必做）**：两个异构协议 adapter 通过同一 fake-server/contract
  suite——
  - OpenAI Chat Completions-compatible（自定义 base URL，覆盖多数兼容云服务与本地服务）；
  - Anthropic Messages（结构不同的 content block 协议）。
- **Slice 2（增量协议，owner 按需排期，可推迟到有真实使用需求）**：OpenAI Responses、
  Gemini native content/interaction API；新增 adapter 只加 adapter 与 descriptor，
  不改 3.11 领域契约（这是 Slice 1 必须证明的性质）。
- 密钥走 macOS Keychain 或等价 secure store；日志、SQLite、bundle 全链路脱敏。
- 设置 UI（最小面）：选择 provider、用途、数据离开设备范围、连通性/能力测试与费用上限；
  自定义 endpoint 显示数据去向警告。
- 标准化错误：offline、auth、rate limit、timeout、refusal、truncated、schema invalid、
  unsupported capability。

### Out

- **LLM-judge 资格评估（开发集/留出集、人工 gold、资格裁决）→ Phase 3.12.1**。
  本 phase 产出的判定一律停留在"未获显示资格"状态，不进入任何学习 surface。
- 自动写 reading/speaking/writing capability projection。
- 通用聊天机器人、agent tools、web search、RAG 或平台内置工具使用。
- 托管 LLPlayerNext 代理服务、账号计费与跨设备密钥同步。
- 将 OpenAI-compatible 误认为完整能力兼容；每个能力必须 probe/declare。

## Dependencies

- 3.11 Rubric/Judgment/Adjudication contract 与 persistence。
- 网络 API 是可选能力；本地核心路径不得成为其依赖。

## Key Work

1. Slice 1：traits + 两个异构 adapter 过同一 fake-server/contract suite（成功、拒绝、
   schema invalid、截断、限流、超时全覆盖），证明 trait 非单厂商形状。
2. Secure profile storage 与设置/连通测试；自定义 endpoint 显示数据去向警告。
3. 结构化输出 parser/validator、有限重试、费用/usage 记录、取消和超时。
4. Capability descriptor/probe 机制与 per-provider 差异记录。
5. 新 ADR：provider neutrality、secrets/privacy、provenance、adapter capability semantics。
6. （Slice 2，可推迟）OpenAI Responses 与 Gemini native adapter 增量接入。

## Exit Signal

- 两个异构协议 adapter 通过同一 rubric/judgment contract smoke；协议特有限制有明确
  descriptor；新增第三个 adapter 被证明只需 adapter 层工作量（Slice 2 落地或以
  设计评审形式确认）。
- 切换 provider 后领域 JSON 与 UI 语义不变；历史 judgment 仍指向原 provider/model/prompt。
- 删除/禁用 API key 后核心任务可用，自动反馈诚实降级。
- 密钥全链路不落普通存储；错误信息不回显 credential/header。

## Guardrails

- Flutter 与 HTTP route 不拼 prompt、不持有厂商 SDK 类型。
- 密钥不落普通数据库或日志；错误信息不得回显 credential/header。
- 不保存供应商隐藏 reasoning；只保存产品需要的结构化断言和公开 provenance。
- `source_kind=llm_judgment` 与 validation class 分离。
- 本 phase 完成不授予任何 judge 显示/证据资格；资格语义全部在 3.12.1 裁决。
