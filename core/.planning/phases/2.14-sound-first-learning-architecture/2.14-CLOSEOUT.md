# Phase 2.14 Closeout: Sound-First Learning Architecture

完成时间：2026-06-26 CST
状态：COMPLETED

## Scope

Phase 2.14 建立了第二条声音线的第一版生产/消费闭环：

```text
CTC observed phones
  + expected pronunciation
  -> stable LearningPhone
  -> syllables
  -> pause-based prosodic phrases
  -> PhoneTimeline.sound_analysis
  -> Flutter PhonemeRibbon grouped display
```

本阶段最重要的架构准则已落地：

> CTC provides audio evidence and timing; expected pronunciation provides teaching labels.

也就是说，CTC 负责真实音频证据、timing、duration、gap、confidence 和 pause；用户可见的
教学标签默认来自文本/词典/规则的 expected pronunciation。CTC label mismatch 不再直接显示给
学习者。

## Delivered

### 1. Stable Learning Phone Layer

- 新增 `ExpectedPhone / ObservedPhone / LearningPhone` 架构说明：
  `.planning/phases/2.14-sound-first-learning-architecture/2.14-STABLE-LEARNING-PHONE.md`
- Flutter `PhonemeRibbon` 不再直接显示 raw CTC phones。
- 新增 `buildLearningPhones()`：
  - expected label 来自 pronunciation provider。
  - observed CTC 只校准 timing/confidence。
  - `/s/` expected + `/k/` observed mismatch 时，默认仍显示 `/s/`。
  - 无 expected pronunciation 时保留旧 observed-only 降级。

### 2. Domain SoundAnalysis Model

新增 domain 模型：

- `SoundAnalysis`
- `SoundLearningPhone`
- `SoundSyllable`
- `SoundProsodicPhrase`
- `SoundPhoneEvidence`
- `ProsodicBoundaryEvidence`

`PhoneticAnalysis` 和 `PhoneTimeline` 均新增可选 `sound_analysis` 字段，并使用
`serde(default)` 保持旧 JSON 兼容。

### 3. Speech-Analysis Algorithms

新增 `speech_analysis::sound_analysis`：

- canonical expected phones 与 observed CTC phones 对齐生成 `SoundLearningPhone`。
- SSP/onset maximization 音节化。
- 明显 pause 会阻止 onset maximization 跨停顿抢辅音。
- pause-based prosodic phrase detection。
- raw insertion 不进入默认 learning phone display；保留为 observation/evidence 后续使用。
- `detected_in_audio` 升级策略收紧：高置信只是必要条件，generic `phone_substitution`
  不再被当作真实语流检测；只有弱读、flapping、同化、缩约、省音等已知 connected-speech
  family 可升级为 audio detection。

### 4. PhoneTimeline Resource Integration

- `build_ctc_phonetic_analysis()` 自动生成 `sound_analysis`。
- `build_research_fixture_phonetic_analysis()` 也生成 approximate sound analysis，便于测试和降级。
- `create_phone_timeline_from_analysis()` 将 `analysis.sound_analysis` 复制到 `PhoneTimeline`。
- SQLite 继续存完整 `timeline_json`，无需新增 migration。
- LLTimeline export/import 通过既有 PhoneTimeline 资源路径保留 `sound_analysis`。

### 5. Flutter Consumption

- `PhoneTimeline.fromJson()` 解析 `sound_analysis`。
- `PhoneTimeline.toSoundPatternJson()` 将 `sound_analysis` 传入现有 sentence sound-pattern 通道。
- `PhonemeRibbon` 支持：
  - `learning_phones` 作为显示 phones。
  - syllable gap 视觉分隔。
  - prosodic phrase vertical boundary。
  - finding evidence marker overlay；`detected_in_audio` 使用强标记，`supported_by_alignment` /
    `uncertain` 使用弱标记。marker 锚定到 learning phone，不改写教学标签。
  - observed insertion evidence 的最近 learning-phone 锚定 marker；不新增教学 phone，不改变
    label，只让插入/连读类证据在 ribbon 上可见。
- 无 `sound_analysis` 时保留本地 `buildLearningPhones()` fallback。

### 6. Contract

OpenAPI 已新增：

- `SoundAnalysis`
- `SoundLearningPhone`
- `SoundSyllable`
- `SoundProsodicPhrase`
- `SoundPhoneEvidence`
- `SyllableStress`
- `ProsodicBoundaryEvidence`

并补齐既有 `DetectedPhone.display_ipa` contract 字段。

## Deferred

以下内容不阻塞 Phase 2.14 收口：

- F0/pitch-based intonation phrase。
- 多语言音节化 profile 参数。
- 完整 observed insertion 详情 UI（当前仅做最近 learning-phone marker 锚定）。

这些应作为 Phase 2.15 或后续声音线诊断增强推进。

## Outcome

Phase 2.14 establishes the sound-first architecture without sacrificing teaching correctness:

- the text line keeps stable labels;
- the sound line contributes audio timing, rhythm and grouping;
- users are not shown unstable raw CTC guesses as learning targets;
- PhoneTimeline now carries a real sound organization layer ready for future diagnosis evidence.
