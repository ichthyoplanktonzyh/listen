更新时间：2026-06-26 CST
状态：COMPLETED

> **定位**：建立以真实语流为中心的第二条学习主线。Phase 2.13 完成了以文字为中心的
> 音素体验（词典音素 + 合成时间），本阶段的目标是从 CTC 真实音素出发，推导出完全
> 独立于文字的声音组织结构——音节、韵律词、韵律短语——并在 UI 上呈现，让学习者
> 能从声音本身理解语言，而不是依赖文字作为中介。
>

## 2026-06-26 架构修订：稳定教学标签优先

本阶段不把 CTC phone label 当成用户可见的教材答案。CTC 是真实音频观察层，但不是
phone identity 的真值层；它可能把应为 /s/ 的短促或低置信片段误识别成 /k/。学习训练
的默认展示必须稳定、可靠，不能把这种误识别直接暴露给用户。

核心准则：

> **CTC provides audio evidence and timing; expected pronunciation provides teaching labels.**

中文表述：

> **CTC 负责真实声音证据与节奏组织，教学标签由稳定的文本/词典/规则发音提供。**

因此后续所有声音线结构都区分三类 phone：

| 类型 | 来源 | 用途 | 是否默认展示给用户 |
|---|---|---|---|
| `ExpectedPhone` | 字幕文本 + 词典/规则/语言 profile | 稳定教学标签；回答“应该听回什么语言单位” | 是 |
| `ObservedPhone` | CTC / PhoneTimeline | 音频证据、timing、duration、gap、confidence、mismatch | 否，仅作证据 |
| `LearningPhone` | ExpectedPhone aligned to ObservedPhone timing | 用户训练用 phone；label 稳定，timing 尽量贴近真实音频 | 是 |

第一条文字线也必须遵守该规则：有 CTC 时，不再让 phoneme ribbon 直接显示 raw CTC
label；ribbon 显示 `LearningPhone`，即 expected label + observed timing/evidence。

声音线仍以真实声音作为组织中心，但“声音组织中心”指：

- syllable / prosodic phrase 的时间结构来自音频 observation；
- pause / duration / confidence / weak evidence 来自 CTC；
- 用户可见 label 由 expected pronunciation 约束；
- raw observed mismatch 保留给诊断和高级 evidence view，不作为默认训练答案。

## 两条线的关系

| | 文字线（Phase 2.13） | 声音线（本 Phase） |
|---|---|---|
| 数据来源 | Whisper 转录 → 词 → 词典发音 | CTC 模型 → 真实音素序列 |
| 组织层级 | Sentence → Word → Token → Phoneme | Sentence → Prosodic Phrase → Syllable → Phone |
| 时间边界 | 词边界（文字强加于声音） | 韵律边界（声音的自然断点） |
| 学习内容 | "说了什么" | "怎么说的" |
| 两者差异 | — | "为什么听不懂" |

两条线共享 sentence 作为最高作用域边界，数据共存于同一个 lltime.json。

## 理论基础

韵律层级（Nespor & Vogel 1986, Selkirk 1984）：

```
Phone → Syllable → Foot → Prosodic Word → Phonological Phrase → Intonation Phrase
```

- **音节**是语音产出的基本单位（MacNeilage 1998, Levelt et al. 1999）
- **韵律短语**由停顿、末尾延长（final lengthening）、语调重置界定
- 词边界在连续语流中经常消失（连读、弱化、省音）
- 声音线揭示的是这些文字线无法表达的真实发音模式

## Steps

### Step 0: Stable Learning Phone Layer

先修正现有文字线 ribbon 与后续声音线共用的 phone 表示，避免 raw CTC label 直接成为
教学标签。

- 输入：
  - `ExpectedPhone`：由 pronunciation provider 从文本、词典和规则生成。
  - `ObservedPhone`：由 CTC / active PhoneTimeline 产生。
- 输出：
  - `LearningPhone`：用户可见 phone。
- 合成规则：
  - `display label` 默认来自 expected phone。
  - `timing` 优先来自对齐到的 observed phone；对齐不足时回退 expected/word timing。
  - `confidence`、`raw observed label`、`mismatch` 作为 evidence 保留，但不覆盖默认 label。
  - 只有高置信且符合合法 allophone/reduction/connected-speech rule 的 observation，才可影响
    用户可见表现；第一版暂不让 observation 改写 label。
- UI：
  - `PhonemeRibbon` 消费 `LearningPhone` 等价结构，不直接消费 raw CTC phones。
  - raw CTC phones 可继续用于诊断面板、loop phone 和高级证据视图。
- 验收：
  - 当 expected 为 `/s/`、CTC 误识别为 `/k/` 时，ribbon 默认显示 `/s/`。
  - 当 CTC timing 可用时，ribbon 的跳动节奏可跟随 observed timing。

### Step 1: 音节化算法

从 `LearningPhone` / expected phones aligned to observed timing 推导音节边界，而不是从
raw CTC label 直接推导用户可见结构。

- 输入：`List<LearningPhone>`（按时间排序；label 稳定，timing 可来自 observed evidence）
- 输出：`List<Syllable>`，每个 syllable 包含 onset/nucleus/coda 音素索引
- 算法：响度排列原则（Sonority Sequencing Principle, SSP）
  - 元音为 nucleus（响度最高点）
  - 辅音按响度下降排向两侧
  - Onset Maximization：歧义辅音优先归入下一音节的 onset
- 响度等级（从低到高）：plosive < fricative < nasal < liquid < glide < vowel
- 实现位置：Rust `speech-analysis` crate，纯算法无 ML 依赖
- 测试：先用小型手工 gold fixture 覆盖清晰英语音节、/str/ onset、弱读 schwa、CTC mismatch
  不污染 label；TIMIT phone annotation 可作为后续 timing/evidence 参考，不假定存在天然
  syllable gold。

### Step 2: 韵律短语检测

从 aligned learning phones / observed timing 的时间特征推导短语边界。

- 边界证据（按可靠度排序）：
  1. **静音段**（silence/pause）：音素间 gap > 阈值（~100ms）
  2. **末尾延长**：短语末音节的 nucleus 时长显著长于句内平均
  3. **音素间距突变**：相邻音素间 gap 的局部峰值
- 输出：`List<ProsodicPhrase>`，每个 phrase 包含 syllable 索引范围 + 边界证据类型
- 不依赖 F0（基频）——CTC 模型不输出 pitch，且 F0 提取需额外工具。
- 第一版只把 pause/gap 边界标为高置信；末尾延长和局部峰值标为 tentative，避免把不稳定
  observation 呈现成确定事实。
- 实现位置：Rust `speech-analysis` crate

### Step 3: Domain 模型与持久化

- `domain` 新增 `Syllable`、`ProsodicPhrase`、`SoundAnalysis` 结构体
- `SoundAnalysis` 挂在 `PhoneticAnalysis` 之下（CTC 分析完成后自动推导）
- SQLite 存储：复用 `phonetic_analysis_results` 的 JSON 字段扩展
- LLTimeline export/import 保留 `sound_analysis`
- API 新增 `GET /v1/tracks/{id}/sound-analysis/{sentence_id}`

### Step 4: Flutter 消费与 UI

- `SubtitleController` 新增 `soundAnalysisBySentence`
- `PhonemeRibbon` 增强：可选按音节分组显示（音节间加视觉分隔）
- 韵律短语边界在 ribbon 上以垂直分隔线标记
- 新增声音线视图模式：ribbon 按韵律短语分段，而非按句子整条显示
- 与文字线的 chunk 对比视图（高级功能，可延后）

### Step 5: 声音线 Finding 关联

- 连读/省音/弱化等语流现象（speech rules）现在可以用声音证据佐证
  - 文字线：规则预测（"did you 可能连读"）
  - 声音线：真实证据（"检测到 /dɪdʒə/ 跨词边界"）
- Finding 的 `evidence_source` 区分 `rule_prediction` vs `audio_detection`
- 在 ribbon 上叠加 finding 标记（底部标记条/角标），点击展开详情
- raw CTC mismatch 不直接作为用户训练标签；必须通过 confidence、expected alignment 和合法
  connected-speech rule 过滤后，才升级为 `audio_detection` finding。

### Step 6: 测试与验收

- 音节化：英语 TIMIT 样本验证 + 手动标注对比
- 韵律短语：停顿检测准确率（precision/recall）
- 端到端：CTC 分析 → 自动推导音节/短语 → ribbon 显示分组 → 跳动
- lltime.json round-trip：export → import 保留 sound_analysis
- 性能：一句话通常 3-8 音节、1-3 韵律短语，无额外性能负担

## Risk & Mitigation

| 风险 | 应对 |
|---|---|
| SSP 音节化对英语不完美（如 /str/ onset） | 允许例外列表（language profile 可扩展） |
| 纯时间特征的韵律短语检测不够准确 | 先做高置信度（停顿），低置信度标为 tentative |
| 用户不理解"声音线"和"文字线"的区别 | UI 层面不暴露术语，用视觉差异（ribbon 分组方式）自然呈现 |
| 多语言适用性 | 音节化和韵律检测的核心原理跨语言通用；语言特异性通过 profile 参数化 |

## Success Criteria

1. CTC 分析完成后，音节边界和韵律短语自动推导可用
2. lltime.json 中 `sound_analysis` 字段可导入导出
3. Ribbon 可按音节分组显示，韵律短语边界可见
4. 声音线与文字线的差异（连读/省音等）在 UI 上可感知
5. 整条链路不依赖 F0 提取或额外 ML 模型
