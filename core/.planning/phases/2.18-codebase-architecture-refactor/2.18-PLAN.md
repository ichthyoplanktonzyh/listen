# Phase 2.18 Plan: Codebase Architecture Refactor

状态：COMPLETED

## Objective

趁项目尚未继续膨胀，把 2026-06-27 架构复盘中暴露的代码层问题收口为可验证的工程底座：

```text
冻结行为与契约
  -> 收敛核心数据模型
  -> 拆清 Rust 应用 / 持久化 / API 边界
  -> 重建 Flutter 状态机与 workflow coordinator
  -> 主干 quick gate、文档事实源和契约 parity 恢复可信
```

约束更新：本 phase 不需要历史兼容性。旧数据库、旧 LLTimeline JSON、旧 WordProfile 资源、
旧 API/UI adapter 都可以删除或失效；以新模型和新架构的清晰性为最高优先级。

### 0. Behavior Freeze And Safety Net

重构前先建立新目标行为护栏。这里的 freeze 保护的是用户仍需要的产品流程，不保护旧数据格式或旧资源：

- 固定当前关键 workflows 的 characterization tests：
  - 导入媒体和字幕。
  - 激活 subtitle resource。
  - 生成/激活 WordTimeline、ChunkTimeline、PhoneTimeline。
  - 用新 schema 导出/导入 LLTimeline。
  - 词汇状态更新、phrase candidate、diagnosis。
  - Flutter cue change 触发 diagnosis / phrase / pronunciation refresh。
- 整理 quick gate，确保每个后续拆分都能用同一组命令验证。
- 明确允许的行为变化清单；未列入的变化必须视为回归。

### 3. Core Domain Model Convergence

目标：决定学习资产和 timeline resource 的权威模型，避免新功能继续同时写入多套概念。

必须完成：

- 明确 `LexicalEntry` + `LexicalUnit` 是否成为新学习资产权威模型。
- 删除 `WordProfile` 作为业务模型的地位：
  - 若短期仍需保留旧 endpoint，endpoint 内必须转换到新模型。
  - 若旧 endpoint 不再值得保留，可以直接删除并同步 OpenAPI/generated client。
- 给 `WordStatus` 重命名或语义说明：
  - 如果未来覆盖 phrase / char / morpheme，不应继续暗示只属于 word。
- 为 `LexicalEntryKind` 与 `LexicalUnit.granularity/normalization` 制定桥接策略，避免两套身份轴长期并存。
- 抽象 timeline resource lifecycle：
  - `Candidate -> Active -> Archived` 为通用 lifecycle。
  - `Published` / `UserAdjusted` 等为 revision/provenance，不再混入状态语义。
- 将关键 `metrics_json` / `evidence_json` 收敛为 typed envelope：
  - 保留 `extra` 扩展字段。
  - 关键字段必须可测试、可迁移、可在 Dart 端 typed parse。

Acceptance gate：

- 架构文档记录权威模型决策和删除旧模型的取舍。
- Rust domain tests 覆盖 lexical identity、new asset id stability、timeline lifecycle transition。
- 新增代码不再创建 `WordProfile`；旧 `WordProfile` 代码被删除，或只剩临时 endpoint 转换层并有移除计划。

### 4. Persistence And Repository Boundary Refactor

目标：让 repository trait 按聚合/资源边界表达，不再由 `SubtitleRepository` 承担所有职责。

拆分方向：

- `SubtitleTrackRepository`
  - subtitle track / sentence CRUD。
  - status / language lifecycle。
- `PronunciationRepository`
  - word pronunciation cache。
  - sentence pronunciation analysis。
- `TimelineResourceRepository`
  - WordTimeline / ChunkTimeline / PhoneTimeline shared lifecycle。
  - active resource selection。
  - resource import/export support。
- `LLTimelineResourceRepository`
  - persisted LLTimeline metadata/artifacts。
- `LearningAssetRepository`
  - lexical asset authoritative path。
  - no legacy word adapter path unless explicitly temporary.

同时处理：

- active timeline uniqueness 从“查询最新 active”升级为 repository-level/schema-level invariant；
  如 schema 可承载，应增加 partial unique index 或等价事务测试。
- 明确哪些 JSON blob 是资源快照，哪些字段必须规范化为 queryable columns。
- 保留单连接 SQLite 作为当前本地 sidecar 的实现细节，但让 trait 边界不再假设单仓储巨对象。
- 允许重建 SQLite schema，不要求旧数据库自动迁移。

Acceptance gate：

- `application::AppServices` 不再直接依赖一个全能 `SubtitleRepository`。
- persistence tests 覆盖 active timeline 唯一性、archive/delete active 后的降级行为。
- schema 说明记录破坏性变更；旧数据库可以被丢弃或由开发者手动重建。

### 5. Application And API Boundary Refactor

目标：让 application 表达 use case，API 表达 transport，不让算法 crate DTO 或 router 字符串成为事实源。

必须完成：

- `application::dto` 不再公开 `speech_analysis::*` 类型别名；改为 application-owned DTO。
- `speech-analysis` 只通过 provider/use-case 边界进入 application。
- `api-http` 建立 route manifest，router 注册、OpenAPI parity test、generated client 更新共同消费同一事实源或同一校验源。
- `api-http/src/lib.rs` 保留 composition root，不继续扩大 route chain。
- SSE event payload 有 typed envelope；Flutter 不再以裸 `Map<String, dynamic>` 分发核心事件。

Acceptance gate：

- `rg "pub type .*speech_analysis" crates/application/src` 为空。
- OpenAPI route parity 缺口为 0。
- API tests 对 event payload / route groups 有最小 typed 覆盖。

### 6. Flutter State Machine Refactor

目标：把 `main.dart` 从业务流程中心收缩为 composition root，让状态机能表达 loading、ready、stale、error 和 media session 边界。

拆分方向：

- `MediaSessionController`
  - open media、save/restore progress、session generation。
- `BackendEventCoordinator`
  - SSE event routing。
  - typed event parsing。
  - stale event drop。
- `SubtitleWorkflowController`
  - primary/secondary track activation。
  - subtitle resource lifecycle。
- `TimelineResourceController`
  - word/chunk/phone summary refresh。
  - active timeline activate/archive/delete/generate。
- `LearningWorkflowController`
  - current cue diagnosis、phrase candidates、pronunciation lookup。
  - request generation guard。

状态建模要求：

- 对异步 workflow 使用 session/generation token，至少绑定：
  - media id。
  - primary track id。
  - cue id。
  - request kind。
- API responses 进入 UI 前尽量 parsed typed model。
- 仅保留真正开放扩展的 payload 为 `Map<String, dynamic>`，并用 wrapper model 隔离。
- `main.dart` 不再新增业务 workflow；保留 app composition、top-level layout 和 dialog wiring。

Acceptance gate：

- `main.dart` 明显缩小，并且不再直接实现 diagnosis / phrase / pronunciation / timeline refresh 的核心流程。
- `LearningState` / `SubtitleState` 中的核心字段不再使用裸 `Map<String, dynamic>`。
- cue 切换、媒体切换、track 切换期间的 stale async result 有测试或可复现 guard。
- `flutter analyze`、相关 Flutter tests 通过。

## Acceptance Criteria

- 核心学习数据模型不再双写或双读；旧模型已删除或只剩明确短期移除项。
- timeline resource lifecycle 有统一抽象和测试覆盖。
- `SubtitleRepository` 不再作为字幕、发音、timeline、LLTimeline 的全能接口。
- `application::dto` 不再向外暴露 `speech_analysis` DTO。
- Flutter `main.dart` 收缩为 composition root；核心 workflow 进入 controllers/coordinators。
- 核心 Flutter state 不再依赖裸 `Map<String, dynamic>` 表达业务状态。
- media / track / cue 切换期间的 async stale result 被 generation guard 丢弃。
- OpenAPI 覆盖所有已实现 `/v1` route，且没有记录未实现 route。
- `contracts/generated/local-api-v1.ts` 覆盖新增/补齐端点。
- `./scripts/validate-contracts.sh` 通过。
- `cargo test -p api-http openapi --quiet` 通过。
- `./scripts/test.sh --quick --low-memory` 通过。
- README 中不存在坏 handoff 链接。
- `.planning/codebase/*` 不再记录明显过期事实：
  - `api-http` 直接依赖 `speech-analysis`
  - DB 路径 `llplayer.db`
  - 当前最高 migration 0010
  - `domain/src/lib.rs` 仍约 1317 行
- `.planning/phases/2.18-codebase-architecture-refactor/2.18-REFACTOR-AUDIT.md`
  中列出的 P0/P1 架构问题均关闭或在 closeout 中明确转为后续 phase。
