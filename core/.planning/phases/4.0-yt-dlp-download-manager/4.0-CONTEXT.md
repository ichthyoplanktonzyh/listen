# Phase 4.0 Context: yt-dlp Download Manager

## 背景

在 Phase 3.35 听力工作台 UI 重设计中，yt-dlp 下载状态条（`DownloadStatusBar`）仍然
显示在主页面内容区与播放控制条之间。该设计在 UX 讨论中被指出不合适：

1. 下载状态条干扰听力学习体验，与工作台"零打扰"原则冲突。
2. 仅有一个简单的进度条/完成/失败状态，无完整的下载生命周期管理。
3. 只支持单次下载，无队列/并发/历史记录功能。

## 调研结论

调研了 5 个 GitHub 开源 yt-dlp GUI 项目（yt-dlp app、ytDownloader、YouTubeGO、
BKSalman/ytdlp-gui、YTDLnis），提取了共性功能模式：

- URL 输入 → `--dump-json` 解析元数据 → 格式/质量选择 → 加入队列 → 实时进度 → 历史记录
- 主流方案均提供格式选择、队列管理、并发下载、下载历史
- 与学习场景强相关：字幕下载、纯音频模式、播放列表解析
- Flutter 生态无成熟可用的 yt-dlp 管理 UI 组件

## 与 3.x 学习管线的关系

Phase 4.0 是**纯工具功能**，与 3.x 学习管线无耦合关系：

- 下载管理是基础设施层，为学习管线提供媒体资源来源
- 不修改 Rust 后端、不修改学习数据 schema
- 下载完成后的媒体通过现有的 `MediaSessionCoordinator.openMediaPath()` 进入学习工作流
- 可独立使用，即使 3.x 所有功能关闭，下载管理器仍可正常工作

## 现有基础设施复用

| 现有组件 | 复用方式 |
|---|---|
| `ExternalTools.downloadOnlineMedia()` | 保持不动，进程启动逻辑正确 |
| `OnlineMediaDownload` | 保持不动，进度流/完成回调正确 |
| `DownloadController` | **升级**：从单任务扩展为多任务队列管理 |
| `ExternalTools.resolveOnlineMedia()` | 用于 URL 解析（`--get-url`），播放列表场景保持 |

## 入口位置

下载管理入口放在首页左侧 `_HomeSidebar` 的"我的学习"区段，位于"复习"之下：

```
我的学习
├── 字幕资源
├── 词汇本
├── 复习
├── 下载管理     ← 新增
└── ...
```

点击后通过 `Navigator.push(MaterialPageRoute(builder: (_) => DownloadManagerScreen()))`
打开全屏页面，与词汇本 (`_openVocabulary`)、复习 (`_openReviewQueue`) 行为一致。
