# Phase 3.6.1 — Sense Folders Closeout

**Status:** COMPLETE  
**Closed:** 2026-07-10  
**Owner QA:** Accepted

## Outcome

The listening dictionary now has an optional, durable sense organization layer:

```text
LexicalEntry
  ├── unassigned personal source clips
  └── user-owned sense folders
        └── manually assigned personal source clips
```

This validates the consumer-side boundary required for future semantic teaching
content without making LLPlayerNext depend on SceneLex, a remote service, or
automatic word-sense disambiguation.

## Delivered

- `LexicalSenseFolder` and folder-to-occurrence organization edges, with a
  stable local `LexicalSenseId` and optional opaque `external_ref` alignment
  metadata.
- SQLite schema v30 migration. Parent-entry agreement is enforced in the
  database; one occurrence can be assigned to one folder at a time.
- Application and REST CRUD/assignment operations; entry details and existing
  `LexicalEntryChanged` events expose the additive `sense_folders` read model.
- OpenAPI and Dart contracts, plus a localized dictionary-detail UI for
  creating/editing/deleting folders and assigning/unassigning clips.
- Vocabulary asset export v7 with v5/v6 import compatibility.

## Preserved invariants

- The local folder is the identity authority. External semantic references are
  optional annotations and have no authority to merge or mutate user assets.
- Folder assignment is not learning evidence. No `LearningObservation`, review
  schedule, capability projection, or legacy status is changed.
- Entry-level capability remains the only active capability authority. Subtitle
  highlighting, vocabulary filters, corpus search and other hot paths remain
  entry-level.
- Classification remains manual and optional. Unassigned clips are complete
  first-class data, not an error state.

## Validation

- `cargo test -p application -p persistence-sqlite -p api-http` — passed
  (application 50, persistence 81, api-http 35 plus 12 HTTP integration tests).
- `flutter analyze` and `flutter test` — passed.
- `./scripts/validate-contracts.sh` and `git diff --check` — passed.
- Focused coverage includes v29→v30 migration, asset round-trip, cross-entry
  assignment rejection, HTTP create/assign/delete lifecycle, and detail-widget
  creation/unassigned-clip behavior.
- Owner executed and accepted the real-media desktop QA checklist.

## Deferred deliberately

- SceneLex API/resource pack integration, rendered scene media and async
  generation jobs.
- Automatic WSD, sense-level capability profiles/evidence/review scheduling,
  graph views and global sense search.

## Next recommended work

Run a small SceneLex consumer-contract spike: define the published external
sense/resource read model, version and publication-state semantics, and the
mapping from that external reference to the now-stable local folder seam. Do
not begin resource download or generation implementation in that spike.
