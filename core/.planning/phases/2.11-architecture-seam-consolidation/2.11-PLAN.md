# Phase 2.11 Plan: Architecture Seam Consolidation

更新时间：2026-06-24 CST
状态：PLANNED

> 前置：Phase 2.6–2.9 在多语言扩展中预留了多个设计 seam。本阶段将可独立落地的
> seam 实现为代码，减少 client 端硬编码和技术债积累。部分 seam（A1/A2）依赖
> Phase 2.10 音频分析进展，标记为条件推进。

## Objective

1. 将语言能力矩阵从后端暴露到 client，消除脚本门控硬编码
2. 学习语言来源支持用户手动选择
3. domain 巨型文件拆分，提升可维护性
4. 为 Phase 2.10 音频分析结果的消费准备好架构接口（L1 seam、听觉锚定）

## Position In Roadmap

```text
2.6 Multilingual Foundation (seams reserved)
  -> 2.10 English Real Speech Analysis (音频层)
  -> 2.11 Architecture Seam Consolidation  ← 当前
```

Phase 2.10 和 2.11 可部分并行：Step 1–3 不依赖 2.10，Step 4–5 依赖 2.10 有初步
结果后才有实际效果。

## Steps

### Step 1: 能力矩阵 API [独立，不依赖 2.10]

将 `LanguageLearningProfile` 能力矩阵暴露给 client：

- api-http 新增 `/v1/languages/capabilities` 端点，返回当前支持语言的能力矩阵
  （tokenization / dictionary / pronunciation / word_timeline / chunk_timeline
  各项的 Supported / Degraded / Unsupported 级别）
- Flutter client 读取能力矩阵，替换 `_isHan` 等脚本门控
- 词面板：逐字拼音、诊断因素等功能按能力矩阵显示/隐藏
- OpenAPI contract 同步

### Step 2: 学习语言来源 [独立，不依赖 2.10]

支持用户手动选择学习语言：

- 后端新增用户偏好：`preferred_learning_language: Option<LanguageCode>`
- 优先级：用户手动选择 > active 字幕轨语言 > 媒体 metadata > en fallback
- Flutter 设置页或播放器工具栏增加语言选择入口
- `_learningLanguage` 读取新优先级链

### Step 3: domain `lib.rs` 拆分 [独立，不依赖 2.10]

Mechanical decomposition，与 Phase 2.3.5 同原则（只拆不改行为）：

- 按领域拆分：`word_timing.rs`、`chunk_timeline.rs`、`phone_timeline.rs`、
  `language_profile.rs`（已拆出）、`subtitle.rs`、`learning.rs` 等
- root `lib.rs` 保留 module declarations 和 re-exports
- 不改 API contract、不改 SQLite schema、不新增功能

### Step 4: L1 诊断 seam 落地 [条件推进，依赖 2.10 初步结果]

将 L1 参数引入诊断链路：

- `diagnose` 函数签名增加 `l1: Option<LanguageCode>`
- 初版 L1×L2 对比难度表（硬编码小规模，如 zh→en 弱读难、ja→en 连读难）
- 诊断结论标注 L1 相关因素：从"这里可能有弱读"到"这里可能有弱读，
  中文母语者需注意"
- 不落 schema（v1 不持久化 L1），仅运行时推断

### Step 5: 听觉锚定 seam 准备 [条件推进，依赖 2.10]

为 ListeningUnit 锚定做代码层准备：

- 定义 `ListeningUnit` 数据结构（从设计文档落到 domain）
- 允许 observation 锚定 `ListeningUnit`（除了现有的 word/token）
- 不改变现有 observation 行为——新增一个可选锚定维度
- 实际的 ListeningUnit 检测（如 "want to" → /wɒnə/）由 Phase 2.10 的
  phone findings 驱动

### Step 6: identity 边界 profile 化 [低优先级]

仅在 Step 1（能力矩阵）完成后评估是否推进：

- `normalize_lemma` 改走 profile 的归一策略
- 当前 en/zh/ja 行为不变（都无大小写问题）
- 仅为未来土耳其语等做准备

## Verification Criteria

1. Flutter client 通过能力矩阵 API 门控功能，无脚本硬编码
2. 用户可手动选择学习语言
3. domain `lib.rs` 拆分后体量 < 300 行
4. `cargo test --workspace` 全通过
5. 英语 + 中文行为不变（回归基线）
6. `flutter analyze` + `flutter test` 通过

## Out of Scope

- 新语言的 profile/provider 实现（属各语言专项）
- 完整 L1×L2 contrastive analysis 数据库（v1 仅小规模硬编码）
- ListeningUnit 的持久化和 UI（仅做数据结构准备）
