## Objective

把 3.12 已就绪的 LLM provider（judge + rubric 两个 application seam）真正接进三个 Studio
的任务流并显示，让用户能用自有 provider 实测「AI 出题 + AI 判定」。全程保持显示诚实边界：
LLM 输出是**可纠正的辅助反馈**、可 adjudicate、evidence_class 保持 `heuristic_proxy`，
**不自动写 observation/projection**。manual rubric + 自评路径继续为一等公民。

## User Value

在 3.13–3.15 之前，Studio 里的「AI 反馈」只是预留接口：rubric 要手写、判定只有用户自评。
本 phase 让 LLM 真正生成理解题草稿、真正逐点判定作答，用户不再手写题目，也能立刻看到模型
对自己答案的判读并纠正它。

## Scope

### In

- **Reading 竖切（Slice 1–2，首个真实 consumer）**：
  - LLM judgment 显示：作答后可「请求 AI 反馈」，调用已就绪 judge 路由，逐点显示 LLM 判定，
    标注可纠正、可 adjudicate；与用户自评并存不互相改写。
  - LLM rubric 生成：新增后端 `generate_semantic_rubric` 用例 + `POST /v1/llm/providers/{id}/rubric`
    路由（调用 `SemanticRubricProvider`，服务端铸身份/版本/快照 hash、落库）；Flutter「AI 生成
    理解题」→ 用户复核可编辑 → 保存为 rubric v1。
- **复制到 Speaking + Writing（Slice 3）**：同一 judge 显示接线用于 Speaking retelling 与
  Writing 任务；Writing 内容/组织判定走同一 SemanticJudgeProvider（区别于已有 Harper 表面 finding）。
- 无 provider / provider 失败时诚实降级：不写 judgment、不阻塞 manual 路径（复用 3.12 契约）。
- Flutter 侧 provider 选择（复用 3.12 已注册 profile 列表）。

### Out

- 任何 observation/projection 写入（继续零 writer；projection 归 3.17）。
- 留出集资格评估、fixture gold、跨 provider 一致性报告（3.12.1 已取消，不复活）。
- 费用预算强制、并发限流、重试执行（3.12 deferred，按需另做）。
- 新协议 adapter（3.12 增量项，不在本 phase）。

## Slices

- **Slice 1 — Reading LLM judgment 显示（纯 Flutter，后端已就绪）**：
  `coach_llm.dart` 新增 `judgeViaLlmProvider`；`ReadingTaskController` 新增
  `requestLlmJudgment`；task sheet 在 assessing/done 阶段提供「请求 AI 反馈」入口与逐点
  LLM 判定展示（可 adjudicate）。契约解析测试 + 无 provider 隐藏入口。
- **Slice 2 — Reading LLM rubric 生成（后端新路由 + Flutter）**：
  application `generate_semantic_rubric` + api-http `POST /v1/llm/providers/{id}/rubric`
  + OpenAPI；`coach_llm.dart` 新增 `generateRubric`；editing 阶段「AI 生成理解题」→ 复核编辑
  → 落库。provider 失败降级回手写模板。
- **Slice 3 — 复制到 Speaking + Writing**：同 judge 显示接线；Writing 内容判定接 SemanticJudge。

## Exit Signals

- Reading：配置真实 provider 后可「AI 生成理解题→复核落库→作答→AI 逐点判定→纠正」，
  且无 provider 时手写+自评路径完整可用。
- LLM judgment 以 `heuristic_proxy` 落库，零 observation/projection（负向测试钉住）。
- provider 五类失败（离线/认证/拒绝/截断/schema 无效）均不写 judgment、不阻塞任务。
- 三个 Studio 均可显示 LLM 反馈；显示文案明确「可纠正的辅助反馈」。

## Guardrails

- LLM 判定永不冒充用户自评，也不改写 manual judgment；两者并存、各自 provenance。
- 身份/版本/快照 hash 一律服务端铸造，provider 只回内容草稿（守 ADR 0021 四层分离）。
- 显示诚实边界不因「跳过 3.12.1」而放松：仍不写能力层。
- 密钥不落普通存储（复用 3.12 keychain + auth_ref）。
