# Phase 2.3 Plan: Manual Timeline Review UI

更新时间：2026-06-20 00:34:23 CST

## Objective

完成 app 端人工校正闭环：用户能在当前句中检查和微调 WordTimeline 边界，保存为
`user_adjusted` WordTimeline，并立即作为 active timeline 驱动播放高亮。

## Design Principle

先做可信、可验证、低风险的句子级 inspector，再进入更复杂的波形拖拽编辑器。

```text
Production candidate remains immutable
  -> User creates adjusted revision
  -> Adjusted revision becomes active
  -> Export keeps both production and user timeline
```

## Work Breakdown

### Step 1: Data Model And API Audit

- 梳理当前 `CreateWordTimeline` 是否足够表达 user-adjusted timeline。
- 确认 `parent_timeline_id`、`created_by=user`、`timing_source=user_adjusted`、
  `metrics_json.lifecycle` 的约定。
- 设计保存策略：
  - 从 active timeline 克隆全部 words。
  - 只替换用户编辑过的 word boundaries。
  - 保存为新 WordTimeline，而不是覆盖 production candidate。

Exit criteria:

- 明确是否需要新增 API，还是复用 `POST /v1/subtitles/{track_id}/word-timelines`。
- 明确 user-adjusted timeline 的 status、parent、metrics_json 约定。

### Step 2: Manual Review State And Client

- Flutter client 支持创建 user-adjusted WordTimeline。
- SubtitleController 或独立 review controller 持有：
  - 当前 review timeline source。
  - 当前句 word timing draft。
  - dirty state / validation errors。
- 保存成功后刷新 timeline summaries 和 speech enhancements。

Exit criteria:

- App 能从 active timeline 创建 draft，并保存为 user-adjusted timeline。

### Step 3: Sentence Word Timing Inspector UI

- 从 Timeline Resource Summary 的 Manual Review 入口打开 inspector。
- 显示当前句 tokens 和 word timing rows。
- 每个 word row 显示：
  - token text
  - start/end
  - duration
  - provider/source
  - confidence
- 支持微调：
  - start/end 数字输入。
  - 小步进按钮（例如 ±10ms / ±50ms）。
  - 基本边界校验：start < end，句内非负，不产生明显倒序。

Exit criteria:

- 用户能在一个句子内完成人工边界微调。

### Step 4: Playback Verification Controls

- 支持播放当前句片段。
- 支持播放当前词片段。
- 调整 draft 后，试听使用 draft 边界。
- 保存后主播放器高亮使用新 active timeline。

Exit criteria:

- 用户能边听边修，保存后能马上看到高亮变化。

### Step 5: Save, Activate, Export

- 保存 user-adjusted timeline。
- 自动激活保存后的 timeline。
- 刷新 Timeline Resource Summary。
- 验证 export 的 LLTimeline 包含原 production candidates 和新 user-adjusted timeline。

Exit criteria:

- 人工校正版本可持久化、可激活、可导出。

### Step 6: Closeout And Phase 2.4 Handoff

- 更新 docs 和 changelog。
- 明确 ChunkTimeline 生成依赖：
  - active user-adjusted WordTimeline。
  - production readiness / human reviewed 状态。
  - chunk generation UI entry。

Exit criteria:

- Phase 2.3 closeout 完成，Phase 2.4 可直接进入 ChunkTimeline 生成与消费。

## Testing

- Rust/API:
  - create user-adjusted WordTimeline with parent.
  - activation refreshes compatibility `word_timings`.
  - export includes both production candidate and user-adjusted revision.
- Flutter:
  - manual review entry opens inspector.
  - draft edits validate boundaries.
  - save creates/activates adjusted timeline.
  - no-resource fallback remains unchanged.
- Regression:
  - candidate activation still works.
  - legacy `trackWordTimings()` path still works.

## Open Questions

- 保存按钮是否总是创建新 timeline，还是允许继续编辑同一个 user-adjusted draft？
- `human_reviewed` 应该由 active user timeline 推断，还是显式写入 LLTimeline metadata？
- 初版 inspector 是否只编辑当前句，还是可以通过 Prev/Next 连续校对整条字幕？
- 自动校验是否只阻止非法边界，还是也提示 suspicious gap/overlap？
