# Phase 3.5 Plan: Difficulty & Content Triage

状态：PLANNED

上游输入：`3.0-PHASE-BREAKDOWN.md`、`.planning/discuss/listen-learning-activity-path.zh.md`

## Objective

实现双维难度（Meaning fit × Sound fit）并把它从"标签"升级为"内容分拣器"：
进入的材料被路由到泛听队列 / 精听靶单 / 暂缓区。分拣只建议、不阻塞、可无视。

产品决策：双维难度直接实现，不做前置分化实验；换取条件是**每个分数必须可解释**
（点开可见依据信号），且所有参数按 `heuristic_proxy` 记录。

## User Value

> "这段你大概率看得懂，但会卡在弱读和 chunk 边界——适合精听，不适合今天泛听。"

用户不再纠结"今天听什么"；"看得懂、听不出"的黄金靶材料被自动挑出来。

## Scope

### In

- **双维难度计算**（媒体级 + 句级，`ContentDifficultyProfile` 落地）：
  - Meaning fit：unknown_meaning 密度、词汇覆盖率（用户词汇画像 × transcript）。
  - Sound fit：known_not_recognized 密度、语速（WordTimeline）、弱读/压缩密度
    （document-level rhythm_frames，按 audible-structure v1 现状消费）、chunk 长度、
    resource quality；有练习历史时叠加个人 decoding 表现。
  - 输出定性档位（too_easy / comprehensible / challenging / too_hard 按两维分别给出），
    不展示伪精确数字。
- **可解释性**：每个分数点开显示依据（"弱读密度高、平均语速 5.2 词/秒"）与证据
  等级（初始估计 / 已被你的使用校准）。
- **三队列分拣**：泛听队列 / 精听靶单（meaning 高 + sound 低 特别标出）/ 暂缓区；
  媒体库与当前媒体摘要展示 fit 与建议用途。
- **反馈回流**：3.3 的理解度自报 + 精听/练习表现回流校准个人 sound fit。
- **冷启动校准**：新材料导入后抽高频词快速标注流（两分钟级别，可跳过）。
- **熟料回听供给**：3.2 的熟料标记进入泛听队列（"原速重听？"），作为可选来源，
  推荐克制、可关闭。
- 词汇状态不足时的诚实降级：提示先标关键词，给保守估计。

### Out（Non-goals）

- 订阅源自动抓取/夜间批量精炼调度（生产端工程，另立 phase 或工具化；本 phase
  只对"已在库材料"分拣）。
- 局部智能变速（记录为后续候选，需真实听感验证）。
- 兴趣/主题维度建模。
- 用 fit 阻塞或隐藏任何材料（P3/P5 红线）。

## Dependencies

- 词汇画像（现有 LexicalEntry/LearningStatus）。
- 3.2 熟料标记、3.3 理解度自报存在时接入；缺席时对应供给/校准通道空转，分拣仍成立。

## Key Work

1. difficulty 计算服务（application 层）+ `DifficultyRepository` 持久化/缓存。
2. 双维信号提取：词汇覆盖、语速、rhythm_frames 弱读/压缩密度、chunk 统计。
3. 媒体库/媒体摘要 fit UI + 可解释详情。
4. 三队列模型与入口 UI；熟料回听供给接入。
5. 反馈回流管道（自报 + 练习表现 -> 个人校准项）。
6. 冷启动快速标注流。
7. 在真实素材库上跑通并人工抽查合理性（manual_product_qa 记录）。

## Exit Signal

- 媒体库每个媒体显示双维 fit、依据可解释、证据等级诚实。
- 至少一个真实媒体被正确识别为"精听靶材料"（meaning 高 / sound 低）并经人工确认合理。
- 从队列一键开始泛听/精听；完全无视分拣时所有功能行为不变。
- **独立可用**：fit 展示对只当播放器用的用户完全无感。

## Guardrails

- 分数是预期管理不是判决；文案避免"你不行/太难了"式表达。
- 所有阈值/权重记 evidence class（heuristic_proxy），预留后续校准。
- 不因 fit 低而隐藏、锁定或劝退任何材料。
