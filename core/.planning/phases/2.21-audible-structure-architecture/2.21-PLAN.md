# Phase 2.21 Plan: Audible Structure Architecture

状态：ACTIVE

## Objective

Turn the Phase 2.20 rhythm-first direction into a stable audible-structure
architecture:

```text
actual audible structure contract
  -> provenance-bearing RhythmFrame data model
  -> WordTimeline/duration/energy generation path
  -> evaluation/UI updated to distinguish predicted vs measured claims
```

This phase is allowed to break old `RhythmFrame` compatibility if the old shape
blocks the architecture.

## Source Of Truth

- `2.21-AUDIBLE-STRUCTURE-MODEL.md` is the contract.
- Phase 2.20 documents are input history and scaffolding, not the active
  architecture when they disagree with this phase.

## Step 0: Architecture Lock

Deliverable:

- Move the audible-structure model into Phase 2.21.
- Normalize definitions:
  - rhythm group / foot can attach pre-head or trailing weak material;
  - default connected form is ranked/contextual, not a single always-rule;
  - nucleus is phrase-scoped and may abstain when evidence is insufficient;
  - syllable timing is an explicit seam, even if v1 approximates it from
    WordTimeline + dictionary.

Acceptance:

- `2.21-AUDIBLE-STRUCTURE-MODEL.md` is the top-level reference.
- Phase 2.20 handoff/STATE/ROADMAP point future structure work to Phase 2.21.

## Step 1: Contract Rewrite

Goal:

Replace the v0 `RhythmFrame` shape with a model that can honestly represent:

- A/B/C references:
  - citation;
  - default connected variants;
  - actual delivery;
- L1 prominence anchors with `prominence`, `prominence_cues`,
  `evidence_class`, and source provenance;
- L2 phrase-scoped `nuclei`;
- L3 phrase boundaries with timing/energy/pitch cues;
- L4 connected-speech refs rather than duplicate segmental truth;
- quality fields that distinguish `text_prior`, `timing`, `energy`, `pitch`,
  and `phone_segmental`.

Implementation target:

- `crates/domain/src/sound_analysis.rs`
- `contracts/openapi/v1.yaml`
- Flutter typed model in `apps/desktop/lib/models/timeline.dart`
- fixture resources and tests that exercise the new model

Acceptance:

- Contract validation passes.
- Rust and Flutter model tests parse the new shape.
- Old v0-only assumptions such as `quality.timing_source = phone_timeline` are
  removed from active fixtures/tests when they contradict the lock.

## Step 2: Generation Boundary

Goal:

Route production generation around the locked dependency direction:

```text
WordTimeline + dictionary/syllable structure + duration/energy
```

and keep CTC phones as L4 segmental evidence.

Deliverable:

- A production-side generator design or implementation path that can emit
  RhythmFrame L1-L3 without phone evidence.
- A clear seam for future syllable timing and pitch/F0.
- CTC connected-speech evidence linked via refs, not used as the rhythm skeleton.

Acceptance:

- A no-phone-evidence fixture can still produce valid anchors, weak groups,
  compression spans, phrase boundaries, and nuclei candidates.
- Phone evidence can enrich L4/hotspots without changing L1-L3 ownership.

## Step 3: Evaluation Realignment

Goal:

Adapt Phase 2.20 evaluators so they score the new architecture rather than the
old field names.

Deliverable:

- Manual QA schema updated for predicted vs measured claims.
- Helsinki/LibriTTS scorer mapped to prominence/boundary fields with evidence
  provenance.
- Duration/RMS harness kept as experiment input and aligned to the model terms.

Acceptance:

- Scorers report evidence class and signal source.
- Product gates depend on manual product QA for learner-facing usefulness, not
  tiny smoke-score tuning.

## Step 4: UI Semantics

Goal:

Keep the rhythm-first surface but make provenance honest.

Deliverable:

- UI distinguishes predicted/text-prior cues from timing/energy-supported
  audible cues.
- Phrase nucleus is visible or inspectable when available.
- Phone details remain an expandable L4 evidence surface.

Acceptance:

- Learner-facing copy does not call text-only predictions "actual".
- Missing measured evidence degrades cleanly to predicted/reference mode.

## Step 5: Closeout Criteria

Phase 2.21 can close when:

1. The new audible-structure contract is implemented in Rust/OpenAPI/Flutter.
2. The generation boundary no longer requires CTC phone evidence for L1-L3.
3. The evaluation tools understand provenance and predicted-vs-measured claims.
4. The UI can render the new model without reviving v0 semantics.
5. Handoff clearly states the next implementation phase or closeout path.
