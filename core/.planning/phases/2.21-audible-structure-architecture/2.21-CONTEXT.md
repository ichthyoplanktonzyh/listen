# Phase 2.21 Context: Audible Structure Architecture

状态：ACTIVE

日期：2026-06-30

## Why This Phase Exists

Phase 2.20 proved the product direction:

```text
show the learner how this sentence actually sounds before exposing phone detail
```

It delivered useful scaffolding:

- `sound_analysis.rhythm_frame` v0 contract;
- subtitle-layer rhythm UI and rhythm/phones toggle;
- expected pronunciation reference;
- rhythm cue loop;
- manual QA scorer and Helsinki/LibriTTS weak-label scorer;
- duration/RMS manual QA harness.

But Phase 2.20 also exposed a deeper architecture problem: the v0 generator and
contract can still let text-predicted or CTC-derived signals masquerade as actual
audible structure. That is a definition bug, not just a threshold bug.

Phase 2.21 is therefore split out as a focused architecture phase:

```text
lock the audible-structure model
  -> rewrite the RhythmFrame contract around that model
  -> then rebuild generation/evaluation against the contract
```

## Non-Compatibility Decision

This phase may break old `RhythmFrame` resource shape, generated fixtures, API
schema, Flutter typed models, and local `.tmp` artifacts if compatibility blocks
the architecture.

The current project is still pre-release and Phase 2.18 already established that
old SQLite data, old LLTimeline JSON, old learning assets, and old adapter paths
do not need historical compatibility when they conflict with the active model.

Compatibility is nice-to-have. Correct structure is the goal.

## Product Invariant

The learner-facing UI may show a claim as **actual / audible** only when at least
one audio-backed signal supports it:

```text
timing | energy | pitch | phone_segmental
```

Text-only claims are allowed, but they must remain marked as predicted.

## Architecture Invariant

RhythmFrame L1-L3 must be valid without phone evidence:

```text
WordTimeline + dictionary/syllable structure + duration/energy
```

CTC phones belong to L4 connected-speech/segmental evidence. They may annotate or
strengthen reduction explanations, but they must not gate prominence, nucleus, or
phrase-boundary structure.
