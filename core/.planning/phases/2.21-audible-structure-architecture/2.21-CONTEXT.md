# Phase 2.21 Context: Audible Structure Architecture

状态：ACTIVE

日期：2026-06-30

## Why This Phase Exists

Phase 2.20 proved the product direction:

```text
show the learner how this sentence actually sounds before exposing phone detail
```

It delivered useful scaffolding:

- `sound_analysis.rhythm_frame` v0 contract;
- subtitle-layer rhythm UI and rhythm/phones toggle;
- expected pronunciation reference;
- rhythm cue loop;
- manual QA scorer and Helsinki/LibriTTS weak-label scorer;
- duration/RMS manual QA harness.

But Phase 2.20 also exposed a deeper architecture problem: the v0 generator and
contract can still let text-predicted or CTC-derived signals masquerade as actual
audible structure. That is a definition bug, not just a threshold bug.

Phase 2.21 is therefore split out as a focused architecture phase:

```text
lock the audible-structure model
  -> rewrite the RhythmFrame contract around that model
  -> then rebuild generation/evaluation against the contract
```

## Non-Compatibility Decision

This phase may break old `RhythmFrame` resource shape, generated fixtures, API
schema, Flutter typed models, and local `.tmp` artifacts if compatibility blocks
the architecture.

The current project is still pre-release and Phase 2.18 already established that
old SQLite data, old LLTimeline JSON, old learning assets, and old adapter paths
do not need historical compatibility when they conflict with the active model.

Compatibility is nice-to-have. Correct structure is the goal.

## Product Invariant

The learner-facing UI may show a claim as **actual / audible** only when at least
one audio-backed signal supports it:

```text
timing | energy | pitch | phone_segmental
```

Text-only claims are allowed, but they must remain marked as predicted.

## Architecture Invariant

RhythmFrame L1-L3 must be valid without phone evidence:

```text
WordTimeline + dictionary/syllable structure + duration/energy
```

CTC phones belong to L4 connected-speech/segmental evidence. They may annotate or
strengthen reduction explanations, but they must not gate prominence, nucleus, or
phrase-boundary structure.

## Current Implementation Snapshot

As of 2026-06-30, the contract rewrite is implemented across Rust domain,
OpenAPI, Flutter typed models, UI, QA scorers, and committed fixtures.
`speech-analysis` now prefers active WordTimeline timing plus dictionary/canonical
stress for L1-L3 RhythmFrame generation and can generate valid L1-L3 structure
with observed phone evidence coverage at `0.0`.

The generator also has a narrow `RhythmWordAcousticCue` seam for normalized
word-level energy prominence. That cue propagates into prominence/nucleus
selection and signal-source provenance, but application builders currently pass
no acoustic cues. A calibrated product audio feature provider remains future
work; the duration/RMS harness remains manual QA input, not production truth.

LLTimeline export now has a first-class, non-fixture resource path for this
model: document-level `rhythm_frames` are derived from the active WordTimeline +
dictionary/canonical stress and consumed by Flutter before the older
`PhoneTimeline.sound_analysis` fallback. Imported rhythm-frame resources are
validated as LLTimeline resources; the persisted source of regeneration remains
the active WordTimeline until a dedicated editable rhythm-frame lifecycle is
needed.

Reference B is now real for English: `speech-analysis::connected_speech_rules`
predicts default connected forms from text, including function-word weak forms,
phrase reductions such as `could have -> K UH D AH V`, linking, t/d weakening,
assimilation, contraction, and flapping candidates. RhythmFrame connected-speech
refs use those predictions to distinguish `teachable_rule` from
`clip_specific`; pure B predictions remain `TextPrior` / `Predicted`.

Energy cue wiring is now product-side but not yet release-calibrated:
`production_pipeline.py` emits `rhythm_word_acoustic_cues` artifacts from RMS
relative word energy, and application export consumes those artifacts into
`RhythmWordAcousticCue`. W8 manual listening QA is still required before the
current RMS calibration is treated as a product gate. As of 2026-07-01 the W8
QA tooling can gate WordTimeline/energy RhythmFrames, nuclei, and connected
speech refs, but the local Phase 2.17 real-media artifacts still predate the new
product path: they expose only one old v0 phone-timeline RhythmFrame and no
energy prominence RhythmFrames, so they must be regenerated before manual W8
labels can close the phase.

Reference A OOV fallback is hardened to `fallback-v2`: when CMUdict is missing a
word, the deterministic fallback handles common English digraphs and assigns a
single primary stress rather than marking every fallback vowel as primary.

The prominence text prior now includes a small information-structure adjustment:
repeated content is backgrounded and phrase-final content is treated as a likely
focus candidate. This remains a text prior and does not create audio-supported
claims on its own.
