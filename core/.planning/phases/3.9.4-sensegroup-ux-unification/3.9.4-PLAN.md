# Phase 3.9.4 Plan: SenseGroup UX Unification

状态：ACTIVE（2026-07-14）

起点：main `8bbbd3ba`，分支 `phase/3.9.4-sensegroup-ux-unification`

## Objective

修复 SenseGroup 从语法分析到前端显示的四层断链（持久化、激活、触发、反馈），
并在不违反 ADR 0016 的前提下给语义分组补齐播放跟随、点击跳转和视觉对等。
决策依据见 `3.9.4-CONTEXT.md`（D1–D6）。

## Slice 0 — application 持久化用例（Rust）

新增 `MediaAnalysisUseCases::persist_sense_group_analysis_from_batch`
（`crates/application/src/sense_groups.rs`）：

- 签名：`(track_id: &SubtitleTrackId, batch: &SyntacticConsumerBatch)
  -> Result<Option<SenseGroupAnalysis>, ApplicationError>`。
- 映射：对 batch 每句的 `sense_groups: Vec<SyntacticSenseGroupSpan>` 逐 span
  转 `SenseGroup`。字段一一对应（start/end_token_index、sources、confidence、
  label、head_token_index）；`text` 与 `id` 的推导复用现有
  `sense_group_from_span` 的逻辑（token 过滤 + original_text 切片 +
  `SenseGroupId::from_fingerprint`），抽公共 helper，不复制粘贴。
- provider 元数据：任一 span 带 `syntactic_analysis_id` → 使用
  `SYNTAX_PROVIDER_ID/VERSION/ALGORITHM`，否则纯文本三元组
  （常量在 `speech_analysis::audible_structure`）。`metrics_json` 记录
  `analyzed_sentence_count` / `fallback_sentence_count` / 每 provider 来源计数。
- fingerprint/id：沿用现有 `SenseGroupAnalysisId::from_fingerprint` 模式，
  输入含 track id、provider version、groups 序列化。
- 幂等（D3）：先查 track 的 active analysis，`id` 相同则返回 `Ok(None)`
  不写库；否则 save 为 Candidate 后立即 activate。
- groups 为空（无句子）返回 `Ok(None)`，不报错。
- 单测（`crates/application/` 现有测试布局）：
  - 混合 batch（部分句 syntax、部分句 fallback）→ 全部句子持久化、
    provider 为 syntax、metrics 计数正确。
  - 纯 fallback batch → 纯文本 provider。
  - 重复调用同 batch → 第二次 `Ok(None)`，库中仍单 active。
  - 已有文本回退 active、新 batch 含 syntax → 新 analysis 接管 active。
  - 与 `generate_sense_group_analysis`（无 syntax 路径）在同输入下产出
    span 一致（钉住双入口一致性）。

## Slice 1 — syntax 路由接线（Rust）

`crates/api-http/src/routes/syntax.rs` `run_track_syntax_analysis`：

- 新鲜计算分支：在 `write_track_cache` 之后、返回之前，
  `analyzed_sentence_count > 0 || fallback 全量文本规则可用` 时调用
  Slice 0 用例（batch 里 fallback 句也有文本规则 sense_groups，所以只要
  `!batch.sentences.is_empty()` 就调用）。错误不 fail 整个请求：
  记 `tracing::warn!` 并继续返回分析结果（sense group 持久化失败不应
  拖垮 syntax 分析本身）。
- cache-hit 分支（D4）：命中缓存提前返回前，同样调用持久化用例
  （幂等保证不重复写）。
- capability 未 ready 的 Unavailable 早退分支：不加逻辑（D5 由 Flutter 触发）。
- 集成测试（现有 api-http 测试布局，参考 3.9.3 的 syntax 路由测试）：
  - run 语法分析后：GET `/v1/subtitles/{id}/sense-group-analyses` 返回
    非空且含 `Active` 状态项，groups 数与 batch 一致。
  - 二次 run（cache hit）：不产生第二个 analysis。
  - `force=true` 重算同内容：仍单 active。

  - 注意：语法能力 ready 时后台 syntax 分析会产出 syntax-aware 版本并接管
    active（Slice 0 D3），Flutter 不需要区分来源。
- 设置页 `settings_dialog.dart` grouping mode 下拉（对照上游文档 3.2.4）：
  - `semantic` / `compare` 选项旁标注可用状态；当前轨道无 sense group 数据
    时给出文案说明（文案进 `localization.dart`，中英）。
  - 选中 `semantic` 但数据缺失时，`token_line.dart` 不再纯静默：字幕区域
    保持逐词回退（不打扰播放），但设置项处显示"数据未就绪"状态。
    不做全局弹窗。
- Flutter 测试：controller 测试覆盖"空 → 触发生成 → 重载非空"与

## Slice 3 — Flutter 播放跟随 + 点击跳转 + 视觉对等

- 投影 helper（D1，新增于 Flutter timeline model 或 controller 层）：
  `senseGroupPlaybackRange(SenseGroup, List<WordTiming>) -> (startMs, endMs)?`
  ——按 `tokenIndex ∈ [start_token_index, end_token_index]` 过滤后取
  min(start)/max(end)；无匹配 timing 返回 null（该组不可交互，UI 静默）。
- `token_line.dart`：
  - `semantic` 模式：当前播放位置落入某组投影区间 → 该组胶囊高亮
    （复用 prosodic chunk 的当前组高亮样式/设置，不新增配置项）。
  - 胶囊点击 → seek 到组投影 start（复用 chunk 点击跳转的既有回调通路）。
  - 视觉：`semantic` 纯模式实线胶囊（去掉 provisional 虚线降级）；
    `compare` 模式保留虚线/差异标记（该模式价值就是差异）。
- Flutter 测试：投影 helper 纯函数单测（含空 timing、部分 token 缺 timing、
  乱序 timing）；token_line widget 测试覆盖高亮与点击回调。
