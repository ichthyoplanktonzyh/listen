## 方法

以 `LLPLAYERNEXT_DB` 指向临时数据库启动 `api-http` sidecar（共享用户真实
syntax capability root，只读使用其 venv/model；产生的 2 个临时 track cache
文件已在 QA 后删除），用 curl 驱动 HTTP 接口，对两条真实字幕轨道走完
Slice 0–2 的全部后端路径。

## 轨道 1：Brooklyn cell phone ban（244 句，CNN 真实新闻）

| 步骤 | 结果 |
|---|---|
| 导入前 GET sense-group-analyses | `[]`（干净基线） |
| POST syntax-analysis（fresh，37.9s 冷启动含 sidecar spawn） | status `partial`，243/244 analyzed（与 3.9.3 已知单句 invalid-tree fallback 一致），batch 内 sense_groups 共 450 |
| GET sense-group-analyses | **1 个 active**，provider `syntax-aware-sense-group`，algorithm `dependency_teaching_partition_v1`，**450 groups 与 batch 完全一致** |
| metrics_json | `analyzed 243 / fallback 1`；来源计数 `syntax 449 + rule 1`（Partial 轨道逐句混合，决策 D2 生效） |
| 抽样 group | `"upbeat music"`，label `NP`，token span 正确 |
| 二次 POST（cache-hit 路径，决策 D4） | `cache_hit: true`，仍 1 个 active，id 不变（幂等，决策 D3） |
| POST force=true 重算 | 重新分析 243 句，仍 1 个 active，无重复记录 |

## 已验证结论

- P0 断链修复：语法分析 → SQLite 持久化 → 激活 → GET 可读，全链路真实数据通过。
- Partial 轨道不被整轨拒绝，逐句混合来源正确记账。
- cache-hit 补偿、force 重算、重复运行均保持单 active、无重复行。
- 文本规则回退生成 + 激活（无语法能力路径的后端部分）可用。
- syntax-aware 结果对文本回退 active 的接管行为正确。

## Owner GUI 清单（需真人在 App 内确认）

自动化无法覆盖的交互/视觉项，建议打开真实媒体后逐项确认：

1. 设置 → 分组模式选 `semantic`：字幕显示实线语义胶囊（不再是虚线临时标记）。
2. 播放中当前语义组胶囊高亮跟随（复用 chunk 高亮设置，需开启该设置）。
3. 点击语义胶囊跳转到该组起点（有字幕 offset 时验证不偏移）。
4. `compare` 模式视觉不变（prosodic 底 + 虚线差异标记）。
5. 设置页 semantic/compare 选项显示"· 可用"；对无数据轨道显示"· 数据未就绪"
   且选中后 helper 显示逐词回退说明。
6. 未安装语法能力的环境（或全新轨道）：打开语音增强后语义分组自动出现
   文本规则版本（Flutter 回退触发）。
