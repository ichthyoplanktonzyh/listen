# Phase 3.19.1 Scheme B: Speaking And Realtime Product Convergence

状态：COMPLETE — B1/B2/B3/B4/B5 + OWNER REAL-DEVICE QA PASS

日期：2026-07-22

## Product Conclusion From Current Code

### Speaking

Speaking is a bounded practice container, not a chat container. Its retained product capabilities are:

1. L2 content retelling with an immutable 10–60 second Content Selection, including immediate and delayed recall;
2. Shadowing over source audio, with its separate imitation/comparison facts;
3. Pattern Production from a user-owned sentence pattern and explicit prompt.

The content channel now owns the post-selection activity choice. Its Speak entry offers retelling, shadowing and
content-anchored conversation as siblings. Conversation enters a dedicated Realtime route directly; Speaking no
longer owns Realtime page state or renders a conversation button inside `SpeakingTaskStudio`.

`SpeakingTaskSource` also currently carries both media retelling prompts and user-owned pattern prompts. Their
durable semantic kinds are already distinct, but the Flutter prompt type is still overloaded. Splitting that union
is a later Speaking-local deepening slice; it must preserve the existing semantic-attempt and Personal Expression
authority decision rather than silently deleting one fact.

### Realtime Conversation

Realtime Conversation is the only multi-turn interaction container for free and topic-anchored conversation. Its
interface is: launch with optional explicit anchor, accept provider events, expose an ordered timeline, and reach
one honest finish/cancel/failure result.

The code audit found these concrete gaps:

- barge-in stopped audio but left the active assistant item streaming and unsaved;
- cancel did not fence already queued learner post-processing from later finalization;
- finish waited for one response signal but did not explicitly flush an active assistant item;
- provider event assembly, transport, local ASR, persistence and history lived in one controller;
- Realtime launch imported `SpeakingTaskSource`, making the conversation container depend on a practice prompt;
- timeline status is item-oriented, but the panel still lacks explicit listening/thinking/speaking semantics,
  automatic scroll and route-exit coverage.

### History, Corpus And Evidence

- Conversation History owns both roles and ordered local sequence.
- Provider item IDs are ephemeral correlation only.
- Production Corpus owns a rebuildable learner-only projection.
- Review and gap surfaces read that projection; they do not write conversation, observation, proposal or review
  facts.

The audit found that `rebuild_production_corpus()` rebuilt only writing semantic attempts. Its SQLite replacement
also preserved existing realtime documents, which made a combined rebuild conflict on realtime unique keys. B2
now atomically replaces the full projection and derives it from writing attempts plus finalized local-authoritative
realtime learner turns. Assistant, failed and interrupted turns remain negative cases.

### Current LiveKit HEAD Supplement

Direct inspection of LiveKit Agents GitHub `main` at `c67c44e607f1fe60bfa312853c9f8c91235d5015` confirms and
sharpens the fixed-reference mapping:

- `voice/events.py` keeps user/agent speaking state, interim/final user transcript and committed conversation item
  as separate event types; provider `item_id` is optional on transcript progress.
- `llm/chat_context.py` owns an ordered serializable item list and local item IDs; insertion can be time ordered,
  while provider correlation is not promoted into the container identity.
- `AgentSession.drain()`, `shutdown(drain: ...)` and `aclose()` are distinct lifecycle operations, and
  `interrupt()` completes only after chat context has been updated.
- `test_audio_sink_proxy.py` asserts that replacing an output with in-flight audio completes the pending segment as
  interrupted so a playout waiter cannot hang. LLPlayerNext maps that method to its barge-in and close-flush tests.

These are borrowed patterns and test methods only; no LiveKit runtime dependency is introduced.

## Executable Slices

### B1 — Realtime Turn Assembly And Terminal Semantics (implemented)

- pure local-sequence `RealtimeTurnAssembler`;
- provider IDs remain correlation only;
- barge-in persists interrupted assistant turns;
- cancel interrupts active items and fences queued learner post-processing;
- finish finalizes a drained assistant transcript or persists an interrupted timeout/incomplete item;
- transition tests cover local identity, final-without-delta, duplicate terminal events, barge-in and cancel.

### B2 — Rebuildable Learner-only Corpus (implemented)

- full rebuild reads writing semantic attempts and durable realtime sessions/turns;
- one document per finalized local-authoritative learner turn;
- assistant turns remain conversation history only;
- the SQLite projection replacement is atomic across both sources.

### B3 — Realtime-owned Launch Contract (implemented)

- Realtime owns `RealtimeConversationAnchor`;
- Speaking may adapt an explicit Content Selection into that contract temporarily;
- no Realtime controller/model depends on `SpeakingTaskSource`.

### B4 — Entry And Duplicate Attempt Authority (implemented)

1. The content channel owns a sibling activity chooser for retelling, shadowing and topic conversation. Realtime is
   removed from `SpeakingTaskStudio`, `SpeakingChannelCoordinator` and `SpeakingChannelHost`.
2. Pattern Production keeps two intentionally linked facts: the semantic attempt owns prompt/transcript/recording;
   the Personal Expression Use owns pattern-version usage, assistance and self-assessment. New speaking uses require
   `semantic_attempt_id`; historical JSON remains readable without inventing a relationship.

### B5 — Timeline And Recovery Completion (implemented)

- typed session phase and separate voice-activity enums instead of UI string switches (implemented);
- explicit listening/thinking/learner-speaking/assistant-speaking presentation (implemented); draining and
  post-processing remain session lifecycle states rather than voice activity (implemented);
- auto-scroll while the learner remains near the live edge, without pulling manual history review back to the
  bottom (implemented);
- retry after microphone start/provider connection failure resets items, activity and pending work before a new
  session;
- active route close requires destructive confirmation, while draining/post-processing cannot be abandoned halfway;
- explicit cancel fences pending local ASR, clears pending presentation and closes the route;
- provider drain has an injectable bounded timeout and preserves an active partial assistant item as interrupted;
- controller tests cover both startup retry paths, provider drain timeout and pending-ASR cancellation; widget tests
  cover route back confirmation, continue-talking and cancel-and-close behavior.

The GitHub product analogue audit and its direct mapping are recorded in `3.19.1-GITHUB-ANALOGS.md`. Its conclusion
does not change the domain language: no inspected project provides the full Content Selection → Realtime ordered
turn → local learner authority → learner-only corpus boundary, so no external product model or provider identity is
adopted.
