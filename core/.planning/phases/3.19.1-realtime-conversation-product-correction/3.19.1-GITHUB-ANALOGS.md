# Phase 3.19.1 GitHub Analogues: Product And Architecture Mapping

状态：RESEARCHED — current public HEADs inspected on 2026-07-22

## Conclusion

No inspected open-source project implements LLPlayerNext's complete boundary: an explicit media Content Selection,
true multi-turn realtime voice conversation, per-learner-turn local authoritative transcription, durable ordered
Conversation History, and a rebuildable learner-only Production Corpus while keeping Retelling, Shadowing and
Pattern Production as separate practice facts.

The useful result is therefore a composition of patterns, not a repository to adopt. Realtime Conversation remains
one deep Module whose Interface accepts an optional explicit anchor and emits an ordered local timeline. Speaking
remains a bounded practice Module. Provider SDKs and generated scenarios are Adapters or transient inputs at that
Seam; neither may become domain identity.

## Product Mapping

### Speaking

- Retelling owns an immutable short Content Selection and an open L2 recall response.
- Shadowing owns target segment playback, learner imitation and comparison.
- Pattern Production owns an explicit pattern prompt and semantic attempt, linked to but not collapsed into Personal
  Expression usage.
- Subtitle repeat, pronunciation comparison and target-answer exercises stay here; they never become conversation
  items just to reuse a chat UI.

### Realtime Conversation

- Free and content-anchored conversation share one route, timeline and lifecycle.
- The optional anchor is a visible local snapshot. Provider prompt construction is an Adapter at the launch Seam.
- Live provider IDs correlate deltas/finals only. Local sequence and local session ID remain durable identity.
- `finish` drains and flushes; `cancel` discards/fences post-processing; route close during an active session asks for
  destructive confirmation; draining cannot be cancelled halfway through persistence.
- Timeline activity and durable items stay separate. Auto-scroll follows only while the learner remains at the live
  edge.

### History, Corpus And Review

- Conversation History preserves ordered learner and assistant facts.
- Only finalized local-authoritative learner turns project into Production Corpus.
- Provider captions, assistant output, generated scenarios, failed/interrupted turns and review prose never enter
  learner Production Corpus.
- Review/evidence reads durable facts and projections; it does not rewrite conversation identity or invent a
  fixed-answer rubric for free dialogue.

## Resulting Implementation Slices

1. Keep the already implemented content activity chooser and Realtime-owned anchor Interface.
2. Complete explicit close semantics: active route exit confirms, cancel closes after fencing work, finish uses a
   bounded provider drain and persists a truthful interrupted partial assistant item on timeout.
3. Prove retry after microphone/provider startup failure resets session, items, activity and pending work.
4. Prove cancellation while local ASR is pending cannot later finalize or project that learner turn.
5. Do not add LiveKit, Pipecat, Discute, ElevenLabs or OpenAI Agents as runtime dependencies; their value here is
   state vocabulary, UI patterns and test methods.
