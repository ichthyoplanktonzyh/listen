# Phase 3.19.1 Live Conversation Foundation

状态：IN PROGRESS — QWEN FULL-DUPLEX BASELINE LANDED / REAL PROVIDER + DEVICE QA PENDING

日期：2026-07-22

## Target Experience

这里的 “GPT Live-like” 指连续、低延迟、可随时插话的双向语音会话，而不是把一次录音依次送进
ASR、文本 LLM 和 TTS。最低产品闭环包括：

1. 全双工音频 transport 与增量播放；
2. turn detection、barge-in、response cancel 和已播放位置追踪；
3. ordered learner/assistant conversation facts 与 provider correlation；
4. provider live caption 与本地 learner transcript authority 分离；
5. 麦克风 voice processing（AEC/NS/AGC）和输出泄漏控制；
6. reconnect/terminal-state honesty、延迟/中断/错误 telemetry；
7. provider/model capability discovery，禁止从厂商宣传能力反推 adapter 已实现能力。

## Current Implementation Boundary

| Layer | Implemented now | Missing before Live parity |
|---|---|---|
| Transport | OpenAI/Qwen JSON WebSocket adapters；OpenAI 24 kHz input，Qwen 16 kHz input，均为 24 kHz output | WebRTC/bidirectional-stream adapters；resume/reconnect |
| Turn control | server VAD、manual commit、response cancel、basic barge-in | output buffer clear、conversation truncate、playout cursor |
| Conversation facts | ordered durable learner/assistant turns，provider id only correlation | interrupted playback offsets and resumed-session facts |
| Learner authority | per-turn 16 kHz WAV + local Whisper + learner-only corpus | real-device boundary qualification |
| Audio device | AVAudioEngine capture/playback + Apple voice-processing I/O | real-device AEC/NS/AGC and leakage qualification |
| Modalities/tools | audio + transcript | image input、function/tool events and tool-result continuation |
| Operations | typed provider errors and lifecycle states | latency/cancel/reconnect/cost metrics and production SLOs |

`RealtimeProviderDescriptor.capabilities` describes **this adapter implementation**, not every feature supported by
the vendor or selected model. The first v2 contract records transport/audio format, VAD/manual turns, both transcript
directions, cancel/clear/truncate, function calling, image input and session resume. OpenAI and Qwen currently report
only the common WebSocket/audio/transcript/cancel surface as supported.

## Doubao Finding

豆包确实有同类能力。火山引擎官方产品页把“豆包·实时语音大模型”描述为原生 Speech-to-Speech，
并给出约 1.5 秒整体时延；2025-10 的实时音视频发版说明进一步说明端到端模型有两种运行形态：

- 纯端到端模式：低延迟闲聊；
- 混合编排模式：闲聊走端到端模型，Function Calling 等复杂意图转交 `LLMConfig` 中的模型。

这说明它在产品能力上属于本项目的候选，但不能作为 OpenAI-compatible model string 接入。公开资料还
呈现了“豆包语音服务”与“火山 RTC 实时对话式 AI”两个接入面；在选定产品面、固定 endpoint、鉴权、
音频帧和事件 schema 前，不新增 `DoubaoRealtimeAdapter`，也不宣称工具调用是端到端模型本身的能力。

## Ordered Delivery

1. **Capability contract v2（已完成）**：让 UI/controller/QA 只启用 adapter 真正实现的能力；
2. **Qwen baseline contract（已完成）**：新 profile 默认 `qwen3.5-omni-plus-realtime`、北京地域、
   `Tina`；锁定 workspace endpoint、16 kHz PCM input、24 kHz PCM output 与 server VAD；
3. **Qwen real-provider/device QA**：以 `qwen3.5-omni-plus-realtime` 跑两次 session acknowledgement、三轮、
   barge-in、finish drain 和弱网测试；现有 profile 不静默迁移；
4. **macOS audio path（代码已完成）**：capture tap 前启用 Apple voice-processing I/O，cleanup 时关闭；
   真实设备仍需记录 AEC/NS/AGC、echo/leakage 与首尾音素结果；
5. **Interruption correctness**：加入 playout cursor、output clear 与 conversation truncate；
6. **Observability**：首音频、turn end→first audio、cancel 生效、disconnect/reconnect 指标；
7. **OpenAI reference regression**：有可用凭据时保留 `gpt-realtime-2.1` 跨 provider contract 回归；
8. **Doubao spike**：在豆包语音直连与火山 RTC 编排层之间做一次有凭据的协议/成本/延迟裁决；
9. tools、vision、WebRTC 扩展只在基础语音门通过后进入独立 phase。

## Acceptance Addendum

- capability test 必须证明“厂商支持但 adapter 未实现”的能力仍返回 false；
- Qwen 是当前可付费执行的工程 baseline；真实 provider QA 仍是 owner 验收前的独立门，不能由文档发现代替；
- barge-in 验收不仅看声音停止，还要证明 server conversation context 不含用户未听到的 assistant 尾部；
- 豆包 spike 必须固定具体产品面、region、endpoint、auth、协议版本、音频格式和工具调用归属。
