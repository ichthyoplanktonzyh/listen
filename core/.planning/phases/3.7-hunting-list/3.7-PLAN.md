# Phase 3.7 Plan: Hunting List（猎词单）

状态：PLANNED

上游输入：`3.0-PHASE-BREAKDOWN.md`、`.planning/discuss/listen-learning-activity-path.zh.md`

## Objective

资产感知的泛听增强：用户带 3-5 个攻克目标进入"狩猎模式"，播放器在目标出现的句子
前后给予预算内的轻量提示（priming / check），单键作答产生真实语境识别证据。
这是 noticing（注意假说）的产品化：`known_not_recognized` 的本质是声音流过时
没被注意到，定向提示制造注意时机。

本 phase 是整个 3.x 里"打地鼠化泛听"风险最高的功能，克制设计是第一要求。

## User Value

> "这周我在攻 'would have'。通勤泛听时它飞过 3 次，app 提前半句提醒我竖起耳朵，
> 事后问我听出了没——攒的证据最后变成了状态升级建议。"

## Scope

### In

- **猎词单管理**：
  - 来源三入口：用户手选（词汇本/词典/复习页）、复习反复失败自动候选
    （3.4 候选池）、整理时刻确认的 phrase。
  - 上限 3-5 个（heuristic，可配置下调不可上调超硬上限）。
- **狩猎模式**：泛听会话的显式增强开关（默认关，会话级，不粘滞为全局默认）。
- **目标定位**：对当前媒体 timeline 预扫描目标出现点（word/phrase 匹配沿用
  LexicalUnit 归一口径）。
- **提示交互**：
  - 前置提示（priming）：目标句开始前的轻量提示（视觉低调 + 可选音效）。
  - 后置确认（check）：目标句结束后单键问答"听出了吗？是/否/没注意"。
  - **提示预算**：每次会话硬上限（初始 5 次），同一目标每会话最多 2 次；
    超出预算的出现点静默跳过。
- **证据落库**：作答写入观察证据（语境去重口径与 3.4 一致），流入升级建议聚合。
- 狩猎结果小结：会话结束时随理解度自报一起给一行小结（命中 N 次 / 听出 M 次）。

### Out（Non-goals）

- 默认泛听路径的任何提示（P4 红线）。
- 提示时自动暂停/自动重播（用户不按键就什么都不发生）。
- 猎词单自动扩容、系统自动塞目标（来源必须经用户手确认或明确规则候选）。

## Dependencies

- 3.3（泛听会话与单键交互框架）——硬依赖。
- 3.4（候选池与升级建议证据通道）——软依赖：缺席时手选目标 + 证据仅落库。

## Key Work

1. 猎词单存储与管理 UI（含来源标注、上限约束）。
2. timeline 目标预扫描（含 phrase 多词窗口匹配）。
3. priming/check 提示交互与预算控制器。
4. 作答证据写入 + 会话小结。
5. 真实媒体手工 QA：一次狩猎泛听，验证提示不超预算、不破坏连续感。

## Exit Signal

- 一次真实狩猎泛听：提示次数 ≤ 预算，作答证据正确落库并计入升级建议。
- 关闭狩猎模式后泛听路径与 3.3 行为完全一致（零残留打扰）。
- **独立可用**：猎词单可只作为"我正在攻克的清单"查看，不开狩猎也有展示价值。

## Guardrails

- 显式开启、会话级、预算硬上限——三者缺一不可。
- 提示文案不施压；"没注意"是合法答案且不计为失败。
- 目标只能来自用户自己的资产，系统不夹带推荐词。
