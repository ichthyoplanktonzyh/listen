## Objective

资产感知的泛听增强：用户带 3-5 个攻克目标进入"狩猎模式"，播放器在目标出现的句子
前后给予预算内的轻量提示（priming / check），单键作答产生真实语境识别证据。
这是 noticing（注意假说）的产品化：`known_not_recognized`（现行口径：reading
Acquired + listening NotAcquired）的本质是声音流过时没被注意到，定向提示制造注意时机。

本 phase 是整个 3.x 里"打地鼠化泛听"风险最高的功能，克制设计是第一要求。

## User Value

> "这周我在攻 'would have'。通勤泛听时它飞过 3 次，app 提前半句提醒我竖起耳朵，
> 事后问我听出了没——攒的证据最后变成了 listening 通道的升级建议。"

## Scope

### In

- **猎词单管理**：
  - 来源三入口：用户手选（词典页 / 复习结束页）、复习反复失败自动候选
    （`hunting_candidates`，schema v20，已存在）、整理时刻确认的 phrase。
  - 上限 3-5 个（heuristic，可配置下调不可上调超硬上限）。
  - 猎词单本身是可查看资产（"我正在攻克的清单"），入口放词典页工具栏与泛听会话开关旁。
- **狩猎模式**：泛听会话的显式增强开关（默认关，会话级，不粘滞为全局默认）。
- **目标定位**：
  - 优先复用 `corpus_occurrences` 投影（schema v28/v29）：按 media 过滤 + lemma 归一
    查目标出现点（词 token 与 chunk/句子两类口径都已建索引），出现点自带
    sentence 关联与时间窗。
  - 当前媒体无 corpus 索引时：提示一键重建索引（复用 3.6 reindex 入口），或降级为
    对 active timeline 的一次性预扫描（同一 `normalize_lexical_form` 归一口径）。
- **提示交互**：
  - 前置提示（priming）：目标句开始前的轻量提示（视觉低调 + 可选音效）。
  - 后置确认（check）：目标句结束后单键问答"听出了吗？是/否/没注意"
    （复用 3.3 泛听单键交互框架）。
  - **提示预算**：每次会话硬上限（初始 5 次），同一目标每会话最多 2 次；
    超出预算的出现点静默跳过。
- **证据落库**（现行口径，替代 v1 的"与 3.4 一致"）：
  - "是/否" → `create_lexical_observation` 单写入口（ADR 0017），listening 通道
    RecognizedInContext / NotRecognizedInContext，触发 ADR 0019 listening 重投影；
    `recognition_evidence`（v21）按句子/媒体去重，流入既有 5-语境升级建议聚合。
  - "没注意" → 合法答案，不写观察证据，只计入会话统计（LearningEvent 级）。
  - 出现点必须有 sentence 关联才出提示（与 3.6 逐例标记的禁用口径一致）。
  - 不静默修改 capability override / legacy status。
- **狩猎小结**：3.5.6 之后精听无 session summary，泛听 completion 是 extensive-only
  路由（`POST /v1/listening/sessions/{id}/complete`）。狩猎小结作为该 completion
  理解度自报页上的一行统计（命中 N 次 / 听出 M 次），不新建通用 summary 机制。

### Out（Non-goals）

- 默认泛听路径的任何提示（P4 红线）。
- 提示时自动暂停/自动重播（用户不按键就什么都不发生）。
- 猎词单自动扩容、系统自动塞目标（来源必须经用户手确认或明确规则候选）。
- 狩猎作答不进 content-fit 校准（3.5 折算口径只收练习正确率与理解度自报）。

## Dependencies

- 3.3（泛听会话与单键交互框架）——硬依赖。**注意 3.3 尚未收口**（真实媒体 30 分钟
  QA 与全局热键决策未完成）；开工前先由 owner 裁决：补完收口，或明确豁免后在 3.7
  的真实媒体 QA 中一并覆盖。
- 3.4 `hunting_candidates` 候选池（v20）——已存在，直接消费。
- 3.6 corpus 投影与 reindex 入口——软依赖：缺索引媒体走 timeline 预扫描降级。

## Key Work

1. 猎词单存储与管理 UI（含来源标注、上限约束；文案走 localization）。
2. 目标出现点定位：corpus 投影查询 + 无索引降级路径（含 phrase 多词窗口口径对齐）。
3. priming/check 提示交互与预算控制器（会话级状态，关闭即清零）。
4. 作答证据写入（ADR 0017/0019 链路）+ 泛听 completion 页小结行。
5. 真实媒体手工 QA：一次狩猎泛听，验证提示不超预算、不破坏连续感。

## Exit Signal

- 一次真实狩猎泛听：提示次数 ≤ 预算，作答证据经 ADR 0017 正确落库并计入升级建议聚合。
- 关闭狩猎模式后泛听路径与 3.3 行为完全一致（零残留打扰）。
- **独立可用**：猎词单可只作为"我正在攻克的清单"查看，不开狩猎也有展示价值。

## Guardrails

- 显式开启、会话级、预算硬上限——三者缺一不可。
- 提示文案不施压；"没注意"是合法答案且不计为失败、不写观察证据。
- 目标只能来自用户自己的资产，系统不夹带推荐词。
