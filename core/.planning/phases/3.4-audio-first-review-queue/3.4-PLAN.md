# Phase 3.4 Plan: Audio-first Review Queue

状态：PLANNED

上游输入：`3.0-PHASE-BREAKDOWN.md`、`.planning/discuss/listen-learning-activity-path.zh.md`

## Objective

把 3.0.1 已就绪的 `ReviewItem` / `ReviewAttempt` 后端做成声音卡优先的复习队列 UI，
并落地**升级建议引擎 v1**——多语境识别证据聚合后向用户提议
`known_not_recognized -> known_recognized`，用户确认才改。

## User Value

> "等咖啡的三分钟，耳机里过 8 张声音卡，单键作答。攒够证据后 app 问我：
> 'would have' 要不要标为已能听出？"

## Scope

### In

- **复习队列 UI**：到期列表入口（显眼但不打卡化）、队列播放流。
- **Audio-first 卡型**（v1 收口为四种）：
  - 听音识词（播放词窗口 -> 用户回忆 -> 翻面对照）。
  - chunk cloze（听 chunk 填目标空）。
  - 听句判断目标 phrase 是否出现。
  - 原句回听 + 自评（媒体在时播放真实片段；丢失时 prompt snapshot 降级）。
- **单键作答/评分**：答对/答错/模糊三档；写入 `ReviewAttempt`；失败生成
  `LexicalObservation` 并进入猎词单候选池（池先落库，3.7 消费）。
- **调度 v1**：简单到期规则（失败短间隔、成功递增），参数按 heuristic_proxy 记录；
  不引入完整 SM-2/FSRS，不被 Anki 数据模型绑架。
- **升级建议引擎 v1**：
  - 聚合证据：practice / review / （后续）猎词 / 词典逐例标记，按"不同语境"去重
    （不同媒体/句子）。
  - 达阈值（初始 heuristic，如 5 个不同语境成功）生成建议，用户确认才改
    `LearningStatus`，拒绝则冷却。
  - 建议出现在整理时刻/词汇详情/复习结束页，不弹窗打断播放。
- 复习入口来源：精听存入项、Inbox 整理项、词汇本手动加入（词汇本"加入复习"入口）。

### Out（Non-goals）

- 完整 SRS 算法与参数调优。
- Anki export/AnkiConnect（后续增强）。
- shadowing 评分卡（3.8）。
- 跨例句聚合搜索（3.6 提供后接入新卡型）。

## Dependencies

- 3.0.1 后端（已完成）。3.1/3.3 提供入队来源，但缺席时词汇本手动入队即可独立成立。

## Key Work

1. ReviewController / 队列 Store + 到期查询 API 补齐（如后端缺 list/due 接口则补）。
2. 四种卡型 UI 与音频窗口播放复用。
3. 调度 v1 与 `ReviewAttempt` 写入。
4. 升级建议引擎（证据聚合读侧 + 建议记录 + 确认流）。
5. 猎词单候选池存储。
6. 来源丢失降级路径（snapshot 卡、跳过音频卡）。

## Exit Signal

- 用户从复习入口完成一轮 ≥8 张声音卡，作答全部落库。
- 一个真实词条经多语境成功证据触发升级建议，确认后状态变更且历史可查；
  拒绝后不再重复骚扰。
- 复习失败不修改全局状态，只产生 evidence。
- **独立可用**：仅靠词汇本手动加入即可使用复习，无需精听/泛听沉淀。

## Guardrails

- 不静默改状态（升级与降级都必须用户确认）。
- 低置信音频 case 不强行排进复习。
- 到期数量是信息不是压力：无 streak、无欠账羞辱文案。
