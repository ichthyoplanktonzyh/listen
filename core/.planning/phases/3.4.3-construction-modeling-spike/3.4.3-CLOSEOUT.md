# Phase 3.4.3 Closeout: Construction Modeling Spike

状态：COMPLETED
完成时间：2026-07-10 CST

## Outcome

Phase 3.4.3 establishes an executable, deliberately small modeling boundary for sentence
materials, canonical constructions, occurrences, and user-owned patterns. It does **not** add a
production construction subsystem.

## Delivered

- `crates/domain/src/construction.rs`: pure types, stable identity helpers and fixture validator.
- `testdata/construction-spike/gold-fixture-v1.json`: manual gold fixture for English, Chinese,
  and Japanese.
- Four focused domain tests: fixture validity; nested/multiple occurrences; variant-policy
  rejection; separate canonical/exemplar identity. The fixture additionally asserts that a
  personal template can originate from an exemplar with no system occurrence.
- [ADR 0020](../../../docs/decisions/0020-construction-spike-identity-and-user-pattern-boundaries.md)
  and [failure-mode report](3.4.3-FAILURE-MODES.md).

## Exit Signals

| Signal | Result |
|---|---|
| Same/different canonical construction is explainable | `language + key + schema_version`; variants are construction-owned policy. |
| Concrete sentence and abstraction do not share lifecycle | ✅ exemplar source snapshot vs manually curated construction identity. |
| Personal pattern can optionally link, never depend on a system construction | ✅ fixture covers both linked and unlinked patterns, including an unanalysed source exemplar. |
| Recognition/production does not discard modality | ✅ evidence keeps reading/listening/speaking/writing. |
| Production schema decision | **Do not build now.** |

## Why no schema/API/UI now

The fixture validates representation invariants but does not establish canonical-library
governance, automatic-analysis accuracy, user correction lifecycle, media deletion/import
semantics, or a validated consumer workflow. Persisting all four entities now would freeze
premature answers to those questions.

## Recommended next minimal product slice

Run a user-value slice before any canonical construction schema:

1. From a saved sentence/material, let the learner create and edit a `UserSentencePattern`.
2. Preserve the source text/media snapshot and allow patterns with no system match.
3. Do not surface recognition/production scoring, parser output, or a construction library yet.
4. Observe whether people repeatedly reuse/edit these patterns. Only then decide whether to
   persist `SentenceExemplar + UserSentencePattern`; canonical `Construction` and occurrence
   tables need a separate provider/library decision.

This recommendation is intentionally not an authorization to build the slice in 3.4.3.
