# Phase 3.4.3 Plan: Construction Modeling Spike

状态：COMPLETED — 2026-07-10 CST

共享上下文：
`../3.0-english-listening-learning-loop/3.4.X-LEARNING-DOMAIN-V2-SHARED-CONTEXT.md`

## Objective

用小型固定语料验证 SentenceExemplar、Construction、ConstructionOccurrence 和
UserSentencePattern 的身份、槽位、变体和去重规则，在模型稳定前不建设大规模生产资产表。

## Planned Slices

1. [x] 选择英语、汉语及日语，建立 `testdata/construction-spike/gold-fixture-v1.json`。
2. [x] 定义 exemplar、canonical construction、occurrence slot binding 和个人句模边界。
3. [x] 验证时态/语态/否定/疑问变体、嵌套命中和一个句子多构式。
4. [x] 验证 recognition / production assessment 与 modality-tagged evidence。
5. [x] 形成 ADR、失败模式报告和后续最小产品竖切片建议。

## Exit Signals

- 相同/不同 Construction 的判定规则可解释并能通过固定 fixture。
- 具体收藏句不会与抽象构式共享身份或生命周期。
- 用户个人句模可以关联系统 Construction，但不被系统分析强制覆盖。
- 输出明确回答是否值得进入生产 schema；若证据不足，允许以“不建表”收口。

## Non-goals

- 不自动生成大规模句式库。
- 不在 identity 未稳定时建设完整 UI、SRS 或跨语言构式图谱。
- 不把 parser/LLM 输出直接当作 canonical truth。

## Result

- 领域 spike 位于 `crates/domain/src/construction.rs`；fixture validator 和 4 个 focused
  unit tests 可执行，但不接入 SQLite、API、LLTimeline 或 Flutter。
- canonical `Construction` 的 identity 是人工维护的
  `(language, key, schema_version)`；不从文本或自动分析结果生成跨语言 identity。
- `SentenceExemplar` 的 identity 包含 language、来源快照和文本；它与 `Construction`
  不共享生命周期。`ConstructionOccurrence` 是可重建 annotation，允许嵌套与重叠。
- `UserSentencePattern` 可从任意 exemplar 建立并保留文本快照。它可选关联系统 construction，
  但 fixture 明确覆盖了“来源句没有任何系统 occurrence”的个人模板。
- **生产 schema 决定：不建设。** 当前小型人工 fixture 证明了边界，不足以冻结自动标注、
  canonical library 管理、迁移或 UI 行为。详见 `3.4.3-CLOSEOUT.md`。
