## 1. 全局陷阱（本指南最重要的一节）

### 1.1 索引空间：token index，不是 word 序数

这是唯一容易做错且做错后不易察觉的点：

- `ChunkTimelineChunk.start_word_index / end_word_index` 用的是**过滤后 Word token 的
  序数**（`tokens.filter(kind == Word)` 后 enumerate，见
  `crates/speech-analysis/src/chunk_partition.rs:283`）。
- `SenseGroup.start_token_index / end_token_index` 用的是 **`SubtitleToken.index`
  原始 token 空间**（标点 token 占号），与 `WordTiming.token_index` 同一空间——
  `sense_group_playback_range()` 已按此空间过滤（见 `sense_group.rs`）。

因此 partition provider 输出边界时必须取 `token.index`，**不得**用过滤后的枚举序数。
span 内夹标点是合法的（标点无 WordTiming，投影时自然跳过）。

**测试必须包含带句中标点的句子**，断言 span 覆盖标点 token 且播放投影正确。

### 1.2 active 唯一约束的写法

status 列存的是 serde JSON 字面量。partial unique index 必须照抄
`0013_chunk_timelines.sql` 的写法（注意双引号）：

```sql
CREATE UNIQUE INDEX sense_group_analysis_runs_one_active_per_track_idx
  ON sense_group_analysis_runs(track_id)
  WHERE status = '"active"';
```

### 1.3 生成不依赖 active word timeline（与 chunk 的关键差异）

`generate_chunk_timeline` 要求 active word timeline（chunks.rs:54-57）。SenseGroup 是
纯文本标注（ADR 0016 决策 2），**不得**有这个硬依赖：

- 无 active word timeline 时照常生成，`parent_word_timeline_id = None`；
- 有时记录其 id 作为 provenance，但不读取任何时间数据。

### 1.4 ADR 0016 决策 9（overlay 不排除性）

- provider 产出的持久化 `SenseGroupAnalysis` 行内**永不**出现 `SenseGroupSource::User`；
- 本阶段**不建** overlay 表、不做编辑 API（无写入方）；
- schema 与读模型不得假设"一个句子的全部 groups 必然来自单一 analysis 行"
  ——实践上：不要写出依赖该假设的 UNIQUE 约束或合并逻辑即可。

### 1.5 环境已知问题

`./scripts/validate-contracts.sh` 在缺 `jieba` 的机器上有 4 个 CJK 分词测试失败，
是既有环境问题（2026-07-07 已在无改动树上复现确认），与本阶段无关。
`pip install jieba` 可消除；不要为绕过它改测试。

## 2. Slice 2 — 规则回退 partition provider

新文件 `crates/speech-analysis/src/sense_group_partition.rs`，在 `lib.rs` 注册模块。

参照物（读完再写）：

- `crates/speech-analysis/src/text_chunk_detection.rs` — 纯文本标点/长度切分的现成写法
- `crates/speech-analysis/src/chunk_partition.rs` — PhraseCandidate 保护、config 模式

实现要求：

```rust
pub const PROVIDER_ID: &str = "rule-based-sense-group";
pub const PROVIDER_VERSION: &str = "v1";
pub const ALGORITHM: &str = "punctuation_length_rule_v1";

pub struct SenseGroupPartitionConfig {
    pub min_words: usize,              // 建议默认 2
    pub soft_max_words: usize,         // 建议默认 5
    pub hard_max_words: usize,         // 建议默认 8
    pub target_groups_per_sentence: usize, // 建议默认 4，仅作 metrics 参考
}

pub fn partition_sentence(
    sentence: &SubtitleSentence,
    phrase_candidates: &[PhraseCandidate],
    config: &SenseGroupPartitionConfig,
) -> Vec<SenseGroupSpan>   // (start_token_index, end_token_index, sources, confidence)
```

规则（按优先级）：

1. 强标点（. ! ? ; ： 。！？；）后强制边界 → source `Punctuation`。
2. 弱标点（, 、 —）后倾向边界：若当前组已 ≥ min_words 则断开 → `Punctuation`。
3. 组内 Word token 数达 soft_max_words 后遇任意标点即断；达 hard_max_words 强制断
   → `LengthLimit`。
4. PhraseCandidate 命中的 token 区间不得被边界切开（与规则 3 冲突时短语保护优先，
   除非超 hard_max）→ 命中的组附加 source `Rule`。
5. 句子 Word token 数 < min_words*2 时整句一组。
6. confidence：纯规则输出统一 0.5（诚实的低置信度，为将来 UD/LLM provider 留出区分度）。

长度均按 **Word kind token 计数**（CJK 下 subtitle-core 已分词，token 即词，规则同样成立），
但边界索引输出按 1.1 节用原始 `token.index`。

测试（同文件 `#[cfg(test)]`）：

- 英文 ≥5 句：短句单组 / 常规带逗号句 / 长无标点句触发 LengthLimit /
  含插入语（两侧逗号）/ 含 PhraseCandidate 跨弱标点验证保护。
- 中文 ≥3 句：常规句 / 带顿号 / 长句。可参照
  `crates/speech-analysis/tests/chunk_partition_golden_test.rs` 的 fixture 构造方式，
  用 subtitle-core 真实 tokenizer 生成 token（不要手搓假 token 掩盖分词差异）。
- 不变量断言：组互不重叠、连续覆盖全部 Word token、每组 ≥1 个 Word token。
