# Phase 2.17 Plan: Real Media Sound-Line QA

状态：PLANNED

## Objective

建立一组可复现的真实英语声音线 QA 材料，用来验证：

- `sound_analysis.learning_phones` 是否能稳定支撑声音线显示。
- `sound_analysis.connected_speech` 是否能解释真实语流现象，而不是放大 raw CTC mismatch。
- 声音线 marker、tooltip 和 "listen to this moment" 回放窗口是否对学习者有帮助。
- 哪些 CTC mismatch 应用于教学解释，哪些只适合高级诊断，哪些应默认隐藏。

本 phase 不继续扩大模型覆盖面，而是把 Phase 2.14-2.16 已经打通的链路固定成可回归资产：

```text
media/subtitle
  -> WordTimeline
  -> ChunkTimeline
  -> PhoneTimeline
  -> sound_analysis.learning_phones
  -> sound_analysis.connected_speech
  -> sound-line marker
  -> listen-to-this-moment playback
  -> QA decision
```

## Working Principles

- **真实材料优先**：主验收材料必须包含真实英语媒体或自然语流，不只依赖合成 fixture。
- **许可保守**：无明确再分发许可的媒体、字幕、benchmark 本体不提交 repo，只提交 manifest、
  checksum、local-only locator 和复现说明。
- **人工听感不伪装成客观指标**：manual QA 是产品判断输入；verifier 只做资源形状和安全边界检查。
- **TIMIT 是 sanity check，不是主验收**：TIMIT 可验证 phone-level 边界/identity，但不代表真实媒体体验。
- **raw CTC mismatch 默认有罪推定**：只有能被 connected-speech family、稳定 timing 和人工听感支持的
  mismatch，才可进入学习者可见解释。

## Benchmark Strategy

Phase 2.17 使用三层材料。下一个智能体应优先搭建 Layer 1 + Layer 2 + 至少一个 Layer 3 case。

| Layer | Dataset / Source | Role | Repo handling |
|---|---|---|---|
| 1. Phone gold sanity | TIMIT（用户本地已有） | 验证 phone boundary、phone identity、marker 越界、CTC mismatch 粗错误 | local-only manifest；不提交本体 |
| 2. Natural connected speech | Buckeye Corpus（优先） | 验证 weak form、deletion、linking、flapping、assimilation 等真实语流 | local-only manifest；记录 license/source |
| 3. Product-like media | 本地新闻/访谈视频、TED-LIUM、LibriSpeech/VCTK/Common Voice 选一到二种 | 验证 UI、回放窗口、字幕/时间轴资源链路和学习体验 | 有许可才提交小片段；默认 local-only |

### Dataset Guidance

- **TIMIT**：用于自动 verifier smoke 和 phone-level regression。适合回答“phone range 是否越界、
  timing 是否荒唐、alignment 是否完全跑偏”。不适合判断真实 connected speech 教学价值。
- **Buckeye**：本 phase 最推荐新增 benchmark。自然美式对话、带 word/phone timing 和 actual
  pronunciations，最接近 connected-speech validation。
- **TED-LIUM / 本地新闻视频**：最接近产品输入形态（媒体 + 字幕 + app UI）。用于 manual QA 和截图/观察记录。
- **LibriSpeech / VCTK**：朗读体，适合批量稳定性、speaker/accent coverage，不作为 connected-speech 主证据。
- **Common Voice**：适合噪声和口音鲁棒性；短句和上下文较弱，作为 supplemental。
- **L2-ARCTIC**：非母语英语可用于后续区分 learner pronunciation vs native connected speech，本 phase
  只作为研究附录，不进入主验收。

### 2. Lightweight Verifier

新增脚本：

```text
scripts/verify-sound-line-real-media.py
```

Primary command:

```sh
python scripts/verify-sound-line-real-media.py \
  --manifest testdata/sound-line-real-media/manifest.jsonl
```

Required checks:

- manifest JSONL 可解析；每行包含 `case_id`、`layer`、`source`、`lltimeline`、`qa_notes`。
- `case_id` 唯一，且只包含 lowercase ASCII、数字、短横线。
- referenced QA notes 文件存在。
- referenced `.lltimeline.json` 存在，或者 `lltimeline.local_only == true` 且有清晰 local path/status。
- 如果 `.lltimeline.json` 存在：
  - `schema == "llplayer.timeline.v1"`。
  - `segments`、`word_timelines`、`phone_timelines` 字段存在。
  - 至少一个 active/candidate `PhoneTimeline` 含 `sound_analysis.learning_phones`。
  - 每个 `learning_phone` 的 `start_ms < end_ms`。
  - 每个 `connected_speech` 的 `phone_start` / `phone_end` 不越界。
  - marker 对应的 playback window duration 在 40ms-1500ms 之间。
  - `confidence` 在 0-1 范围内。
  - `status` 属于 `possible_by_rule` / `supported_by_audio` / `detected_in_audio`。
- 全局至少一个 case 含非空 `sound_analysis.connected_speech`。
- 全局至少两个 case 可用于 regression；local-only 缺文件时输出 warning，不应误报为 schema failure。

Suggested CLI behavior:

- 默认：缺少 local-only resource 是 warning；缺少非 local-only resource 是 error。
- `--strict-local`：local-only 缺文件也作为 error，便于本机完整验收。
- `--json`：输出 summary JSON，便于后续 CI 或 agent 汇总。
- `--require-ready`：最终验收模式，要求至少一个 timeline case 含 learning phones 和
  connected-speech markers；当前中间态允许失败。

### 3. Manual QA Records

每个 case 创建一个 notes 文件：

```text
testdata/sound-line-real-media/cases/<case-id>.md
```

每个 case 至少 3 条 observation：

- 一个“有帮助”的 marker。
- 一个“可疑/误导”的 marker。
- 一个“应该有但没有”的听感现象，若存在；若没有，明确写 `none observed`。

Observation 模板：

```md
## Observation 1

- timestamp_ms:
- sentence / words:
- phone_range:
- connected_speech_family:
- ui_label:
- marker_status:
- playback_window_ms:
- playback_result:
- qa_decision: keep | filter | downgrade | needs_provider_investigation
- mismatch_source: timing | phone_identity | transcript_alignment | unclear | none
- notes:
```

Case notes 还应包含：

- source / license summary。
- generation command 或复现步骤。
- known false positives。
- known false negatives。
- screenshot / UI observation references，如有。

### 4. CTC Mismatch Findings

新增：

```text
.planning/phases/2.17-real-media-sound-line-qa/2.17-CTC-MISMATCH-FINDINGS.md
```

文档必须至少记录 5 条 decision input，每条包含：

- case id
- timestamp / phone range
- expected symbols
- learning symbols
- observed symbols
- connected-speech family, if any
- confidence / status
- listening judgment
- decision: `teach` / `advanced_diagnostic` / `hide_by_default` / `needs_provider_fix`
- cause: `timing` / `phone_identity` / `alignment` / `real_connected_speech` / `unclear`

该文档最后给出策略建议：

- 哪些 mismatch 可以支持 connected-speech explanation。
- 哪些 mismatch 只能作为高级诊断。
- 哪些 mismatch 应默认隐藏。
- 哪些问题来自 timing，哪些来自 phone identity。

### 5. Optional UI Bug Fixes

如果 QA 暴露小范围 UI bug，可在本 phase 内修复，例如：

- marker tap 的 playback window 太长/太短。
- tooltip 文案泄漏 raw CTC label。
- 空 `sound_analysis` 时声音线状态不清晰。
- marker 越界导致前端异常。

不在本 phase 内做：

- 重写 CTC provider。
- 新增完整 Prosodic Hierarchy。
- 大规模 connected-speech model 重构。
- 多语言 sound-line 扩展。

### Step 4: Manual Listening QA

对每个主 case，在 app 中执行：

1. 导入或挂载媒体。
2. 导入字幕/LLTimeline。
3. 激活对应 WordTimeline / ChunkTimeline / PhoneTimeline。
4. 打开声音线。
5. 点击 connected-speech marker 的 evidence 回放。
6. 记录至少 3 条 observation。

Manual decision guide:

- `keep`：marker 和回放可听，解释对学习者有帮助。
- `downgrade`：可能有现象，但文案/置信度应弱化。
- `filter`：marker 对学习者误导，应默认隐藏。
- `needs_provider_investigation`：像是 provider/timing/identity 问题，不能靠 UI 文案解决。

Exit criteria:

- 每个主 case 至少 3 条 observation。
- 至少 5 条 observation 可提炼为 CTC mismatch / connected-speech decision input。
