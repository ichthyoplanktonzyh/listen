## Teach-Worthy Mismatch Patterns

These markers have `detected_in_audio` status and represent real connected speech phenomena observable in natural English:

1. **Flapping (T→DX)**: The /t/ between vowels becomes a flap [ɾ]. Example: "with a" → DX. This is ubiquitous in American English and every learner should know it.

2. **Weak form / vowel reduction (AH→AX)**: Unstressed vowels reduce to schwa. Examples: "dealing", "phone", "show". These are common and well-detected.

3. **Assimilation**: Consonants change to match adjacent sounds. Example: "What's" AHT→EI5 (likely t-glottalization before "up"). Value depends on IPA label accuracy.

4. **Rhotic reduction (EHR→EY)**: R-colored vowels simplify. Example: "city" EHR→EY. Worth teaching but less common than flapping.

**Recommendation**: `detected_in_audio` status markers with `confidence > 0.7` and non-empty `observed_symbols` should be the default visible set for learners.

## Advanced Diagnostic Only Patterns

1. **`possible_by_rule` markers with plausible context**: Word-final /d/ deletion ("And" → "An'") and /t/ flapping that wasn't detected but is probable. These could be useful for advanced learners or researcher debugging.

2. **`supported_by_audio` markers**: The algorithm found acoustic evidence but couldn't confirm with high confidence. Intermediate status between rule-based guess and full detection.

**Recommendation**: Show in an "advanced" or "detailed" view mode, not in default learner view.

## Hide-By-Default Patterns

1. **Sentence-initial deletions**: All `possible_by_rule` deletions on the first token of a sentence (e.g., "And" D, "I'm" AY). These are almost certainly alignment artifacts — the CTC model's first-frame alignment doesn't perfectly match the canonical phone boundary.

2. **`possible_by_rule` deletions in general**: Without audio evidence, these are noise to learners. Deletions are hard to confirm from CTC alone.

3. **Duplicated markers on same phone**: The original Brooklyn artifact had duplicated linking markers on the same phone. The generic insertion gate removes this case from the default connected-speech layer; future provider work should still deduplicate lower-level diagnostic findings.

**Recommendation**: These should be filtered from default learner view. `possible_by_rule` markers should require explicit learner opt-in.

## Timing vs Phone Identity Failures

- **Timing issues**: Sentence-initial deletions look like alignment boundary artifacts. CTC models have worst timing accuracy at segment boundaries.
- **Phone identity issues**: The linking markers with empty expected_symbols suggest the canonical phone pipeline didn't produce expected symbols for those positions, or the token-to-phone mapping is off.
- **Mixed**: `possible_by_rule` markers combine both: the rule says "this phone could be deleted", but timing ambiguity means we can't be sure the model detected actual deletion vs. boundary misalignment.

## Recommended Next Phase Actions

1. **Keep generic insertion hidden**: Do not re-enable learner-facing `linking` from raw CTC insertion unless the rule has explicit cross-token boundary evidence.

2. **Downgrade `possible_by_rule` display**: In the default learner view, show only `detected_in_audio` markers. Put `possible_by_rule` and `supported_by_audio` behind an advanced/diagnostic mode.

3. **Filter sentence-initial markers**: Skip `possible_by_rule` markers on the first phone/token of a sentence.

4. **Minimum confidence threshold**: Consider a floor such as 0.6 for `detected_in_audio` markers shown to learners.

5. **Add reference scoring later**: TIMIT/Buckeye/TED-LIUM should get a separate scoring harness for phone identity, boundary error, and transcript alignment. Phase 2.17 establishes the reproducible materials and failure evidence; it does not claim a final benchmark score.

6. **Build UI E2E in a later testing phase**: The headless runner proves the API path. A later phase should launch the desktop app, create a phonetic job through UI controls, and click sound-line markers to verify playback windows.

## Default Filtering Strategy Summary

```text
Default learner view:
  - Show: status=detected_in_audio AND confidence >= 0.6 AND expected_symbols is non-empty
  - Hide: status=possible_by_rule (all)
  - Hide: status=supported_by_audio (all, move to advanced view)
  - Hide: duplicate markers on same phone index

Advanced/diagnostic view:
  - Show all markers
  - Sort by confidence descending
  - Group by connected_speech_family
```
