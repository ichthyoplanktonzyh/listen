# Phase 2.10 Context: English Real Speech Analysis

## 问题

当前英语语流分析是纯文本规则引擎：

```
用户看到: "the" → 可能弱读 (LikelyByContext, 0.72)
实际需要: 音频检测到说话人确实把 /ðiː/ 弱化为 /ðə/ (DetectedInAudio, 0.91)
```

`speech-analysis` crate 的 `analyze_rules()` 基于 11 条弱读规则 + 6 条连接语流规则
（contraction/assimilation/linking/deletion/flapping），全部是文本启发式。没有音频层。

## 候选 phone recognizer

| 候选 | 优势 | 劣势 | 许可证 |
|------|------|------|--------|
| **MFA phone alignment** | 已有 sidecar，TIMIT 评估最优，phone-level boundaries | 对齐 canonical phone，不证明真实弱读 | MIT |
| **ZIPA 64M / CTC** | 64 语言，IPA 输出，harness 已存在 | 模型许可证元数据不明，timestamp projection 待验证 | 待查 |
| **Wav2IPA / Wav2Vec2Phoneme** | HuggingFace 生态，fine-tuned for phoneme | 具体模型/训练数据 provenance 待锁定 | 待查 |
| **Allosaurus** | 跨语言 baseline | 不适合作默认英语 provider | BSD |

## 质量门禁（Phase 2.5 定义）

进入默认 product path 前必须同时满足：
1. 至少 10 条 development cases 通过 `validate-inputs`
2. phones 单调、位于音频范围、可映射到 sentence/token
3. 不能把弱读/省音/闪音规范化回字典发音后仍声称 detected
4. 记录 PER、timeline validity、token association coverage、failure rate、RTF、peak RSS
5. 高置信 findings 需人工 precision review
6. provider/model revision、checksum、许可证明确
7. 低置信/canonical-only 结果不标成 `detected_in_audio`

## 关键技术问题

1. **canonical vs detected**：MFA 对齐的是字典发音（canonical），不是说话人实际发音。
   如何从 canonical alignment 推断真实语流现象？
   - 方案 A：canonical alignment + 声学证据（能量/频谱偏差）→ detected
   - 方案 B：直接用 phoneme recognizer（ZIPA/Wav2IPA）输出 detected phones
   - 方案 C：两层结合——canonical alignment 提供边界，recognizer 提供内容

2. **评估方法**：如何验证"说话人真的弱读了"？
   - TIMIT 有 phone-level gold，但是朗读语体
   - 需要 connected speech 样本（自然对话/新闻）的人工标注子集

3. **产品诚实**：不同置信度的结论用不同 UI 呈现
   - `DetectedInAudio`：高置信，音频分析确认
   - `LikelyByContext`：文本规则预测，未经音频验证
   - `PossibleByRule`：低置信，仅规则匹配
