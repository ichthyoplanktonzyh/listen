## Manual Smoke Paths

### A. Local Media And Playback

1. Open a local video or audio file.
2. Confirm the no-media control bar is replaced by normal playback controls.
3. Toggle subtitle visibility and confirm the side panel remains reachable when a primary subtitle exists.
4. Confirm secondary subtitle controls are disabled with an explicit unavailable reason when no secondary track is loaded.

Expected result:

- Media/playback state is understandable before and after a file is loaded.
- Hiding subtitles does not hide unrelated transcript/resource/diagnosis context.

### B. Local Whisper Default Path

1. Open local media.
2. Start local Whisper subtitle generation.
3. Confirm bottom controls show a typed subtitle-generation task chip.
4. Wait for generated subtitles to load.
5. Open resource/timeline panels and confirm readiness for Subtitles, Word sync, Chunk replay, Listening structure and Phone evidence.

Expected result:

- Task feedback is typed, not only a free-form status string.
- Generated primary subtitles refresh speech enhancements and capability readiness.
- Missing Word sync, Listening structure or Phone evidence is explained honestly.

### C. Plain SRT/VTT Import

1. Open media.
2. Import a plain SRT or VTT subtitle.
3. Confirm subtitle text and transcript/overlay work.
4. Inspect capability panels.

Expected result:

- Subtitles are available.
- Word sync, Chunk replay, Listening structure and Phone evidence show unavailable/degraded states instead of pretending to be ready.
- Vocabulary and basic diagnosis paths remain usable.

### D. LLTimeline Import

1. Open the matching media.
2. Import or attach an `.lltimeline.json`.
3. If prompted, handle fingerprint mismatch intentionally.
4. Activate the imported resource.
5. Inspect capability and advanced resource details.

Expected result:

- Word sync uses active WordTimeline when present.
- Chunk replay uses active ChunkTimeline when present.
- Listening structure prefers document-level `rhythm_frames`.
- Phone evidence appears only when PhoneTimeline/sound-analysis evidence exists.

### E. Degraded Evidence States

1. Open a subtitle with no WordTimeline.
2. Switch to Listening structure mode.
3. Switch to Phone evidence mode when no detected phones are available.
4. Inspect any predicted/text-prior cues.

Expected result:

- Missing-state ribbons remain visible.
- Predicted or estimated claims are not presented as measured audio.
- Phone evidence absence is visible rather than silently hiding the layer.

### F. URL And Download

1. Resolve or download an online URL.
2. Observe downloading, completed, failed, cancel and dismiss states.
3. Cancel or dismiss an active download and wait for late backend completion/failure.

Expected result:

- Download bar follows the typed `DownloadStatusSnapshot`.
- Late futures do not resurrect a dismissed bar.
- Completed/failed states are clear and dismissible.

### G. Word, Vocabulary And Diagnosis

1. Click a subtitle word.
2. Confirm the word panel opens with lexical information.
3. Change learning status.
4. Confirm subtitle/transcript styling and diagnosis refresh paths remain coherent.

Expected result:

- Word actions are reachable from playback.
- Learning state changes do not conflict with subtitle or diagnosis UI.

### H. Audio Analysis Task

1. Run Phone evidence/audio analysis for the active primary subtitle.
2. Confirm bottom controls show a typed audio-analysis task chip.
3. On completion, inspect speech enhancement/resource details.
4. Force a no-model or failure path if available locally.

Expected result:

- Audio analysis shows typed working/success/error state.
- Completion refreshes speech enhancements.
- Failure is visible, even though detailed backend failure reasons remain a recorded backend gap.

## Known Manual Remainders

- Practice/Review readiness remains a named user capability but awaits a backend product contract before a confident frontend entry can close.
