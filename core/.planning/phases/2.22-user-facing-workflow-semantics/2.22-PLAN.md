# Phase 2.22 Plan: User-Facing Workflow Semantics

状态：ACTIVE

## Objective

Make the existing LLPlayerNext feature set usable as coherent end-to-end workflows.

```text
feature capability model
  -> canonical user paths
  -> typed readiness/status
  -> clearer UI language and entry points
  -> end-to-end verification
```

This phase is allowed to rename UI labels, move controls, add readiness panels, and retire confusing historical copy when that improves the user path.

## Source Of Truth

- `2.22-CONTEXT.md` explains why the phase exists.
- `2.22-FEATURE-SEMANTICS-MODEL.md` is the user-facing capability model.
- `2.22-CURRENT-FEATURE-INVENTORY.md` is the seed inventory for all current user-facing features.
- Phase 2.21 remains the source of truth for audible-structure correctness.
- The old `worktree-ui-feature-semantic-mapping` docs are design input and feature-description seed material, not current implementation truth.

## Step 0: Current UI Audit

Goal:

Establish an exact map from current code to user-visible workflows.

Deliverables:

- Current feature inventory using the Phase 2.22 feature template, seeded from the UI worktree and verified against current code.
- Current user-visible state map for AppBar, playback overlay, side panel, bottom controls, task centers and status feedback.
- List of UI labels that expose obsolete or internal semantics.

Acceptance:

- Media open/playback, URL/download, drag/drop and no-media/error states are documented.
- Subtitle acquisition paths are documented: SRT/VTT, local Whisper, OpenSubtitles and embedded subtitle extraction.
- Local Whisper default path is documented from click to rendered learning surface.
- LLTimeline import path is documented from import/attach to rendered capabilities.
- Plain SRT/VTT degraded path is documented.
- Vocabulary, diagnosis, settings, task centers and resource lifecycle are included in the inventory.
- Every identified P0 confusion has an owner step.

## Step 1: Capability Readiness Model

Goal:

Introduce a frontend representation for user-facing capability readiness.

The model should answer:

```text
For the current app/session/media/subtitle state, what can the learner do right now?
```

Deliverables:

- A typed readiness model for at least:
  - media source and playback;
  - subtitles;
  - transcript/overlay;
  - word sync;
  - chunk replay;
  - listening structure;
  - phone evidence;
  - vocabulary;
  - diagnosis;
  - downloads/jobs/system tasks;
  - practice/review backend readiness where applicable.
- Mapping from existing resource summaries and `LLTimelineDocument` to readiness.
- Tests for local Whisper, plain SRT/VTT and LLTimeline fixture states.

Acceptance:

- UI can distinguish `available`, `generating`, `degraded`, `unavailable`, `unsupported`, `stale` and `error`.
- Readiness logic is testable without rendering the full app.
- No major feature relies only on a free-form status string for user state.

## Step 2: Local Whisper Default Path

Goal:

Make the most common path obvious and self-explanatory:

```text
Open media -> Generate subtitles -> Word sync -> Listening structure
```

Deliverables:

- Transcription completion state clearly says what was created:
  - generated subtitle track;
  - Word sync available/unavailable;
  - listening structure available/degraded/unavailable.
- If automatic generated-track loading succeeds, the UI surfaces the new track capabilities.
- If the event is missed, Transcription Center still provides a clear "Load generated subtitles" fallback.
- The generated subtitle path does not require the user to manually know or import `rhythm_frames`.

Acceptance:

- A user can discover the path without opening Settings first.
- After local Whisper generation, the active subtitle resource panel reflects Word sync and listening structure readiness.
- If no word timings are available, the UI explains that word sync/listening structure requires word-level timing.

## Step 3: Resource And Capability Surfaces

Goal:

Turn the resource panels from internal run lists into user-understandable capability surfaces.

Deliverables:

- Subtitle resources show both lifecycle state and learning capabilities.
- Timeline resource summary groups internal resources under:
  - Word sync;
  - Chunk replay;
  - Listening structure;
  - Phone evidence;
  - Production artifacts.
- Advanced details still expose ids, provider versions and metrics.
- Refresh/activate/archive/delete actions remain clear.

Acceptance:

- A user can answer "which subtitle should I use?" from the resource panel.
- A user can answer "why is listening structure missing?" from the same surface.
- Activating a different subtitle/timeline refreshes readiness and overlay state predictably.

## Step 4: Listening Structure UI Semantics

Goal:

Rename and reorganize the rhythm/phone surfaces around the Phase 2.21 model.

Deliverables:

- Primary label changes from vague `sound pattern` language to `Listening structure` or equivalent.
- Mode labels separate:
  - Listening structure;
  - Phone evidence.
- Copy explains document-level `rhythm_frames` availability without mentioning JSON fields.
- Missing-state copy distinguishes:
  - no active subtitle;
  - no WordTimeline/word sync;
  - no listening structure resource;
  - predicted-only evidence;
  - no phone evidence.
- Settings remain as preferences, but a contextual playback/overlay entry makes the layer discoverable.

Acceptance:

- Local Whisper + WordTimeline can show listening structure without running phone analysis.
- Phone evidence remains available as detail when present.
- Text-prior/predicted cues are not described as actual measured audio.

## Step 5: Typed Status And Task Feedback

Goal:

Replace scattered user-visible free strings with typed state where it affects UI behavior.

Deliverables:

- A small app/task status model for:
  - idle;
  - working;
  - success/result;
  - warning/degraded;
  - error;
  - actionable next step.
- Download status becomes one state object rather than split `activeDownload` / `downloadedMediaPath` logic.
- Completed/failed transient bars either auto-dismiss or are clearly persistent with a reason.
- Backend task events update typed task state before producing summary text.

Acceptance:

- Download complete and failed states have deterministic dismissal behavior.
- UI tests can assert status category without matching exact prose.
- A task status cannot silently conflict with capability readiness.

## Step 6: Layout And Entry Point Hardening

Goal:

Remove surprising UI behavior around side panels, controls and hidden dependencies.

Deliverables:

- Side panel visibility rules become explicit.
- No-media state hides or simplifies irrelevant bottom controls.
- Secondary subtitle toggle explains no-secondary-track state.
- Major learning tools are reachable from predictable places.
- Settings are reorganized so experimental/audio layers are not a dumping ground.

Acceptance:

- Hiding subtitles does not unexpectedly hide unrelated resource/word/diagnosis context, or the UI explains the relationship.
- With no media loaded, primary call to action is opening media rather than inactive playback controls.
- Secondary subtitle controls are not ambiguous when no secondary track exists.

## Step 7: End-To-End Verification

Goal:

Create a repeatable QA pack for current user journeys.

Deliverables:

- Fixture-driven Flutter tests for readiness states and labels.
- At least one local smoke checklist for:
  - local media + Whisper subtitle generation;
  - plain SRT/VTT import;
  - LLTimeline import with document-level `rhythm_frames`;
  - missing evidence/degraded states.
- Regression tests for the confusing states fixed in Steps 4-6.

Acceptance:

- `flutter analyze` passes.
- Focused Flutter tests cover the new readiness/status logic.
- Rust/API tests run when resource mapping changes.
- Manual smoke checklist records what was verified and what remains manual.

## Closeout Criteria

Phase 2.22 can close when:

1. The local Whisper default path is coherent from media import through listening structure display.
2. Existing SRT/VTT and LLTimeline paths degrade honestly.
3. Resource panels show user-facing capabilities, not only internal ids.
4. Listening structure and phone evidence are semantically separated in UI.
5. Free-string status no longer controls core user-visible behavior.
6. P0/P1 issues from the user-visible state audit are fixed or explicitly deferred.
7. The phase has a repeatable end-to-end verification checklist and focused automated tests.
