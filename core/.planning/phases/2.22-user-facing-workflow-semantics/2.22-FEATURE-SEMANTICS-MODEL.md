# Phase 2.22 Feature Semantics Model

状态：DRAFT

日期：2026-07-01

## Objective

Define the user-facing capability model that Flutter should expose.

The model deliberately avoids making users think in database tables, JSON fields, or internal pipeline names.

## Capability Stack

Every current feature belongs to one of these user-visible layers.

| Layer | User-facing name | Internal resources | User question |
|---|---|---|---|
| L0 | Media source | media record, local path, URL, download, archive state | What am I playing and where did it come from? |
| L1 | Playback | player adapter, position, duration, audio tracks, loop state | Can I play, seek, loop and control this media? |
| L2 | Subtitles | SubtitleTrack, primary/secondary tracks, segments, tokens | What text is aligned to this media? |
| L3 | Transcript and overlay | TokenLine, transcript panel, subtitle display settings | What line/word am I seeing now? |
| L4 | Word Sync | WordTimeline, word timings | Which word am I hearing now? |
| L5 | Chunk Replay | ChunkTimeline, chunk partitions | Which phrase/chunk should I replay? |
| L6 | Listening Structure | document-level `rhythm_frames`, RhythmFrame | What should I listen for in this sentence? |
| L7 | Phone Evidence | PhoneTimeline, SoundAnalysis phone findings | What detailed sound evidence explains this spot? |
| L8 | Vocabulary | LexicalEntry, LexicalUnit, LearningStatus | Which words do I know or miss? |
| L9 | Diagnosis | diagnosis-core, sentence diagnosis, listening hints | Why did I not understand this sentence? |
| L10 | Practice/Review | PracticeAttempt, ReviewItem, LearningEvent | How do I turn this diagnosis into training? |
| L11 | System and tasks | backend connection, jobs, downloads, settings, tools | What is the app doing and what needs attention? |

## Model ↔ Code Reconciliation

The Capability Stack is the *conceptual* vocabulary. It is NOT all modeled in code
yet. There must be exactly one mapping between these layers, the code
`UserCapability` enum, and the readiness lanes in
`2.22-USER-VISIBLE-STATE-MACHINE.md` Section C. This table is that mapping.

| Stack layer | Code `UserCapability` | Readiness lane modeled? |
|---|---|---|
| L0 Media source | — | No |
| L1 Playback | — | No |
| L2 Subtitles | `subtitles` | Yes (inline in `fromResources`) |
| L3 Transcript and overlay | — | No |
| L4 Word Sync | `wordSync` | Yes (`_wordSyncReadiness`) |
| L5 Chunk Replay | `chunkReplay` | Yes (`_chunkReplayReadiness`) |
| L6 Listening Structure | `listeningStructure` | Yes (`_listeningStructureReadiness`) |
| L7 Phone Evidence | `phoneEvidence` | Yes (`_phoneEvidenceReadiness`) |
| L8 Vocabulary | — | No |
| L9 Diagnosis | — | No |
| L10 Practice/Review | — | No |
| L11 System and tasks | — | Partial via `UserTaskStatus` + `DownloadStatusSnapshot`, not a readiness lane |

Rules that keep the three vocabularies from drifting again:

1. `UserCapability` enum values must be a subset of the Capability Stack, using
   the same names. Adding a capability means adding its stack layer here first.
2. `2.22-PLAN.md` Step 1 asked for readiness on media/playback, transcript/overlay,
   vocabulary, diagnosis, downloads/jobs and practice/review. Those are the "No"
   rows above. Until they exist, Step 1 is **partially** complete, not complete.
3. A layer marked "No" must not be reported as "readiness modeled" in STATE.md,
   PLAN checkpoints, or CHANGELOG.

## User-Facing Names

Internal names are still valid in code and advanced diagnostics, but primary UI copy should prefer these terms.

| Avoid As Primary UI | Prefer | Notes |
|---|---|---|
| WordTimeline | Word sync | Advanced resource details may still show `WordTimeline`. |
| ChunkTimeline | Chunk replay | Use `ChunkTimeline` in resource inspector only. |
| PhoneTimeline | Phone evidence | Phone evidence is detail, not default listening structure. |
| SoundPatternRibbon | Listening structure layer | `sound pattern` is too vague and currently mixes rhythm and phones. |
| RhythmFrame | Listening structure | Advanced details may show RhythmFrame/provider id. |
| sound_analysis | Audio analysis result | Do not expose JSON field names as product language. |
| phonetic analysis | Phone evidence analysis | Use when the task is specifically about phones. |
| LLTimeline | Timeline resource | Use `.lltimeline.json` in import/export labels. |
| Transcription job | Subtitle generation | Use job wording in task center/detail views. |
| downloadedMediaPath | Downloaded media | Never expose implementation field names. |

## Capability Readiness States

Every layer should resolve to one of these UI states.

| State | Meaning | UI obligation |
|---|---|---|
| `unavailable` | No input exists for this layer. | Say what input is missing. |
| `available` | Ready and usable. | Show the feature or a clear enable control. |
| `generating` | A job or refresh is in progress. | Show progress and the target capability. |
| `degraded` | Usable, but lower quality or missing evidence. | Explain what is missing without blocking the path. |
| `unsupported` | This media/language/path cannot support the layer. | Say why and do not suggest impossible actions. |
| `stale` | Data exists but may not match the active subtitle/media state. | Offer refresh or reattach action. |
| `error` | Attempt failed. | Preserve error message and offer retry where possible. |

## Readiness Examples

> Layer IDs below are the SAME `Lx` numbers as the Capability Stack table above.
> Never renumber layers inside examples. (A prior draft numbered these examples
> `L1..` starting at Subtitles, which contradicted the stack. Fixed.)

### Local Whisper Subtitle

After a successful local Whisper job:

- L2 Subtitles: `available`
- L4 Word Sync: `available` if Whisper JSON/DTW produced word timings; otherwise `degraded`
- L5 Chunk Replay: `available` if chunk generation succeeded; otherwise `degraded` or `unavailable`
- L6 Listening Structure: `available` if document-level `rhythm_frames` can be generated from active WordTimeline; `degraded` if timing is estimated or only text prior exists
- L7 Phone Evidence: `unavailable` unless phone analysis has run

### Plain SRT/VTT

- L2 Subtitles: `available`
- L4 Word Sync: `unavailable` or `degraded` unless timings are later generated
- L6 Listening Structure: `unavailable` for actual audible structure; predicted references may exist only if explicitly labeled
- L8 Vocabulary: `available`
- L9 Diagnosis: `available` for lexical diagnosis, degraded for sound diagnosis

### Production LLTimeline

- L2 Subtitles: `available`
- L4 Word Sync: `available` when active WordTimeline exists
- L5 Chunk Replay: `available` when active ChunkTimeline exists
- L6 Listening Structure: `available` when document-level `rhythm_frames` exist or can be regenerated
- L7 Phone Evidence: `available` when PhoneTimeline / sound analysis exists

## Interaction Principles

1. **Primary workflow beats settings.** Settings configure defaults. They should not be the only way to discover a major capability.
2. **Show capability before showing raw resource.** Users should see "Word sync available" before `word_timeline_runs`.
3. **A disabled control must explain itself.** If a listening layer cannot show, the UI should name the missing layer.
4. **Advanced resource details remain available.** Internal ids, providers, versions, metrics and artifacts belong in resource inspector/detail views.
5. **Predicted vs audio-supported must stay visible.** Text-prior cues may be useful, but they must not read like measured audio facts.
6. **One task should have one obvious entry.** Secondary expert entries are allowed, but the canonical path must be clear.
7. **Status text is not state.** Free-form strings can summarize, but typed state should drive rendering and tests.

## Canonical Surface Map

| Surface | Primary responsibility | Should not do |
|---|---|---|
| AppBar | Open media, open resources, open major centers | Hide common tasks inside unrelated menus |
| Playback overlay | Current sentence learning and listening layers | Become a full resource manager |
| Side panel | Transcript, resources, word details, diagnosis | Depend on subtitle visibility in surprising ways |
| Bottom controls | Playback, loop, word/chunk navigation, visibility toggles | Show many inactive controls with no media loaded |
| Resource panel | Capability readiness and resource lifecycle | Expose only raw run ids without user meaning |
| Settings | Defaults and preferences | Act as the only activation point for major learning tools |
| Task centers | Long-running jobs and retry/cancel/history | Replace inline completion feedback |
