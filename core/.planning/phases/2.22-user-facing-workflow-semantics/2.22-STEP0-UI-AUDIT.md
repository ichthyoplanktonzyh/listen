# Phase 2.22 Step 0 UI Audit

Status: AUDIT COMPLETE

Date: 2026-07-01

## Scope And Method

This audit records the current Flutter user-facing behavior for Phase 2.22.
The older UI worktree documents were used only as feature-description seed
material. Code facts were checked against the current `apps/desktop` Flutter
implementation in this working tree.

This pass does not define new product behavior. It maps what users can reach
today, how the app labels those paths, which states are visible, and which
confusing states must be owned by later Phase 2.22 steps.

Primary code surfaces:

- `apps/desktop/lib/main.dart`
- `apps/desktop/lib/transcription_ui.dart`
- `apps/desktop/lib/phonetic_analysis_ui.dart`
- `apps/desktop/lib/vocabulary_screen.dart`

## Minimal Plan From Step 0

Step 0 found that the app has the necessary backend and Flutter entrypoints, but
the user-facing semantics are uneven. The next work should stay ordered by user
path, not by historical internal resource name.

1. Finish capability readiness surfacing for the active media/subtitle resource.
2. Make the local Whisper default path explain what it produced after generation.
3. Reframe resource panels around Word sync, Chunk replay, Listening structure,
   and Phone evidence before showing internal timeline details.
4. Separate Listening structure from Phone evidence in overlay, settings, and
   missing-state copy.
5. Replace user-visible free-string task/download state with typed state where
   it drives behavior.
6. Harden side panel, no-media, and secondary-subtitle entry semantics.
7. Verify the main end-to-end paths with focused Flutter tests and manual smoke.

## User-Visible State Regions

| Region | Current visible states | Step 0 finding |
| --- | --- | --- |
| Backend/core shell | Starting, connected, startup error, retry | Good top-level gate. User cannot confuse backend startup failure with media failure. |
| AppBar | Subtitle Resources, Vocabulary, Open Media, Open URL, primary/secondary subtitle menus, More menu | Broad coverage, but several important learning paths are buried under menus and Settings. Menus stay visible even when preconditions are missing, then fall back to status strings. |
| Player surface | No media CTA, local media playback, online playback, drag hover/drop, native video subtitle selection | Media state is clear enough at the center surface. Bottom controls still remain visible and partly irrelevant in no-media state. |
| Subtitle overlay | No subtitle, hidden subtitle, primary overlay, secondary overlay, word-highlight overlay, chunk grouping, phoneme/listening ribbon | The data flow is powerful, but visible missing states are inconsistent. Listening structure can be absent, predicted-only, or audio-backed, and users need a clearer explanation. |
| Bottom controls | Playback, sentence seek/loop, chunk seek/loop/expand, source loop stop, word styles, subtitles, secondary subtitles, speed, audio track, subtitle track, offsets, volume, status | Dense and useful during playback. In no-media or missing-resource states, controls are often inert without an explanation. |
| Side panel | Hidden, transcript, word learning, resources, diagnosis | Resources can be selected independently, but Transcript visibility is still coupled to subtitle visibility. Word details can keep the side panel open after subtitles are hidden. |
| Download bar | Hidden, active progress, cancel, completed downloaded path | Download completion is split between `activeDownload` and `downloadedMediaPath`. Failure is mostly global status text, not a typed bar state. |
| Task centers | Transcription Center, Phonetic/Audio Analysis Center | Jobs expose status and actions. Their results are not yet summarized as user-facing learning capabilities after completion. |
| Full-screen tools | Vocabulary, Subtitle Resources, Settings, logs, learning assets/resources | Tools exist and are reachable. The conceptual boundary between task center, resource manager, and Settings is still blurry. |
| Global feedback | Status string, snackbars, dialogs | Flexible, but too many core states rely on prose strings that tests and UI logic cannot safely classify. |

## End-To-End Journey Audit

### 1. Media And Playback

User intent: open a video/audio file and control playback.

Canonical entry: `Open Media` in the AppBar. Secondary entries: drag/drop media,
URL resolve/play, completed download open, archived media recovery.

Current flow:

1. User opens a media file.
2. App registers the media, loads saved progress, loads subtitle resources and
   speech enhancement resources, then starts playback.
3. Player surface shows media; bottom controls expose seek, play/pause, sentence
   navigation, speed, audio track and volume.
4. If no media exists, the player surface shows a centered open-media CTA.

Visible readiness/degradation:

- Backend startup failure is separated from media failure.
- No-media state is visible in the player surface.
- Unsupported playback and open failures fall back to global status/error copy.
- Bottom controls remain visible even when no media is loaded.

Owner steps:

- Step 6 owns no-media control simplification and disabled-state explanations.
- Step 5 owns typed media/task status where global strings currently stand in.

### 2. URL Playback And Download

User intent: paste an online media URL, either play it directly or download it
for local use.

Canonical entry: `Open URL` in the AppBar.

Current flow:

1. User opens the URL dialog.
2. App resolves the URL. The user can play the resolved URL or start a yt-dlp
   download.
3. Direct URL playback clears local media/subtitle state and plays online.
4. Download shows an active progress bar and cancel action.
5. Completed download exposes an open action through the download bar.

Visible readiness/degradation:

- Active download progress is visible.
- Completed download is visible if a downloaded path exists.
- Failure and several edge states are only global status text.
- The bar is driven by split state: active download object plus downloaded path.

Owner steps:

- Step 5 owns a single typed download lifecycle: idle, downloading, cancelled,
  success, warning, error, dismissed.
- Step 6 owns how downloaded media re-enters the canonical local media flow.

### 3. Drag And Drop

User intent: quickly add local files without using menus.

Canonical entry: drop files onto the app.

Current flow:

1. Drop target accepts media and subtitle files.
2. Media files go through the local media path.
3. Subtitle files go through subtitle import.

Visible readiness/degradation:

- Drag/drop is convenient, but multi-file priority and unsupported-file feedback
  are mostly implicit.
- Subtitle drop depends on media preconditions.

Owner steps:

- Step 6 owns no-media/drop feedback and unsupported drop explanations.

### 4. SRT/VTT Subtitle Import

User intent: attach an existing subtitle file as primary or secondary subtitle.

Canonical entry: AppBar primary/secondary subtitle menu `Import`.
Secondary entry: drag/drop subtitle file.

Current flow:

1. User imports SRT/VTT.
2. Primary import routes through active primary subtitle setup.
3. Secondary import sets secondary subtitle state.
4. Resource panel can show the subtitle resource and available timeline
   resources when they exist.

Visible readiness/degradation:

- Plain SRT/VTT gives readable subtitles and transcript.
- Word sync, Chunk replay, Listening structure, and Phone evidence may be absent.
- Historically this absence appeared as raw missing timeline details or no
  explanation.

Owner steps:

- Step 1/3 own capability readiness display for plain SRT/VTT degraded paths.
- Step 6 owns clearer precondition copy when importing subtitles without media.

### 5. Local Whisper Subtitle Generation

User intent: generate subtitles from the current media and immediately use them
for learning.

Canonical entry: primary/secondary subtitle menu `Generate`.
Secondary entry: Transcription Center.

Current flow:

1. User chooses generation options in the subtitle generation dialog.
2. A local ASR/transcription job runs.
3. Backend events report transcription progress.
4. On completion, generated subtitle track can be loaded into primary or
   secondary subtitle state.
5. Speech enhancement resources are refreshed for the active track.
6. Transcription Center remains a fallback place to load completed generated
   subtitles if automatic loading is missed.

Visible readiness/degradation:

- Job progress is visible in Transcription Center and global status.
- Loaded subtitle feedback is generic; it does not yet summarize generated
  subtitle, Word sync, Chunk replay, Listening structure, or Phone evidence.
- A user can still feel required to know internal resource terms to understand
  why listening structure is missing.

Owner steps:

- Step 2 owns the local Whisper default path from click to rendered learning
  surface.
- Step 5 owns typed ASR task status and result summary categories.

### 6. Embedded Subtitle Extraction

User intent: use subtitle tracks already inside a media file.

Canonical entry: More menu embedded subtitle action.

Current flow:

1. App inspects media tracks with ffprobe/ffmpeg.
2. User chooses an embedded subtitle track.
3. Text tracks can be extracted and imported as primary or secondary subtitles.
4. Bitmap or unsupported tracks cannot become text subtitles.

Visible readiness/degradation:

- Extraction is reachable but secondary to file/open flows.
- Unsupported embedded subtitle types need stronger user-facing explanation.
- After import, capability readiness is the same as other plain subtitle paths
  unless timeline resources exist.

Owner steps:

- Step 3 owns the resource/capability explanation after import.
- Step 6 owns clearer unsupported embedded-track copy.

### 7. OpenSubtitles

User intent: search online subtitles for the current media.

Canonical entry: primary/secondary subtitle menu `OpenSubtitles`.
Secondary entry: More menu.

Current flow:

1. App prompts for or uses an API key.
2. User searches and downloads a subtitle.
3. Downloaded subtitle is imported as a primary or secondary track.

Visible readiness/degradation:

- API key and search are user-visible.
- Missing media/API key/search failure falls back to dialogs or status text.
- Downloaded subtitles then share the plain SRT/VTT capability profile unless
  resources are later generated/imported.

Owner steps:

- Step 5 owns typed network/search failure where it affects user flow.
- Step 6 owns making API-key preconditions actionable from the entrypoint.

### 8. Subtitle Resource Lifecycle

User intent: choose, maintain, and export subtitle resources for the current
media.

Canonical entry: Subtitle Resources AppBar button or Resources side-panel tab.

Current flow:

1. Panel lists resources for current media.
2. User can activate, archive, restore, delete, export SRT, and export
   `.lltimeline.json`.
3. Panel also exposes timeline resource summaries for the active subtitle.

Visible readiness/degradation:

- Lifecycle actions exist.
- Resource ids, timeline ids, and raw internal names are visible.
- The panel historically did not answer the user question: "which learning
  abilities are available if I use this subtitle?"

Owner steps:

- Step 3 owns turning resource lifecycle into a capability-first surface.
- Step 7 owns tests for activate/archive/delete/export semantics.

### 9. Timeline Resource Import And Activation

User intent: attach a richer `.lltimeline.json` resource and unlock learning
features.

Canonical entry: Resources panel import timeline action.

Current flow:

1. User imports a `.lltimeline.json`.
2. App checks media fingerprint and asks for confirmation on mismatch.
3. Imported document is attached to the media/subtitle resource.
4. Active resource loads WordTimeline, ChunkTimeline, PhoneTimeline, phonetic
   analyses, and document-level timeline data where present.
5. User can activate/archive/delete timeline candidates.

Visible readiness/degradation:

- Import and mismatch confirmation are visible.
- Advanced candidate state is visible.
- User-facing capability mapping needs to be primary: Word sync, Chunk replay,
  Listening structure, Phone evidence.

Owner steps:

- Step 3 owns grouping internal timeline resources under user capabilities.
- Step 4 owns document-level listening structure copy that does not require the
  user to know the JSON field name.

### 10. Subtitle Display And Transcript

User intent: read subtitles, follow the transcript, and interact with words.

Canonical entry: active subtitle playback plus side panel Transcript.

Current flow:

1. Primary subtitle appears in the overlay and TokenLine.
2. Secondary subtitle can appear when loaded and enabled.
3. Transcript side panel follows current sentence and allows sentence seek.
4. Word clicks open learning details.
5. Settings control subtitle style, position, transcript width, colors, and
   display preferences.

Visible readiness/degradation:

- Primary/secondary display is present and configurable.
- Secondary toggle can be ambiguous when no secondary track exists.
- Transcript side panel visibility is coupled to subtitle visibility.

Owner steps:

- Step 6 owns side-panel visibility and secondary-subtitle disabled semantics.
- Step 4 owns contextual overlay discovery for Listening structure/Phone
  evidence.

### 11. Word Sync

User intent: see which word is being spoken and jump through word-aligned text.

Canonical entry: generated/imported resources plus playback overlay.

Current flow:

1. Active WordTimeline or legacy word timing data is loaded for the active
   subtitle.
2. Current word tracking updates during playback.
3. TokenLine and transcript can style current/learned words.

Visible readiness/degradation:

- When active and audio-backed, the feature is visible through word highlight.
- When missing, the absence is easy to confuse with a display preference or
  subtitle problem.
- Estimated timing can exist but must be explained as degraded.

Owner steps:

- Step 1/3 own readiness states for available/degraded/unavailable/stale/error.
- Step 2 owns explaining Word sync after local Whisper generation.

### 12. Chunk Replay

User intent: replay meaningful phrase chunks instead of whole sentences.

Canonical entry: bottom controls for previous/next chunk, chunk loop, expand
chunk; TokenLine chunk grouping.

Current flow:

1. Active ChunkTimeline or chunk partitions load for the active subtitle.
2. TokenLine shows chunk grouping/highlight.
3. Controls navigate and loop chunks.

Visible readiness/degradation:

- Controls are visible even when chunks are unavailable.
- Missing chunk data is not always explained near the controls.
- Active chunk state can be hard to distinguish from sentence state.

Owner steps:

- Step 3 owns capability explanation in resources.
- Step 6 owns disabled/missing state copy in controls.

### 13. Listening Structure

User intent: understand the sentence's stress, compression, phrase boundaries,
weak groups, and hotspots.

Canonical entry: overlay layer/ribbon and diagnosis card when evidence exists.

Current flow:

1. Overlay prefers document-level listening structure from the imported/generated
   timeline document.
2. It can fall back to analysis-derived rhythm frames when present.
3. Settings expose layer visibility and mode.
4. Diagnosis card uses available rhythm/listening evidence for the current
   sentence.

Visible readiness/degradation:

- The data model supports document-level listening structure without phone
  analysis.
- Some UI surfaces historically used vague sound-pattern/rhythm copy.
- Predicted/text-prior cues and audio-backed cues need clearer separation.
- Missing listening structure can be visible in one surface but invisible in
  another.

Owner steps:

- Step 4 owns Listening structure semantics and missing-state copy.
- Step 2 owns local Whisper result summary for generated listening structure.

### 14. Phone Evidence

User intent: inspect measured or inferred phone-level evidence when audio
analysis exists.

Canonical entry: overlay Phone evidence mode, diagnosis card, More menu
Phonetic/Audio Analysis Center, analyze-current/track actions.

Current flow:

1. User can open the audio/phonetic analysis center.
2. User can run sentence or track analysis when model/provider setup exists.
3. Active PhoneTimeline/sound analysis provides phone observations.
4. Overlay and diagnosis card can show phone details.

Visible readiness/degradation:

- Phone evidence is a detail layer, not a prerequisite for Listening structure.
- Provider/model setup and analysis job state are still separate from capability
  readiness.
- If phone evidence is missing, some surfaces collapse silently.

Owner steps:

- Step 4 owns the Listening structure versus Phone evidence split.
- Step 5 owns typed audio-analysis job feedback.
- Step 3 owns Phone evidence readiness in resource panels.

### 15. Vocabulary And Word Learning

User intent: mark words, inspect definitions/pronunciation, and build a
learning vocabulary.

Canonical entry: click a word in overlay/transcript. Secondary entry:
Vocabulary screen.

Current flow:

1. Token click opens word learning details in the side panel.
2. User can change learning status and notes/definitions.
3. Vocabulary screen supports search, filter/status views, import/export, and
   word details.
4. Source sentence replay is available when media/source mapping exists.
5. Phrase candidates, phrase status, lemma correction, learning assets and
   resources are reachable from menus/tools.

Visible readiness/degradation:

- Core word learning path exists.
- Missing source sentence/media recovery is visible but not part of a unified
  readiness model.
- Vocabulary status changes refresh the learning surface and diagnosis, but this
  is not framed as an end-to-end path.

Owner steps:

- Step 1 owns vocabulary readiness at the capability model level.
- Step 6 owns predictable entries for phrase/learning-resource tools.
- Step 7 owns status-change regression tests.

### 16. Diagnosis

User intent: understand what makes the current sentence difficult and what
evidence supports the diagnosis.

Canonical entry: diagnosis card in the side panel.

Current flow:

1. Diagnosis card reads current sentence, lexical details, pronunciation
   references, listening/rhythm evidence, phone findings, and analysis actions.
2. User can analyze current sentence or whole track when audio analysis is
   configured.
3. Status changes and resource refreshes can update diagnosis.

Visible readiness/degradation:

- Diagnosis is useful when evidence exists.
- Missing dictionary, timing, listening structure, or phone evidence should be
  categorized rather than left as absent sections.
- Analysis actions need clearer connection to Phone evidence readiness.

Owner steps:

- Step 4 owns diagnosis copy for listening/phone evidence.
- Step 5 owns analysis task status.
- Step 7 owns regression coverage for degraded diagnosis states.

### 17. Settings And Tools

User intent: configure display, language, tools, transcription defaults, and
analysis providers.

Canonical entry: More menu Settings.

Current flow:

1. Settings control UI language, learning language, subtitle display, transcript
   width, colors, external tool paths, transcription defaults, OpenSubtitles API
   key, word/chunk display, phoneme/listening layer visibility/mode, and
   phonetic/audio analysis provider/model/cache.
2. More menu also exposes logs, archive media, transcription center, analysis
   center, learning assets/resources, phrase tools, and lemma correction.

Visible readiness/degradation:

- Settings correctly holds preferences and tool paths.
- Several user-facing capabilities are discoverable mainly through Settings,
  which makes them feel like experimental toggles rather than learning features.
- Internal labels can leak through advanced settings.

Owner steps:

- Step 4 owns contextual overlay entry for Listening structure/Phone evidence.
- Step 6 owns reorganizing entrypoints so Settings configures defaults rather
  than becoming the primary feature map.

### 18. Task Centers And Global Feedback

User intent: see long-running work, recover from missed events, and understand
what action is needed next.

Canonical entries: Transcription Center, Audio/Phonetic Analysis Center,
download bar, global status area/snackbars.

Current flow:

1. Transcription Center lists ASR models and jobs with job states/actions.
2. Audio analysis center lists provider/model setup and analysis jobs.
3. Backend events update global status and can load generated subtitles or
   speech enhancements.
4. Download bar handles online-media download progress and completion.

Visible readiness/degradation:

- Centers are strong recovery surfaces for jobs.
- Completion feedback does not consistently translate job output into learning
  capability readiness.
- Global status strings are too weak as a state contract.

Owner steps:

- Step 5 owns typed task status and deterministic bar/task dismissal.
- Step 2 owns ASR completion result summary.
- Step 4 owns audio analysis result semantics for Phone evidence.

## Label And Semantics Debt

| Current/internal term | User-facing semantic target | Debt |
| --- | --- | --- |
| `WordTimeline` | Word sync | Acceptable in advanced details, but primary resource panels should lead with Word sync. |
| `ChunkTimeline` | Chunk replay | Advanced name is useful for debugging; controls and resource summaries should say what the user can do. |
| `PhoneTimeline` | Phone evidence | Needs consistent distinction from Listening structure. |
| Sound pattern / rhythm copy | Listening structure | Historical labels make document-level `rhythm_frames` sound like raw audio analysis. |
| Phonetic analysis | Audio analysis / Phone evidence | The provider/job center can keep technical detail, but the learning feature is Phone evidence. |
| `LLTimeline` | Timeline resource / learning resource package | File extension can remain visible during import/export; user-facing copy should say what capabilities it carries. |
| Transcription job | Subtitle generation | Task center may say transcription; default path should say generated subtitles and resulting capabilities. |
| `activeDownload` + `downloadedMediaPath` | Download status | Split hidden state creates ambiguous success/failure/dismissal behavior. |
| Global `status` string | Typed app/task feedback | Core UI should not infer workflow state from free-form prose. |
