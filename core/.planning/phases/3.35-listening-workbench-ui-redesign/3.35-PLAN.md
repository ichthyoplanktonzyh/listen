# Phase 3.35 Plan: Listening Workbench UI Redesign

状态：IN_PROGRESS

上游输入：`3.35-CONTEXT.md`、Phase 2.22、Phase 3.1/3.2 closeout、Phase 3.3 当前实现、
`docs/brand/listen/README.md`

## Objective

参考每日英语听力成熟的内容层级和播放学习一体化组织，重构 `listen` 桌面端 UI，建立可承载
Phase 3.4 至 3.10 的统一听力工作台。改造以现有功能更清晰、更紧凑、更一致为目标，不新增
学习业务语义。

## User Value

> “打开后我马上知道去哪里选内容、在哪里听和看字幕、这句话能做什么；需要深入时再展开，
> 不需要时播放器保持安静。”

## Scope

### In

- **参考与基线审计**：
  - 截取当前 app 在空态、本地媒体、精听、泛听、Inbox、诊断和练习状态的基线图。
  - 审计每日英语听力官方现行界面，形成“借鉴 / 不借鉴 / listen 独有”对照表。
  - 建立当前问题清单：层级、密度、对齐、可发现性、状态一致性和窄窗口退化。
- **信息架构**：
  - 稳定一级入口：内容库、当前播放、学习资产、设置/任务。
  - 内容库同时容纳本地导入、URL 与未来 YouTube/provider 来源；来源显示 provenance，
    不改变本地优先的数据和播放原则。
  - 精听 / 泛听作为当前播放内的清晰模式；Inbox 等上下文工具保持可快速进入和退出。
- **主工作台重构**：
  - 媒体舞台、同步字幕/文稿、上下文学习面板和播放条形成稳定空间关系。
  - 支持合理的分栏尺寸、折叠和窄窗口重排，动态内容不得挤压或覆盖播放控制。
  - 当前句、当前 chunk、循环范围和当前模式使用一致状态表达。
- **视觉系统**：
  - 建立颜色、文字、间距、边框、surface、焦点、hover、selected、disabled 等 design tokens。
  - 统一按钮、icon button、segmented control、tab、list row、panel、dialog、badge、tooltip、
    empty/loading/error state。
  - 优先使用现有 icon library；图标按钮提供 tooltip；避免文字胶囊和 card-in-card。
- **现有功能迁移**：
  - 媒体/字幕导入、URL、资源状态、播放与句控制。
  - 字幕 token、词汇状态、词典、诊断和声音证据。
  - Understand / Test / Shadowing 三姿态、卡点、summary、悬案区。
  - 泛听 toggle、软/硬打断与 Listening Inbox 整理。
- **质量验证**：
  - widget/golden 测试覆盖共享组件与关键工作台状态；golden 使用稳定 fixture。
  - 在至少 `1440x900`、`1280x800` 和 `900x700` 三种窗口尺寸截图审查。
  - 使用真实本地媒体执行精听和泛听主路径手工 QA。
  - 检查键盘焦点、tooltip、对比度、文本溢出、缩放和 Reduced Motion 基础行为。

### Out

- YouTube API/provider 实现、在线 feed、下载管理和账号系统。
- Phase 3.4 review queue 及之后的新功能。
- 全量移动端 UI；本 phase 只保证信息架构与领域状态不绑定桌面像素结构。
- 播放器或后端领域模型重写。
- 每日英语听力像素级复刻。

## Work Plan

1. **Audit and acceptance baseline**
   - 保存 before screenshots、关键流程录像/步骤与问题优先级。
   - 产出 reference matrix 和初版工作台线框。
2. **Design foundation**
   - 收敛 theme extension / token 命名，建立共享 primitive 和状态规范。
   - 用一个静态 fixture workbench 验证布局、密度和多尺寸响应。
3. **App shell and source-neutral library**
   - 重做一级导航、空态和内容入口。
   - 本地文件、URL、未来 provider 使用统一 source item 视觉结构。
4. **Playback workbench**
   - 重排 PlayerStage、Subtitle transcript、SidePanel 和 PlaybackBar。
   - 固定高频播放/句控制，按上下文呈现学习动作。
5. **Learning surfaces migration**
   - 迁移词汇、诊断、practice、卡点 summary、泛听和 Inbox。
   - 对 loading/error/degraded/disabled 状态做完整视觉收口。
6. **Verification and polish**
   - 自动化测试、截图对比、真实媒体 QA、性能/重建观察。
   - 逐项关闭基线问题清单，留下明确的后续 UI debt，而不是临时补丁。

## Exit Signal

- 当前 app 的主要功能不再依赖用户理解内部资源名或隐藏入口才能发现。
- 本地媒体可从内容入口进入统一工作台；未来 YouTube/provider 有清晰预留但没有伪可用入口。
- 精听、泛听、诊断、练习、卡点和 Inbox 主路径在新 UI 中均可完成。
- 三种目标窗口尺寸无文字溢出、控件重叠、不可达主动作或布局跳动。
- before/after 截图与 reference matrix 经 owner 确认，新界面明显改善层级、一致性和长时间使用舒适度。
- `flutter analyze`、`flutter test`、相关 golden/widget tests、`git diff --check` 通过。
- 真实媒体精听与至少 30 分钟泛听 QA 通过，播放同步和零打扰原则无回归。
- **独立可用**：不依赖 3.4 及后续功能；业务 API 和 durable learning facts 保持兼容。

## Guardrails

- 继承 Phase 3.x 全局规则，尤其是可组合、capability gating、泛听零打扰和不游戏化。
- 参考产品只用于设计研究；不复制品牌资产、专有文案或整套界面。
- 不把未来在线来源误写成“本地失败后的次等模式”；local-first 描述数据所有权与默认路径，
  不限制内容来源。
- 不以大面积卡片、装饰性渐变、超大标题或营销式 hero 取代实际工作台。
- 不因重排 UI 改变 practice/review/status 的领域语义。
- 视觉调整必须有真实截图验证，不能只凭 widget test 宣告完成。

## Implementation Progress — 2026-07-04

- 第一批：完成来源中立首页、桌面侧栏、浅色工具栏与独立空态播放条；本地媒体与 URL
  保持并列入口，未伪造尚未实现的在线 provider。
- 第二批：新增 `MediaWorkbench`，宽窗口默认约 42/58 媒体/学习分栏，分隔线可拖动并有
  双侧最小宽度；窄窗口自动改为上下布局。右侧学习导航改为等宽图标 tab，文稿移除固定
  行高，长字幕可以完整显示。
- 播放控制：移除横向拖动依赖，高频动作固定可见，低频轨道、偏移、音量和停止操作收进
  播放设置弹窗。
- 视觉系统：新增集中式 `ListenTheme`，采用冷杉绿 `#167C72`、雾灰 `#F3F5F4`、暖金
  `#D89A32`、近黑媒体画布 `#101715`。统一 app shell、按钮、输入、弹窗、菜单、滑杆、
  选中/禁用态，以及字幕资源、timeline、练习、诊断、人工校对、任务和下载状态配色。
- 第三批：字幕资源列表与时间轴资源详情改为同一高度池内的可拖动上下分栏，timeline 详情
  移除固定高度上限并在自身区域滚动，避免独立资源页和右侧资源 tab 在矮窗口下相互挤压或
  顶穿底部播放区。
- 第四批：右侧文稿随播放当前句同步改为基于真实列表行的 `ensureVisible`，移除旧的固定行高
  估算，适配长字幕可变行高；目标行未构建时先预定位再校准。
- 第五批：完成 P0-P2 UX 走查收口，包括首页继续学习、工具栏/播放条主次分层、布局比例
  持久化、资源技术详情折叠、诊断摘要/证据、词汇学习层级、设置分类、添加来源流程和
  media overlay 语义色 token。
- 自动验证：`flutter analyze` 通过；`flutter test` 186 项通过；`git diff --check` 通过。
- 收尾材料：新增 reference matrix、owner 手工 QA 清单和 awaiting-owner-QA closeout 草稿。
- 待完成：owner 截图视觉 QA、多窗口真实媒体检查，以及根据反馈继续调整密度、比例和
  局部对比度。Phase 保持 `IN_PROGRESS`。
