# Phase 3.9.2 Plan: Syntax Provider Qualification Correction and Product Activation

状态：ACTIVE（v1，2026-07-13）

上游：Phase 3.9.1 冻结产物、ADR 0023、Phase 3.9 Reference B、Phase 3.4.2 SenseGroup、
Phase 3.4.3 Construction Spike。

## Objective

纠正 3.9.1 将产品保守策略误作唯一句法 gold 的资格方法，以修正版 locked holdout 重新评估
spaCy artifact 与逐项 consumer query capability；若通过，则把它接入可选本地 syntax capability，
使同一 validated artifact 同时服务 B、syntax-aware SenseGroup 和 Construction candidate
matcher，并对未获资格的 query 保持现有精确降级。

## Workload Judgment

范围为小到中等：consumer seam 已完成，预计主要新增 corrected fixture/scorer、composition、
capability lifecycle 和端到端测试。若部署审计证明必须捆绑 Python/大型 runtime、修改
LLTimeline schema 或增加复杂安装 UI，则停止扩大本 phase，另立部署 phase；不得用“接线很小”
掩盖分发成本。

## Slice 0 — Corrected evidence contract

- 新建 v2 development/locked validation fixture；不修改 3.9.1 v1 fixture/report。
- 将原争议句标为 `ambiguous_policy_abstain`，只检查产品保守行为，不计 parser attachment accuracy。
- 加入清晰最小对照：
  - subject extraction/block：`Which candidate do you want to win the election?`
  - object extraction/allow：`Which game do you want to win?`
  - lexical object/allow：`Which team do you want to beat in the final?`
- 预登记 correctness、abstain、mapping/tree/coverage、真实字幕与资源 gate 后，再运行 locked set。
- Provider artifact 资格与 consumer query 资格分开：某个 query 不合格只禁止该 query 激活，不能
  用一个语义任务否决已通过 mapping/tree/failure gate 的共享 artifact，也不能反向授权全部 query。

## Slice 1 — Single-provider qualification and delivery gate

- 以 spaCy `en_core_web_sm` 为首个产品候选，Stanza 只作对照，不同时接入两个产品 runtime。
- 重新生成 development/locked/real-media report，人工核对错误传播到 B/SenseGroup/matcher。
- 审计产品运行边界：runtime/model 安装位置、版本/checksum、刷新、卸载、磁盘/RSS、错误恢复。
- Python/model 不得成为字幕导入、播放或基础学习能力的硬依赖；不默认塞入消费者 bundle。
- 只有 artifact、许可、资源和降级 gate 全部通过，才授予版本化 product artifact 决策；B
  `going_to` / `used_to` / `have_to` / `want_to`、SenseGroup 和 matcher capability 分别记录资格。

## Slice 2 — Shared product orchestration

- composition root 建立可选 `SyntacticAnalysisProvider` capability，不在消费者中判断
  `provider_id == spacy`。
- 对同一 source/provider/model/profile fingerprint 每句只 finalise 一份 artifact；一次请求内让
  B、SenseGroup、dependency matcher 共享引用，不重复解析。
- B：只启用逐项验证通过的 syntax gates，provenance 保持 `syntax_model` + `PossibleByRule`，绝不
  进入 C；开发探针已证明 spaCy basic dependency 无法可靠区分所有 want-to wh extraction，若
  locked set 仍不能区分，该 query 明确 abstain 并继续 text heuristic。
- SenseGroup：生成独立 `syntax-aware-sense-group/v1` candidate；rule run 与历史 lifecycle 保留。
- Construction：只返回 occurrence candidate；不写 canonical identity、capability 或持久化权威。
- missing/unqualified/invalid/timeout/low-coverage 时，B 与 rule SenseGroup 输出和当前基线一致。

## Slice 3 — Product QA and closeout

- owner 真实媒体验证安装/探测、首次生成、刷新、模型移除、损坏和 fallback。
- 证明同一句只调用 provider 一次，三个消费者读取同一 artifact ID。
- 对 B 对照听感、SenseGroup 教学粒度和 matcher 候选做人工抽查；不以 parser 输出自证正确。
- 全量 Rust/contracts；若增加用户可见 capability/install 状态，再补 Flutter contract/UI QA。

## Exit Signals

- corrected locked holdout 不再把歧义政策伪装为唯一句法 gold，且 spaCy 资格结论可复现。
- 若 spaCy 获资格：同一句只产生一份 provenance-complete artifact，B/SenseGroup/matcher 共用。
- B 的逐项资格矩阵可复现；已通过的 query 优于文本启发式，未通过或歧义 query abstain/fallback，
  模型缺席时精确 fallback。不得用 provider 总体资格暗示每个 B query 都可靠。
- syntax-aware SenseGroup 保持 phrase/NP/PP/clause 与教学粒度，rule provider/ChunkTimeline 可用。
- matcher 复用 artifact，但没有 Construction canonical/occurrence/capability authority。
- runtime/model 安装不是基础产品硬依赖；失败不会阻断字幕、播放、B 或 rule SenseGroup。

## Non-goals

- 同时产品化 Stanza 与 spaCy。
- 删除 B 或 rule SenseGroup fallback。
- 用 parser 直接生成 C、音素或韵律事实。
- 建立 Construction canonical identity 或学习 capability。
- 为了保持“小 phase”而跳过模型生命周期、许可或真实媒体 QA。
