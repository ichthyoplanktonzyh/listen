## Objective

将单值 `LearningStatus` 迁移为 reading / listening / speaking / writing 四通道能力画像，明确
区分尚未评估、尚未掌握和已经掌握，并把 evidence、system projection 与 user override 分层。
迁移必须保留 Phase 3.4 已有听力证据、升级建议、词汇资产和来源历史，且 main 在每个切片后
保持可运行。

## User Value

> “我可以准确看到：这个词我读得懂，但还听不稳；至于会不会说、会不会写，系统没有证据时
> 就诚实地说尚未评估，而不是替我判定不会。”

## Requirements

### Capability semantics

- 四个独立通道：reading / listening / speaking / writing。
- 每个通道：unassessed / not_acquired / acquired。
- 不建立通道间强制升级链。
- 用户可以设置或清除单个通道 override。

### Evidence and projection

- 既有 LexicalObservation / PracticeAttempt / ReviewAttempt / recognition evidence 保持 durable。
- 现有 recognized/not-recognized context evidence 明确映射到 listening。
- system projection 与 user override 分开持久化。
- effective assessment 优先使用 override，否则使用 projection，否则 unassessed。
- 自动证据只能更新 projection 或生成 suggestion，不能静默覆盖 override。

### Compatibility

- schema v21 -> v22 additive migration。
- `lexical_entries.status` 在本阶段保留为 deprecated compatibility field。
- legacy status 按 shared context 固定映射回填，并记录 migration source。
- API 先 additive 暴露 capability profile，旧字段在兼容窗口内保留。
- portable vocabulary asset 支持新画像和旧 bundle 导入。
- 第一阶段允许 capability target 的 `sense_id = null`，不实现完整词义系统。

## Exit Signals

1. 新词条四通道默认全部 unassessed，诊断不产生伪障碍。
2. 旧 `known_not_recognized` 数据迁移后为 reading acquired + listening not_acquired。
3. 用户设置 listening override 不改变 reading/speaking/writing。
4. 练习/复习成功证据只更新 listening projection 或 suggestion，不静默覆盖用户 override。
5. 诊断能区分 unknown meaning、known but not heard、unassessed 和 other factors。
6. 旧 v21 数据库、旧 vocabulary bundle 与当前 Phase 3.4 数据均无损迁移或明确记录近似来源。
7. Flutter 不把 unassessed 展示成不会，并可独立修改/清除单个通道。
8. `cargo test --workspace`、contract validation、Flutter analyze/test 和迁移恢复测试通过。

## Guardrails

- 不用四个 bool 表示领域状态。
- 不在本阶段实现 LexicalSense/WSD。
- 不让 speaking/writing 因缺少证据默认 not_acquired。
- 不删除或重写已有 practice/review/observation 历史。
- 不让 compatibility legacy view 重新成为权威写入模型。
- 不把 schema rollback 交给 git revert。
- 不混入 SenseGroup、UD parser 或 Construction 实现。
