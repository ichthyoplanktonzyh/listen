# Phase 2.2 Plan: App Timeline Resource UI Alignment

更新时间：2026-06-19 15:55:21 CST

## Objective

把生产端输出的 `.lltimeline.json` 变成 app 端可见、可选择、可消费的资源。先完成
资源闭环，再进入人工校正和 chunk timeline 编辑。

## Design Principle

Phase 2.2 不把 app 变成重型生产引擎。app 只消费资源、展示来源、选择 active
timeline，并保持旧路径降级。

```text
Production Engine
  produces .lltimeline.json

LLPlayerNext App
  imports resource
  shows timeline candidates
  activates one WordTimeline
  drives word highlight / later chunk playback
```

## Work Breakdown

### Step 1: Resource Intake Audit

- 梳理当前 `.lltimeline.json` import/export API、SQLite 持久化和 Flutter client
  暴露情况。
- 确认 app 端是否已有导入入口，若没有，设计最小入口。
- 确认 active WordTimeline 是否已经同步到旧 `word_timings` 兼容缓存。

Exit criteria:

- 明确 app 端需要改哪些 API client、state/provider、页面和组件。
- 明确无资源时的现有降级路径不变。

### Step 2: Timeline Resource Summary UI

- 在媒体/字幕相关 UI 中展示 LLTimeline 资源状态。
- 展示 active WordTimeline 的 provider、algorithm、word count、human_reviewed、
  quality readiness。
- 展示生产 artifacts：preprocessing、post_alignment、post_alignment_failure。

Exit criteria:

- 用户能判断当前高亮时间轴来自 WhisperX、MFA、MMS_FA、人工修正或旧 ASR。

### Step 3: WordTimeline Candidate Selection

- 显示候选 WordTimeline 列表。
- 支持激活 candidate timeline。
- 激活后播放器和 legacy word timing 兼容层使用该 timeline。

Exit criteria:

- 用户可以在 WhisperX/MFA/MMS_FA/人工版本之间切换。
- 激活操作失败时有明确错误，不破坏当前 active timeline。

### Step 4: Playback Binding Verification

- 验证词级高亮读取 active WordTimeline。
- 验证没有资源时仍使用现有字幕/估算/旧 word timing。
- 验证切换 active timeline 后，播放高亮能刷新。

Exit criteria:

- app 端可作为生产资源消费端使用。

### Step 5: Prepare Manual Review Entry

- 增加“人工复核/校正”入口占位。
- 展示 production-report readiness。
- 暂不实现完整拖拽编辑器，只确定入口、数据依赖和下一阶段计划。

Exit criteria:

- Phase 2.3 可以自然进入人工校正和 ChunkTimeline 生成。

## Testing

- API contract tests：LLTimeline import/export、WordTimeline summary、activate。
- Flutter/client smoke：资源状态渲染、timeline 激活、播放器高亮刷新。
- Regression：无 LLTimeline 资源、旧 ASR 轨道、估算 word timing 路径不回归。

## Open Questions

- UI 入口放在媒体详情、字幕面板、播放器工具栏，还是单独 Timeline Inspector？
- 生产资源是否要支持“关联但不导入数据库”的只读模式？
- 人工校正后的 timeline 是直接保存在数据库，还是导出为新的 `.lltimeline.json`
  resource revision？
