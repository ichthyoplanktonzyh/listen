# Phase 3.5.7 Plan: Slice Playback Window（切片回听播放器）

状态：PLANNED（2026-07-10 立项）

上游输入：
`.planning/discuss/personal-listening-dictionary-and-slice-player.zh.md`（D1–D5 与 §9 评审结论）、
`../3.5.6-intensive-practice-window/3.5.6-PLAN.md`（浮窗容器先例）、
`apps/desktop/lib/controllers/playback_actions_coordinator.dart`（`playOccurrence` 现状，L190–249）。

## Objective

把"播放一个词条的来源语境"从主播放器劫持模式（加载全片 + seek + sourceLoop）改为独立的
切片回听浮窗：独立解码实例、默认只出声音、可展开视频画面；打开时暂停主播放器，关闭后
主播放器的媒体与位置不受影响。该组件同时是 Phase 3.6 听力词典例句回听的统一播放端。

纯 Flutter 客户端工作：不改 `LexicalOccurrence` 数据模型，不改 Rust / OpenAPI 契约。

## User Value

> "我点一条来源原句，弹出的小窗只播那三秒，循环听几遍就关掉；我正在学的视频原地没动。"

## Scope

### In

- 新建 `SlicePlaybackWindow` 浮动小窗（复用 3.5.6 `IntensivePracticeWindow` 的拖动、viewport
  定位与窄窗口降级模式；组件与状态完全独立，不共享 practice 状态）。
- 独立播放实例（第二个 video_player / fvp controller）：加载 occurrence 所属媒体文件，在
  `[start_ms_snapshot, end_ms_snapshot]` 内循环；重播、播放/暂停、循环开关。
- 默认音频形态（不渲染视频画面）；"展开画面"切换显示视频。
- 跨媒体文件解析复用 `playOccurrence` 已有逻辑（linked media → 文件存在性 → 用户定位 +
  指纹验证 + registerMedia），提取为可复用 resolver，不在浮窗内重写第二份。
- 音频焦点策略：任一浮起播放源独占音频。切片窗打开 → 暂停主播放器（含精听浮窗正在驱动的
  range loop 发声）；切片窗关闭 → 不自动恢复播放，主播放器保持暂停在原位置。
- 入口迁移：所有 A 组"播放这个词的一个语境"入口（WordLearningPanel 侧面板 / 词汇本弹窗、
  词汇本全屏页、词汇详情视图、学习资产页）全部改走切片窗；实施时以
  `grep -rn playOccurrence apps/desktop/lib/` 的真实调用清单为准。
- 迁移完成后 `playOccurrence` 若无剩余调用方，删除该方法，保留提取出的 resolver。

### Out（Non-goals）

- B 组 loopRange 场景（复习卡回听、精听回放、音素/节奏 evidence 回听）不迁移，维持当前
  媒体内 sourceLoop（见讨论文档 §9：语境在当前媒体内，无劫持问题，统一是无收益重构）。
- 不改任何数据模型/契约；不加 `sense_id`；不做词典页（3.6）。
- 不做变速、AB 打点、逐字高亮等播放器功能扩展。
- 不做切片音频的物理抽取/缓存文件。

## Critical Boundary

第二解码实例是本 phase 的技术前提，必须由 Slice 0 spike 先证实：

1. fvp（`third_party/flutter/fvp` 本地 fork）+ video_player 双 controller 共存，无音频
   设备/纹理冲突；
2. 不渲染 VideoPlayer widget 时的资源占用可接受（fvp 若支持真正 audio-only decode 为加分项，
   不是阻断项）；
3. 区间循环精度（循环回起点的 gap）在听感可接受范围。

spike 失败即停止本 phase 并回报 owner 裁决降级方案（快照/恢复主播放器完整状态），**不得
自行实现降级路径**。

## Work Plan

### Slice 0 — Second-instance spike

- [ ] 最小验证：在临时 debug 入口用第二个 controller 加载本地媒体、区间循环一个 3 秒切片、
      与主播放器同时存在；记录内存/CPU 观察值与循环 gap 体感。
- [ ] 结论写入本文件末尾"Spike Notes"一节（通过/阻断/备注），阻断即停并上报。

### Slice 1 — Occurrence media resolver 提取（纯重构）

- [ ] 从 `playback_actions_coordinator.playOccurrence` 提取媒体解析段（linked media 查询、
      文件存在性、file picker、指纹验证、registerMedia）为独立可注入单元
      `OccurrenceMediaResolver`，输出"可播放的本地路径或明确失败原因"。
- [ ] `playOccurrence` 改为调用 resolver，现有行为不变；补 resolver 测试（linked media 命中、
      指纹不匹配、文件缺失三条路径）。

### Slice 2 — Slice window shell + playback core

- [ ] `SlicePlayerController`：持有第二播放实例生命周期（open → resolve → load → range loop；
      close → dispose），暴露播放/暂停/重播/展开画面状态。
- [ ] `SlicePlaybackWindow`：标题（词形 + 媒体标题快照）、句子快照文本、播放控制、音频/视频
      形态切换、关闭；拖动与 viewport 定位复用 3.5.6 模式（注意
      `intensive_practice_window_test.dart` 暴露过的 `Positioned`/`LayoutBuilder` 教训）。
- [ ] 打开即暂停主播放器；关闭释放解码实例；窗口存活期间主播放器控制不被劫持。
- [ ] controller 单测（fake 播放 adapter）+ widget 测试。

### Slice 3 — Entry migration and focus policy

- [ ] 盘点 `playOccurrence` 全部调用方（当前已知 `main.dart`、`side_panel.dart`、
      coordinator 自身；以 grep 为准），逐一改为打开切片窗。
- [ ] 焦点互斥：切片窗打开时暂停精听浮窗正在驱动的 range loop；精听浮窗重新播放时停切片窗
      发声（实现取其一，行为必须在测试中固定）。
- [ ] 删除无调用方的 `playOccurrence`；`loopOccurrence` 状态标签等死代码一并清理。
- [ ] 文件丢失/指纹不匹配在窗内呈现定位文件流程与失败文案，不静默失败。

### Slice 4 — Verification and closeout

- [ ] `flutter analyze`、`flutter test` 全量通过；`git diff` 证明无 Rust/契约变更。
- [ ] 真实媒体手工 QA 清单：同媒体切片、跨媒体切片、文件丢失定位、展开视频、与精听浮窗
      并存、窄窗口。
- [ ] CLOSEOUT、STATE、CHANGELOG；冻结 phase 文件夹。

## Exit Signals

1. 任一 A 组入口点击 occurrence：主播放器暂停且媒体/位置不变，小窗循环播放切片。
2. 跨媒体 occurrence 不再更换主播放器加载的媒体。
3. 源文件丢失时窗内可定位文件并做指纹验证，失败有明确文案，无静默死路。
4. 切片窗与精听浮窗不同时发声。
5. `playOccurrence` 劫持路径从代码库消失，B 组 loopRange 行为无回归。
6. `flutter analyze` / `flutter test` 通过，契约零变更。

## Guardrails

- 高频播放控制全部本地，不经 HTTP。
- 不修改 `LexicalOccurrence` / 后端契约；发现模型缺口记入 3.6 议题，不顺手改。
- resolver 是唯一的跨媒体定位路径，浮窗内不得复制第二份定位逻辑。
- 每个提交同步 `CHANGELOG.md`。
- 不修改冻结的 3.5.5 / 3.5.6 文档。
