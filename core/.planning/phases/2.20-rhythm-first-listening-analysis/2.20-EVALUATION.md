# Phase 2.20 Evaluation: Rhythm-First Listening Quality

状态：ACTIVE

## Evaluation Question

Phase 2.20 的评测不再只问：

```text
phone recognizer 的 PER 是多少？
```

而是问：

```text
系统是否能解释这句话为什么实际听起来难？
```

Phone-level benchmark 仍然保留，但它是 evidence quality，不是唯一产品指标。

## Benchmark Pivot: 2026-06-30

Phase 2.20 benchmark should now be organized around stress/rhythm listening quality.
The detailed research note is:

- `.planning/phases/2.20-rhythm-first-listening-analysis/2.20-BENCHMARK-RESEARCH.md`
- `.planning/phases/2.20-rhythm-first-listening-analysis/2.20-ALGORITHM-METRICS-RESEARCH.md`
- `.planning/phases/2.20-rhythm-first-listening-analysis/2.20-ACOUSTIC-FEATURE-PATH.md`
- `.planning/phases/2.20-rhythm-first-listening-analysis/2.20-ROUTE-CORRECTION.md`

Key decision:

- TIMIT/Buckeye/TED-LIUM remain useful, but they are not all the same kind of benchmark.
- TIMIT is now evidence-layer phone/timing sanity, not the main rhythm product gate.
- Helsinki Prosody / LibriTTS prosody labels are the preferred first public weak-label
  regression target for prominence/stress anchors and phrase boundaries.
- BU Radio Speech, Rhythm and Pitch Corpus, and Aix-MARSEC/ProPOSEC are optional
  human prosody gold targets if local access/licensing is available.
- Buckeye/TED-LIUM/product media remain necessary for weak groups, compression spans,
  and learner-facing hotspot usefulness because those are product judgments, not just
  ToBI-style labels.

Benchmark roles:

| Role | Candidate Material | What It Answers |
|---|---|---|
| `evidence_quality` | TIMIT, Buckeye, TED-LIUM | whether text/timing/phone evidence is trustworthy enough |
| `weak_prosody_regression` | Helsinki Prosody / LibriTTS labels | whether stress anchors and phrase boundaries drift against public weak labels |
| `human_prosody_gold` | BU Radio Speech, RaP, Aix-MARSEC/ProPOSEC | whether anchor/boundary mapping agrees with human prosody labels |
| `product_listening_qa` | Buckeye windows, TED-LIUM windows, local product media | whether weak groups, compression spans, and hotspots are learner-useful |
| `robustness_probe` | IViE, NXT Switchboard, Wav2ToBI-derived probes | later dialect/conversation/model-comparison checks |

Calibration principle:

- Current project metrics and small local smoke samples are diagnostic signals, not truth.
- Do not tune `RhythmFrame` thresholds to a tiny sample or to whichever metric is easiest to
  improve.
- Before turning a score into a closeout gate, compare it with published corpus/tool baselines
  where available, such as Helsinki Prosody model results, ToBI/prosody annotation agreement
  reports, forced-alignment boundary error ranges, or human QA agreement on product labels.
- Record whether a metric is `gold`, `silver_label`, `heuristic_proxy`, or `manual_product_qa`.
- Treat Helsinki/LibriTTS labels as automatic silver labels: useful for drift/regression, not
  sufficient proof that the learner-facing explanation is correct.

## Evaluation Layers

### Layer 1: Text And Timing Integrity

Purpose:

- 确认系统没有把错误 transcript 或错误时间窗拿去做声音解释。

Datasets:

- TED-LIUM `.stm`
- product media manual transcript
- TIMIT/Buckeye metadata where applicable

Metrics:

- transcript exact / normalized text match
- segment start/end MAE
- word timing monotonicity
- coverage

Failure meaning:

- 如果这一层失败，后续 rhythm/phone 分析都不可信。

### Layer 2: Phone Evidence Quality

Purpose:

- 衡量 CTC/phone evidence 能不能支撑局部解释。

Datasets:

- TIMIT `.PHN`
- Buckeye `.phones`

Metrics:

- PER
- coverage
- unknown symbol rate
- matched phone boundary MAE / median / p95
- insertion/deletion/substitution distribution

Failure meaning:

- High PER does not necessarily kill rhythm frame.
- High PER does limit phone-level explanation confidence.
- Unknown symbol spikes point to mapping/model/pipeline issues.

### Layer 3: Stress Anchor Quality

Purpose:

- 判断系统是否标对了用户应该优先抓的声音/语义锚点。

References:

- public weak prosody labels where available
- optional human pitch-accent/prominence/tonic-stress labels
- lexical stress from dictionary/pronunciation provider
- content-word heuristic
- manual labels for product media
- optional TIMIT word/phone timing sanity

Metrics:

- anchor precision
- anchor recall
- anchor timing overlap with word/syllable
- false-anchor rate on function words
- missed-anchor rate on content words

Manual label:

```json
{
  "case_id": "p220-example",
  "sentence_id": "s1",
  "stress_anchors": [
    {
      "text": "market",
      "word_index": 3,
      "syllable": "mar",
      "start_ms": 920,
      "end_ms": 1180,
      "importance": "primary"
    }
  ]
}
```

### Layer 4: Rhythm Group / Weak Group Quality

Purpose:

- 判断系统是否把真实听感中的强弱组织表达出来。

References:

- manual rhythm QA for product media
- Buckeye natural speech windows
- TED-LIUM manually sampled windows
- optional prosodic phrase/break labels from human prosody corpora

Metrics:

- weak group span precision
- weak group span recall
- compression span overlap IoU
- phrase boundary precision/recall/F1
- weak-group attachment error count

Manual label:

```json
{
  "weak_groups": [
    {
      "words": ["could", "have"],
      "word_range": [4, 5],
      "heard_as": "kuda",
      "evidence": ["short_duration", "function_words", "connected_speech"]
    }
  ],
  "compression_spans": [
    {
      "word_range": [4, 7],
      "start_ms": 1200,
      "end_ms": 1580,
      "reason": "four words packed into short duration"
    }
  ]
}
```

### Layer 5: Listening Explanation Quality

Purpose:

- 判断 UI/算法给出的解释是否真的帮助用户理解“为什么听不懂”。

References:

- manual listening rubric
- real product media
- sampled Buckeye/TED-LIUM windows

Rubric:

| Score | Meaning |
|---|---|
| correct | explanation matches audible evidence and is learner-useful |
| useful_but_incomplete | points to the right area but misses details |
| unclear | not obviously wrong, but not useful enough |
| misleading | explanation points to the wrong sound/word/reason |
| unsupported | explanation may be text-predicted but lacks audio evidence |

Manual label:

```json
{
  "hotspot_id": "hs1",
  "word_range": [2, 5],
  "system_explanation": "these function words are compressed before the next stress",
  "manual_score": "correct",
  "audible_evidence": "the phrase is short and unstressed; next content word is prominent",
  "notes": "phone-level detail is not needed for the default explanation"
}
```

## Dataset Roles

| Dataset | Primary role | Not suitable for |
|---|---|---|
| TIMIT | clean phone/boundary sanity, lexical stress sanity | natural connected-speech difficulty |
| Buckeye | natural speech reductions, weak groups, rhythm compression | clean transcript UI polish |
| TED-LIUM | long-form transcript/timing, public-speech rhythm smoke | phone-level gold |
| local media | product usefulness and UI manual QA | automated objective phone scoring |

## Phase 2.20 Gates

### Gate A: Resource Integrity

Required before judging quality:

- transcript/timing coverage is known
- sound_analysis exists or missing state is explicit
- rhythm_frame has provenance and confidence
- phone evidence coverage is reported separately
- scorer gate: `--min-rhythm-coverage`

### Gate B: No Misleading Default UI

Required:

- raw CTC phone labels are not default teaching labels
- low-confidence phone evidence cannot create high-confidence learner explanations by itself
- unsupported rhythm predictions are marked as predicted/tentative
- scorer gate: `--max-hotspot-unsupported-rate`

### Gate C: Minimum Product Usefulness

For a sampled product-media set:

- at least most stress anchors should be judged useful/correct by manual QA
- weak/compressed spans should point to the right region more often than not
- misleading explanations should be rare and explicitly counted
- scorer gates: `--min-annotated-sentences`, `--min-overall-useful-rate`,
  `--max-hotspot-misleading-rate`

No fixed numeric threshold is set before the first manual round. The first round establishes baseline.

## Relationship To Phase 2.19

Phase 2.19 continues to score phone evidence:

- TIMIT PER
- Buckeye PER
- unknown phone symbols
- boundary offsets

Phase 2.20 consumes that output as one input:

```text
phone evidence quality -> confidence of phone-level explanations
```

It must not collapse the whole product decision into PER.
