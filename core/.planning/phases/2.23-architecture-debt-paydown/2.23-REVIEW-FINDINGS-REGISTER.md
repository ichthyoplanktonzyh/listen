## A. 本次会话已修（2026-07-02，高优先级架构缺陷）

### A-1 ✅ 诊断归一化接缝缺陷（屈折形式落 unclassified）

- 缺陷：`diagnosis-core::diagnose` 用裸字符串把 `token.normalized`（小写表面形式，
  如 "went"）与 `entry.normalized_form`（provider 词元，如 "go"）匹配，两个
  名字空间只对无屈折词一致；用户已标记 "go" 时 "went" 仍被诊断为 unclassified。
- 修复：`diagnose` 契约新增 `lexical_keys: &HashMap<String, String>`（token
  归一化形式 → 权威词条 key）；`AppServices::diagnose_sentence` 用
  `normalize_lexical_form`（用户纠正 → provider 词元 → en-us 规则）为每个 token
  解析一次映射，同一映射用于词条查询与 core 匹配。
- 文件：`crates/diagnosis-core/src/lib.rs`、`crates/application/src/diagnosis.rs`。
- 测试：`inflected_token_resolves_through_lexical_key_map`、
  `inflected_token_without_key_map_stays_unclassified_by_surface_form`。

### A-2 ✅ 观察身份统一（悬挂引用消除）

- 缺陷：`lexical_observations` 有三套身份轴（文档 entry+sentence+form；DDL
  UNIQUE(entry,sentence)；三个 ID 生成点分别混入 created_at_ms / attempt.id /
  created_at_ms），且 `ON CONFLICT DO UPDATE SET id=excluded.id` 会替换旧观察
  ID，使 `practice_attempts.generated_observation_ids` 悬挂。
- 修复：新增 `domain::lexical_observation_id(entry, sentence)` 作为唯一身份函数
  （确定性指纹，轴 = entry + sentence）；三处生成点（API 创建 / practice 失败 /
  vocabulary import）全部收敛到该函数。同句新观察覆盖 result 但 ID 稳定，
  attempt 引用永不悬挂；import 幂等性同步改善（同 bundle 重复导入同 ID 被
  IGNORE）。upsert 中 `id=excluded.id` 保留：作用变为把历史随机 ID 行迁移到
  确定性 ID。
- 文件：`crates/domain/src/learning.rs`、`crates/application/src/vocabulary.rs`、
  `crates/application/src/practice.rs`、`crates/persistence-sqlite/src/lexical.rs`。
- 测试：`observation_id_is_deterministic_on_entry_and_sentence`（domain）+
  持久化测试扩展（同句二次观察 ID 稳定、单行、latest result wins）。
- 文档已同步：`DATA-MODEL.md` 身份表与观察语义段。

### A-3 ✅ SSE 事件枚举契约 parity（含实际漂移修复）

- 缺陷：`contracts/events/v1.schema.json` 枚举缺 `sound-line-changed` /
  `sound-line-completed`（Rust `EventName` 与 Flutter 消费者均已存在）；
  `validate-contracts.sh` 只校验 version 常量，抓不到此类漂移。
- 修复：schema 补齐两个枚举值；`api-events` 新增 `EventName::ALL` +
  编译期穷尽守卫（新增 variant 不更新 ALL 即编译错误）+ 双向 parity 测试
  （implemented↔documented 集合相等，报告具体差集）。
- 文件：`contracts/events/v1.schema.json`、`crates/api-events/src/lib.rs`。
- 测试：`event_names_match_contract_schema_bidirectionally`。

### A-4 ✅ LLTimeline 导入身份重写所有权归一 + 不变量测试

- 缺陷：remap 是手工维护的"全知函数"，且 track/media 重写散落在调用方
  （`word_timelines.rs` 四个循环）——W8 acoustic-cue 脱钩 bug 正是此类
  "新字段忘了扩 remap"。
- 修复：函数更名为 `remap_lltimeline_identity(document, track_id, media_id)`，
  吸收调用方的 track/media 重写循环，文档注释明确其为导入身份重写唯一所有者；
  新增不变量测试：以 committed fixture 为基底补齐全部资源类型（双 word
  timeline 含 parent 引用、chunk timeline+chunk、phone timeline、rhythm frame、
  acoustic-cue artifact），remap 后序列化全文档，断言任何原始 ID 零残留。
- 文件：`crates/application/src/lib.rs`、`crates/application/src/word_timelines.rs`、
  `crates/application/src/tests.rs`。
- 测试：`remap_lltimeline_identity_leaves_no_original_ids`。

### A-5 ✅ LexicalEntry 双身份轴单源硬化（桥接债第一刀）

- 缺陷：`LexicalEntry` 同时携带旧轴（kind/language/normalized_form/display_form）
  与新轴（unit.*），写读两侧均无一致性校验，冗余字段可静默漂移。
- 修复：`LexicalEntryKind::granularity()/from_granularity()` 成为 domain 内唯一
  kind↔granularity 映射（application 的手写 match 已替换）；新增
  `LexicalEntry::validate_unit_coherence()`（校验 language/granularity/
  normalized_key/display_form 四轴）+ `DomainError::LexicalUnitMismatch`；
  persistence 的 upsert（原来只查两轴）与行读取均改为完整校验，漂移行为
  从静默返回变为显式错误。
- 边界说明：本刀不删冗余字段、不改 API shape；字段删除见 C-4。
- 文件：`crates/domain/src/learning.rs`、`crates/domain/src/lib.rs`、
  `crates/application/src/lexical.rs`、`crates/persistence-sqlite/src/lexical.rs`。
- 测试：domain 4 个新测试（映射双向、一致通过、三种漂移各自报错）。

## C. 归 Phase 3.x（主体工作/设计决策，不是修补）

### C-1 📐 词组与多词单位进入诊断

- 现状：`diagnose_sentence` 只取 `LexicalEntryKind::Word`；phrase 词条、
  `ConnectedSpeech` practice target 都是一等公民，唯独诊断把句子退化为
  独立单词集合。多词序列/公式化语块是真实听力失败的高频单位。
- 归属：3.x 诊断层升级的一部分，需要 token span → phrase 词条的匹配设计。

### C-2 📐 声音证据流入诊断（"先诊断再练习"的闭合点）

- 现状：诊断的 `reasons` 是静态语言 profile 列表；RhythmFrame 已检测出的
  弱读音团/压缩区/hotspot 不进入诊断。2.21 模型锁的 layer ownership 表已
  设计该集成（RhythmFrame 拥有声音形式错配，L1 过滤/处理速度归诊断），
  未建造。
- 归属：3.x 第一优先——产品论点的核心兑现点。

### C-3 📐 词条身份对 provider 可用性的依赖（重归一化策略）

- 现状：ECDICT 词元索引未安装时走 en-us 规则回退，同一表面形式在资源
  安装前后产生不同 normalized key → 不同词条身份。词条已记录
  normalization_provider/version 溯源，但无重归一化迁移故事。
- 归属：3.x 设计决策：provider 升级/安装时的词条合并策略（利用溯源字段 +
  `lemma_overrides`），或明确接受双词条并在 UI 提供合并入口。

### C-4 📐 LexicalEntry 冗余投影字段删除（桥接债收尾）

- A-5 已让 unit 成为受校验的权威轴；彻底删除 kind/normalized_form 等冗余
  字段涉及 OpenAPI shape、Flutter model、导出 bundle v5 → v6，属于契约演进，
  与 3.x 的 API 演进合并做，避免两次破坏。

### C-5 📐 状态词元级 vs 识别词形级的张力

- 策略建议（待 3.x 确认）：status 保持词元级（用户心智负担小），识别类
  判断从词形级观察（`original_form` 已记录）聚合，不从 status 直接推。

### C-6 📐 learning_loop 纸面抽象逐切片验证

- `CorpusOccurrence`、`ContentDifficultyProfile`、`LearnerProfile`、
  `L1L2DifficultyProfile`、`RecordingAsset`、`ShadowingComparison`、
  `PlayableSegment`、`InputFit` 等约三分之一 domain 类型无持久化、无消费方。
- 工作方式约定：3.x 逐切片实现时把它们视为待证伪草案，允许改形状，
  不因"类型已在 domain"而当成约束。

### C-7 📐 SSE 事件 payload typed 化

- A-3 已守住事件名枚举；payload 仍是 Rust 侧 ad-hoc `json!` + schema 侧
  `{type: object}` + Dart 侧手写解析三方无守卫。
- 归属：3.x 大量新增事件消费前，把高频 payload（transcription/phonetic job、
  lexical changed）typed struct 化并在 schema 中定义 per-event payload。
