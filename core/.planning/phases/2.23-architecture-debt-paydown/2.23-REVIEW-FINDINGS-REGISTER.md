## A. 本次会话已修（2026-07-02，高优先级架构缺陷）

### A-1 ✅ 诊断归一化接缝缺陷（屈折形式落 unclassified）

- 缺陷：`diagnosis-core::diagnose` 用裸字符串把 `token.normalized`（小写表面形式，
  如 "went"）与 `entry.normalized_form`（provider 词元，如 "go"）匹配，两个
  名字空间只对无屈折词一致；用户已标记 "go" 时 "went" 仍被诊断为 unclassified。
- 修复：`diagnose` 契约新增 `lexical_keys: &HashMap<String, String>`（token
  归一化形式 → 权威词条 key）；`AppServices::diagnose_sentence` 用
  `normalize_lexical_form`（用户纠正 → provider 词元 → en-us 规则）为每个 token
  解析一次映射，同一映射用于词条查询与 core 匹配。
- 文件：`crates/diagnosis-core/src/lib.rs`、`crates/application/src/diagnosis.rs`。
- 测试：`inflected_token_resolves_through_lexical_key_map`、
  `inflected_token_without_key_map_stays_unclassified_by_surface_form`。

### A-2 ✅ 观察身份统一（悬挂引用消除）

- 缺陷：`lexical_observations` 有三套身份轴（文档 entry+sentence+form；DDL
  UNIQUE(entry,sentence)；三个 ID 生成点分别混入 created_at_ms / attempt.id /
  created_at_ms），且 `ON CONFLICT DO UPDATE SET id=excluded.id` 会替换旧观察
  ID，使 `practice_attempts.generated_observation_ids` 悬挂。
- 修复：新增 `domain::lexical_observation_id(entry, sentence)` 作为唯一身份函数
  （确定性指纹，轴 = entry + sentence）；三处生成点（API 创建 / practice 失败 /
  vocabulary import）全部收敛到该函数。同句新观察覆盖 result 但 ID 稳定，
  attempt 引用永不悬挂；import 幂等性同步改善（同 bundle 重复导入同 ID 被
  IGNORE）。upsert 中 `id=excluded.id` 保留：作用变为把历史随机 ID 行迁移到
  确定性 ID。
- 文件：`crates/domain/src/learning.rs`、`crates/application/src/vocabulary.rs`、
  `crates/application/src/practice.rs`、`crates/persistence-sqlite/src/lexical.rs`。
- 测试：`observation_id_is_deterministic_on_entry_and_sentence`（domain）+
  持久化测试扩展（同句二次观察 ID 稳定、单行、latest result wins）。
- 文档已同步：`DATA-MODEL.md` 身份表与观察语义段。

  - 迁移 6 处发射点（transcription / speech_jobs×3 / sound_line /
    phonetic_analysis / pronunciation route），消灭这些文件内的手写 payload。
  - 新增跨语言 golden 契约：`contracts/events/examples.json` 提交 Flutter
    typed 消费的全部 6 个事件的代表信封；Rust 侧
    `event_contract_examples_match_producers` 用真实 producer 构造并断言
    与提交文件完全相等（`UPDATE_EVENT_EXAMPLES=1` 再生成）；Dart 侧
    `test/contract/backend_event_contract_test.dart` 解析同一文件，断言
    每个信封落入 typed event 类且关键字段存活。producer 改形状 → Rust 测试
    红 → 更新 fixture → Dart 测试验证消费端仍可解析，漂移链路闭合。
- C-7 剩余（仍归 3.x 前/早期）：m18 与 pronunciation routes 的零散小事件

## C. 归 Phase 3.x（主体工作/设计决策，不是修补）

### C-1 📐 词组与多词单位进入诊断

- 现状：`diagnose_sentence` 只取 `LexicalEntryKind::Word`；phrase 词条、
  `ConnectedSpeech` practice target 都是一等公民，唯独诊断把句子退化为
  独立单词集合。多词序列/公式化语块是真实听力失败的高频单位。
- 归属：3.x 诊断层升级的一部分，需要 token span → phrase 词条的匹配设计。

### C-2 📐 声音证据流入诊断（"先诊断再练习"的闭合点）

- 现状：诊断的 `reasons` 是静态语言 profile 列表；RhythmFrame 已检测出的
  弱读音团/压缩区/hotspot 不进入诊断。2.21 模型锁的 layer ownership 表已
  设计该集成（RhythmFrame 拥有声音形式错配，L1 过滤/处理速度归诊断），
  未建造。
- 归属：3.x 第一优先——产品论点的核心兑现点。

### C-3 📐 词条身份对 provider 可用性的依赖（重归一化策略）

- 现状：ECDICT 词元索引未安装时走 en-us 规则回退，同一表面形式在资源
  安装前后产生不同 normalized key → 不同词条身份。词条已记录
  normalization_provider/version 溯源，但无重归一化迁移故事。
- 归属：3.x 设计决策：provider 升级/安装时的词条合并策略（利用溯源字段 +
  `lemma_overrides`），或明确接受双词条并在 UI 提供合并入口。

### C-4 📐 LexicalEntry 冗余投影字段删除（桥接债收尾）

- A-5 已让 unit 成为受校验的权威轴；彻底删除 kind/normalized_form 等冗余
  字段涉及 OpenAPI shape、Flutter model、导出 bundle v5 → v6，属于契约演进，
  与 3.x 的 API 演进合并做，避免两次破坏。

### C-5 📐 状态词元级 vs 识别词形级的张力
