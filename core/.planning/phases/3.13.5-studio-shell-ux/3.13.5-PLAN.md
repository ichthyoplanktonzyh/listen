## Owner 裁决（2026-07-15，本 phase 的立项依据）

Owner 确认四个痛点全部成立，且指明核心问题与设计原则：

1. **阅读不像阅读（核心）**：chip 排、段落交互密度高，没有沉浸的正文体验。
   设计原则定为**场景原生 UX**——阅读要像一个阅读器，后续听、说、写也
   各自要符合其真实场景的体验，参考外部参考库中对应项目的成熟交互。
2. 操作藏得深、入口难找（读一下/任务/听测埋在侧栏与 chip 里）。
3. 弹层/浮窗/对话框太杂（六种表面类型无统一规则，上下文跳变突兀）。
4. 任务流程繁琐费解（rubric 编辑→作答→自评→仲裁挤在 bottom sheet，
   阶段不可见）。

排期方式采纳"3.14 前插入独立 UX phase"（沿 3.35 先例），不并入 3.14 首切片。

## Objective

在 3.14/3.15 开工前建立四通道共享的 UX 底盘：裁决导航模型、收敛表面语法、
建立共享任务容器、把阅读姿态改造成真正的阅读器体验。3.13 的功能语义不变，
只重塑其承载方式；3.14/3.15 直接复用底盘而不是各自发明。

## User Value

> "我点进阅读就是在读一篇文章——正文干净、查词回听顺手不打断；要做任务时
> 我清楚自己在哪一步。以后练口语、写作也各是顺手的场景，而不是又一堆弹窗。"

## Scope

### In

- **导航模型裁决（Slice 0 把门）**：四通道是 3.35 姿态的扩展还是平级 Studio
  切换；各 Studio 入口（媒体工作台/词典/dashboard）；退出/返回语义。以
  低保真原型呈现 2 个候选方案，owner 裁决后钉死。
- **表面语法收敛**：定死"整面 / 侧栏 / 浮窗 / 文内"四类表面的使用规则，
  从现状六种收敛；现有 3.13 表面按新规则迁移（听测不再整面替换、读听差异
  不再用 dialog、任务流不再用 bottom sheet——具体归宿由规则推出）。
- **共享任务容器**：来源区/产出区/反馈区三区布局 + attempt 阶段可见
  （未作答/已提交/自评完成/可重做）；3.13 段落任务流迁入作为首个住户；
  形状按 3.14 录音循环、3.15 写作编辑器的需求预演过再定。
- **阅读器化改造**：正文排版（版心宽度、字号行距、段落节奏）；句子悬停/
  选中出现轻量工具栏（播放/任务/听测），替代 chip 排；查词保持在正文附近
  不打断阅读（对照 Read Frog 选区工具栏、Lute 查词流）。
- **Reference Matrix**：Slice 0 一并交付 `3.13.5-REFERENCE-MATRIX.md`
  （模板见参考库 §5，含"对应既有契约/不变量"与"证据等级"必填列）。
- 3.13 剩余 owner GUI 走查项并入本 phase 收口走查，避免对旧 UI 重复走查。

### Out

- 任何学习语义/证据模型/后端契约变更（3.11 事实族、observation 通道、
  reading_positions 均不动）。
- 3.35 听力工作台基线的重新设计（只在其上加导航层接缝，不重开视觉改版）。
- 3.14/3.15 的功能实现（本 phase 只为其预演容器形状，不提前做录音/写作）。
- 主题/品牌系统重做（沿用 ListenTheme）。

## Key Work

1. **Slice 0 — 低保真原型 + 导航裁决（把门）**：一次性 HTML 原型呈现
   （a）两个导航候选（姿态扩展 vs Studio 切换）、（b）阅读器化正文与文内
   工具栏、（c）共享任务容器三区布局、（d）3.14 录音循环与 3.15 写作编辑器
   在同一容器里的骨架预演。owner 走查裁决后才动 Flutter。同步交付
   Reference Matrix 与表面语法规则草案。**通过标准**：owner 对导航模型、
   表面规则、任务容器形状三项给出明确裁决。
2. **Slice 1 — 导航与入口落地**：按裁决实现一级导航心智与各 Studio 入口/
   退出；侧栏在阅读姿态下的内容相关性收敛。
3. **Slice 2 — 阅读器化正文**：排版 + 句子悬停/选中工具栏替代 chip 排；
   查词/SenseGroup/翻译渐隐保持既有语义。
4. **Slice 3 — 共享任务容器 + 3.13 任务流迁入**：三区布局、阶段可见、
   中途退出语义明确；听测与读听差异按表面规则迁移。
5. **Slice 4 — 真实媒体 GUI 走查 + closeout**：合并 3.13 剩余走查项，
   新闻+对话两类材料完整走"阅读→查词→任务→听测→差异→回听"；写
   `3.13.5-CLOSEOUT.md`；STATE/CHANGELOG/MILESTONES 按维护规则。

## Exit Signal

- 打开阅读即是干净的阅读器正文；回听/任务/听测从文内 affordance 自然进入。
- 表面语法规则成文且现有表面全部合规；无 bottom sheet 承载多阶段流程。
- 3.13 任务流在共享容器中语义不变地运行，阶段始终可见。
- 3.14 的录音循环与 3.15 的写作编辑器在原型层验证过可入住同一容器。
- owner 走查通过，3.13 遗留走查项一并清偿。

## Guardrails

- 场景原生 UX 是承载方式的改造，不是学习语义的改造；任何"顺手改一下
  语义"都出界。
- 低保真先行：Slice 0 未裁决前不写 Flutter 布局代码。
- 参考项目只借交互与信息层级，不复制品牌/文案/像素布局（3.35 规则沿用）。
- 词汇状态显示定为**词汇透镜**（owner 2026-07-15 修正："了解本篇材料自己
  的词汇情况"是核心能力，不是禁项）：干净正文与状态着色为一键切换的透镜，
  另设材料级词汇概览；默认透镜与着色浓淡由 Slice 0 原型走查裁决。仍然
  防住两个 Lute 陷阱：不引入"必须逐词处理才能清除高亮"的记账语义，
  着色的通道来源（听力证据/投影 vs 阅读标记）必须诚实标示。
- 共享容器为 3.14/3.15 预演形状，但不提前实现其功能。
